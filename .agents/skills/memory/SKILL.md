# Memory

Persistent self-improvement layer. `memory/entries/*.md` = canonical concepts; `memory/archive/` = retired; `index.md` = **derived** (regenerated by `bun .agents/skills/memory/memory.ts rebuild`, never hand-edited); `log.md` = update history. The KB lives at the repo root, data apart from the skill that manipulates it. This skill owns the write side — loads only when a memory event needs capturing. Conservative like `feedback`: most events fail the write gate; that is correct.

**Concept schema:**

    ---
    type: decision                                  # REQUIRED. correction for a fix
    title: Imperative title (the rule/fact itself)
    description: One-sentence actionable core.      # loads by default; rebuild guards ≤ 200 chars
    tags: [arch, contract]                          # coarse scoping
    timestamp: 2026-05-02                           # last meaningful change
    last_confirmed: 2026-05-02                      # bump on every re-verification (staleness surface)
    triggers: [api-contract, rename-symbol]         # ≥ 2 task words (rebuild-guarded); the discovery surface — avoid bare common words
    supersedes: 009                                 # ONLY if retiring another concept
    ---
    # Why       rationale / alternatives / what breaks if ignored
    # Evidence  source citation, the passing command, or the error it fixes

Concept ID = numeric prefix of the filename stem; entries are `NNN-slug.md` — slug derived ONCE from the title on first rebuild (a later title change does not re-rename). `title`/`description` live in frontmatter, not body. Quote any frontmatter value containing `: `, leading YAML indicators, or `"`; list values (`tags`, `triggers`) must be bracketed `[a, b]` or they parse as one string.

**Command form:** `bun .agents/skills/memory/memory.ts <cmd>` (repo KB resolved automatically). Commands: `add`, `rebuild`, `supersede`, `stale`, `prune`, `query`, `stats`, `log`. `rebuild` also renames bare `NNN.md` → `NNN-slug.md` and guards the schema — description > 200 chars or triggers < 2 prints each violation and exits 1 (index still regenerates; fix the entry, rerun).

## Step 1 — Confirm memory event, not feedback event

A memory event: retry after failure revealed the correct approach; non-obvious fact confirmed against source/docs (not from memory); justified deviation from a stated rule; user correction. Route: rule change → `feedback`. Recallable fact/decision → here. One sink per event; if both apply, feedback takes the rule, memory takes the residual fact.

## Step 2 — Apply the write gate

Write only if ALL hold: verified this session against source, a passing check, or an explicit user statement (never inference); load-bearing (recalling it later changes an action or avoids rework); not already captured (grep `memory/` first — duplicates merge, not multiply). Any fails → do not write.

## Step 3 — Write the concept

`memory.ts add` allocates the next id and writes the template (`--fix` for `type: correction`); fill frontmatter+body in template order. Triggers/tags/description live in the concept file only. After any write/edit: `memory.ts rebuild`. Write commands (`add`, `supersede`, `log`) append to `log.md`. Forgetting rebuild is the one remaining failure mode — it closes every write.

## Step 4 — Supersede on contradiction (one-in-one-out)

New concept retires an active one → `memory.ts supersede <old> <new>`: moves old to `archive/`, sets `supersedes:` on the new, logs, rebuilds. Location is the retire signal; no status field. Never leave two active concepts that disagree.

## Step 5 — Refresh on staleness

`memory.ts stale` lists concepts with `last_confirmed` older than 180 days (pass a count to override). Each: re-verify against current source before trusting. Still true → bump `last_confirmed` + `timestamp`, `rebuild`. False → Step 4 + act on the new truth. Loading is the trigger; no scheduled maintenance.

## Step 6 — Prune archive orphans

Archive serves only the supersession narrative (an active concept's `supersedes:` → one read hop). After a chain settles: `memory.ts prune` (dry-run lists orphans) → `prune --apply` deletes them. `--apply` is deletion — dry-run first, apply only with intent.

## Self-check

Memory event, not a feedback rule change; write gate passed (verified + load-bearing + non-duplicate); retire used `supersede` (no two active disagreements); every write closed with `rebuild`; no orphaned archive entries after chains settle.
