# Memory

Persistent self-improvement layer. `memory/entries/*.md` = concept documents (canonical); `memory/archive/` = retired; `index.md` = **derived** listing, regenerated by `python3 .agents/skills/memory/memory.py rebuild` (never hand-edited); `log.md` = update history. `prime` loads concepts on trigger. This skill owns the write side — never loads on every run, only when a memory event needs capturing. Conservative like `feedback`: most events fail the write gate; that's correct.

The KB lives at the repo root (`memory/`), separate from this skill folder (`.agents/skills/memory/`) — data apart from the code that manipulates it; one canonical copy per repo.

**Concept schema** — frontmatter keys:

    ---
    type: decision                                  # REQUIRED. correction for a fix
    title: Imperative title (the rule/fact itself)
    description: One-sentence actionable core.      # loads by default; rebuild inlines it into index.md
    tags: [arch, contract]                          # coarse scoping
    timestamp: 2026-05-02                           # last meaningful change
    last_confirmed: 2026-05-02                      # bump on every re-verification (staleness surface)
    triggers: [api-contract, rename-symbol]         # 2–4 task words; the discovery surface (avoid bare common words that over-fire)
    supersedes: 009                                 # ONLY if retiring another concept
    ---
    # Why       rationale / alternatives / what breaks if ignored
    # Evidence  source citation, the passing command, or the error it fixes

Concept ID = filename stem. `title`/`description` live in frontmatter, not body. Quote any frontmatter value containing `: `, leading YAML indicators, or `"` — `memory.py` parses both bare and double-quoted scalars.

**Command form.** `python3 .agents/skills/memory/memory.py <cmd>`. Resolves the repo KB automatically (`<git-toplevel>/memory`); the path is fixed in this repo. Commands: `add`, `rebuild`, `supersede`, `stale`, `prune`, `log`.

## Step 1 — Confirm memory event, not feedback event

A memory event fires when a run produced a durable, recallable learning:
- Retry after failure revealed the correct approach.
- Non-obvious fact confirmed against source/docs (not from memory).
- Deviation from a stated rule was necessary and justified.
- The user corrected you.

Route: `feedback` owns it if it should change always-on text in `AGENTS.md`, `guides/`, or a skill (rule change). `memory` owns it if it's a decision/fact worth recalling on demand but not a rule. One sink per event; if both apply, feedback takes the rule, memory takes the residual fact.

## Step 2 — Apply the write gate

Write only if ALL hold:
- Verified this session against source, a passing check, or an explicit user statement — not inference or memory.
- Load-bearing: recalling it later would change an action or avoid rework.
- Not already captured (grep `memory/` first; duplicates merge, not multiply).

Any fails → do not write.

## Step 3 — Write the concept

File: `memory/entries/NNN.md`. Run `python3 .agents/skills/memory/memory.py add` to allocate the next id and write the template (`--fix` for `type: correction`). Frontmatter+body order is the template above. Triggers/tags/description live in the concept file (single source) — NOT in index.md. After writing/editing any concept, regenerate the derived index: `python3 .agents/skills/memory/memory.py rebuild`. Write commands (`add`, `supersede`, `log`) also append to `log.md`. Forgetting rebuild is the only remaining failure mode, so it closes every write.

## Step 4 — Supersede on contradiction (one-in-one-out)

New concept contradicts/retires an active one → one command:

    python3 .agents/skills/memory/memory.py supersede <old> <new>

Moves `entries/<old>.md` → `archive/`, sets `supersedes: <old>` on the new concept, appends a Deprecation line to `log.md`, rebuilds index.md. Location is the retire signal; no status field. Never leave two active concepts that disagree.

## Step 5 — Refresh on staleness

`python3 .agents/skills/memory/memory.py stale` lists concepts with `last_confirmed` older than 180 days (default; pass a day count to override). For each: re-verify against current source before trusting. Still true → bump `last_confirmed` + `timestamp`, then `rebuild`. False → Step 4 (supersede) + act on the new truth. Loading is the trigger; no scheduled maintenance.

## Step 6 — Prune archive orphans

Archive exists only to serve the live supersession narrative (an active concept's `supersedes:` → one read hop). Concepts referenced by no active entry are dead weight git already holds, and greppable stale-truth is a footgun. After a supersession chain settles:

    python3 .agents/skills/memory/memory.py prune            # dry-run: list orphans
    python3 .agents/skills/memory/memory.py prune --apply    # delete them

`--apply` is deletion — dry-run first, apply only with intent.

## Self-check

Confirmed memory event, not a rule change for feedback; write gate passed (verified + load-bearing + non-duplicate); retiring a concept → `memory.py supersede` ran with no two active disagreements; write closed with `memory.py rebuild` (the one remaining failure mode); no orphaned archive entries after supersession chains.
