# Build a Blog App

Build a post browsing app with search, pagination, post details, and user profiles, powered by [store](/reference/store/store), [router](/reference/router/router), and [resource](/reference/resource/resource) working together.

Jump to the [Complete Code](#complete-code) for the finished application.

## What You'll Learn

- **[store](/reference/store/store)**: Centralized app state with granular reactive properties
- **[resource](/reference/resource/resource)**: Async data fetching with cache keys that trigger their own fetches
- **[router](/reference/router/router)**: Client-side routing with params, query strings, and scroll behavior
- **[signal](/reference/core/signal)**: Reactive values for the swapped page view
- **[computed](/reference/core/computed)**: Derived pagination state from resource data
- **[effect](/reference/core/effect)**: Keeping the document title in sync with the store
- **[style](/reference/css/style) / [vars](/reference/css/vars)**: Design tokens and scoped hashed classes
- **[ForEach](/reference/dom/foreach)**: Rendering lists with keyed reconciliation
- **[navigate](/reference/router/navigate)**: Programmatic navigation with query strings

The core pattern: router handlers write the store and render page components into a view [signal](/reference/core/signal). Resources derive their cache keys from store state, so a key change is the whole trigger - submit a search, turn a page, or open a post and the fetch fires by itself. No component ever calls `fetch()` manually. Components that need to move the user dispatch [navigate](/reference/router/navigate) instead.

## App State

This app uses [store](/reference/store/store) for centralized state and [resource](/reference/resource/resource) for data fetching. The store holds the search draft, the submitted query, the page number, the selected ids, and the page title. Resources derive their cache keys from store properties, so a key change is the whole trigger: submit a search or turn a page and the fetch fires by itself.

Create `src/state.ts`:

```tsx
import { effect } from "@hellajs/core";
import { resource } from "@hellajs/resource";
import { store } from "@hellajs/store";

export interface PostData {
  id: number;
  title: string;
  body: string;
  tags: string[];
  reactions: { likes: number; dislikes: number };
  views: number;
  userId: number;
  message?: string;
}

interface PostsResponse {
  posts: PostData[];
  total: number;
  skip: number;
  limit: number;
}

interface User {
  id: number;
  firstName: string;
  lastName: string;
  email: string;
  image: string;
  company: { title: string; name: string; department: string };
  message?: string;
}

export const appStore = store<{
  searchValue: string;
  query: string;
  page: number;
  postId: string | null;
  userId: string | null;
  title: string;
}>({
  searchValue: "",
  query: "",
  page: 1,
  postId: null,
  userId: null,
  title: "",
});

effect(() => (document.title = `Blog - ${appStore.title()}`));

const BASE = "https://dummyjson.com";
const cacheTime = 300000;

export const postsResource = resource<PostsResponse, string>(
  (urlPath) => fetch(`${BASE}/${urlPath}`).then((r) => r.json()),
  {
    key: () => {
      const search = appStore.query();
      const skip = (appStore.page() - 1) * 10;
      const base = search ? "posts/search" : "posts";
      const params = new URLSearchParams({ limit: "10", skip: String(skip) });
      if (search) params.set("q", search);
      return `${base}?${params}`;
    },
    refetchOnKeyChange: true,
    keepPreviousData: false,
    staleTime: 30000,
    cacheTime,
  },
);

export const postResource = resource<PostData, string | null>(
  (id) => fetch(`${BASE}/posts/${id}`).then((r) => r.json()),
  { key: () => appStore.postId(), refetchOnKeyChange: true, cacheTime },
);

export const userResource = resource<User, string | null>(
  (id) => fetch(`${BASE}/users/${id}`).then((r) => r.json()),
  { key: () => appStore.userId(), refetchOnKeyChange: true, cacheTime },
);

export const userPostsResource = resource<PostsResponse, string | null>(
  (id) => fetch(`${BASE}/users/${id}/posts`).then((r) => r.json()),
  { key: () => appStore.userId(), refetchOnKeyChange: true, cacheTime },
);
```

**Code Explanation**

- **[`store`](/reference/store/store)`<{ ... }>({ ... })`**: Creates a deeply reactive store where each property is an independent signal, typed by the generic
- **`searchValue` vs `query`**: `searchValue` is the input draft, updated on every keystroke. `query` is the submitted search, written only when the user presses Enter or the Search button. The posts key reads `query` only, so typing alone never fires a request
- **`page`**: The current page number, set from the URL by the `/posts` route handler
- **`postId` and `userId`**: Selected items for the detail and profile views. They start `null`, and a `null` key makes the fetch skip until a route sets the id
- **`title`**: The current page heading. Route handlers write it, the header reads it, and the effect below mirrors it into the browser tab
- **[`effect`](/reference/core/effect)`(() => ...)`**: Reads `appStore.title()` and re-runs whenever it changes, keeping `document.title` in sync
- **[`resource`](/reference/resource/resource)`<PostsResponse, string>`**: Creates a reactive async data container. The first type parameter is the data shape, the second is the key shape
- **`key: () => ...`**: A function reading store properties. It builds the request path from the submitted query and the page, picking the `posts/search` endpoint when a query exists and adding `q` and `skip` params. The key doubles as the cache identity
- **`refetchOnKeyChange: true`**: Turns the key into the whole trigger. The initial fetch fires on its own, and every later key change (a submitted search, a new page, a new post id) refetches automatically. No component calls `fetch()`
- **`keepPreviousData: false`**: On a key change the list data clears and the loading state shows, instead of displaying the previous page's rows while the next page loads
- **`staleTime: 30000`**: Data stays fresh for 30 seconds. Reads within that window return cached data instantly
- **`cacheTime: 300000`**: Cached data persists for 5 minutes in memory, shared across every resource with the same key
- **`postResource`, `userResource`, `userPostsResource`**: The id resources key directly on the selection. `userResource` and `userPostsResource` share the same `userId` key, so both fetch in parallel when a profile opens

## Shared Styles

Define reusable design tokens with [`vars`](/reference/css/vars) and global element styles with [`css`](/reference/css/css). Each component file adds its own [`style`](/reference/css/style) call for component-specific styles.

Create `src/theme.ts`:

```tsx
import { css, reset, vars } from "@hellajs/css";

css(reset);

export const theme = vars({
  color: {
    bg: "#f5f5f5",
    surface: "#fff",
    border: "#e0e0e0",
    text: "#333",
    muted: "#555",
    subtle: "#888",
    link: "#2563eb",
    tag: "#e8e8e8",
  },
  radius: {
    sm: "0.375rem",
    md: "0.5rem",
    pill: "1rem",
  },
});

css({
  body: {
    margin: 0,
    fontFamily: "sans-serif",
    backgroundColor: theme.color.bg,
    color: theme.color.text,
  },
  a: {
    color: theme.color.link,
    textDecoration: "none",
    "&:hover": {
      textDecoration: "underline",
    },
  },
});
```

**Code Explanation**

- **[`css`](/reference/css/css)`(reset)`**: Applies the preflight reset that ships with `@hellajs/css`, normalizing browser default styles across the app
- **[`vars`](/reference/css/vars)`({ ... })`**: Creates CSS custom properties and returns an object where each value is a `var()` reference. `theme.color.bg` resolves to `var(--color-bg)`; use it anywhere you'd use a CSS value
- **Nested objects**: `color: { bg: "..." }` becomes `--color-bg`. Dots become hyphens in the variable name. Pass a `prefix` option if the tokens could collide with another app's variables on the same page
- **[`css`](/reference/css/css)`({ body: ..., a: ... })`**: Registers global element selectors. The `a` rules give every link the theme link color with an underline on hover, so plain anchors anywhere in the app look consistent without per-component work
- **`"&:hover"`**: The `&` refers to the parent selector, producing `a:hover { text-decoration: underline }`

## Routing

The router maps URL patterns to handlers. Each handler writes the store through `$update` and swaps the page component into `currentView`, a [signal](/reference/core/signal) holding the rendered DOM. Store writes are what make the resources fetch: a new `postId` or a new `page` changes a resource key, and `refetchOnKeyChange` does the rest.

Create `src/router.tsx`:

```tsx
import { signal } from "@hellajs/core";
import { router } from "@hellajs/router";
import { Placeholder } from "./components/Placeholder";
import { PostDetail } from "./pages/PostDetail";
import { PostList } from "./pages/PostList";
import { UserProfile } from "./pages/UserProfile";
import { appStore } from "./state";

export const currentView = signal(<Placeholder message="Loading..." />);

router({
  scrollBehavior: "top",
  routes: {
    "/": "/posts",
    "/posts": (_params, query) => {
      appStore.$update({
        page: query.page ? Number(query.page) : 1,
        postId: null,
        userId: null,
        title: "Posts",
      });
      currentView(PostList());
    },
    "/posts/:id": ({ id }) => {
      appStore.$update({
        postId: id,
        userId: null,
        title: `Post ${id}`,
      });
      currentView(PostDetail());
    },
    "/users/:id": ({ id }) => {
      appStore.$update({
        postId: null,
        userId: id,
        title: `User ${id}`,
      });
      currentView(UserProfile());
    },
  },
  notFound: () => currentView(PostList()),
});
```

**Code Explanation**

- **[`signal`](/reference/core/signal)`(<Placeholder ... />)`**: `currentView` holds a DOM node, initialized to a loading placeholder that shows before the first route resolves
- **[`router`](/reference/router/router)`({ routes, ... })`**: Maps URL patterns to handler functions and starts listening for navigation immediately
- **`"/": "/posts"`**: Redirect from the root path to `/posts`
- **`appStore.$update({ ... })`**: Writes several store properties in one call. Each handler resets the ids it does not own, so navigating from a profile back to the list clears `userId` and the user resources stop being keyed
- **`query.page ? Number(query.page) : 1`**: The `/posts` handler's second argument carries the query string. The page comes from `?page=2` style URLs, defaulting to 1 - this keeps pagination shareable and back-button friendly
- **`currentView(PostList())`**: Evaluates the page component and stores its DOM in the signal. The entry point renders `{currentView}`, so the page swaps on every navigation
- **`"/posts/:id": ({ id }) => ...`**: Dynamic parameters arrive as properties of the first argument. Writing `postId` changes `postResource`'s key, which fetches the post
- **`notFound: () => ...`**: Unknown URLs render the post list instead of a blank screen
- **`scrollBehavior: "top"`**: Scrolls to the top on every navigation, so opening a post starts at its heading

## Entry Point

The entry point renders the app shell: a centered container, the store-driven heading, and the current view. The heading reads `appStore.title` directly, so it updates on every navigation without any wiring of its own.

Create `src/main.tsx`:

```tsx
import { style } from "@hellajs/css";
import { mount } from "@hellajs/dom";
import { currentView } from "./router";
import { appStore } from "./state";
import "./theme";

const container = style({
  maxWidth: "48rem",
  margin: "0 auto",
  padding: "1rem",
  h1: {
    fontSize: "1.5rem",
    marginBottom: "1rem",
  },
});

const App = (
  <div class={container}>
    <h1>{appStore.title}</h1>
    {currentView}
  </div>
);

mount(App, "#app");
```

**Code Explanation**

- **`import "./theme"`**: A side-effect import. Registering the reset, the tokens, and the global styles only needs the module to run; nothing is imported from it here
- **[`style`](/reference/css/style)`({ ..., h1: { ... } })`**: Returns a content-hashed class. Nested selectors scope under the generated class, so the `h1` rules only apply to headings inside the container
- **`{appStore.title}` and `{currentView}`**: Store properties and signals passed as children bind reactively. Both update the DOM when the value behind them changes
- **[`mount`](/reference/dom/mount)`(App, "#app")`**: Renders the app into the `#app` div from `index.html`

Start the development server to see your app in action.

```bash
npm run dev
```

Your app will be running at `http://localhost:5173`. With only the shell in place you'll see the loading placeholder; the pages that fill the view come next.

### Tags

Renders a list of tag badges using [ForEach](/reference/dom/foreach).

Create `src/components/Tags.tsx`:

```tsx
import { style } from "@hellajs/css";
import { ForEach } from "@hellajs/dom";
import { theme } from "../theme";

interface TagsProps {
  tags: string[];
}

const list = style({
  display: "flex",
  gap: "0.4rem",
  flexWrap: "wrap",
  marginTop: "0.5rem",
});

const badge = style({
  fontSize: "0.8rem",
  padding: "0.15rem 0.5rem",
  borderRadius: theme.radius.pill,
  backgroundColor: theme.color.tag,
  color: theme.color.muted,
});

export const Tags = ({ tags = [] }: TagsProps) => (
  <div class={list}>
    <ForEach each={tags} use={(tag) => <span class={badge}>{tag}</span>} />
  </div>
);
```

**Code Explanation**

- **[`ForEach`](/reference/dom/foreach)` each={tags} use={(tag) => ...}`**: Renders each item through the `use` callback. Items are keyed by an explicit `key` attribute if present, then by the item's `id` property, then by index - tags have neither, so they fall back to index keys, which is fine for a static per-post list
- **`tags = []`**: Default parameter handles a post with no tags
- **`theme.radius.pill`**: Resolves to `var(--radius-pill)` for consistent rounded badges

Displays like and view counts.

### Post

The post card: a title link, the body, tags, reactions, and a user link. Composed from the components above.

Create `src/components/Post.tsx`:

```tsx
import { style } from "@hellajs/css";
import type { PostData } from "../state";
import { theme } from "../theme";
import { Reactions } from "./Reactions";
import { Tags } from "./Tags";

interface PostProps {
  data: PostData;
}

const post = style({
  cursor: "pointer",
  marginTop: "1rem",
  h3: {
    fontSize: "1.2rem",
    marginBottom: "0",
  },
  p: {
    color: theme.color.muted,
    fontSize: "0.9rem",
  },
  ".user-link": {
    fontSize: "0.8rem",
  },
});

export const Post = ({ data }: PostProps) => {
  const { id, title, body, tags, reactions, views, userId } = data;

  return (
    <div class={post}>
      <div>
        <h3>
          <a href={`/posts/${id}`}>{title}</a>
        </h3>
        <p>{body}</p>
        <Tags tags={tags} />
        <Reactions likes={reactions?.likes} views={views} />

      </a>
    </div>
```

**Code Explanation**

## Interactive Components

These components own interaction: the search bar writes the draft into the store, and pagination navigates. Both read the store directly instead of taking props - state stays centralized, and the components stay drop-in.

### SearchBar

A search input bound to the store draft, with Enter-to-submit and clear-on-empty behavior.

Create `src/components/SearchBar.tsx`:

```tsx
import { style } from "@hellajs/css";
import { theme } from "../theme";
import { appStore } from "../state";

const search = style({
  display: "flex",
  gap: "0.5rem",
  marginBottom: "1rem",
  "& input, & button": {
    borderRadius: theme.radius.sm,
    border: `1px solid ${theme.color.border}`,
    fontSize: "0.9rem",
    padding: "0.5rem 0.75rem",
  },
  input: {
    flex: 1,
  },
});

const { searchValue } = appStore;

const submitSearch = () => appStore.query(appStore.searchValue());

export const SearchBar = () => {
  const handleKeyup = (e: KeyboardEvent) => {
    (e.key === "Enter" || searchValue() === "") && submitSearch();
  };

  return (
    <div class={search}>
      <input
        type="text"
        placeholder="Search..."
        name="search"
        value={searchValue}
        on:input={(e) => searchValue((e.target as HTMLInputElement).value)}
        on:keyup={handleKeyup}
      />
      <button on:click={submitSearch}>Search</button>
    </div>
  );
};
```

**Code Explanation**

- **`const { searchValue } = appStore`**: Destructures the store property into a local signal handle, keeping the JSX below free of repeated `appStore.` prefixes
- **`value={searchValue}`**: The signal passed as the `value` prop makes the binding two-way: the input displays `searchValue()`, and typing updates it
- **`on:input={(e) => searchValue(...)}`**: Delegated input event. Every keystroke writes the draft into the store - this is `searchValue`, not `query`, so no request fires while typing
- **`submitSearch`**: The single line that moves the draft into `query`. Writing `query` changes the posts resource key, and `refetchOnKeyChange` fires the request
- **`(e.key === "Enter" || searchValue() === "") && submitSearch()`**: Submits on Enter, and also submits whenever the input is empty on keyup - emptying the field clears the search and returns to the plain list
- **`"& input, & button"`**: Nested selector scoping both children under the generated class in one rule

### Pagination

Prev/Next controls derived from the resource data. Reads the page from the store and navigates with a query string.

Create `src/components/Pagination.tsx`:

```tsx
import { computed } from "@hellajs/core";
import { style } from "@hellajs/css";
import { navigate } from "@hellajs/router";
import { appStore, postsResource } from "../state";
import { theme } from "../theme";

const pagination = style({
  display: "flex",
  justifyContent: "center",
  alignItems: "center",
  gap: "0.5rem",
  marginTop: "1rem",
});

const pageInfo = style({
  fontSize: "0.85rem",
  color: theme.color.subtle,
  padding: "0 0.5rem",
});

const { data } = postsResource;
const { page } = appStore;

const totalPages = computed(() => {
  const posts = data();
  return posts ? Math.ceil(posts.total / 10) : 0;
});

const goToPage = (p: number) =>
  navigate("/posts", {
    query: {
      page: String(p),
    },
  });

export const Pagination = () => {
  const pages = totalPages();

  return (
    <>
      {pages > 1 && (
        <div class={pagination}>
          <button on:click={() => goToPage(Math.max(1, page() - 1))} disabled={() => page() <= 1}>
            Prev
          </button>
          <span class={pageInfo}>
            Page {page} of {pages}
          </span>
          <button
            on:click={() => goToPage(Math.min(pages, page() + 1))}
            disabled={() => page() >= pages}
          >
            Next
          </button>
        </div>
      )}
    </>
  );
};
```

**Code Explanation**

- **[`computed`](/reference/core/computed)`(() => ...)`**: Derives the total page count from the resource data. It caches until `data()` changes, and a `null` response (before the first fetch) yields 0 pages, which hides the whole control
- **[`navigate`](/reference/router/navigate)`("/posts", { query })`**: Pagination navigates instead of writing the store. The `/posts` route handler reads `query.page` back out of the URL and writes `page` itself, producing shareable `/posts?page=2` URLs
- **`Math.max(1, page() - 1)` and `Math.min(pages, page() + 1)`**: Clamp the target page so the buttons can never navigate out of range
- **`disabled={() => page() <= 1}`**: A function-valued attribute is reactive - the buttons disable and enable as the page changes, with `Prev` dead on page 1 and `Next` dead on the last page
- **`{page} of {pages}`**: `page` renders as the signal itself (reactive), while `pages` is the plain number captured above - it only needs to be current for this render, since `totalPages()` changing re-runs the component's expression
- **The fragment wrapper `<>...</>`**: A component must return a node, not a bare boolean. The conditional lives inside the fragment, and the compiler wires its signal reads into a reactive child

## Post List Page

The list page composes the search bar, the posts, and pagination. It never fetches: `postsResource` fetched itself when its key was set, and every later search or page change refetches the same way.

Create `src/pages/PostList.tsx`:

```tsx
import { computed } from "@hellajs/core";
import { ForEach } from "@hellajs/dom";
import { Pagination } from "../components/Pagination";
import { Placeholder } from "../components/Placeholder";
import { Post } from "../components/Post";
import { SearchBar } from "../components/SearchBar";
import { appStore, postsResource } from "../state";

const { isFetching, data } = postsResource;
const { searchValue } = appStore;

const posts = computed(() => data()?.posts ?? []);

export const PostList = () => (
  <>
    <SearchBar />

    {isFetching() ? (
      <Placeholder message="Loading posts..." />
    ) : posts().length > 0 ? (
      <ForEach each={posts} use={(post) => <Post data={post} />} />
    ) : (
      <Placeholder message={`No posts found "${searchValue()}".`} />
    )}

    <Pagination />
  </>
);
```

**Code Explanation**

- **`const posts = computed(() => data()?.posts ?? [])`**: A derived list that is always an array, so the length check below never fights `undefined`. It recomputes when the resource data changes
- **`{isFetching() ? ... : ... ? ... : ...}`**: Expression children that read signals are reactive by default - the compiler wraps them, so this ternary re-runs whenever `isFetching()` or `posts()` change. It covers the three states in one expression: loading, results, empty
- **[`ForEach`](/reference/dom/foreach)` each={posts}`**: The computed list renders each post through `Post`. Posts carry an `id`, so items are keyed by id: reordering or replacing the array reuses DOM nodes instead of rebuilding them
- **`searchValue()` in the empty message**: Reads the live draft so the message echoes exactly what the user typed when the search came back empty
- **`<Pagination />` rendered unconditionally**: The component itself decides visibility from the derived page count, keeping the page's markup free of pagination wiring

## Post Detail Page

The detail page reads the single-post resource. Same key-driven flow: the route wrote `postId`, the key changed, the fetch fired.

Create `src/pages/PostDetail.tsx`:

```tsx
import { BackLink } from "../components/BackLink";
import { Placeholder } from "../components/Placeholder";
import { Post } from "../components/Post";
import { postResource } from "../state";

const { isFetching, data } = postResource;

export const PostDetail = () => (
  <>
    <BackLink />

    {() => {
      const post = data();

      return (
        <div class="post-detail">
          {isFetching() ? (
            <Placeholder message="Loading post..." />
          ) : post?.body ? (
            <Post data={post} />
          ) : (
            <Placeholder message="Post not found" />
          )}
        </div>
      );
    }}
  </>
);
```

**Code Explanation**

- **`<BackLink />` outside the reactive block**: Static elements never re-render. Only the content inside the function expression updates when the resource changes
- **`{() => { ... }}`**: An explicit function child. Same reactivity as the list page's bare ternary, written as a block so `data()` can be read once into a local
- **`post?.body`**: Truthiness check on the body. The DummyJSON API answers invalid ids with a `{ message: "..." }` object rather than a 404, and that object has no `body` - so this one check routes bad ids to the not-found placeholder
- **`<Post data={post} />`**: The same card component the list page uses; the detail page just renders one of them

## User Profile Page

The profile page reads two resources at once - the user and their posts - both keyed on `userId`, both fetched in parallel by the same key change.

Create `src/pages/UserProfile.tsx`:

```tsx
import { style } from "@hellajs/css";
import { ForEach } from "@hellajs/dom";
import { BackLink } from "../components/BackLink";
import { Placeholder } from "../components/Placeholder";
import { Post } from "../components/Post";
import { userResource, userPostsResource } from "../state";
import { theme } from "../theme";

const avatar = style({
  width: "4rem",
  height: "4rem",
  borderRadius: "50%",
  objectFit: "cover",
});

const info = style({
  display: "flex",
  gap: "1rem",
  alignItems: "center",
  marginBottom: "1rem",
});

const meta = style({
  fontSize: "0.85rem",
  color: theme.color.subtle,
  p: {
    margin: "0.15rem 0",
  },
});

const { data: userData, isFetching: isFetchingUser } = userResource;
const { data: postsData, isFetching: isFetchingPosts } = userPostsResource;

export const UserProfile = () => (
  <div>
    <BackLink />

    {() => {
      const user = userData();

      const { firstName, lastName, email, image, company } = user || {};

      if (isFetchingUser()) return <Placeholder message="Loading user..." />;

      if (!user?.id) return <Placeholder message="User not found." />;

      return (
        <div>
          <div class={info}>
            <img class={avatar} src={image} alt={`${firstName} ${lastName}`} />
            <div>
              <h2 class="title" style="margin-bottom: 0.25rem">
                {firstName} {lastName}
              </h2>
              <div class={meta}>
                <p>{email}</p>
                <p>
                  {company?.title} at {company?.name}
                </p>
              </div>
            </div>
          </div>
        </div>
      );
    }}

    <h3>Recent Posts</h3>

    {() => {
      const posts = postsData()?.posts ?? [];

      return isFetchingPosts() ? (
        <Placeholder message="Loading posts..." />
      ) : posts.length > 0 ? (
        <ForEach each={posts} use={(post) => <Post data={post} />} />
      ) : (
        <Placeholder message="No posts found." />
      );
    }}
  </div>
);
```

**Code Explanation**

- **`const { data: userData, isFetching: isFetchingUser } = userResource`**: Destructuring with renames keeps the two resources' handles distinct - `userData` vs `postsData`, `isFetchingUser` vs `isFetchingPosts`
- **Two independent reactive blocks**: The user card and the posts list each live in their own function child. The user block re-renders without touching the posts block and vice versa, so a slow user fetch never rebuilds the post list
- **`const { firstName, ... } = user || {}`**: Destructures with a fallback so the fields are `undefined` rather than throwing while the first fetch is in flight
- **`isFetchingUser()` first, then `!user?.id`**: Loading wins over not-found. The DummyJSON API returns a `{ message: "..." }` object for invalid ids; that object has no `id`, so the second check catches it after loading finishes
- **`company?.title`**: Optional chaining tolerates users whose company field is missing
- **`style="margin-bottom: 0.25rem"`**: A one-off inline style string. For anything reused, a `style()` class is the tool; a single static declaration is fine inline

```tsx
import { effect } from "@hellajs/core";
import { resource } from "@hellajs/resource";
import { store } from "@hellajs/store";

export interface PostData {
  id: number;
  title: string;
  body: string;
  tags: string[];
  reactions: { likes: number; dislikes: number };
  views: number;
  userId: number;
  message?: string;
}

interface PostsResponse {
  posts: PostData[];
  total: number;
  skip: number;
  limit: number;
}

interface User {
  id: number;
  firstName: string;
  lastName: string;
  email: string;
  image: string;
  company: { title: string; name: string; department: string };
  message?: string;
}

export const appStore = store<{
  searchValue: string;
  query: string;
  page: number;
  postId: string | null;
  userId: string | null;
  title: string;
}>({
  searchValue: "",
  query: "",
  page: 1,
  postId: null,
  userId: null,
  title: "",
});

effect(() => (document.title = `Blog - ${appStore.title()}`));

const BASE = "https://dummyjson.com";
const cacheTime = 300000;

export const postsResource = resource<PostsResponse, string>(
  (urlPath) => fetch(`${BASE}/${urlPath}`).then((r) => r.json()),
  {
    key: () => {
      const search = appStore.query();
      const skip = (appStore.page() - 1) * 10;
      const base = search ? "posts/search" : "posts";
      const params = new URLSearchParams({ limit: "10", skip: String(skip) });
      if (search) params.set("q", search);
      return `${base}?${params}`;
    },
    refetchOnKeyChange: true,
    keepPreviousData: false,
    staleTime: 30000,
    cacheTime,
  },
);

export const postResource = resource<PostData, string | null>(
  (id) => fetch(`${BASE}/posts/${id}`).then((r) => r.json()),
  { key: () => appStore.postId(), refetchOnKeyChange: true, cacheTime },
);

export const userResource = resource<User, string | null>(
  (id) => fetch(`${BASE}/users/${id}`).then((r) => r.json()),
  { key: () => appStore.userId(), refetchOnKeyChange: true, cacheTime },
);

export const userPostsResource = resource<PostsResponse, string | null>(
  (id) => fetch(`${BASE}/users/${id}/posts`).then((r) => r.json()),
  { key: () => appStore.userId(), refetchOnKeyChange: true, cacheTime },
);
```

```tsx
import { signal } from "@hellajs/core";

import { Placeholder } from "./components/Placeholder";
import { PostDetail } from "./pages/PostDetail";
import { PostList } from "./pages/PostList";

import { appStore } from "./state";

export const currentView = signal(<Placeholder message="Loading..." />);

router({
  scrollBehavior: "top",
  routes: {
    "/": "/posts",
    "/posts": (_params, query) => {
      appStore.$update({
        page: query.page ? Number(query.page) : 1,
        postId: null,
        userId: null,
        title: "Posts",
      });
      currentView(PostList());
    },
    "/posts/:id": ({ id }) => {
      appStore.$update({
        postId: id,
        userId: null,
        title: `Post ${id}`,
      });
      currentView(PostDetail());
    },
    "/users/:id": ({ id }) => {
      appStore.$update({
        postId: null,
        userId: id,
        title: `User ${id}`,
      });
      currentView(UserProfile());
    },
  },
  notFound: () => currentView(PostList()),
});
```

```tsx
import { computed } from "@hellajs/core";
import { style } from "@hellajs/css";
import { navigate } from "@hellajs/router";
import { appStore, postsResource } from "../state";
import { theme } from "../theme";

const pagination = style({
  display: "flex",
  justifyContent: "center",
  alignItems: "center",
  gap: "0.5rem",
  marginTop: "1rem",
});

const pageInfo = style({
  fontSize: "0.85rem",
  color: theme.color.subtle,
  padding: "0 0.5rem",
});

const { data } = postsResource;
const { page } = appStore;

const totalPages = computed(() => {
  const posts = data();
  return posts ? Math.ceil(posts.total / 10) : 0;
});

const goToPage = (p: number) =>
  navigate("/posts", {
    query: {
      page: String(p),
    },
  });

export const Pagination = () => {
  const pages = totalPages();

  return (
    <>
      {pages > 1 && (
        <div class={pagination}>
          <button on:click={() => goToPage(Math.max(1, page() - 1))} disabled={() => page() <= 1}>
            Prev
          </button>
          <span class={pageInfo}>
            Page {page} of {pages}
          </span>
          <button
            on:click={() => goToPage(Math.min(pages, page() + 1))}
            disabled={() => page() >= pages}
          >
            Next
          </button>
        </div>
      )}
    </>
  );
};
```
