# Build an SSR Routing App

Server-render a routed app end to end: [`router`](/reference/router/router) resolves the request URL on the server, [`ssr`](/reference/ssr/ssr) stringifies the tree, [`cssText`](/reference/css/csstext) collects the styles, and the client [`hydrate`](/reference/dom/hydrate)s the **same** tree against the existing DOM, adopting nodes, never rebuilding them. One isomorphic route map drives both sides.

Jump to the [Complete Code](#complete-code) for the finished application.

## What You'll Learn

- **[`signal`](/reference/core/signal)**: Hold the currently-rendered view in a reactive view signal
- **[`router`](/reference/router/router)`({ url })`**: Resolve the request URL on the server (no `window`)
- **[`ssr`](/reference/ssr/ssr)** + **[`doc`](/reference/ssr/doc)**: Serialize the tree to HTML and wrap it into a full document
- **[`vars`](/reference/css/vars)** + **[`cssText`](/reference/css/csstext)**: vars registers custom properties and css registers rules (both platforms), and cssText collects them into one `<style>` through `doc()`
- **[`hydrate`](/reference/dom/hydrate)**: Re-bind the server-rendered tree in place (no flash, no rebuild)

This example runs on [Node](https://nodejs.org) with [Hono](https://hono.dev): `@hono/node-server` serves every request, and an esbuild build step compiles both entries (the client for the browser, the server for node) through `babel-plugin-hellajs`, the same compile pass every HellaJS app uses to turn JSX into [`HellaNode`](/reference/dom/component) objects.

## Project Setup

### Installation

Create a project folder and install the packages. This tutorial requires [Node](https://nodejs.org) 20 or later for the server.

```bash
mkdir ssr-routing && cd ssr-routing
npm init -y
npm install @hellajs/core @hellajs/dom @hellajs/router @hellajs/ssr @hellajs/css
npm install -D hono @hono/node-server esbuild @babel/core @babel/preset-typescript babel-plugin-hellajs
```

### Configuration

`package.json` marks the project as an ES module and adds the run scripts. `dev` runs the build in watch mode (it also restarts the built server on change); `start` builds once and boots.

```json
{
  "name": "ssr-routing",
  "private": true,
  "version": "0.0.0",
  "type": "module",
  "scripts": {
    "build": "node build.mjs",
    "dev": "node build.mjs --watch",
    "start": "node build.mjs && node dist/server.mjs"
  },
  "devDependencies": {
    "@babel/core": "^7.28.6",
    "@babel/preset-typescript": "^7.28.6",
    "@hono/node-server": "^2.1.3",
    "esbuild": "^0.28.2",
    "hono": "^4.13.12"
  }
}
```

JSX cannot run under raw `node`, so both entries compile up front. Create `build.mjs`:

```js
// build.mjs
import { build, context } from 'esbuild';
import { transformAsync } from '@babel/core';
import babelPluginHellajs from 'babel-plugin-hellajs';
import presetTypeScript from '@babel/preset-typescript';
import { readFile } from 'node:fs/promises';
import { spawn } from 'node:child_process';

const hellajsJsx = {
  name: 'hellajs-jsx',
  setup(build) {
    build.onLoad({ filter: /\.tsx$/ }, async (args) => {
      if (args.path.includes('node_modules')) return undefined;
      const source = await readFile(args.path, 'utf8');
      const result = await transformAsync(source, {
        filename: args.path,
        plugins: [babelPluginHellajs],
        presets: [presetTypeScript],
        sourceType: 'module',
        babelrc: false,
        configFile: false,
      });
      return { contents: result.code, loader: 'js' };
    });
  },
};

const client = {
  entryPoints: ['src/client.tsx'],
  bundle: true,
  format: 'esm',
  platform: 'browser',
  outfile: 'dist/client.js',
  plugins: [hellajsJsx],
};

const server = {
  entryPoints: ['src/server.tsx'],
  bundle: true,
  format: 'esm',
  platform: 'node',
  outfile: 'dist/server.mjs',
  external: ['@hellajs/*', 'hono', '@hono/node-server'],
  plugins: [hellajsJsx],
};

const watch = process.argv.includes('--watch');

if (watch) {
  const clientCtx = await context(client);
  const serverCtx = await context(server);
  await clientCtx.rebuild();
  await serverCtx.rebuild();
  await clientCtx.watch();
  await serverCtx.watch();
  spawn('node', ['--watch', 'dist/server.mjs'], { stdio: 'inherit' });
} else {
  // `build()` tears esbuild's service down when done; `context()` would keep
  // the process alive for incremental rebuilds.
  await build(client);
  await build(server);
}
```

**Code Explanation**

- **`hellajsJsx`**: An esbuild plugin whose `onLoad` runs every `.tsx` file through [`transformAsync`](https://babel.dev/docs/babel-core) with `babel-plugin-hellajs`, the compiler that turns JSX into HellaNode objects. `@babel/preset-typescript` strips the TypeScript annotations in the same pass
- **`client`**: Bundles `src/client.tsx` for the browser. esbuild resolves the bare `@hellajs/*` specifiers itself and inlines the runtime into `dist/client.js`
- **`server`**: Bundles `src/server.tsx` for node (`platform: "node"`) but keeps `@hellajs/*` and hono `external`, so the built server resolves them from `node_modules` at runtime and stays current with your installed versions
- **`--watch`**: Switches both entries to esbuild's incremental `context().watch()` and spawns `node --watch` on the built server, so a source edit rebuilds and restarts in one step

## The Shared App

One isomorphic module defines the view signal, the route map, and the shell. The same module is imported by the server and the client; there is no server/client fork of the routes.

The key pattern is the **view signal**: each route handler is a *pure state-setter* that updates `currentView` and does nothing else. The shell reads `currentView`, so changing the signal changes the rendered view. This shape is what makes routing isomorphic: the same handlers fire on the server (driven by `router({ url })`) and on the client (driven by `router({ routes })` + `hydrate`).

Create `src/app.tsx`:

```tsx
// src/app.tsx
import { signal } from '@hellajs/core';
import { route } from '@hellajs/router';

export const currentView = signal(<h1>Loading…</h1>);

const Home = () => <h1>Home</h1>;
const User = ({ id }) => <h1>User {id}</h1>;
const NotFound = () => <h1>Not Found</h1>;

export const routes = {
  '/': () => currentView(Home()),
  '/users/:id': (params) => currentView(User({ id: params.id })),
};

export const notFound = () => currentView(NotFound());

const activeClass = (path) => route().active(path) ? 'active' : '';

export const App = () => (
  <>
    <nav>
      <a href="/" class={activeClass('/')}>Home</a>
      <a href="/users/1" class={activeClass('/users/1')}>User</a>
    </nav>
    <main>{currentView}</main>
  </>
);
```

**Code Explanation**

- **`currentView` signal**: Holds the node for the currently-rendered view. Route handlers set it; the shell reads it
- **Pure-setter handlers** `() => currentView(View())`: They only update the signal. The matched handler fires once during `router()` on both sides, so a pure setter is idempotent and side-effect-free
- **Reactive active class**: `class={() => activeClass('/')}` wraps the getter in a reactive effect, so [`route`](/reference/router/route)`().active(href)` re-runs on every navigation. Use a function, not a plain string: a plain attribute is set once at mount and never updates

<Callout variant="error">Route handlers must be pure setters, not <code>() => mount(...)</code>. <a href="/reference/dom/mount">mount</a> needs a <code>document</code> and throws on the server. Put side effects (analytics, subscriptions) in component <a href="/reference/core/effect">effect</a> bodies, not in the handler.</Callout>

## Styles

[`vars`](/reference/css/vars) registers custom-property declarations and [`css`](/reference/css/css) registers its rules (on both platforms, the same way). [`cssText`](/reference/css/csstext) then collects both (the css-side rules in registration order, then the vars buckets) as the text for a single `<style>` tag through `doc()`'s `styles`.

Create `src/theme.js`:

```js
// src/theme.js
import { css, vars, cssText } from '@hellajs/css';

export const tokens = vars({
  color: { primary: '#2563eb', text: '#333' },
  space: { nav: '1rem' },
});

css({
  body: {
    fontFamily: 'sans-serif',
    margin: '0',
    color: tokens.color.text,
  },
  nav: {
    display: 'flex',
    gap: tokens.space.nav,
    padding: tokens.space.nav,
    borderBottom: '1px solid #e5e7eb',
    a: {
      color: tokens.color.primary,
      textDecoration: 'none',
      '&.active': {
        fontWeight: '700',
        textDecoration: 'underline',
      },
    },
  },
  main: {
    padding: tokens.space.nav,
  },
});

// The registered rule text (css rules + vars buckets), collected after the calls above.
export const stylesheet = cssText();
```

**Code Explanation**

- **[`vars`](/reference/css/vars)**`({ color: { primary, text }, … })`: Registers `--color-primary`, `--color-text`, … on both platforms and returns the `var()` proxy: nested keys join into kebab-case names (`color.primary` → `--color-primary`), so `tokens.color.primary` reads back as `var(--color-primary)`
- **[`css`](/reference/css/css)**`({ … })`: Registers the rules on both platforms; [`cssText`](/reference/css/csstext)`()` collects the generated text (rules + vars buckets). The same call injects a stylesheet on the client: one API, one collector
- **`export const stylesheet`**: The server imports it and lists it in `doc({ head: { styles } })`

## Server Rendering

The server resolves the request URL with [`router`](/reference/router/router)`({ url })`, stringifies the tree with [`ssr`](/reference/ssr/ssr), and wraps it into a full document with [`doc`](/reference/ssr/doc). Pass the request URL via the `url` option; there is no `window` on the server. Resolution is synchronous, so `currentView` already holds the matched view when `ssr` walks the tree.

A [Hono](https://hono.dev) app serves the document plus the client bundle `build.mjs` emitted.

Create `src/server.tsx`:

```tsx
// src/server.tsx
import { readFileSync } from 'node:fs';
import { Hono } from 'hono';
import { serve } from '@hono/node-server';
import { router } from '@hellajs/router';
import { ssr, doc } from '@hellajs/ssr';
import { routes, App, notFound } from './app.js';
import { stylesheet } from './theme.js';

// Serve the client bundle emitted by build.mjs. The server no longer bundles at
// startup: JSX cannot run under raw `node`, so build.mjs compiles both entries
// (client + server) before this file ever boots.
const client = readFileSync(new URL('../dist/client.js', import.meta.url), 'utf8');

const app = new Hono();

// Serve the client bundle from disk.
app.get('/client.js', (c) => c.body(client, 200, { 'content-type': 'text/javascript; charset=utf-8' }));

// One catch-all: Hono never routes. `@hellajs/router` matches the request URL
// against the shared route map, on the server and on the client alike.
app.get('*', (c) => {
  const { pathname, search } = new URL(c.req.url);

  // url overrides window.location (there is none on the server); router init
  // is synchronous, so currentView holds the matched view before ssr walks the
  // tree. The whole block is synchronous (no await between router and ssr), so
  // no second request can interleave and overwrite the router's module-level
  // signals mid-render.
  router({ routes, url: pathname + search, notFound });

  // Wrap the output so the client has an #app container to hydrate into:
  // hydrate('#app') adopts the existing nodes instead of rebuilding them.
  const body = `<div id="app">${ssr(<App />)}</div>`;

  return c.html(doc({
    lang: 'en',
    head: {
      title: 'SSR Routing',
      styles: [stylesheet],
      scripts: [{ src: '/client.js', type: 'module' }],
    },
    body,
  }));
});

serve({ fetch: app.fetch, port: 3000 });
```

**Code Explanation**

- **[`router`](/reference/router/router)`({ routes, url: pathname + search, notFound })`**: `url` overrides `window.location` for the initial resolution. An explicit `url` is re-honored on every call, so each request resolves its own URL
- **`router()` → `ssr()` with no `await` between them**: One synchronous block. No second request can interleave and overwrite the router's signals mid-render: synchronous `ssr` is concurrency-safe, so you do not need a router instance per request
- **`` `<div id="app">${ssr(<App />)}</div>` ``**: [`hydrate`](/reference/dom/hydrate)`('#app')` needs a container to adopt. `doc()` places `body` verbatim, so wrap the output in `<div id="app">`
- **[`doc`](/reference/ssr/doc)`({ head, body })`**: `styles` emits `stylesheet` as one `<style>` tag; `scripts` emits the client tag
- **`readFileSync(new URL('../dist/client.js', import.meta.url))`**: Loads the client bundle `build.mjs` emitted, relative to this file inside `dist/`
- **`app.get(path, handler)`**: Registers a Hono route. `/client.js` serves the bundle from disk; the single catch-all renders the document for every other path
- **[`serve`](https://hono.dev/docs/getting-started/nodejs)`({ fetch: app.fetch, port: 3000 })`**: Runs the Hono app on Node's HTTP server

## Client Hydration

The client omits `url`: it reads `window.location` and resolves synchronously (the same URL the server resolved), so `currentView` matches the server-rendered view and [`hydrate`](/reference/dom/hydrate) adopts the existing nodes rather than rebuilding them.

Create `src/client.tsx`:

```tsx
// src/client.tsx
import { hydrate } from '@hellajs/dom';
import { router } from '@hellajs/router';
import { routes, App, notFound } from './app.js';

router({ routes, notFound });

// afterMount fires automatically during hydrate; no flush() needed
hydrate(<App />, '#app');
```

**Code Explanation**

- **[`router`](/reference/router/router)`({ routes, notFound })` (no `url`)**: `url` is server-only. The client reads `window.location` and resolves the same URL, so the view matches the server output
- **[`hydrate`](/reference/dom/hydrate)**: Re-executes the component tree against the existing DOM (the same node passed to `ssr`), attaching effects/handlers/state without replacing nodes. `afterMount` hooks fire automatically during hydrate.

## Run the App

Start the dev build. `build.mjs` compiles both entries, watches them, and restarts the built server when a rebuild lands.

```bash
npm run dev
```

The server renders at `http://localhost:3000`. Each request renders the matched route; view-source shows the full HTML:

```bash
curl -s localhost:3000/users/1
# …<div id="app"><nav>…</nav><main><!--[--><h1>User 1</h1><!--]--></main></div>…

curl -s localhost:3000/
# …<h1>Home</h1>…
```

After the client script loads, clicking a nav link updates the view and the active class without a full reload: `hydrate` adopted the server nodes, so there is no flash and no rebuild.
