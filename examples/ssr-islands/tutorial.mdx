# Build an SSR Islands App

Render a static HTML shell on the server with [`ssr`](/reference/ssr/ssr), then make it interactive on the client without a full re-render: mount a reactive island into an empty slot the server left open. No router, no full-tree [`hydrate`](/reference/dom/hydrate) (the lightest server-rendered mode).

Jump to the [Complete Code](#complete-code) for the finished application.

## What You'll Learn

- **[`ssr`](/reference/ssr/ssr)**: Serialize a view tree to an HTML string on the server
- **[`doc`](/reference/ssr/doc)**: Wrap rendered HTML into a full document with a stylesheet and script tag
- **[`css`](/reference/css/css)**: Register styles on both platforms, collected by [`cssText`](/reference/css/csstext) for `doc()` to emit
- **[`mount`](/reference/dom/mount)**: Mount a reactive island into an empty slot the server left open

This example runs on [Node](https://nodejs.org) with [Hono](https://hono.dev): `@hono/node-server` serves the shell, and an esbuild build step compiles both entries (the client for the browser, the server for node) through `hellajs-compiler`, the same compile pass every HellaJS app uses to turn JSX into [`HellaNode`](/reference/dom/component) objects.

## Project Setup

### Installation

Create a project folder and install the packages. This tutorial requires [Node](https://nodejs.org) 20 or later for the server.

```bash
mkdir ssr-islands && cd ssr-islands
npm init -y
npm install @hellajs/core @hellajs/dom @hellajs/css @hellajs/ssr
npm install -D hono @hono/node-server esbuild hellajs-compiler
```

### Configuration

`package.json` marks the project as an ES module and adds the run scripts. `dev` runs the build in watch mode (it also restarts the built server on change); `start` builds once and boots.

```json
{
  "name": "ssr-islands",
  "private": true,
  "version": "0.0.0",
  "type": "module",
  "scripts": {
    "build": "node build.mjs",
    "dev": "node build.mjs --watch",
    "start": "node build.mjs && node dist/server.mjs"
  },
  "devDependencies": {
    "@hono/node-server": "^2.1.3",
    "esbuild": "^0.28.2",
    "hellajs-compiler": "^0.1.0",
    "hono": "^4.13.12"
  }
}
```

JSX cannot run under raw `node`, so both entries compile up front. Create `build.mjs`:

```js
// build.mjs
import { build, context } from "esbuild";
import { transform } from "hellajs-compiler";
import { readFile } from "node:fs/promises";
import { spawn } from "node:child_process";

const hellajsJsx = (target) => ({
  name: "hellajs-jsx",
  setup(build) {
    build.onLoad({ filter: /\.tsx$/ }, async (args) => {
      if (args.path.includes("node_modules")) return undefined;
      const source = await readFile(args.path, "utf8");
      const result = transform(source, {
        filename: args.path,
        lang: "tsx",
        target: target ?? "ast",
      });
      if (!result) return undefined;
      return { contents: result.code, loader: "js" };
    });
  },
});

const client = {
  entryPoints: ["src/client.tsx"],
  bundle: true,
  format: "esm",
  platform: "browser",
  outfile: "dist/client.js",
  plugins: [hellajsJsx("dom")],
};

const server = {
  entryPoints: ["src/server.tsx"],
  bundle: true,
  format: "esm",
  platform: "node",
  outfile: "dist/server.mjs",
  external: ["@hellajs/*", "hono", "@hono/node-server"],
  plugins: [hellajsJsx()],
};

const watch = process.argv.includes("--watch");

if (watch) {
  const clientCtx = await context(client);
  const serverCtx = await context(server);
  await clientCtx.rebuild();
  await serverCtx.rebuild();
  await clientCtx.watch();
  await serverCtx.watch();
  spawn("node", ["--watch", "dist/server.mjs"], { stdio: "inherit" });
} else {
  await build(client);
  await build(server);
}
```

**Code Explanation**

- **`hellajsJsx`**: An esbuild plugin whose `onLoad` runs every `.tsx` file through `hellajs-compiler`'s `transform`, the compiler that turns JSX into HellaNode objects for the server and imperative `@hellajs/dom/runtime` construction for the client. TypeScript strips natively in the same pass; a JSX-free file transforms to `null` and falls through to esbuild's own `tsx` loader
- **`client`**: Bundles `src/client.tsx` for the browser. esbuild resolves the bare `@hellajs/*` specifiers itself and inlines the runtime into `dist/client.js`
- **`server`**: Bundles `src/server.tsx` for node (`platform: "node"`) but keeps `@hellajs/*` and hono `external`, so the built server resolves them from `node_modules` at runtime and stays current with your installed versions
- **`--watch`**: Switches both entries to esbuild's incremental `context().watch()` and spawns `node --watch` on the built server, so a source edit rebuilds and restarts in one step
- **`build()` vs `context()`**: The one-shot branch uses `build()`, which tears esbuild's service down when done; `context()` would keep the process alive for incremental rebuilds

## The App Template

The shared module is pure data, no DOM: a global button rule and a static shell (a heading plus an empty `#app` slot for the island). The server renders the view with [`ssr`](/reference/ssr/ssr); the client mounts an island into the slot by selector.

Create `src/app.tsx`:

```tsx
// src/app.tsx
import { css } from "@hellajs/css";

css({
  button: {
    padding: "0.5rem 1rem",
    border: "1px solid #2563eb",
  },
});

export const App = () => (
  <div>
    <h1>SSR Islands</h1>
    <div id="app"></div>
  </div>
);
```

**Code Explanation**

- **`<div id="app"></div>`**: An empty placeholder. The client mounts a reactive island here
- **[`css`](/reference/css/css)`({ button: { ... } })`**: Registers the rules on both platforms (state-only on the server); the server entry later collects the text with [`cssText`](/reference/css/csstext)`()`
- **`App`**: A component returning JSX. The build step compiles it to a HellaNode tree; nothing parses at runtime

## Server Rendering

The server stringifies the view with [`ssr`](/reference/ssr/ssr) and wraps it into a full document with [`doc`](/reference/ssr/doc). Importing `./app` runs the module's `css()` registration; the server then calls [`cssText`](/reference/css/csstext)`()` and delivers the collected text through `doc()`'s `head.raw`, inside a `<style>` carrying the `hella-css` id: the adoption contract that keeps a hydrating client from re-registering the same rules into a second tag. A [Hono](https://hono.dev) app serves the document plus the client bundle `build.mjs` emitted.

Create `src/server.tsx`:

```tsx
// src/server.tsx
import { readFileSync } from "node:fs";
import { Hono } from "hono";
import { serve } from "@hono/node-server";
import { cssText } from "@hellajs/css";
import { ssr, doc } from "@hellajs/ssr";
import { App } from "./app";

const client = readFileSync(new URL("../dist/client.js", import.meta.url), "utf8");

const app = new Hono();

app.get("/client.js", (c) =>
  c.body(client, 200, { "content-type": "text/javascript; charset=utf-8" }),
);

app.get("*", (c) =>
  c.html(
    doc({
      lang: "en",
      head: {
        title: "SSR Islands",
        raw: `<style id="hella-css">${cssText()}</style>`,
        scripts: [{ src: "/client.js", type: "module" }],
      },
      body: ssr(App()),
    }),
  ),
);

serve({ fetch: app.fetch, port: 3000 });
```

**Code Explanation**

- **`import { App } from "./app"`**: Pulls the view from the shared module; the import also runs its `css()` registration on the server
- **[`cssText`](/reference/css/csstext)`()`**: Collects the registered CSS text at call time (after the `./app` import ran the registrations) into the `hella-css`-tagged `<style>`
- **`readFileSync(new URL('../dist/client.js', import.meta.url))`**: Loads the client bundle `build.mjs` emitted, relative to this file inside `dist/`
- **`app.get(path, handler)`**: Registers a Hono route. `/client.js` serves the bundle from disk; the catch-all renders the document
- **[`ssr`](/reference/ssr/ssr)`(App())`**: Walks the view tree to an HTML string. `App()` runs server-side; the compiled output is DOM-free
- **[`serve`](https://hono.dev/docs/getting-started/nodejs)`({ fetch: app.fetch, port: 3000 })`**: Runs the Hono app on Node's HTTP server
- **[`doc`](/reference/ssr/doc)`({ head, body })`**: Assembles a full document. `head.raw` carries the `hella-css`-tagged `<style>` verbatim; `scripts` emits each tag

## Client Enhancement

The client mounts a reactive `Counter` island into the empty `#app` slot the server left open. The island owns the count (a `<p>` bound to the signal plus an Increment button), so the server shell needs no full re-render.

Create `src/client.tsx`:

```tsx
// src/client.tsx
import { signal } from "@hellajs/core";
import { mount } from "@hellajs/dom";

const count = signal(0);

const Counter = () => (
  <>
    <p>Count: {count}</p>
    <button on:click={() => count(count() + 1)}>Increment</button>
  </>
);

mount(Counter, "#app");
```

**Code Explanation**

- **[`signal`](/reference/core/signal)`(0)`**: Holds the click count
- **`<p>Count: {count}</p>`**: A reactive text binding. Interpolating the signal creates a node that updates automatically when `count` changes
- **`on:click={() => count(count() + 1)}`**: Updates the signal value on click
- **[`mount`](/reference/dom/mount)`(Counter, "#app")`**: Renders the island into the empty slot. The server left `#app` empty, so nothing is wiped

<Callout variant="error">mount calls replaceChildren on its target: pointing it at any element the server already populated wipes that HTML. Always mount into an empty slot.</Callout>

**Good:** Target the empty server slot
```tsx
mount(Counter, "#app");
```

**Bad:** Target a populated container (wipes its contents)
```tsx
mount(Counter, "body");
```

## Run the App

Start the dev build. `build.mjs` compiles both entries, watches them, and restarts the built server when a rebuild lands.

```bash
npm run dev
```

The server renders at `http://localhost:3000`. The initial HTML contains the server-rendered shell with an empty slot:

```bash
curl -s localhost:3000
# <!DOCTYPE html>...<h1>SSR Islands</h1>...<div id="app"></div>...
```

After the client script loads, the `Counter` island mounts into `#app`. Clicking Increment updates the count reactively, without replacing the server-rendered shell.
