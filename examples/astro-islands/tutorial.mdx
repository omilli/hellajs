# Build an Astro Islands App

Run HellaJS components as first-class islands in an [Astro](https://astro.build) project: one page, three islands, three integration modes. A server-rendered JSX counter hydrates in place, a client-only `html` template tracks the cursor, and a `$ref` island binds reactive state to HTML that Astro itself rendered.

Jump to the [Complete Code](#complete-code) for the finished application.

## What You'll Learn

- **[Astro integration](/plugins/astro)**: Register the renderer and reach HellaJS components from `.astro` pages with `client:*` directives
- **[`hydrate`](/reference/dom/hydrate)**: Adopt server-rendered HTML in place on the client
- **[`html`](/reference/dom/html)**: Build client-only islands from tagged templates in plain `.ts` files
- **[`$ref`](/reference/dom/$ref)**: Bind reactive state to DOM nodes Astro rendered outside any island
- **[`style`](/reference/css/style)**: Declare scoped, content-hashed island classes right next to the markup that uses them
- **[Frontmatter styles](/plugins/astro)**: Fold page-level [`css`](/reference/css/css) calls at build into page-scoped CSS that Astro delivers itself

We'll start with a server-rendered island, then add the two client-only modes step by step so you can see what each directive changes.

## Project Setup

### Installation

Create a project folder and install Astro with the HellaJS integration.

```bash
mkdir astro-islands && cd astro-islands
npm init -y
npm install astro astro-plugin-hellajs @hellajs/core @hellajs/dom @hellajs/css
```

### Configuration

`astro.config.mjs` registers the integration. It wires the HellaJS Vite plugin (JSX and `html` templates compile to HellaNode objects) and adds a framework renderer named `astro-hellajs`.

```js
// astro.config.mjs
import { defineConfig } from 'astro/config';
import hellajs from 'astro-plugin-hellajs';

export default defineConfig({
  integrations: [hellajs()],
});
```

`tsconfig.json` opts into JSX and pulls in the HellaJS JSX types.

```json
// tsconfig.json
{
  "compilerOptions": {
    "jsx": "preserve",
    "types": ["@hellajs/dom"]
  }
}
```

`package.json` marks the project as an ES module and wires the Astro scripts.

```json
{
  "name": "astro-islands",
  "private": true,
  "version": "0.0.0",
  "type": "module",
  "scripts": {
    "dev": "astro dev",
    "build": "astro build",
    "preview": "astro preview"
  },
  "dependencies": {
    "@hellajs/core": "^1.0.11",
    "@hellajs/css": "^1.1.1",
    "@hellajs/dom": "^1.4.2",
    "astro-plugin-hellajs": "^0.1.0"
  },
  "devDependencies": {
    "astro": "^7.0.0"
  }
}
```

## Server-Rendered JSX Island

The default mode: the component renders to HTML on the server and hydrates on the client. Create `src/pages/index.astro` importing a `Counter` component and mounting it with `client:load`:

```astro
// src/pages/index.astro
---
import Counter from '../components/Counter.tsx';
---
<html lang="en">
  <head>
    <meta charset="utf-8" />
    <title>Astro Islands</title>
  </head>
  <body>
    <h1>Astro Islands</h1>

    <!-- Island 1: server-rendered JSX, adopted in place by hydrate() -->
    <Counter client:load initial={0} />
  </body>
</html>
```

Create `src/components/Counter.tsx`:

```tsx
// src/components/Counter.tsx
import { signal } from "@hellajs/core";
import { style } from "@hellajs/css";

export const counterBtn = style({
  padding: "0.5rem 1.25rem",
  fontSize: "1rem",
  cursor: "pointer",
  borderRadius: "0.375rem",
  border: "1px solid #2563eb",
  backgroundColor: "#eff6ff",
}, {
  label: "counter-btn"
});

export default function Counter({ initial = 0 }: { initial?: number }) {
  const count = signal(initial);
  return <button class={counterBtn} on:click={() => count(count() + 1)}>{count()}</button>;
}
```

**Code Explanation**

- **[`signal`](/reference/core/signal)`(initial)`**: Holds the count. `initial` arrives as a prop from the `.astro` page
- **`{count()}`**: The Babel transform wraps child expressions that call signals into reactive thunks, so the button label tracks `count` without manual wiring
- **`on:click`**: The HellaJS event prefix. Handlers attach through global event delegation after hydration
- **[`style`](/reference/css/style)`({ ... }, { label: "counter-btn" })`**: Declares the button's class in the module, above the component; `class={counterBtn}` applies the returned name. The label keeps the hashed class readable, and the hash derives from the rule text, so the server and the client always produce the same class name

When Astro renders the page, the integration's server entry runs `Counter({ initial: 0 })` and stringifies the resulting tree with [`ssr`](/reference/ssr/ssr). Reactive regions are wrapped in `<!--[-->...<!--]-->` markers. On the client, Astro's island runtime loads the component and [`hydrate`](/reference/dom/hydrate) re-runs it against the existing server DOM, attaching state and handlers in place instead of replacing the HTML.

Start the dev server and open the page:

```bash
npm run dev
```

The app serves at `http://localhost:4321`. View the page source: the button arrives with its initial label already inside it, wrapped in `<!--[-->` markers within an `<astro-island>` element.

## Client-Only Island with `html`

Cursor tracking has nothing worth server-rendering: the coordinates start at zero and only matter once a mouse is present. Mount the next island with `client:only="astro-hellajs"` and it never runs on the server: Astro emits an empty island, and `hydrate` renders fresh into it on the client.

Create `src/components/MouseTracker.ts`. Note the `.ts` extension: the Vite plugin transforms plain TypeScript files too, so `html` templates work without JSX.

```ts
// src/components/MouseTracker.ts
import { signal } from "@hellajs/core";
import { style } from "@hellajs/css";
import { html } from "@hellajs/dom";

export const tracker = style({
  marginTop: "1rem",
  padding: "1rem",
  minHeight: "3rem",
  border: "1px dashed #9ca3af",
  borderRadius: "0.375rem",
}, {
  label: "tracker"
});

export default function MouseTracker() {
  const pointerX = signal(0);
  const pointerY = signal(0);

  return html`
    <div class=${tracker} on:mousemove=${(event: MouseEvent) => {
      pointerX(event.clientX);
      pointerY(event.clientY);
    }}>
      Move your cursor here. Pointer: ${pointerX}, ${pointerY}
    </div>
  `;
}
```

Add the import and the island to `src/pages/index.astro`:

```astro
---
//... existing imports
import MouseTracker from '../components/MouseTracker.ts';
---
<!-- ... -->
<!-- Island 2: client-only html template, rendered fresh on the client -->
<MouseTracker client:only="astro-hellajs" />
```

**Code Explanation**

- **[`html`](/reference/dom/html)**: Tagged template parsed into a HellaNode tree. Interpolations become reactive bindings
- **`${pointerX}, ${pointerY}`**: Interpolating the signals themselves (not calling them) creates live text bindings that update as the cursor moves
- **`on:mousemove`**: The same event prefix as JSX, usable inside `html` templates
- **`client:only="astro-hellajs"`**: Skips the server entirely. The value is the renderer name registered by the integration; Astro requires it because it cannot detect which framework a `client:only` component belongs to
- **`tracker`**: The island's own class, declared the same way as the counter's and applied to the box through `class=${tracker}`

## Binding Astro's HTML with `$ref`

The third mode needs no island markup of its own: `$ref` reaches into HTML that Astro rendered anywhere on the page. Add a plain input and greeting paragraph to `src/pages/index.astro`, plus the island that wires them together:

```astro
---
//... existing imports
import NameSync from '../components/NameSync.ts';
---
<!-- ... -->
<!-- Plain Astro-rendered HTML that island 3 binds to from the outside -->
<label for="name-input">Name</label>
<input id="name-input" value="World" />
<p id="greeting"></p>

<!-- Island 3: client-only $ref bindings into Astro's own HTML -->
<NameSync client:only="astro-hellajs" />
```

Create `src/components/NameSync.ts`:

```ts
// src/components/NameSync.ts
import { signal } from "@hellajs/core";
import { style } from "@hellajs/css";
import { $ref, html } from "@hellajs/dom";

export const note = style({
  color: "#6b7280",
}, {
  label: "note"
});

export default function NameSync() {
  const name = signal("World");

  $ref("#name-input").on("input", (event) => {
    const input = event.target as HTMLInputElement;
    name(input.value);
  });
  $ref("#greeting").bind(() => `Hello, ${name()}!`);

  return html`
    <p class=${note}>Typing in the input above updates the greeting through a $ref binding.</p>
  `;
}
```

**Code Explanation**

- **[`$ref`](/reference/dom/$ref)`("#name-input")`**: Queries `document` at call time and wraps the first match in a chainable reference
- **`.on("input", ...)`**: Attaches a delegated listener. Every keystroke writes the field's value into the `name` signal
- **`.bind(() => ...)`**: Binds a reactive function to the element's text. The greeting updates whenever `name` changes
- **The returned `html` node**: Gives the island a small visible root; the real work happens through the two `$ref` bindings
- **`note`**: The island's own class, declared inline like the others and applied to the returned paragraph

<Callout variant="error">$ref queries document at call time. It throws on the server (no document exists), so keep $ref calls in client:only islands or client scripts. A client:load component body executes during server rendering, which is why NameSync is client:only.</Callout>

**Good:** the component using `$ref` mounted `client:only`
```astro
<NameSync client:only="astro-hellajs" />
```

**Bad:** the same component mounted `client:load` (its body runs during SSR)
```astro
<NameSync client:load />
```

## Styling the Page and the Islands

Each island module already declares its `style()` call next to the markup that uses it. That leaves the page's own rules, and the question of how everything reaches the browser: classes for islands the server renders are collected into the page's CSS at build, `client:only` islands register their rules at runtime when they load, and page-level rules fold out of the frontmatter where they stand. None of it needs a manual style tag.

Page-level global rules go in the frontmatter. Add the `css` import and call to `src/pages/index.astro`:

```astro
---
import { css } from "@hellajs/css";
//... existing island imports

css({
  body: {
    fontFamily: "system-ui, sans-serif",
    maxWidth: "42rem",
    margin: "2rem auto",
    padding: "0 1rem",
  },
  "#name-input": {
    padding: "0.375rem 0.625rem",
    fontSize: "1rem",
    borderRadius: "0.375rem",
    border: "1px solid #d1d5db",
  },
  "#greeting": {
    fontSize: "1.25rem",
    fontWeight: "600",
  },
});
---
```

**Code Explanation**

- **[`css`](/reference/css/css)`({...})`**: Registers global rules. The `#name-input` and `#greeting` selectors reach HTML that Astro itself rendered, outside any island
- **Frontmatter folding**: The integration evaluates this call at build, folds it to a no-op (its rules are already collected), and injects an import for the page's collected CSS. Astro bundles that import as a page-scoped style tag, so none of these rules ship to the client
- **Import-graph collection**: Starting from the page, the integration follows the imports the server module actually carries, so `Counter`'s co-located `style()` call is collected and spliced into a `<style id="hella-css">` in the page's head; the server-rendered button arrives styled at first paint. `MouseTracker` and `NameSync` never join that module (`client:only` skips the server entirely), so their calls stay runtime-only. At hydration the islands' re-registrations claim the delivered rules in place, so nothing duplicates

Build the app and inspect `dist/index.html`: two style tags in the head, one per channel. The `hella-css` tag carries the island classes; Astro's own page-scoped tag carries the frontmatter rules:

```html
<!-- dist/index.html (built head, abridged) -->
<style id="hella-css">
  .counter-btn-cboxgjt{cursor:pointer;background-color:#eff6ff;border:1px solid #2563eb;border-radius:.375rem;padding:.5rem 1.25rem;font-size:1rem}
  /* ...one rule per island class */
</style>
<style>

  body{max-width:42rem;margin:2rem auto;padding:0 1rem;font-family:system-ui,sans-serif}
  #name-input{border:1px solid #d1d5db;border-radius:.375rem;padding:.375rem .625rem;font-size:1rem}
  #greeting{font-size:1.25rem;font-weight:600}
</style>
```

**Code Explanation**

- **Two channels**: Island-collected rules ride the `hella-css` tag because the islands re-register those same rules at hydration: the runtime adopts the tag (claims each delivered rule against its re-registration, so nothing inserts twice), so each rule exists exactly once. The page's frontmatter rules are never re-registered, so they stay in Astro's pipeline tag
- **`client:only` islands**: `MouseTracker` and `NameSync` are absent from the collected CSS. Their `style()` calls ship inside their client bundles and register when the islands load, appending into the adopted `hella-css` tag. The class names match the page's because the hash derives from the rule text

Styles that need runtime values do not fold: move them into an island module instead. A page that must manage its CSS manually can reference [`cssText`](/reference/css/csstext), which opts it out of extraction entirely (see [Frontmatter styles](/plugins/astro)).
