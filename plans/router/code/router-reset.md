## [ ] Implement resetRouter factory reset (Code)
**Type:** Code
**Depends on:** None

### Strategy
Per `packages/router/AGENTS.md`, `lib/state.ts` holds eight singleton config signals and re-running `router()` removes the prior popstate/hashchange/click listeners via the composed `cleanupListener` (`router.ts:46,105-109`). `resetRouter()` factory-resets all of that without touching the browser URL — the URL is external state (resetting it triggers navigation; tests that need a path call `navigate()`). Reuse the existing listener-detach path rather than duplicating it, and rewrite each of the eight signals to its default through the same setter path `router()` uses. Decision point: if re-running `router({})` with an empty config already achieves exactly the eight-signal reset + listener detach, `resetRouter()` may delegate to it; otherwise implement the reset directly against the eight signals + the listener-detach helper — flag this for the worker to decide after reading `lib/router.ts` and `lib/state.ts`. Do not mutate `window.location` or `history`. Trade-off considered and rejected: also resetting the `route` signal to a blank `RouteInfo` — `route` is derived state regenerated by the next `router()`/`navigate()`, so resetting the eight config signals is sufficient.
