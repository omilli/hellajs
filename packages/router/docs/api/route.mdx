# route

A reactive [`signal`](/reference/core/signal) containing current route information including path, parameters, query, and handler.

## API

```typescript
function route(): RouteInfo

interface RouteInfo {
  handler: Handler | null;
  params: Record<string, string>;
  query: Record<string, string>;
  path: string;
  meta?: Record<string, unknown>;
  crumbs: ReadonlyArray<Crumb>;
  active: (pattern: string) => boolean;
}

interface Crumb {
  readonly segment: string;
  readonly path: string;
  readonly params: Record<string, string>;
}
```

## Basic Usage

Access the `route` signal inside a reactive context to get the current path, parameters, and query string.

```typescript
import { effect } from '@hellajs/core';
import { route } from '@hellajs/router';

effect(() => {
  const { path, params, query } = route();
  
  console.log(`Current path: ${path}`);
  
  if (params.id) {
    console.log(`User ID from params: ${params.id}`);
  }
  
  if (query.sort) {
    console.log(`Sort order from query: ${query.sort}`);
  }
});
```

## Key Concepts

### Reactive Signal

`route()` is a reactive signal that automatically updates when the current route changes, triggering any dependent computations or effects.

```typescript
effect(() => {
  console.log('Route changed to:', route().path);
  // This runs automatically when navigation occurs
});
```

### Route Information

Provides comprehensive route data including the current path, extracted parameters from route patterns, parsed query string values, and optional route metadata. Parameters automatically include inheritance from parent routes in nested structures.

```typescript
// For URL: /users/123?sort=name&page=2 (flat route)
const { path, params, query } = route();
// path: "/users/123?sort=name&page=2"
// params: { id: "123" }
// query: { sort: "name", page: "2" }

// For URL: /admin/users/123/edit (nested route with inheritance)
// Router config: /admin -> /users -> /:id -> /edit
const { path, params, query } = route();
// path: "/admin/users/123/edit"
// params: { id: "123" } (inherited from parent route)
// query: {}
```

### Route Metadata

Access metadata defined on the matched route via the `meta` property.

```typescript
import { router } from '@hellajs/router';

// Router config with meta
router({
  routes: {
    '/about': {
      meta: { title: 'About Us', section: 'info' },
      handler: () => showAbout()
    }
  }
});

// Access in effects or components
effect(() => {
  const { meta } = route();
  document.title = meta?.title || 'My App';
});
```

### Handler Reference

Contains a reference to the active route handler function. The router executes handlers automatically during route resolution. Avoid calling it manually to prevent double execution.

```typescript
effect(() => {
  const { handler } = route();
  // Inspect which handler is active, but don't call it
  if (handler) {
    console.log('Active route handler:', handler.name);
  }
});
```

### Active Link Matching

The `active` predicate tests whether a pattern matches the current route path using ancestor semantics. Pass an href-like path prefix; parent routes stay active when navigating to deeper children. Segment boundaries prevent false matches — `/admin` does not light up at `/administrators`. The root `/` is the one exception: it matches exactly, so a home link lights up only at `/` (under ancestor matching the zero-segment root would otherwise be a prefix of every path).

```typescript
import { router, route, navigate } from '@hellajs/router';

router({
  routes: {
    '/admin': {
      children: {
        '/users': () => {},
        '/settings': () => {}
      }
    }
  }
});

navigate('/admin/users');

route().active('/admin');          // true (ancestor)
route().active('/admin/users');    // true (exact)
route().active('/admin/settings'); // false
route().active('/administrators'); // false (segment boundary)
route().active('/');               // true only at '/' (root is exact, not ancestor)
```

The predicate strips query strings before matching, so `route().active('/search')` returns true at `/search?q=hello`.

### Breadcrumb Chains

The `crumbs` array exposes the parent-to-leaf chain of matched route segments. Each crumb carries the route-map key (`segment`), the cumulative matched URL (`path`), and the inherited parameters through that level (`params`). The array is empty when no route matches (`notFound` resolution).

```typescript
import { router, route, navigate } from '@hellajs/router';

router({
  routes: {
    '/admin': {
      children: {
        '/users/:id': () => {}
      }
    }
  }
});

navigate('/admin/users/123');

route().crumbs;
// [
//   { segment: '/admin',     path: '/admin',           params: {} },
//   { segment: '/users/:id', path: '/admin/users/123', params: { id: '123' } }
// ]

route().crumbs[0].path;  // '/admin' — linkable href for the parent
route().crumbs[1].params; // { id: '123' } — params at the leaf
```

Use `path` for breadcrumb links (valid hrefs including dynamic segments) and `segment` for label lookup against a metadata dictionary.

## Important Considerations

### Destructuring for Clarity

Destructure route data once at the start of effects for cleaner code.

```typescript
// ✅ Destructure once for cleaner code
effect(() => {
  const { path, params, query } = route();
  console.log('Route changed:', path);
  console.log('Route params:', params);
  console.log('Route query:', query);
});

// ✅ Use computed for derived values used in multiple places
const currentPath = computed(() => route().path);
const routeParams = computed(() => route().params);
const hasQueryParams = computed(() => Object.keys(route().query).length > 0);
```

### Route Parsing

Parameters and query values are always strings - cast to other types as needed.

```typescript
// ✅ Cast values as needed
const { params, query } = route();
const userId = parseInt(params.id);
const page = parseInt(query.page) || 1;
```

### Handler Availability

The `handler` property is `null` when no route matches and no `notFound` handler is configured.

```typescript
// ✅ Check handler exists for inspection
effect(() => {
  const { handler } = route();
  if (handler) {
    console.log('Route matched:', handler.name);
  }
});
```

### Atomic Updates

Every navigation — programmatic ([`navigate`](/reference/router/navigate)), browser back/forward (`popstate`), or hash change (`hashchange`) — writes the full resolved route into the [`route`](/reference/router/route) signal in a single update. `path`, `params`, `query`, `handler`, `meta`, and `crumbs` always describe the same matched route.

```typescript
import { effect } from '@hellajs/core';
import { router, route, navigate } from '@hellajs/router';

router({
  routes: {
    '/users/:id': () => {},
    '/about': () => {}
  }
});

effect(() => {
  const { path, params } = route();
  // Runs once per navigation — never sees path='/users/456' with stale params={}
  console.log(path, params.id);
});

navigate('/users/456');
// Logs: "/users/456" "456"
```

Init is synchronous — `route()` is fully resolved (`handler`/`params`/`query`/`path` set) the moment `router()` returns. There is no not-yet-resolved window.
