# resetRouter

Factory-resets the router singleton state to defaults and detaches all event listeners.

## API

```typescript
function resetRouter(): void
```

## Basic Usage

Use `resetRouter` to tear down routing state for session reset, HMR, or return-to-initial-state scenarios. The URL is left untouched — call `navigate` explicitly if a new path is needed.

```jsx
import { mount } from "@hellajs/dom";
import { router, navigate, resetRouter } from "@hellajs/router";

const HomePage = () => <div>Home</div>;

router({ routes: { home: () => mount(<HomePage />) } });
navigate("/home");

// Session reset / HMR / return-to-home:
resetRouter();
// Singleton signals back to defaults + listeners detached; URL untouched
```

## Key Concepts

### What gets reset

`resetRouter` resets all nine singleton signals to their defaults — the eight config signals plus the `route` signal:

- `routes` → `{}`
- `hooks` → `{}`
- `redirects` → `[]`
- `notFound` → `null`
- `mode` → `"history"`
- `scrollBehavior` → `undefined`
- `previousPath` → `"/"`
- `inheritMeta` → `false`
- `route` → default `RouteInfo`: `handler: null`, `params: {}`, `query: {}`, `path: "/"`, `meta: undefined`, `crumbs: []` (frozen), `active` predicate reattached

Reading `route()` immediately after `resetRouter()` returns these defaults, not the prior match.

### What is NOT affected

- **`window.location` and `history`** — the URL and browser history are external state; `resetRouter` does not mutate them.

### Listener cleanup

If `router()` was previously called, its popstate/hashchange and click interception listeners are detached so re-init does not double-fire handlers.
