# router

Set up client-side routing with dynamic parameters, hooks, redirects, and notFound handling.

## API

```typescript
function router(config: RouterConfig): RouteInfo

// RouterConfig shape:
// {
//   routes: Record<string, RouteValue | string>,
//   hooks?: GlobalHooks,
//   redirects?: { from: readonly string[]; to: string }[],
//   notFound?: string | (() => void),
//   mode?: 'history' | 'hash' | 'memory',
//   base?: string,
//   scrollBehavior?: ScrollBehavior,
//   intercept?: boolean,
//   inheritMeta?: boolean,
//   url?: string
// }
```
- `routes`: URL patterns mapped to handlers, handler objects with hooks, nested route objects with children, or redirect strings.
- `hooks`: Optional global hooks (`before`, `after`).
- `redirects`: Optional array of redirect objects with `from` and `to` properties.
- `notFound`: Optional handler for unmatched routes.
- `mode`: URL mode. `'history'` (default) for clean URLs, `'hash'` for `#/path` format, `'memory'` for location-less routing — no URL/history writes and no listeners; drive `route()` with `navigate()`. Browser back/forward are no-ops in memory mode.
- `base`: Base path for apps deployed under a subpath (e.g. `'/app'` when served from `https://example.com/app/`). History mode only — stripped from the URL on every read and re-added on every history commit; hash mode ignores it. Must be a `'/'`-prefixed string (invalid values throw); trailing slashes are normalized (`'/app/'` → `'/app'`). Route patterns, `navigate()` targets, and `route().path` stay base-free. Default: unset.
- `scrollBehavior`: Scroll position after navigation. `'auto'` (default), `'top'`, `'preserve'`, or a custom function.
- `intercept`: Enable automatic same-origin `<a>` click interception. Default `true`.
- `inheritMeta`: Parent-to-child meta inheritance through nested routes. Default `false` (leaf-only meta).
- `url`: Resolve against this URL instead of `window.location`. Accepts a full request URL (e.g. `req.url` in Bun.serve, like `https://host/users/7?q=1`) or a path (`/users/7?q=1`) — the origin and hash fragment are ignored. Invalid URLs throw. Used for SSR, where there is no window. Resolution is synchronous either way.
- **Returns**: The resolved initial [`RouteInfo`](/reference/router/route) — the route is matched synchronously during the call.

## Basic Usage

Define routes by mapping URL patterns to handler functions that update a signal.

```typescript
import { router, route, navigate } from "@hellajs/router";
import { signal } from "@hellajs/core";

const checkAuth = () => true;
const trackPageView = (page: string) => console.log("viewed", page);
const someAsyncCheck = () => Promise.resolve(true);
const currentView = signal("");

router({
  routes: {
    "/": () => currentView("HomePage"),
    "/users/:id": (params) => currentView(`UserProfile: ${params.id}`),
    "/files/*": (params) => currentView(`FileViewer: ${params["*"]}`),
    "/search": (params, query) => currentView(`Search: ${query.q}`)
  },
  notFound: () => currentView("NotFound")
});
```

## Key Concepts

### Route Patterns

URL patterns support dynamic parameters (`:id`) and wildcards (`*`).

```typescript
router({
  routes: {
    '/users/:id': (params) => {
      // /users/123 → params.id = '123'
      currentView(`UserProfile: ${params.id}`);
    },
    '/files/*': (params) => {
      // /files/docs/readme.txt → params['*'] = 'docs/readme.txt'
      currentView(`FileViewer: ${params['*']}`);
    }
  }
});
```

### Nested Routes

Create hierarchical route structures with `children` for automatic parameter inheritance. Nested routes are sorted by specificity: non-wildcard before wildcard, deeper segment count before shallow.

See [routing concepts](/learn/concepts/routing) for parameter inheritance, specificity ordering, and multi-level nesting.

### Navigation Mode

```typescript
// History API (default): example.com/about
router({
  routes: { '/about': () => currentView('AboutPage') }
});

// Hash mode: example.com/#/about
router({
  mode: 'hash',
  routes: { '/about': () => currentView('AboutPage') }
});

// Memory mode: no URL at all — route() is driven by navigate() alone
router({
  mode: 'memory',
  routes: { '/about': () => currentView('AboutPage') }
});

navigate('/about'); // route() updates; window.location and history are untouched
```

Memory mode is useful for tests, Storybook, and non-DOM environments. It keeps no history stack — there is no back/forward navigation.

### Hook System

Global and per-route hooks with `before` and `after` execution points.

Routes can also carry `meta` for analytics, SEO, or feature flags; `inheritMeta` cascades parent meta down the nested match chain. See [route hooks](/learn/concepts/route-hooks#route-metadata) for the cascade, per-route boundaries, and inline `navigate()` precedence.

```typescript
router({
  routes: {
    '/dashboard': {
      before: () => checkAuth(),
      handler: () => currentView('Dashboard'),
      after: () => trackPageView('dashboard')
    }
  },
  hooks: {
    before: () => console.log('Global before'),
    after: () => console.log('Global after')
  }
});
```

### Scroll Behavior

Control scroll position after navigation at three levels: global `scrollBehavior`, route-level `scroll`, and inline `navigate({ scroll })`. Priority: inline > route-level > global. Custom scroll functions receive `(to, from)` paths and return `{ top, left? }` or `null` to skip.

See [routing concepts](/learn/concepts/routing) for scroll priority and per-route overrides.

### Link Interception

The router automatically intercepts same-origin `<a href>` clicks and routes them through `navigate()` for client-side navigation. Enabled by default. Plain `<a>` tags work without any special handling.

```typescript
// ✅ Intercepted automatically — no special handling needed
// <a href="/about">About</a>
```

**Modifier keys** (`metaKey`, `ctrlKey`, `shiftKey`, `altKey`) bypass interception — they preserve the browser default (open in new tab/window).

**Non-http links** (`mailto:`, `tel:`, etc.), **cross-origin** links, `target="_blank"`, `target="_parent"`, and `download` links are never intercepted.

**Hash mode**: `<a href="#/path">` clicks are intercepted and routed through `navigate("/path")`. Hash changes that don't start with `#/` (plain in-page anchors) are ignored by the router.

**History mode**: links that differ from the current URL only by their hash fragment (e.g. in-page anchors like `#faq`) are left to the browser — the native anchor jump happens and the router state is untouched.

To disable interception, pass `intercept: false`:

```typescript
router({
  routes: { '/': () => currentView('Home') },
  intercept: false
});
```

## Important Considerations

### Input Validation

`router()` throws if `config` is `null`, `undefined`, an array, or not an object. The error message follows the shape `[router] router: config must be an object, received <value>`.

```typescript
// ❌ Throws
router(null); // [router] router: config must be an object, received null

// ✅ Valid — routes may be empty
router({ routes: {} });
```

Individual route definitions are validated leniently: malformed routes, `null` children, and non-function handlers resolve to `handler: null` rather than throwing.

### Route Resolution Priority

Resolution follows strict precedence with early exits.

- **Global redirects** (from `redirects` array)
- **Route map redirects** (string values in routes)
- **Nested routes** (prioritized over flat routes)
- **Flat routes** (traditional route matching)
- **Not found handler**

Within nested routes, specific patterns take precedence over wildcards.

### Router Return Value

`router()` resolves the initial route synchronously and returns the matched [`RouteInfo`](/reference/router/route). `handler`, `params`, `query`, and `path` are all set when the call returns.

```typescript
import { effect } from "@hellajs/core";

// ✅ The return value is the resolved route — read it directly
const showUser = (params: Record<string, string>) => console.log(params);
const { handler, params } = router({ routes: { '/users/:id': (params) => showUser(params) } });
console.log(handler); // the matched handler function

// ✅ Or react to later navigations inside an effect
const showHome = () => console.log('home');
router({ routes: { '/': () => showHome() } });
effect(() => {
  const { path } = route();
  console.log(`Now at ${path}`);
});
```

For SSR, pass the request URL so the router resolves against it instead of `window.location` (absent on the server):

```typescript
// server: pathname + search from the incoming request
const routes = { '/': () => {} };
const { pathname, search } = new URL('https://example.com/users/7?q=1');
router({ routes, url: pathname + search });
```

### Parameter Types

All route parameters and query values are strings. Cast to other types as needed.

```typescript
router({
  routes: {
    '/users/:id': ({ id }) => {
      const userId = parseInt(id ?? "0"); // params are strings — cast as needed
    }
  }
});
```

### Arity-Based Dispatch Behavior

Handlers and hooks are typed `(params: Params, query: Params) => unknown`. On dynamic routes (which have path parameters) both arguments are always passed. For static routes (no path parameters), the router uses function parameter arity (`fn.length`) to determine arguments:

- If a function declares 2 or more parameters (e.g. `(params, query) => ...`), the first argument (`params`) will be `undefined`, and the second argument will be the parsed `query` object.
- If a function declares 0 or 1 parameter (e.g. `(query) => ...`), the first argument will be the parsed `query` object — even though the type labels that parameter `params`.

To ensure consistency and prevent errors, always declare handlers and hooks using the full `(params, query)` signature when you need to access query parameters:

```typescript
// ❌ Dangerous: assumes query is always first argument, will fail on dynamic routes
const searchHandler = (query) => {
  console.log(query.q)
}

// ✅ Recommended: consistent across all route types
const searchHandler = (params, query) => {
  console.log(query?.q)
}
```

### Hook Returns

`before` hooks can block or redirect navigation by returning specific values:

| Return | Behavior |
|---|---|
| `void` / `true` / `undefined` | Proceed — handler executes normally |
| `false` | Cancel — navigation is blocked, URL unchanged |
| `string` | Redirect — navigates to the returned path |
| `throw` | Cancel — navigation is blocked, error logged |
| `Promise` | Cannot block — treated as proceed, rejection `.catch`-logged |

```typescript
const authState = signal({ authenticated: false });
const isAuthenticated = () => authState().authenticated;
const currentView = (view: string) => console.log(view);

router({
  routes: {
    '/protected': {
      before: () => {
        if (!isAuthenticated()) return false;
      },
      handler: () => {
        currentView('ProtectedPage');
      }
    }
  }
});
```

Async guards cannot block — guard the handler too:

```typescript
router({
  routes: {
    '/protected': {
      before: async () => {
        if (!isAuthenticated()) await navigate('/login');
      },
      handler: () => {
        if (!authState().authenticated) return;
        currentView('ProtectedPage');
      }
    }
  }
});
```

On `false` or throw in a popstate/hashchange event, the router restores the previous URL via `replaceState`.

### Global Redirects

Use the `redirects` array for complex redirect patterns with multiple source paths.

```typescript
router({
  routes: {
    '/dashboard': () => currentView('Dashboard')
  },
  redirects: [
    { from: ['/home', '/start', '/welcome'], to: '/dashboard' }
  ]
});
```

Redirect chains stop after 20 hops — a cyclic configuration (including mutually redirecting guards) logs `[router] redirect loop detected` and cancels the navigation with the URL unchanged, instead of overflowing the stack.

### Error Handling

Sync errors thrown in `before` hooks cancel navigation — the handler does not execute and the URL remains unchanged. The error is logged with a `[router]` prefix and does not propagate to user code.

```typescript
router({
  routes: {
    '/dashboard': {
      before: () => {
        throw new Error('Guard failed'); // Cancels navigation
      },
      handler: () => currentView('Dashboard') // Never runs
    }
  }
});
```

Errors in `after` hooks are logged but do not affect the already-completed navigation.

Async hook rejections are caught and logged — they cannot block navigation.

```typescript
router({
  routes: {},
  hooks: {
    before: async () => {
      await someAsyncCheck();
    }
  }
});
// Rejection is `.catch`-logged; navigation proceeds
```

For recovery patterns, see [Route Guards](/learn/concepts/route-hooks).
