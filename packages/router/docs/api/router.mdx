# router

Set up client-side routing with dynamic parameters, hooks, redirects, and notFound handling.

## API

```typescript
function router(config: RouterConfig): RouteInfo

// RouterConfig shape:
// {
//   routes: Record<string, RouteValue | string>,
//   hooks?: GlobalHooks,
//   redirects?: { from: string[]; to: string }[],
//   notFound?: string | (() => void),
//   mode?: 'history' | 'hash',
//   scrollBehavior?: ScrollBehavior,
//   intercept?: boolean
// }
```
- `routes`: URL patterns mapped to handlers, handler objects with hooks, nested route objects with children, or redirect strings.
- `hooks`: Optional global hooks (`before`, `after`).
- `redirects`: Optional array of redirect objects with `from` and `to` properties.
- `notFound`: Optional handler for unmatched routes.
- `mode`: URL mode. `'history'` (default) for clean URLs, `'hash'` for `#/path` format.
- `scrollBehavior`: Scroll position after navigation. `'auto'` (default), `'top'`, `'preserve'`, or a custom function.
- **Returns**: The initial [`RouteInfo`](/reference/router/route) (handler is `null` until microtask resolves).

## Basic Usage

Define routes by mapping URL patterns to handler functions that update a signal.

```typescript
import { router } from "@hellajs/router";
import { signal } from "@hellajs/core";

const currentView = signal(null);

router({
  routes: {
    "/": () => currentView("HomePage"),
    "/users/:id": (params) => currentView(`UserProfile: ${params.id}`),
    "/files/*": (params) => currentView(`FileViewer: ${params["*"]}`),
    "/search": (params, query) => currentView(`Search: ${query.q}`)
  },
  notFound: () => currentView("NotFound")
});
```

## Key Concepts

### Route Patterns

URL patterns support dynamic parameters (`:id`) and wildcards (`*`).

```typescript
router({
  routes: {
    '/users/:id': (params) => {
      // /users/123 → params.id = '123'
      currentView(`UserProfile: ${params.id}`);
    },
    '/files/*': (params) => {
      // /files/docs/readme.txt → params['*'] = 'docs/readme.txt'
      currentView(`FileViewer: ${params['*']}`);
    }
  }
});
```

### Nested Routes

Create hierarchical route structures with `children` for automatic parameter inheritance.

```typescript
const currentView = signal(null);

router({
  routes: {
    "/admin": {
      handler: () => currentView("AdminDashboard"),
      before: () => checkAuth(),
      children: {
        "/users": {
          handler: () => currentView("UsersList"),
          children: {
            "/:id": (params) => currentView(`UserDetail: ${params.id}`)
          }
        },
        "/settings": () => currentView("AdminSettings")
      }
    }
  }
});

// /admin → AdminDashboard
// /admin/users → UsersList
// /admin/users/123 → UserDetail: 123 (params inherited)
// /admin/settings → AdminSettings
```

### Navigation Mode

```typescript
// History API (default): example.com/about
router({
  routes: { '/about': () => currentView('AboutPage') }
});

// Hash mode: example.com/#/about
router({
  mode: 'hash',
  routes: { '/about': () => currentView('AboutPage') }
});
```

### Hook System

Global and per-route hooks with `before` and `after` execution points.

```typescript
router({
  routes: {
    '/dashboard': {
      before: () => checkAuth(),
      handler: () => currentView('Dashboard'),
      after: () => trackPageView('dashboard')
    }
  },
  hooks: {
    before: () => console.log('Global before'),
    after: () => console.log('Global after')
  }
});
```

### Route Metadata

Attach metadata to routes for analytics, SEO, or feature flags. Access via [`route()`](/reference/router/route).meta.

```typescript
router({
  routes: {
    '/about': {
      meta: { title: 'About Us', requiresAuth: false },
      handler: () => currentView('About')
    },
    '/admin': {
      meta: { title: 'Admin Panel', requiresAuth: true },
      before: () => checkAuth(),
      handler: () => currentView('Admin')
    }
  }
});

// Access in effects via [`effect`](/reference/core/effect)
effect(() => {
  document.title = route().meta?.title || 'My App';
});
```

### Scroll Behavior

Control scroll position after navigation globally or per-route.

```typescript
// Global scroll behavior
router({
  scrollBehavior: 'top',
  routes: { /* ... */ }
});

// Custom scroll function
router({
  scrollBehavior: (to, from) => {
    if (to.startsWith('/docs')) return { top: 100 };
    return null;
  },
  routes: { /* ... */ }
});

// Route-level override
router({
  scrollBehavior: 'top',
  routes: {
    '/feed': {
      scroll: 'preserve',
      handler: () => currentView('Feed')
    },
    '/chat': {
      scroll: false,
      handler: () => currentView('Chat')
    }
  }
});
```

### Link Interception

The router automatically intercepts same-origin `<a href>` clicks and routes them through `navigate()` for client-side navigation. Enabled by default. Plain `<a>` tags work without any special handling.

```typescript
// ✅ Intercepted automatically — no special handling needed
// <a href="/about">About</a>
```

**Modifier keys** (`metaKey`, `ctrlKey`, `shiftKey`, `altKey`) bypass interception — they preserve the browser default (open in new tab/window).

**Non-http links** (`mailto:`, `tel:`, etc.), **cross-origin** links, `target="_blank"`, `target="_parent"`, and `download` links are never intercepted.

**Hash mode**: `<a href="#/path">` clicks are intercepted and routed through `navigate("/path")`.

To disable interception, pass `intercept: false`:

```typescript
router({
  routes: { '/': () => currentView('Home') },
  intercept: false
});
```

## Important Considerations

### Route Resolution Priority

Resolution follows strict precedence with early exits.

- **Global redirects** (from `redirects` array)
- **Route map redirects** (string values in routes)
- **Nested routes** (prioritized over flat routes)
- **Flat routes** (traditional route matching)
- **Not found handler**

Within nested routes, specific patterns take precedence over wildcards.

### Router Return Value

`router()` returns the current [`RouteInfo`](/reference/router/route) immediately, but the first route resolution is deferred via `queueMicrotask`. The returned value has `handler: null` until the microtask fires.

```typescript
// ❌ handler is null immediately after router() returns
const { handler } = router({ routes: { '/': () => showHome() } });
console.log(handler); // null

// ✅ Use effect to respond to the resolved route
router({ routes: { '/': () => showHome() } });
effect(() => {
  const { handler } = route();
  if (handler) handler();
});
```

### Parameter Types

All route parameters and query values are strings. Cast to other types as needed.

```typescript
'/users/:id': (params) => {
  const userId = parseInt(params.id);
  // ...
}
```

### Arity-Based Dispatch Behavior

When invoking hooks or handlers for static routes (which have no path parameters), the router uses function parameter arity (`fn.length`) to determine arguments:

- If a function declares 2 or more parameters (e.g. `(params, query) => ...`), the first argument (`params`) will be `undefined`, and the second argument will be the parsed `query` object.
- If a function declares 0 or 1 parameter (e.g. `(query) => ...`), the first argument will be the parsed `query` object.

To ensure consistency and prevent errors, always declare handlers and hooks using the full `(params, query)` signature when you need to access query parameters:

```typescript
// ❌ Dangerous: assumes query is always first argument, will fail on dynamic routes
const searchHandler = (query) => {
  console.log(query.q)
}

// ✅ Recommended: consistent across all route types
const searchHandler = (params, query) => {
  console.log(query?.q)
}
```

### Hook Returns

`before` hooks execute before route handlers but do not block handler execution. Use the [`route()`](/reference/router/route) signal or shared state to communicate between hooks and handlers.

```typescript
const authState = signal({ authenticated: false });

'/protected': {
  before: () => {
    if (!isAuthenticated()) navigate('/login');
  },
  handler: () => {
    if (!authState().authenticated) return;
    currentView('ProtectedPage');
  }
}
```

### Global Redirects

Use the `redirects` array for complex redirect patterns with multiple source paths.

```typescript
router({
  routes: {
    '/dashboard': () => currentView('Dashboard')
  },
  redirects: [
    { from: ['/home', '/start', '/welcome'], to: '/dashboard' }
  ]
});
```

### Error Handling

Router hooks use non-blocking error handling. Errors are logged but don't prevent navigation. See the [routing concepts](/learn/concepts/routing#route-guards) page for error recovery patterns.
