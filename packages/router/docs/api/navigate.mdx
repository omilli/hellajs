# navigate

Programmatically navigate to routes with dynamic parameters, query strings, scroll control, and metadata.

## API

```typescript
function navigate<T extends string>(
  path: T,
  options?: {
    params?: ExtractParams<T>;
    query?: Record<string, string>;
    replace?: boolean;
    scroll?: ScrollBehavior | false;
    meta?: Record<string, unknown>;
  }
): void
```

## Basic Usage

Use `navigate` to trigger navigation from event handlers, effects, or anywhere in your application logic.

```typescript
import { navigate } from "@hellajs/router";

// Navigate to a static path
navigate("/dashboard");

// Substitute route parameters
// Navigates to /posts/hello-world
navigate("/posts/:slug", { params: { slug: "hello-world" } });

// Add query parameters
// Navigates to /search?q=reactive
navigate("/search", { query: { q: "reactive" } });
```

## Key Concepts

### params

Route parameters for `:param` pattern substitution with automatic URL encoding.

```typescript
navigate('/users/:id/posts/:postId', {
  params: { id: '123', postId: 'hello-world' }
}); // Results in: /users/123/posts/hello-world

// Special characters are automatically URL-encoded
navigate('/search/:term', {
  params: { term: 'hello world & more!' }
}); // Results in: /search/hello%20world%20%26%20more!
```

**Parameter Behavior:**
- Parameters are **URL-encoded automatically**
- **Unused parameters are ignored** (no error thrown)
- **Missing parameters are removed from URL** (`:param` patterns cleaned)

### Wildcard Substitution

Wildcard routes use the special `"*"` key for path substitution. Unlike `:param` values, wildcard values are inserted raw (not URL-encoded) because they represent path segments that may contain `/`.

```typescript
// Navigate to wildcard route
navigate('/files/*', {
  params: { '*': 'docs/readme.md' }
}); // Results in: /files/docs/readme.md

// Works with query parameters too
navigate('/files/*', {
  params: { '*': 'images/photo.jpg' },
  query: { size: 'thumbnail' }
}); // Results in: /files/images/photo.jpg?size=thumbnail
```

### query

Query parameters serialized with URL encoding.

```typescript
navigate('/search', {
  query: { q: 'reactive', category: 'frameworks', page: '2' }
}); // Results in: /search?q=reactive&category=frameworks&page=2
```

### replace

Replace current history entry instead of adding a new one.

```typescript
// Normal navigation - can go back
navigate('/dashboard');

// Replace - overwrites history entry, user cannot go back
navigate('/login', { replace: true });
```

### scroll

Override scroll behavior for this navigation. Takes precedence over both global and route-level scroll settings.

```typescript
// Scroll to top for this navigation only
navigate('/long-page', { scroll: 'top' });

// Disable scroll handling for this navigation
navigate('/chat', { scroll: false });

// Custom scroll function
navigate('/docs', {
  scroll: (to, from) => ({ top: 100, left: 0 })
});
```

**Scroll Options:**
- `'auto'` - Browser default (no intervention)
- `'top'` - Scroll to top
- `'preserve'` - Keep current scroll position
- `false` - Disable scroll handling
- `(to, from) => { top, left? } | null` - Custom function

### meta

Attach metadata to this navigation. Inline meta **merges** with route-level meta (inline values take precedence on key conflicts).

```typescript
// Set page title dynamically
navigate('/dashboard', {
  meta: { title: 'Dashboard', requiresAuth: true }
});

// Merge with route-level meta
// If route has meta: { title: 'Profile', section: 'user' }
// And you navigate with meta: { title: 'Edit Profile', editing: true }
// Result: { title: 'Edit Profile', section: 'user', editing: true }
navigate('/profile', {
  meta: { title: 'Edit Profile', editing: true }
});
```

## Combined Example

```typescript
navigate('/users/:id', {
  params: { id: '123' },
  query: { tab: 'posts' },
  replace: true,
  scroll: 'top',
  meta: { analytics: 'user-profile-view' }
});
// Results in: /users/123?tab=posts
// With: replace=true, scroll to top, custom meta
```

## Important Considerations

### Asynchronous Navigation

Navigation is asynchronous - the route change isn't immediate. Note that `router()` also returns stale state on initial load (see [`router`](/reference/router/router#router-return-value)).

```typescript
// ❌ Route may not be updated yet
navigate('/dashboard');
console.log(route().path);

// ✅ Use effect for route changes
effect(() => {
  if (route().path === '/dashboard') {
    console.log('Dashboard loaded');
  }
});
```

### Input Validation

`navigate()` throws if `path` is `null`, `undefined`, or not a string. The error message follows the shape `[router] navigate: path must be a string, received <value>`.

```typescript
// ❌ Throws
navigate(null); // [router] navigate: path must be a string, received null

// ✅ Valid
navigate("/dashboard");
```

### Parameter Validation

Parameter key validation is strictly compile-time (via TypeScript types). Invalid parameter keys are silently ignored at runtime.

```typescript
// ✅ Validated at compile-time by TypeScript, works at runtime
navigate('/users/:id', { params: { id: '123' } });

// ❌ TypeScript compilation error, but silently ignored at runtime (param not substituted - gets removed)
navigate('/users/:id', { params: { userId: '123' } });
// Results in: /users/

// ✅ Best practice: validate parameters before navigation
const navigateToUser = (userId) => {
  if (!userId) {
    console.error('User ID is required');
    return;
  }
  navigate('/users/:id', { params: { id: userId } });
};
```
