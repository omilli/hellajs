
# Routing

Short, copy-pasteable code patterns for common routing tasks with [`router`](/reference/router/router), [`navigate`](/reference/router/navigate), and [`route`](/reference/router/route), plus server-rendering recipes for routed apps.

### Basic Route Setup

Map URL patterns to handlers that update a signal. Each handler runs when its pattern matches the current path.

```jsx
import { router } from '@hellajs/router';
import { signal } from '@hellajs/core';

const HomePage = () => <div>Home</div>;
const AboutPage = () => <div>About</div>;
const UserProfile = ({ id }: { id?: string }) => <div>User {id}</div>;
const NotFound = () => <div>Not found</div>;
const DashboardLayout = () => <div>Dashboard</div>;
const Overview = () => <div>Overview</div>;
const UserDetail = ({ id }: { id?: string }) => <div>User {id}</div>;
const SearchResults = ({ term, sort }: { term?: string; sort?: string }) => (
  <div>Results for {term} (sorted by {sort})</div>
);
const Feed = () => <div>Feed</div>;
const Settings = () => <div>Settings</div>;
const Chat = () => <div>Chat</div>;
const Docs = ({ path }: { path?: string }) => <div>Docs {path}</div>;
const Users = () => <div>Users</div>;
const Profile = ({ id }: { id?: string }) => <div>Profile {id}</div>;
const currentView = signal(<div>Loading…</div>);

router({
  routes: {
    '/': () => currentView(<HomePage />),
    '/about': () => currentView(<AboutPage />),
    '/users/:id': (params) => currentView(<UserProfile id={params.id} />)
  },
  notFound: () => currentView(<NotFound />)
});
```

### 404 Page

The `notFound` handler runs when no route matches. Accepts a function or a redirect string.

```jsx
import { router } from '@hellajs/router';
import { signal } from '@hellajs/core';

const HomePage = () => <div>Home</div>;
const NotFound = () => <div>Not found</div>;
const currentView = signal(<div>Loading…</div>);

// Function handler
router({
  routes: { '/': () => currentView(<HomePage />) },
  notFound: () => currentView(<NotFound />)
});

// String redirect
router({
  routes: {
    '/': () => currentView(<HomePage />),
    '/404': () => currentView(<NotFound />)
  },
  notFound: '/404'
});
```

### Auth Guard

Use a `before` hook to block unauthenticated access by returning `false`. No handler-level guard needed for sync checks.

```jsx
import { router } from '@hellajs/router';
import { signal } from '@hellajs/core';

const LoginPage = () => <div>Login</div>;
const Dashboard = ({ user }: { user?: unknown }) => <div>Dashboard</div>;

const user = signal<{ name: string } | null>(null);
const currentView = signal(<div>Loading</div>);

router({
  routes: {
    '/login': () => currentView(<LoginPage />),
    '/dashboard': {
      before: () => {
        if (!user()) return false;
      },
      handler: () => {
        currentView(<Dashboard user={user()} />);
      }
    }
  }
});
```

To redirect to login instead:

```jsx
import { router } from '@hellajs/router';
import { signal } from '@hellajs/core';

const user = signal<{ name: string } | null>(null);
const currentView = signal(<div>Loading</div>);
const Dashboard = ({ user }: { user?: unknown }) => <div>Dashboard</div>;

router({
  routes: {
    '/dashboard': {
      before: () => {
        if (!user()) return '/login';
      },
      handler: () => {
        currentView(<Dashboard user={user()} />);
      }
    }
  }
});
```

Async guards block; return the verdict from the guard itself:

```jsx
import { router } from '@hellajs/router';
import { signal } from '@hellajs/core';

const user = signal<{ name: string } | null>(null);
const currentView = signal(<div>Loading</div>);
const Dashboard = ({ user }: { user?: unknown }) => <div>Dashboard</div>;

router({
  routes: {
    '/dashboard': {
      before: async () => {
        if (!user()) {
          const res = await fetch('/api/check-session');
          return res.ok ? undefined : '/login';
        }
      },
      handler: () => {
        currentView(<Dashboard user={user()} />);
      }
    }
  }
});
```

While the guard is in flight, [`route`](/reference/router/route)`().pending` is `true` and the current match stays committed; use it to render a loading state. No handler-side revalidation is needed: the handler runs only after the guard settles.

### Nested Routes

Organize routes hierarchically with `children`. Child routes inherit all parent parameters automatically.

```jsx
import { router } from '@hellajs/router';
import { signal } from '@hellajs/core';

const DashboardLayout = () => <div>Dashboard</div>;
const Overview = () => <div>Overview</div>;
const UserDetail = ({ id }: { id?: string }) => <div>User {id}</div>;
const currentView = signal(<div>Loading…</div>);

router({
  routes: {
    '/dashboard': {
      handler: () => currentView(<DashboardLayout />),
      children: {
        '/overview': () => currentView(<Overview />),
        '/users/:id': (params) => currentView(<UserDetail id={params.id} />)
      }
    }
  }
});
// /dashboard → DashboardLayout
// /dashboard/overview → Overview
// /dashboard/users/42 → UserDetail (params.id = '42')
```

### Query Parameter Handling

Query parameters are parsed automatically and passed as the second argument. Pass query strings with the `query` option in [`navigate`](/reference/router/navigate).

```jsx
import { router, navigate } from '@hellajs/router';
import { signal } from '@hellajs/core';

const SearchResults = ({ term, sort }: { term?: string; sort?: string }) => <div>Results for {term} (sorted by {sort})</div>;
const currentView = signal(<div>Loading…</div>);

router({
  routes: {
    '/search': (params, query) => {
      currentView(<SearchResults term={query.q} sort={query.sort} />);
    }
  }
});

// Navigate with query → /search?q=hello&sort=date
navigate('/search', { query: { q: 'hello', sort: 'date' } });
```

### Redirect

String values in the routes object act as redirects. Use the `redirects` array to map multiple sources to one destination.

```jsx
import { router } from '@hellajs/router';
import { signal } from '@hellajs/core';

const HomePage = () => <div>Home</div>;
const AboutPage = () => <div>About</div>;
const currentView = signal(<div>Loading…</div>);

router({
  routes: {
    '/': () => currentView(<HomePage />),
    '/home': '/',
    '/old-about': '/about',
    '/about': () => currentView(<AboutPage />)
  },
  redirects: [
    { from: ['/tasks', '/items'], to: '/todos' }
  ]
});
```

### Scroll Behavior

Control scroll position at three levels: global default, route-level override, and inline per-navigation. Priority: inline > route > global.

```jsx
import { router, navigate } from '@hellajs/router';
import { signal } from '@hellajs/core';

const Feed = () => <div>Feed</div>;
const Chat = () => <div>Chat</div>;
const Docs = ({ path }: { path?: string }) => <div>Docs {path}</div>;
const currentView = signal(<div>Loading…</div>);

router({
  scrollBehavior: 'top',
  routes: {
    '/feed': {
      scroll: 'preserve',
      handler: () => currentView(<Feed />)
    },
    '/chat': {
      scroll: false,
      handler: () => currentView(<Chat />)
    },
    '/docs/*': {
      scroll: (to, from) => ({ top: 80 }),
      handler: (params) => currentView(<Docs path={params['*']} />)
    }
  }
});

// Inline override (highest priority)
navigate('/long-page', { scroll: 'top' });
```

### SPA Link Interception

Same-origin `<a href>` clicks are intercepted by default and routed through `navigate()`; no special handling needed.

```jsx
import { router } from '@hellajs/router';
import { signal } from '@hellajs/core';

const HomePage = () => <div>Home</div>;
const AboutPage = () => <div>About</div>;
const currentView = signal(<div>Loading…</div>);

// Plain <a> tags work out of the box
router({
  routes: {
    '/': () => currentView(<HomePage />),
    '/about': () => currentView(<AboutPage />)
  }
});
```

For hybrid SPA + MPA apps, disable interception:

```jsx
import { router } from '@hellajs/router';
import { signal } from '@hellajs/core';

const HomePage = () => <div>Home</div>;
const currentView = signal(<div>Loading…</div>);

router({
  routes: { '/': () => currentView(<HomePage />) },
  intercept: false
});
```

### Active Links

Use [`route`](/reference/router/route)`().active()` to highlight the current section in a nav bar. The predicate reads route().path reactively and uses ancestor semantics: a parent link stays lit while a child route is active.

```jsx
import { router, route } from '@hellajs/router';
import { signal } from '@hellajs/core';

const Dashboard = () => <div>Dashboard</div>;
const Users = () => <div>Users</div>;
const Settings = () => <div>Settings</div>;
const currentView = signal(<div>Loading…</div>);

router({
  routes: {
    '/dashboard': () => currentView(<Dashboard />),
    '/dashboard/users': () => currentView(<Users />),
    '/dashboard/settings': () => currentView(<Settings />)
  }
});

const navItems = [
  { path: '/dashboard', label: 'Dashboard' },
  { path: '/dashboard/users', label: 'Users' },
  { path: '/dashboard/settings', label: 'Settings' }
];

<nav>
  {navItems.map(item => (
    <a href={item.path} class={route().active(item.path) ? 'active' : ''}>
      {item.label}
    </a>
  ))}
</nav>
```

### Breadcrumbs

Render a breadcrumb trail from [`route`](/reference/router/route)`().crumbs`. Each crumb's `path` is a linkable href; `segment` keys into a label dictionary.

```jsx
import { router, route, navigate } from '@hellajs/router';
import { signal } from '@hellajs/core';

const Profile = ({ id }: { id?: string }) => <div>Profile {id}</div>;
const currentView = signal(<div>Loading…</div>);
const labels: Record<string, string> = {
  '/admin': 'Admin', '/admin/users': 'Users', '/admin/users/:id': 'Profile'
};

router({
  routes: {
    '/admin': {
      children: { '/users': { children: { '/:id': ({ id }) => currentView(<Profile id={id} />) } } }
    }
  }
});

// crumbs is parent-to-leaf; each crumb.path is a valid href
<ol class="breadcrumbs">
  {route().crumbs.map(crumb => (
    <li>
      <a href={crumb.path} on:click={(e) => { e.preventDefault(); navigate(crumb.path); }}>
        {labels[crumb.segment] || crumb.segment}
      </a>
    </li>
  ))}
</ol>
```

### Shared App

One isomorphic module defines the view signal, the route map, and the shell. Each handler is a pure state-setter, the view-signal pattern `() => currentView(...)`. Recipes use [`html`](/reference/dom/html) templates so the server entry needs no build plugin.

```js
import { signal } from '@hellajs/core';
import { html } from '@hellajs/dom';
import { router, route } from '@hellajs/router';

const currentView = signal(html`<h1>Loading…</h1>`);

const Home = () => html`<h1>Home</h1>`;
const User = ({ id }) => html`<h1>User ${id}</h1>`;
const NotFound = () => html`<h1>Not Found</h1>`;

const routes = {
  '/': () => currentView(Home()),
  '/users/:id': (params) => currentView(User({ id: params.id }))
};

const notFound = () => currentView(NotFound());

const App = () => html`
  <nav>
    <a href="/" class=${() => route().active('/') ? 'active' : ''}>Home</a>
    <a href="/users/1" class=${() => route().active('/users/1') ? 'active' : ''}>User</a>
  </nav>
  <main>${currentView}</main>
`;

export { routes, App, notFound };
```

The view-signal style is the isomorphic handler form: the same handlers fire on the server (driven by [`router`](/reference/router/router)`({ url })`) and on the client (driven by [`router`](/reference/router/router)`({ routes })` + [`hydrate`](/reference/dom/hydrate)). The `() => mount(...)` style is client-only: [`mount`](/reference/dom/mount) needs a document and throws on the server.

### Server: ssr()

[`ssr`](/reference/ssr/ssr) is synchronous, so resolve the route before stringifying. There is no `window` on the server; pass the request URL via the `url` option. It accepts the full request URL (`req.url`) or a path (`pathname + search`); the origin and hash are ignored.

```js
import { html } from '@hellajs/dom';
import { router } from '@hellajs/router';
import { ssr, doc } from '@hellajs/ssr';
import { routes, App, notFound } from './app.js';

Bun.serve({
  port: 3000,
  fetch(req) {
    const { pathname, search } = new URL(req.url);

    // url overrides window.location; resolution is synchronous, so currentView
    // holds the matched view before ssr walks the tree.
    router({ routes, url: pathname + search, notFound });

    const body = ssr(html`<${App} />`);
    return new Response(
      doc({ lang: 'en', head: { title: 'App' }, body }),
      { headers: { 'content-type': 'text/html' } }
    );
  }
});
```

### Server: ssr.async()

For server-fetched data, return a Promise from a getter child; [`ssr.async`](/reference/ssr/ssr#async) awaits it in tree order. Everything else is identical to the [`ssr`](/reference/ssr/ssr) recipe.

```js
import { signal } from '@hellajs/core';
import { html } from '@hellajs/dom';
import { router } from '@hellajs/router';
import { ssr, doc } from '@hellajs/ssr';

const loadName = (id) => fetch(`/api/users/${id}`).then((r) => r.text());
// A promise-getter child is awaited by ssr.async
const Profile = ({ id }) => html`<h1>${() => loadName(id)}</h1>`;

const currentView = signal(html`<h1>Loading…</h1>`);
const routes = {
  '/': () => currentView(html`<h1>Home</h1>`),
  '/users/:id': (params) => currentView(Profile({ id: params.id }))
};
const App = () => html`<main>${currentView}</main>`;

Bun.serve({
  port: 3000,
  async fetch(req) {
    const { pathname, search } = new URL(req.url);
    router({ routes, url: pathname + search });

    const body = await ssr.async(html`<${App} />`);
    return new Response(
      doc({ lang: 'en', head: { title: 'App' }, body }),
      { headers: { 'content-type': 'text/html' } }
    );
  }
});
```

### Server: ssr.stream()

[`ssr.stream`](/reference/ssr/ssr#stream) flushes the static shell before async values resolve. Wrap an async subtree in [`<Suspense>`](/reference/dom/suspense) for out-of-order streaming: the shell and the `fallback` flush immediately while the children resolve. Assemble the full document with [`doc`](/reference/ssr/doc)'s stream overload: the head and mount wrapper flush first, each body chunk pipes through as it renders, and the closing tags land only after the body closes.

```js
import { signal } from '@hellajs/core';
import { html, Suspense } from '@hellajs/dom';
import { router } from '@hellajs/router';
import { ssr, doc } from '@hellajs/ssr';

const loadName = (id) => fetch(`/api/users/${id}`).then((r) => r.text());
const Profile = ({ id }) => html`
  <${Suspense} fallback=${html`<p>Loading…</p>`}>
    ${() => loadName(id).then((name) => html`<h1>${name}</h1>`)}
  </${Suspense}>
`;

const currentView = signal(html`<h1>Loading…</h1>`);
const routes = {
  '/users/:id': (params) => currentView(Profile({ id: params.id }))
};
const App = () => html`<main>${currentView}</main>`;

Bun.serve({
  port: 3000,
  fetch(req) {
    const { pathname, search } = new URL(req.url);
    router({ routes, url: pathname + search });

    return new Response(
      doc({
        lang: 'en',
        head: { title: 'App', scripts: [{ src: '/client.js', type: 'module' }] },
        body: ssr.stream(html`<${App} />`),
        mount: '#app'
      }).pipeThrough(new TextEncoderStream()),
      { headers: { 'content-type': 'text/html' } }
    );
  }
});
```

Streamed [`<Suspense>`](/reference/dom/suspense) regions stage their resolved children in `<template>` elements; [`hydrate`](/reference/dom/hydrate) swaps each staged template in automatically, so the streamed and sync paths share one client entry: `router({ routes })` (no `url` option) resolves `window.location` synchronously, and [`hydrate`](/reference/dom/hydrate) adopts the existing nodes instead of rebuilding them.

### Keep Handlers Pure

Route handlers should be pure state-setters (`() => currentView(View())`). Put side effects (analytics, subscriptions, `localStorage`) in component [`effect`](/reference/core/effect) bodies, not in the handler: [`ssr`](/reference/ssr/ssr) walks the tree once and never flushes the scheduler, so effects do not run during the server render, only on the client after [`hydrate`](/reference/dom/hydrate). The initial route's handler fires on both the server render and the client hydrate, harmless for a pure setter, visible for an impure one.

### Concurrency

Synchronous [`ssr`](/reference/ssr/ssr) is concurrency-safe: [`router`](/reference/router/router)`({ url })` + the render is one synchronous block with no `await`, so no second request can interleave and overwrite the router's module-level signals mid-render. [`ssr.async`](/reference/ssr/ssr#async) and [`ssr.stream`](/reference/ssr/ssr#stream) yield at each awaited Promise; they stay correct while every shared-signal read (the router's [`route`](/reference/router/route)`()`, your `currentView`) happens before the first `await` in tree order. Full safety under arbitrary streaming concurrency needs a router instance per request; revisit it only when a real concurrent-streaming workload demands it.

One consequence of the synchronous server resolution: async guards cannot block on the server. A `Promise`-returning `before` proceeds immediately (only its rejection is logged) and [`route`](/reference/router/route)`().pending` stays `false`; keep server-gating guards synchronous, and do async data work in [`ssr.async`](/reference/ssr/ssr#async) children instead.
