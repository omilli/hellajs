# Routing

Reactive client-side routing that integrates seamlessly with the reactivity system, with lifecycle hooks, guards, and redirects for controlling navigation.

## Mental Model

HellaJS routing works through three primitives:

- **[`router`](/reference/router/router)** configures route patterns and their handlers
- **[`route`](/reference/router/route)** is a reactive signal holding the current path, params, query, and handler
- **[`navigate`](/reference/router/navigate)** triggers programmatic navigation

Route handlers execute immediately when their pattern matches. The typical pattern is a signal that holds the current view, updated by each route handler:

```jsx
import { router, navigate } from '@hellajs/router';
import { signal } from '@hellajs/core';

const HomePage = () => <div>Home</div>;
const AboutPage = () => <div>About</div>;
const TodoDetail = ({ id }: { id?: string }) => <div>Todo {id}</div>;
const NotFound = ({ attempted }: { attempted?: string }) => <div>Not found: {attempted}</div>;
const UserTodo = ({ userId, todoId }: { userId?: string; todoId?: string }) => (
  <div>Todo {todoId} of user {userId}</div>
);
const AdminDashboard = () => <div>Admin</div>;
const UsersList = () => <div>Users</div>;
const UserDetail = ({ id }: { id?: string }) => <div>User {id}</div>;
const AdminSettings = () => <div>Settings</div>;
const SearchResults = ({ term, sort }: { term?: string; sort?: string }) => (
  <div>Results for {term} (sorted by {sort})</div>
);
const FileViewer = ({ path }: { path?: string }) => <div>File {path}</div>;
const AdminPanel = () => <div>Admin</div>;
const Feed = () => <div>Feed</div>;
const Chat = () => <div>Chat</div>;
const currentView = signal(<div>Loading…</div>);

router({
  routes: {
    '/': () => currentView(<HomePage />),
    '/about': () => currentView(<AboutPage />),
    '/todos/:id': (params) => currentView(<TodoDetail id={params.id} />)
  },
  notFound: (path) => currentView(<NotFound attempted={path} />)
});
```

The `notFound` handler receives the attempted path (query included, same shape as [`route().path`](/reference/router/route)), so the 404 view can show what the user tried to reach.

`notFound` also accepts a string to redirect to another route:

```jsx
router({
  routes: {
    '/': () => currentView(<HomePage />),
    '/404': () => currentView(<NotFound />)
  },
  notFound: '/404'
});
```

The `currentView` signal drives the UI: when navigation occurs, the matching handler updates the signal and any reactive dependencies re-render automatically.

## Route Parameters

### Dynamic Segments

Parameters are extracted from the URL and passed as the first argument to route handlers.

```jsx
import { router } from '@hellajs/router';
import { signal } from '@hellajs/core';

const currentView = signal(<div>Loading…</div>);

router({
  routes: {
    '/users/:userId/todos/:todoId': (params) => {
      // /users/42/todos/7 → params.userId = '42', params.todoId = '7'
      currentView(<UserTodo userId={params.userId} todoId={params.todoId} />);
    }
  }
});
```

### Query Parameters

Query parameters are parsed automatically and passed as the second argument.

```jsx
router({
  routes: {
    '/search': (params, query) => {
      // /search?q=hello&sort=date → query.q = 'hello', query.sort = 'date'
      currentView(<SearchResults term={query.q} sort={query.sort} />);
    }
  }
});
```

### Wildcard Routes

The `*` syntax captures all remaining path segments.

```jsx
router({
  routes: {
    '/files/*': (params) => {
      // /files/docs/readme.md → params['*'] = 'docs/readme.md'
      currentView(<FileViewer path={params['*']} />);
    }
  }
});
```

### Optional Segments

A `:param?` segment matches optionally: the route fires with or without it, and a skipped segment leaves no key in `params`. `?` in a pattern always marks an optional parameter; patterns never carry query strings.

```jsx
router({
  routes: {
    '/users/:id?': (params) => {
      // /users → params.id is undefined (list view); /users/7 → params.id = '7'
      currentView(params.id ? <UserDetail id={params.id} /> : <UsersList />);
    }
  }
});
```

An absent optional token is also stripped from built URLs, together with its preceding slash:

```jsx
import { navigate } from '@hellajs/router';

navigate('/users/:id?');                            // → /users
navigate('/users/:id?', { params: { id: '7' } });  // → /users/7
```

Optional segments work anywhere in a pattern (`/posts/:id?/edit` matches both `/posts/edit` and `/posts/7/edit`) and combine with wildcards (`/files/:id?/*`). [`href`](/reference/router/href) applies the same substitution rules.

All route parameters and query values are strings; cast to other types as needed.

## Nested Routes

Routes can be organized hierarchically using the `children` property. Child routes automatically inherit parameters from their parents.

```jsx
import { router } from '@hellajs/router';
import { signal } from '@hellajs/core';

const currentView = signal(<div>Loading…</div>);

router({
  routes: {
    '/admin': {
      handler: () => currentView(<AdminDashboard />),
      children: {
        '/users': {
          handler: () => currentView(<UsersList />),
          children: {
            '/:id': (params) => currentView(<UserDetail id={params.id} />)
          }
        },
        '/settings': () => currentView(<AdminSettings />)
      }
    }
  }
});

// /admin → AdminDashboard
// /admin/users → UsersList
// /admin/users/123 → UserDetail (params.id = '123', inherited from nested match)
// /admin/settings → AdminSettings
```

Key benefits of nested routes:

- **Hierarchical organization**: route structure mirrors application structure
- **Parameter inheritance**: child routes receive all parent parameters automatically
- **Hook cascading**: parent hooks execute before child hooks, enabling guard patterns
- **Shared layout**: parent handlers set up layout, children fill in content areas

## Route Hooks

Routes can be defined as objects with `before`, `after`, and `handler` properties for lifecycle control.

```jsx
import { router, navigate } from '@hellajs/router';
import { signal } from '@hellajs/core';

const isAuthenticated = () => true;
const trackPageView = (page: string) => console.log("viewed", page);
const UserProfile = () => <div>User profile</div>;
const Home = () => <div>Home</div>;
const TodoList = () => <div>Todos</div>;
const currentView = signal(<div>Loading…</div>);

router({
  routes: {
    '/profile': {
      before: () => {
        if (!isAuthenticated()) {
          navigate('/login');
        }
      },
      handler: () => {
        if (!isAuthenticated()) return;
        currentView(<UserProfile />);
      },
      after: () => trackPageView('profile')
    }
  }
});
```

Hooks execute in cascade order for nested routes:

1. Global `leave` hook, then child `leave` → parent `leave` (only when leaving a matched route)
2. Global `before` hooks
3. Parent `before` → child `before` (top-down)
4. Route `handler`
5. Child `after` → parent `after` (bottom-up)
6. Global `after` hooks

### Global Hooks

Register global hooks on the router configuration object to execute on every navigation.

```jsx
import { router } from '@hellajs/router';
import { signal } from '@hellajs/core';

const loading = signal(false);
const currentView = signal(<div>Loading…</div>);

router({
  routes: {
    '/': () => currentView(<Home />)
  },
  hooks: {
    before: () => {
      loading(true);
    },
    after: () => {
      loading(false);
    }
  }
});
```

Global hooks receive `(to, from)` paths: `to` is the incoming path with its query string (the same shape as [`route()`](/reference/router/route).path) and `from` is the path being left, captured before the route commits. A `before` hook still sees the previous route in [`route()`](/reference/router/route); by the time `after` runs the route is already committed, so `from` is the only way to see where navigation started.

The login-redirect guard uses `to` to preserve the attempted destination:

```jsx
import { signal } from '@hellajs/core';

const user = signal(null);
const LoginPage = () => <div>Login</div>;
const Dashboard = () => <div>Dashboard</div>;

router({
  routes: {
    '/login': () => currentView(<LoginPage />),
    '/dashboard': () => currentView(<Dashboard />)
  },
  hooks: {
    before: (to) =>
      user() || to.startsWith('/login')
        ? true
        : `/login?next=${encodeURIComponent(to)}`
  }
});
```

The login handler reads the encoded target from `query.next` and navigates back after sign-in. Zero-argument global hooks keep working: the paths are additional arguments, ignored by hooks that don't declare them.

See the [`router`](/reference/router/router) reference for all hook configuration options.

## Route Guards

`before` hooks can block navigation or redirect by returning specific values:

| Return value | Behavior |
|---|---|
| `void` / `true` / `undefined` | Proceed: navigation continues normally |
| `false` | Cancel: navigation is blocked, URL stays unchanged |
| `string` | Redirect: navigates to the returned path |
| `throw` | Cancel: navigation is blocked, error logged |
| `Promise` | Blocks on the client: navigation defers until resolution, which is interpreted as the verdict; proceeds + logs on the server |

Basic guard that blocks unauthenticated access:

```jsx
import { router } from '@hellajs/router';
import { signal } from '@hellajs/core';

const LoginPage = () => <div>Login</div>;
const Dashboard = ({ user }: { user?: unknown }) => <div>Dashboard</div>;

const user = signal<{ name: string; isAdmin?: boolean } | null>(null);
const currentView = signal(<div>Loading</div>);

router({
  routes: {
    '/login': () => currentView(<LoginPage />),
    '/dashboard': {
      before: () => {
        if (!user()) return false;
      },
      handler: () => {
        currentView(<Dashboard user={user()} />);
      }
    }
  }
});
```

Redirect instead:

```jsx
router({
  routes: {
    '/dashboard': {
      before: () => {
        if (!user()) return '/login';
      },
      handler: () => {
        currentView(<Dashboard user={user()} />);
      }
    }
  }
});
```

Async `before` hooks block. A `Promise`-returning guard defers the commit: [`route`](/reference/router/route)`().pending` is `true` while the previous match stays current, and the resolution is interpreted as the verdict (`false` cancels, a non-empty string redirects, anything else proceeds; a rejection cancels and logs). Async auth is just an async guard:

```jsx
const checkAuth = async () => {
  const res = await fetch('/api/check-session');
  return res.ok ? true : '/login';
};
const ProtectedPage = () => <div>Protected</div>;

router({
  routes: {
    '/protected': {
      before: checkAuth,
      handler: () => currentView(<ProtectedPage />)
    }
  }
});
```

No handler-side revalidation is needed: the handler runs only after the guard passes. On the server (`url` mode) an async guard cannot block the synchronous render: navigation proceeds and only a rejection is logged.

On popstate/hashchange (browser back/forward), a cancelled guard restores the previous URL via `replaceState`, keeping the address bar consistent.

Multiple guards stack through nesting; the first non-pass verdict short-circuits:

```jsx
const requireAuth = () => {
  if (!user()) return '/login';
};
const AdminSettings = () => <div>Admin settings</div>;

router({
  routes: {
    '/admin': {
      before: requireAuth,
      children: {
        '/settings': {
          before: () => {
            if (!user()?.isAdmin) return '/dashboard';
          },
          handler: () => {
            currentView(<AdminSettings />);
          }
        }
      }
    }
  }
});
```

If `requireAuth` returns `false`, the child's `before` never runs. If it passes but the admin check fails, navigation redirects.

## Leave Guards

`leave` hooks guard the route being *departed*, the unsaved-form flow every app needs. They run on every navigation away from a matched route (browser back/forward included), before any incoming `before` hook: the global `hooks.leave(to, from)` first, then the route chain's `leave` hooks child→parent. Verdicts share the `before` contract from the table above: `false` cancels, a non-empty string redirects, a throw cancels and logs, and a `Promise` blocks on the client (deferring the commit until its resolution; proceeds + logs on the server).

```jsx
import { router, navigate } from '@hellajs/router';
import { signal } from '@hellajs/core';

const Editor = () => <div>Editor</div>;
const Dashboard = () => <div>Dashboard</div>;
const currentView = signal(<div>Loading…</div>);
const dirty = signal(false);

router({
  routes: {
    '/editor': {
      leave: () => (dirty() ? false : undefined),
      handler: () => currentView(<Editor />)
    },
    '/dashboard': () => currentView(<Dashboard />)
  }
});

navigate('/editor');
dirty(true);

navigate('/dashboard'); // cancelled; unsaved changes, URL and route unchanged
navigate('/dashboard', { force: true }); // override; leave guards skipped
```

[`navigate()`](/reference/router/navigate) accepts `{ force: true }` to skip leave guards, the override for a "discard changes?" confirmation. Force skips only leave guards; incoming `before` guards on the target still run, so target auth checks are never bypassable.

Leave guards never fire on same-path navigation (a query-only change stays on the route), on the initial resolution, or when the current position came from a `notFound` landing. A cancelled back/forward restores the previous URL via `replaceState`, same as a cancelled `before`.

## Redirects

The router supports two redirect mechanisms.

```jsx
import { router } from '@hellajs/router';

const Archive = () => <div>Archive</div>;

// String redirects: simplest form
router({
  routes: {
    '/home': '/',              // Redirect /home → /
    '/profile': '/user/me'     // Redirect /profile → /user/me
  }
});

// Global redirects: multiple sources to one destination
router({
  routes: {
    '/todos': () => currentView(<TodoList />)
  },
  redirects: [
    { from: ['/tasks', '/items', '/list'], to: '/todos' }
  ]
});

// Pattern redirects: captured params substitute into the target
router({
  routes: {
    '/users/:id': () => currentView(<UserProfile />),
    '/archive/*': () => currentView(<Archive />)
  },
  redirects: [
    { from: ['/user/:id'], to: '/users/:id' },   // /user/7 → /users/7
    { from: ['/docs/*'], to: '/archive/*' }       // /docs/a/b → /archive/a/b
  ]
});
```

`from` entries match as route patterns (`:param` captures a single segment, `*` captures the rest), with the query string ignored. Captured values replace matching tokens in `to`; unmatched tokens are stripped. The first matching entry in array order wins.

Redirect chains stop after 20 hops: a cyclic configuration logs `[router] redirect loop detected` and cancels the navigation (URL unchanged) instead of overflowing the stack.

See [`router`](/reference/router/router) for the redirect configuration options.

## Navigation

The [`navigate`](/reference/router/navigate) function provides programmatic routing with parameter substitution, query strings, and scroll control. Navigation is synchronous: `route()` is updated before `navigate()` returns.

Same-origin `<a href>` clicks are automatically intercepted and routed through `navigate()` by default. Pass `intercept: false` to `router()` to disable and restore full page reload behavior.

```jsx
import { navigate } from '@hellajs/router';

// Static path
navigate('/dashboard');

// Parameter substitution → /users/123
navigate('/users/:id', { params: { id: '123' } });

// With query string → /search?q=hello&sort=date
navigate('/search', { query: { q: 'hello', sort: 'date' } });

// Replace history entry (user cannot go back)
navigate('/login', { replace: true });

// All options combined
navigate('/users/:id', {
  params: { id: '123' },
  query: { tab: 'overview' },
  replace: true,
  scroll: 'top',
  meta: { analytics: 'user-view' }
});
```

### Navigation in Components

```jsx
import { ForEach } from '@hellajs/dom';

type Todo = { id: number; text: string };

const TodoList = ({ todos }: { todos: Todo[] }) => {
  const viewTodo = (id: number) => {
    navigate('/todos/:id', { params: { id: String(id) } });
  };

  return (
    <ul>
      <ForEach
        each={todos}
        use={(todo) => (
          <li>
            <span>{todo.text}</span>
            <button on:click={() => viewTodo(todo.id)}>View</button>
          </li>
        )}
      />
    </ul>
  );
};
```

See [`navigate`](/reference/router/navigate) for all navigation options including scroll overrides and metadata.

## Route Signal

The [`route`](/reference/router/route) signal provides reactive access to the current route information. Components can read it directly to respond to navigation changes.

```jsx
import { route } from '@hellajs/router';
import { effect } from '@hellajs/core';

// Update page title reactively
effect(() => {
  const { meta, path } = route();
  document.title = typeof meta?.title === "string" ? meta.title : "My App";
});

// Use in components
const Breadcrumbs = () => (
  <nav>
    <span>Path: {route().path}</span>
    {route().params.id && <span> / Item {route().params.id ?? ""}</span>}
  </nav>
);
```

### Route Metadata

Attach metadata to routes for analytics, SEO, or feature flags. Metadata is defined per-route and accessed via `route().meta`:

```jsx
router({
  routes: {
    '/about': {
      meta: { title: 'About Us', requiresAuth: false },
      handler: () => currentView(<AboutPage />)
    },
    '/admin': {
      meta: { title: 'Admin Panel', requiresAuth: true },
      handler: () => currentView(<AdminPanel />)
    }
  }
});
```

See [`route`](/reference/router/route) for the complete `RouteInfo` structure.

Set `inheritMeta: true` on the [`router()`](/reference/router/router) configuration to inherit parent meta through the nested route chain, the same [parent-to-leaf merge order](/learn/concepts/routing#nested-routes) as parameter inheritance. Child keys override parent keys on conflict, and inline meta from [`navigate()`](/reference/router/navigate) always wins over the inherited result. Without `inheritMeta`, only the leaf route's meta is exposed.

```typescript
import { router, route, navigate } from '@hellajs/router';

router({
  inheritMeta: true,
  routes: {
    '/admin': {
      meta: { section: 'admin' },
      children: {
        '/users': {
          meta: { title: 'Users' },
          handler: () => {}
        }
      }
    }
  }
});

navigate('/admin/users');
console.log(route().meta); // { section: 'admin', title: 'Users' }
```

Each route can override the global flag with its own `inheritMeta` field. A route's flag controls whether *it* inherits from its parent: `false` makes the route a boundary that ignores ancestors above, starting the cascade fresh from itself. The boundary route's own meta still flows down to descendants.

```typescript
import { router, route, navigate } from '@hellajs/router';

router({
  inheritMeta: true,
  routes: {
    '/admin': {
      meta: { root: true },
      children: {
        '/section': {
          inheritMeta: false, // boundary: ignore /admin above
          meta: { section: 'a' },
          children: {
            '/page': {
              meta: { title: 'Page' },
              handler: () => {}
            }
          }
        }
      }
    }
  }
});

navigate('/admin/section/page');
console.log(route().meta); // { section: 'a', title: 'Page' }; root omitted, section flows down
```

Set `inheritMeta: true` on a route to opt it into inheritance when the global flag is `false`.

## Router Modes

The router supports three URL modes.

```jsx
import { router, navigate } from '@hellajs/router';

// History API (default): clean URLs: example.com/about
router({
  routes: { '/about': () => currentView(<AboutPage />) }
});

// Hash mode, no server config needed: example.com/#/about
router({
  mode: 'hash',
  routes: { '/about': () => currentView(<AboutPage />) }
});

// Memory mode, no URL at all: route() is driven by navigate() alone
router({
  mode: 'memory',
  routes: { '/about': () => currentView(<AboutPage />) }
});

navigate('/about'); // route() updates; window.location and history are untouched
```

Memory mode routes without a URL: the initial path comes from the `url` option or `/`, nothing is written to `window.location` or history, and no listeners are attached. It fits tests, Storybook, and non-DOM environments. There is no history stack in memory mode: browser back/forward do nothing, and back/forward navigation APIs do not exist; drive the route with `navigate()`.

## Base Path

Apps deployed under a subpath (GitHub Pages project sites, `/~user/` directories, shared hosts) set `base` so the router owns the URL prefix once, instead of hand-prefixing every route pattern, `navigate()` target, and `<a href>`.

```jsx
import { router, navigate } from '@hellajs/router';

router({
  base: '/app', // served from https://example.com/app/
  routes: {
    '/': () => currentView(<HomePage />),
    '/users/:id': (params) => currentView(<UserDetail id={params.id} />)
  }
});

navigate('/users/:id', { params: { id: '7' } });
// URL: /app/users/7
// route().path: '/users/7'; logical, base-free
```

Everything inside the router stays **logical**: route patterns, `navigate()` targets, `route().path`, `active()`, and `crumbs` never see the base. The router strips it from the URL on every read (initial load, `popstate`, intercepted link clicks) and re-adds it on every history commit. Links carry the full deployed URL:

```typescript
// <a href="/app/users/8"> routes logically to /users/8; the base is stripped on click
```

`base` applies to history mode only; hash mode never touches the pathname, so the base is ignored there (documented, not an error). A trailing slash is normalized away (`'/app/'` behaves as `'/app'`), and the value must start with `'/'` or `router()` throws.

## Scroll Behavior

Control scroll position after navigation at three levels of specificity.

```jsx
import { router, navigate } from '@hellajs/router';

// Global default
router({
  scrollBehavior: 'top', // 'auto' (default) | 'top' | 'preserve'
  routes: { /* ... */ }
});

// Route-level override
router({
  scrollBehavior: 'top',
  routes: {
    '/feed': {
      scroll: 'preserve', // Override: keep scroll position
      handler: () => currentView(<Feed />)
    },
    '/chat': {
      scroll: false, // Disable scroll handling
      handler: () => currentView(<Chat />)
    }
  }
});

// Inline override (highest priority)
navigate('/long-page', { scroll: 'top' });
```

Custom scroll functions receive `(to, from, savedPosition)` and return `{ top, left? }` or `null` to skip. `savedPosition` is the scroll position captured when the returned-to page was last left, non-null only on browser back/forward, `null` on pushes and replaces.

```typescript
// Top on push, restore on back/forward (the Vue Router default policy)
router({
  scrollBehavior: (to, from, savedPosition) => savedPosition ?? { top: 0 },
  routes: { /* ... */ }
});
```

**Scroll priority:** Inline `navigate()` > Route-level `scroll` > Global `scrollBehavior`

See [`router`](/reference/router/router) for all scroll configuration options.
