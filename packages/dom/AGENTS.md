<dom-package-instructions>
Surgical DOM rendering — no virtual DOM diffing. Only elements with reactive dependencies update, never whole trees. Client JSX compiles (babel plugin, `target: "dom"`) to imperative `@hellajs/dom/runtime` construction: cached template clones wired by `text`/`prop`/`on`/`child` calls. The `HellaNode` AST is the server's currency — `@hellajs/ssr` stringifies it and the babel `"ast"` target emits it; it is not a mount input (`mount`/`hydrate`/`child` reject hand-built HellaNode with the documented throw). Per-node state lives in a `WeakMap<Node, ElementState>`, never on DOM nodes. Code/test/docs style rules live in `guides/code.md`, `guides/tests.md`, `guides/docs.md` — not duplicated here.

## ElementState (`lib/internal/state.ts`) — `WeakMap<Node, ElementState>`

`getState` lazily creates; `peekState` returns `undefined` if absent; `hasState`/`deleteState` wrap `has`/`delete`. Initial shape: `{ isMounted: false }`. All four collections — `handlers`, `effects`, `directHandlers`, `hooks` — are **lazy-allocated on first use** (`setNodeHandler` → `handlers` object, `registry.addEffect` → `effects` array, the direct-events feature's `bindDirectHandler` → `directHandlers` Map, the hooks feature's `addHook` → `hooks` object) — elements that never carry `on:` / a function-ref prop / `e:` / `hook:` pay zero collection allocation at mount (guide `code.md` §Memory).

| Field | Purpose |
|---|---|
| `effects` | `(() => void)[]` effect disposers; drained during cleanup. |
| `handlers` | `Record<type, EventListener>` delegated handlers (one per type per element); lazily allocated by `setNodeHandler`. |
| `directHandlers` | `Map<type, DirectListenerSpec>` — wrapped `e:` handler + caller options; `removeEventListener`-ed with the same options on cleanup. |
| `hooks` | `Partial<Record<HookType, fn[]>>` stacked lifecycle hooks; all execute in insertion order. |
| `isMounted` | `true` once `afterMount` has fired. Set for root + descendants at the end of `attach()` via the handle's `flush()` — but only while any lifecycle hook exists anywhere (`mountHooksExist` in `lib/features/hooks.ts`, flipped by the first hook registration; hook-free apps skip the walk entirely). For hooks registered post-mount, mounted-ness resolves lazily: `registry.addHook`'s `afterMount` immediate-fire and `registry.addEffect`'s update-hook gate both fall back to `element.isConnected` (both suppressed while `isMountInFlight()` — a mount/hydrate attach is running; under hydrate the suppression is load-bearing, because adopted elements are connected from the start and a premature `isMounted = true` would let the flush walk's idempotence gate permanently suppress their `afterMount`). The scoped `MutationObserver` only catches *later* dynamic additions; `queueMountWalk` covers inserts into targets no observer watches (Portal's remote target). |
| `componentScope` | Dispose fn from `scope()`, attached when a node is created by `component()`. |
| `portalCleanup` / `forEachCleanup` / `lazyCleanup` / `transitionCleanup` / `suspenseCleanup` | Optional component disposers. Every dynamic component registers on its **anchor** (its own persistent text anchor, or the hydrate region anchor under `adoptRegion`), so cleanup fires when the anchor is removed or drained (`drainAnchorCleanup`). |
| `errorConfig` | Set when the node carries any `error:` attribute. |
| `originalBuild` | The element's own build fn, set by the runtime's `errorConfig()` wiring (`error:` prefix) — `dispatchError`'s reset arm re-invokes it for fresh nodes on `context.reset()`. |
| `cachedBoundary` | Memoized nearest boundary (revalidated each lookup). |
| `dirtyChildren` | `Set<Node>` of nearest state-carrying descendants, lazily allocated at first registration; `clean` drains it transitively so subtree cleanup visits only state-carrying nodes. Strong refs, lifetime bounded by this state's WeakMap entry. |
| `registeredIn` | Ancestor node whose `dirtyChildren` holds this node — O(1) unregister on cleanup. Set at state creation: the climb walks `parentNode` to the nearest state-carrying ancestor, falling back to the `buildParents` stack while a build frame is mid-build (build wiring completes before `appendChild`, so `parentNode` is null at build-path creations). Restored by the observer additions loop on cross-parent moves; repaired by `wireFragmentScope` when a post-order carrier wire creates state over already-built descendants. |

## HellaNode (`lib/types/nodes.d.ts`) — server/compiler currency

Plain object produced by the babel plugin's `"ast"` target and consumed by `@hellajs/ssr`'s stringifier. Not a mount input on the client: `mount`/`hydrate`/`child` reject it with the documented throw. `isHellaNode` (`internal/utils.ts`) = `isObject(v) && v.tag !== undefined` — the hot-path structural discriminator. Dom-local and deliberately skips the `isPlainObject` proto/`toString` cost; DOM Nodes expose `tagName` (not `tag`), so they fail the `tag` own-property check and are correctly rejected.

| Field | Purpose |
|---|---|
| `tag` | Element tag, or `"$"` for fragment. |
| `props` | Static attributes applied once at mount via `renderProp`. |
| `on` | Delegated handlers (`on:` prefix). |
| `e` | Direct non-delegated handlers (`e:` prefix); value = handler function or `{ handler, options }` spec. |
| `hooks` | Lifecycle hooks (`hook:` prefix). |
| `error` | `error:fallback` / `error:category` / `error:boundary` (`error:` prefix). |
| `children` | Always flat — one `HellaChild[]` level at most (the type admits no nested arrays); the babel plugin emits flat arrays. |
| `componentScope` | Attached by `component()` (a static root is spread into a fresh node first — the shared template node is never mutated) and **chained, never overwritten**, when the node already carries an inner component's scope (a component returning another component's result). Server-side: the scope rides the node through `ssr`'s walk. |
| `static` | Hoist marker — set by the babel plugin on a fully-static subtree compiled into a shared module constant (ast target only; the dom target folds statics into its template html). Inert server metadata: the shared AST is stringified directly, and `component()` spreads the root per instance so the shared reference is never mutated. |

### `RenderFn` / `SsrMeta` (isDynamic components)

`RenderFn = ((element) => void) & { isDynamic: true; ssr?: SsrMeta }` — the return type of the five isDynamic components (`ForEach`/`Portal`/`Lazy`/`Transition`/`Suspense`). Each attaches `fn.ssr = { kind, props }` before returning, carrying its kind (`"forEach"`/`"transition"`/`"portal"`/`"lazy"`/`"suspense"`) and the resolved props object. `SsrMeta` is consumed **type-only** by `@hellajs/ssr`, which reads `kind` to re-implement each component's render without DOM access. `props` is typed `object` (not `Record<string, unknown>`) because TS interfaces (`ForEachProps`, etc.) lack a string index signature; ssr casts to index it. A user-authored isDynamic function has no `ssr` and renders as nothing in SSR.

## Attribute prefixes

| Prefix | Bucket (ast target) | Behavior |
|---|---|---|
| `on:` | `node.on` | Delegated: one `document.body.addEventListener(type, …, true)` (capture phase) per type. |
| `e:` | `node.e` | Direct: per-instance `addEventListener` (bubble phase), error-boundary-wrapped. Value = handler function or `{ handler, options }` spec forwarding native listener options (`once`/`passive`/`capture`). |
| `hook:` | `node.hooks` | Lifecycle: `beforeMount` / `afterMount` / `beforeDestroy` / `afterDestroy` / `beforeUpdate` / `afterUpdate`. |
| `error:` | `node.error` | Config: `error:fallback` (fn) / `error:category` (string) / `error:boundary` (boolean). |
| (none) | `node.props` | Attribute; a function-ref value (signal / `() => …`) is reactive (effect-wrapped), else applied once. |

The dom target emits the same buckets as runtime wiring calls: `on` (delegated), `direct` (e:), `hook`, `errorConfig`. A prefixed attribute in COMPONENT position stays verbatim in the component's props — the component's own emission re-emits it onto an element, and the runtime spread funnels every key through `prop()`, whose four-family routing (`on:`/`e:`/`hook:`/`error:` → the `on`/`direct`/`hook` bodies + a per-key `errorConfig` merge that never touches `originalBuild`) lands it live; element-position syntax still loads the feature. There is no hand-built escape hatch (hand-built input throws).

## `mount(node, target = "#app")` (`lib/mount.ts`)

The handle scaffolding (`flush`/`unmount` closures, `attached`/`cancelled` state, thenable dispatch, `beginMountPhase`/`endMountPhase` bracket) is shared with `hydrate` via `createMountHandle` (`lib/internal/handle.ts`); only `attachImpl` differs, and `hydrate`'s optional `afterFlush` arg starts the deferred-region watch after the first `flush()`. `attachImpl` returns the `mountedNodes` root array the handle's `unmount()` iterates (`cleanupSubtree` + `parentNode?.removeChild` each); mount's is `Array.from(container.childNodes)` after `replaceChildren`, so a spread fragment root's children all unmount.

Input contract: a flagged build fn (`isTemplateBuild`), a sync wrapper returning one, or an async fn resolving to one — anything else throws the documented hand-built rejection. `attachImpl` invokes the build through `resolveNode`'s flagged branch inside a build frame (creation-time overlay climbs see the container; `componentScope` wires onto the constructed root), then `container.replaceChildren(el)` → `registerContainer(container)` (starts scoped observer) → `attached = true` → `flush()` (drains the mount queue: sets `isMounted = true` and fires `afterMount` for root + descendants; idempotent).

- **Async mount rejections** route through `dispatchError(err, { phase: 'mount' })` — no element context, so no fallback rendering; surfaces via `onError` or `console.error('[dom]', err)`.

## `hydrate(node, target = "#app")` (`lib/hydrate.ts`, `lib/internal/hydrate.ts` + `internal/deferred.ts` + `internal/adoption.ts` + `internal/claims.ts`)

Attaches reactivity to existing server-rendered HTML in place — re-executes the compiled build and wires effects/handlers/state to the DOM the server shipped, **never `replaceChildren`** (the core invariant vs `mount`). Input contract mirrors `mount` (flagged builds only; the hand-built throw applies).

- **Flagged imperative root (compiled hydration)** — the once-resolved node must be a flagged build fn (`isTemplateBuild` checked BEFORE `resolveValue`'s re-resolve in `attachImpl` — the fn is the root; re-resolving would run the build outside the adoption context). `hydrate` runs it under the internal adoption context (`adoptTemplateRoot`, `lib/internal/claims.ts`): `template()`/`fragment()` create fns **claim** the matching server nodes (tag/type-verified at the claim site via `tagMatches`; identity preserved — nothing is cloned, callers never re-append) and `text`/`prop`/`on`/`child` wire onto the claimed nodes. An empty container mounts fresh through the same create arms (context absent → clones). **Claim order = construction order = document order** — sound only because the compiler's emission rule pins it: *the compiler emits every dynamic site in document order, and claims never skip an unconsumed region marker*. Static text/child calls are no-ops under adoption (the claimed subtree already carries them — appending would duplicate). Divergence — a claim with no matching node, a marker where an element claim expected a node, or server DOM no claim consumed (trailing static structure is fine: only an unconsumed `[` marker or a non-empty remembered region throws) → `throw` `[dom] hydrate: unmatched server DOM for imperative root`. The context is reentrancy-safe (prev-context restore in `adoptClaimFrame`'s `finally`, which `adoptTemplateRoot`'s frame runs under).
- **Claim machinery** (`lib/internal/claims.ts`): `claimElement` claims a single-root template's server node positionally (the claimed root is already positioned — callers never re-append) with `verifyFoldedChildren` checking folded static structure; `claimFragmentRoots` claims a fragment's static roots eagerly and remembers inter-root regions for its wiring calls to dequeue — the **fragment token** is the view the compiled build member-addresses (`firstElementChild`, `children[i]`): a `Proxy` over an empty detached fragment resolving those against the claimed roots in claim order (mount-path clones have real children; the adoption token must answer the same member accesses), keyed by identity into `adoption.fragments` so wiring calls route through `routeClaimParent`. An all-wirings fragment (no static slots) claims no roots — its scope carrier is picked after the build from the record's `claimedAnchors[0]`. `claimFlaggedChild` (from `child()`'s isDynamic/template arms under adoption) probes the cursor: a marker → `consumeRegion` + `adoptDynamicRegion` (the shared `ssr` meta switch) for isDynamic renders, or a nested flagged build's `adoptClaimFrame` (cursor seeded at the gathered head, bound at the region's close-marker successor) for non-meta builds; no marker → `runInClaimFrame` positional claims. `claimAndAdoptRegion` (from `text`/`child` reactive arms) dequeues fragment-remembered regions first, else consumes at the cursor, then `adoptReactiveRegion`. The machinery is split from the adoption STATE half (`lib/internal/adoption.ts` — the ctx, its push/pop accessors, `adopting`/`peekAdoption`/`peekClaimParent`/`routeClaimParent`, `constructFresh`, and the `setClaims` seam): it registers into the seam at module init (the `runEffectHooks` injection pattern, single-object form), and the runtime's claim sites resolve the registered object behind their `adopting()` guards — `runtime.ts`'s static import graph reaches the state half only, so a bundle that never imports `hydrate` (or the opt-in meta-components) tree-shakes all claim/adopt code.
- **`HydrateCtx` + stack** (`peekHydrateContext`/`push`/`pop`) — an **internal** type in `lib/internal/hydrate.ts` (NOT in `nodes.d.ts`; `RenderFn`'s public signature is unchanged). Carries `{ anchor, existingNodes, stageMissing?, claimBound? }`. `adoptRegion` pushes it around each isDynamic `fn(parent)` call so the component adopts the marker-gathered region nodes instead of building fresh; `claimBound` carries the region's close-marker successor so a meta body claiming under its own nested frame (Suspense) stops its leftover scan at the region's edge. Reentrancy-safe for nested regions. `adoptRegion` + `swapSuspenseStage` are exported `@internal` and registered into `internal/deferred.ts` via `setDeferredAdopters` at module init (the injection-pattern cycle break: deferred.ts needs the region-coupled fns, hydrate.ts needs the deferred-state accessors, so deferred.ts imports no hydrate.ts values).
- **isDynamic dispatch** (`adoptDynamicRegion`, the shared `ssr` meta switch — `child()`'s isDynamic arm routes here under adoption): `consumeRegion` gathers the region's nodes + positions the anchor; `adoptRegion` pushes the ctx + calls `fn`. `ForEach`/`Transition` claim+wire the gathered nodes (their compiled builds resolve under claim frames, wiring handlers/effects onto the server DOM — details below); `Portal` passes `[]` (server rendered nothing in-place) and re-mounts into the target; `Lazy` adopts the gathered nodes too — server content (a loaded render from `ssr.async`/`ssr.stream`, or a sync render's loading UI) stays until the loader's fresh run swaps it (`Lazy.ts` skips the loading insert when the region is non-empty and `clearRenderedNodes`s the server nodes on settle — no flash). `Suspense` runs `swapSuspenseStage` — the no-script/HappyDOM fallback (a staged `<template>` whose id matches a sentinel comment replaces the fallback; the swap also returns the sentinel comment itself). In a browser the inline `$hs` swap script (emitted by `@hellajs/ssr`) has already swapped each region as it arrived, so this runs only when that script hasn't (e.g. in tests). Either way it then adopts the resolved children — the swapped-stage arm re-invokes the flagged child under `adoptClaimFrame` seeded at the stage's first node (`claimBound` bounds the leftover scan), so its create fns claim and wire the stage nodes in place (never a fresh re-render — the documented hydrate contract). When the sentinel is present but its staged `<template>` never arrived (interrupted stream), the ctx is flagged `stageMissing` and `<Suspense>` degrades to fresh-mount semantics — fallback kept, child re-suspended client-side, content swapped on settle, rejections bubbled — EXCEPT while `document.readyState === "loading"` (hydrate executing mid-parse), where the region is instead registered in `deferredRegions` (`deferSuspenseRegion`, `internal/deferred.ts`): the fallback stays mounted, `fn` is NOT called, and `hydrate`'s attach starts the deferred-region watch (`startDeferredRegionWatch`, `internal/deferred.ts`) — a MutationObserver on the hydrate container (`childList + subtree`) calling `recheckDeferredRegions` on mutation (template arrived → swap+adopt; sentinel detached + fallback replaced externally → adopt what now occupies the region slot, anchor → recorded `next`), a raw `document.body` capture listener buffering the discrete set `{click, mousedown, mouseup, keydown, change}` whose `composedPath()` crosses a pending region's recorded nodes, and a `document` `readystatechange` listener that drains remaining regions to `stageMissing` degrade when the document completes (dead stream). On adoption, buffered events replay POSITIONALLY — on the original target while connected, else on the adopted node at the same top-level index (a detached target cannot reach the delegated body listener, and the handler lives on the resolved content); entries with no connected counterpart are dropped; an `isReplaying` guard prevents re-buffering; synthesized `new Event(type, { bubbles, cancelable, composed })`, no coordinate fidelity. The watch tears down at zero pending; the inline `$hs` no-ops for a deferred region (hydrate consumed its markers — the balance walk finds no open `[`), leaving the template for the watcher. ForEach's first-render adopts via `hctx.existingNodes` into `keyToNode`/`keyToItem`/`currentKeys` **iff `existingNodes.length === arr.length`** (count-strict): a flagged-build item resolves under `adoptClaimFrame` (head = the item's gathered node, bound = the next item's head else the region's `claimBound`; fragment results throw the single-element contract) so its handlers/effects wire onto the claimed node; non-build results pair positionally. The region anchor then relocates after the last adopted node, so reconcile inserts (boundary = first suffix node else anchor) match mount semantics — post-hydrate appends land after the adopted items. On mismatch it warns + removes the gathered nodes + fresh-builds (the LIS update path is unchanged). `Transition` claim+wires its children build under `adoptClaimFrame` (`existingNodes[0]` head, `claimBound` bound) when visible, assigning the claimed root as `current` (applies `appear`); an empty region keeps the fresh-mount path.
- **Marker contract** — `ssr()` wraps every dynamic region (reactive child, isDynamic component, nested fragment) in `<!--[->…<!--]-->` Comment markers; hydrate reads them. There is **no coalescing/rebuild**: each reactive value is its own bounded region, adopted in place. Missing markers on a reactive region → `console.warn` + fresh-mount (graceful degradation); a missing raw marker or an unmatched root claim is divergence (throws — see above). Reset: `resetHydrateState()` clears the stack and delegates its deferred half to `resetDeferredState()` (`internal/deferred.ts` — registry + replay queue cleared, watch torn down; wired into `resetDom()`).

## `lib/internal/render.ts` — resolve/classify machinery

The shared construction seams the runtime's wiring calls and the mount/hydrate entries drive. Holds `NO_VALUE` (the prop-effect memo sentinel, shared with `runtime.ts`'s reactive `prop`), `HTML_NS` (namespace seam constant), `createDomElement`/`childNamespaceOf`/`parseRawHtml`/`cloneUpgrading` (feature seams — see §Feature gating), `clearRenderedNodes` (region teardown helper), `getBoundaryConfig`/`findBoundary`-backed runtime boundary resolution, `resolveNode`, and `runReactiveChild`.

- **`resolveNode(value, parent?, ns?)`** — the single classifier: a raw DOM `Node` returns as-is; an array → each item resolved into a `DocumentFragment`; a raw sentinel (`{ raw }`) → `parseRawHtml`; a flagged build fn → invoked inside a build frame (`pushBuildParent(parent)` so creation-time overlay climbs see the future parent; a non-undefined `ns` also opens an insertion-namespace frame — `pushInsertionNs` — so the create fn's clone step can re-create boundary-crossing content whose parse could not know its ancestry) with `fn.componentScope` wired onto the returned root — element root onto its own state; fragment root through `wireFragmentScope` onto the carrier (mount/clone: the fragment's last child; adoption: the claim record's `claimedAnchors[0]` — the token returns before its wirings run, so the carrier is unknowable at claim time); any other function → a reactive child region: a persistent empty-text anchor riding a detached carrier fragment (returned for the caller to insert — the effect's first, synchronous run fills the carrier; later runs find the live parent), driven by `runReactiveChild`; a primitive → text node.
- **`runReactiveChild(anchor, nodes, child, parent, boundary?, ns?)`** — the shared effect body for every reactive child region (runtime `child()` function arm, `resolveNode`'s function branch, `text()`'s reactive arm equivalent): deep-resolves the child (`resolveDeep` — plain-fn chains resolve to their final value, stopping at `isDynamic` and template builds), `clearRenderedNodes` on the previous run's nodes, then re-classifies: a dynamic function → a `Proxy` parent intercepts `appendChild` to track nodes while still inserting before the anchor (its render errors PROPAGATE — meta-components pass through `component()` verbatim with no catch; swallowing would hide Portal's target-not-found contract); node/array/template-build/raw → `resolveNode` in a build frame, inserted before the anchor; text settles INTO the anchor (`anchor.textContent`) — the anchor doubles as the persistent text node, so text regions keep their DOM node identity across updates (Portal's pinned contract). Each re-run first calls `drainAnchorCleanup(anchor)` so component state left on the persistent region anchor never outlives its run. Errors from the reactive VALUE resolution dispatch `phase: 'mount'` (boundary resolved at run time — `currentBoundary ?? findBoundary(actualParent)`); the fallback builds fresh inside `constructFresh` (mount semantics under an active claim frame) and inserts before the anchor — **preserves siblings**.
- **Namespace threading** (`lib/features/namespaces.ts`, registered via `setNamespaceResolution`). The feature's `createDomElement`: `tag === "svg"` → `createElementNS(SVG_NS)`, `tag === "math"` → `createElementNS(MATHML_NS)`, else `ns ? createElementNS(ns, tag) : createElement(tag)` (HTML hot path unchanged; the unloaded default is bare `createElement`). `childNamespaceOf(parent)` is the single derivation: the parent's own `namespaceURI` when foreign, `undefined` for HTML parents / fragments / text anchors / `foreignObject` (HTML integration point). The `ns` param is consumed only at creation — children re-derive from the live parent element, so there is one source of truth. All child-creation call sites thread it: ForEach (`actualParent`), Transition/Suspense (`parent`), Lazy (anchor's parent), Portal (remote `target`), `adoptReactiveRegion` (`parent`), the runtime's template parse (`parseWithContext(html, ns)` rebuilds the parsed tree `createElementNS`-correct — the root intent is the compiler-emitted `ns` param, not tag tables; `child()`'s flagged arm passes `childNamespaceOf(parent)` so component-boundary templates re-create under `resolveNode`'s insertion-ns frame when the parsed namespace ≠ intent).

## `@hellajs/dom/runtime` (`lib/runtime.ts`) — compiled construction

Public compiler-contract subpath (explicit `package.json` exports entry, NOT re-exported from the barrel): `template` / `fragment` (html + optional parse `ns` → cached create fn; parse-once per html+ns pair, create fns identity-stable per pair — the compiler emits `ns` from static JSX ancestry for svg/math-interior templates, replacing the deleted runtime tag tables with a tableless namespace walk at parse plus a mismatch-guarded insertion-ns re-create for component-boundary content; `template` clones the single root ELEMENT per call and `getState`s it before returning — root-state-first is the module invariant, so child wiring never orders its calls; `fragment` clones the whole content and state-inits its FIRST child as the scope carrier, the fragment itself being ephemeral on append), `mark(fn, props?)` (flags `isTemplate: true` + reconciliation `props`), `text` / `prop` / `on` / `direct` / `hook` / `errorConfig` / `child`. `TemplateBuildFn = (() => Element) & { isTemplate: true; props?; componentScope? }` is defined here. All ten wiring fns route through the same seams the mount paths use (`setNodeHandler`, `bindDirectHandler`, `registry.addEffect`/`addHook`, `renderProp`, `parseRawHtml`); `prop`'s four prefixed families (`on:`/`e:`/`hook:`/`error:`) route BEFORE the reactive branch — `on`/`direct`/`hook` bodies verbatim, `error:` a per-key merge into `getState(el).errorConfig` that never touches `originalBuild` — so rest-forwarded spread keys land live, a function value under a prefixed key never enters the effect path, and a later routed write wins per key for the override families (`hook:` stays accumulative; wiring order decides — registry canonicals that compose an internal same-event handler register it after the attrs spread and so override a spread-routed caller handler, while canonicals that honor a forwarded handler take it as a named prop wired inside the internal handler, e.g. AccordionTrigger's `"on:click": userClick`); `prop`'s reactive arm carries the `NO_VALUE` memo and dispatches errors `phase: "update"` (boundary resolved at run time via `findBoundary`); `text`'s static arm appends a text node (no-op under adoption — the claimed subtree carries it); `child`'s arms: an isDynamic render fn dispatches DIRECTLY against the parent on mount (the walker's semantics — its render errors propagate to the wiring call; Portal's target-not-found contract) and through `claimFlaggedChild` under adoption; a flagged build appends `resolveNode`'s product (adoption: `claimFlaggedChild`); a plain function opens a reactive region (`claimAndAdoptRegion` under adoption); a HellaNode THROWS (hand-built input); a raw DOM node appends (no server counterpart — client-only values, e.g. `element()` slot arrays); strings/numbers append text (no-op under adoption); arrays recurse.

- **Custom-element upgrade at clone time (feature-gated).** The compiler hoists `template(...)` calls to module evaluation — the parse can precede the element's `customElements.define`. The custom-elements feature (registered via `render.setCloneUpgrader`) arms each builder at creation: its parse-time hyphen scan flags templates containing a hyphenated local name, and those builders' create fns re-create each defined custom element in the fresh clone as an upgraded instance (`upgradedShell`: attributes + children moved across, `namespaceURI === HTML_NS` guarded, `instanceof` skip for already-upgraded clones) and walk descendants (`upgradeClones`). Without the feature the runtime resolves every builder to a no-upgrade create path (the default `cloneUpgrading` is `undefined`) — the scan and walk ship only with the feature import. Without the upgrade, `renderProp`'s custom-element property branch misses (the clone is a plain `HTMLElement`, `"data" in el` false → attribute-branch stringification) and the insert-time platform upgrade re-runs constructor field initializers, clobbering wired values. happy-dom's `customElements.upgrade` is a no-op, so the create fn performs the upgrade itself.

**Flagged-fn protocol.** `isTemplateBuild(value)` (`@internal`, `internal/utils.ts`, `import type { TemplateBuildFn } from "../runtime"` — type-only, no runtime edge) is the discriminator; every consumer that accepts flagged fns branches on it BEFORE the reactive-region/`isFunction` classification: `resolveNode`'s flagged branch (build frame only when `parent` is passed — ForEach already frames; wires `fn.componentScope` onto the returned root), `child()`'s template arm, `ForEach`'s initial-build and keyed-reuse key fallbacks (`element.props?.key` read off flagged fns), and `component()` (fn result → `isTemplate = true`, `componentScope` chained onto the fn, flagged fn returned as the wrapper result; HellaNode results verbatim — the server currency; isDynamic results returned verbatim with the scope chained on). `resolveDeep` **stops at template builds** (they classify by themselves — invoking one would construct outside the consumer's build frame and reduce the root to a text coercion), so `runReactiveChild` and `adoptReactiveRegion` accept a resolved build fn through their element/array branches (`resolveNode` constructs it in-frame, scope wired). `ElementState.originalBuild` (`() => HellaElement`) + `dispatchError`'s reset arm: `originalBuild` present → `boundary.replaceChildren(build())` re-invoking the stored build.

**JSX.Element typing.** The global `JSX.Element` in `lib/index.ts` is `HellaNode & RenderFn & TemplateBuildFn` — one JSX type serving both compile targets: the `HellaNode` arm is the ast/ssr view, the `TemplateBuildFn` call shape is what the dom emission produces (so JSX literals are assignable to `mount`/`hydrate` while plain hand-built HellaNode objects stay non-assignable — the flip's compile-time rejection).

## Feature gating (`lib/features/{errors,hooks,direct-events,raw,namespaces,custom-elements}.ts`)

Each gated subsystem's wiring lives in a feature module that registers into always-shipped seams at module init (the injection pattern: an exported `let` binding swapped by a `set*` registration fn — call sites read the live binding). The babel plugin emits a bare `import "@hellajs/dom/features/<name>"` when a file's JSX uses the feature's syntax, and `package.json` `sideEffects: ["dist/features/*.js"]` keeps those imports alive; unused features tree-shake entirely. No new logic lives in features — registration plus moved wiring only. Loaders without JSX detection: `lib/error.ts` re-exports `onError` from `features/errors.ts`, `lib/raw.ts` re-exports `raw` from `features/raw.ts`, `lib/hydrate.ts` imports `features/namespaces.ts` + `internal/claims.ts` (the claim machinery's seam registration) + registers ForEach's hydrate-context source, and `$ref`/`$collection` (via `internal/reactive.ts`) import `features/hooks.ts` — their `.hooks()` registers with no JSX to detect.

| Feature | Loads via | Registers into | Moves |
|---|---|---|---|
| `features/errors.ts` | `error:` JSX, `lib/error.ts` | `dispatch.setErrorDispatch` (`dispatchError`/`findBoundary`/`resolveErrorConfig`/`resetErrorState`) | handler Set + boundary walk + dispatch + onError + mount-time `errorConfig` application (the runtime's `errorConfig()` fn snapshots `originalBuild` for the reset arm) |
| `features/hooks.ts` | `hook:` JSX, `$ref`/`$collection` | `registry.setHooksFeature` (`addHook` + `runEffectHooks`), `queue.setMountQueueArm` | hook registration, effect update-hook bracket, mount queue + drain + observer additions |

| `features/custom-elements.ts` | hyphenated JSX tag names | `render.setCloneUpgrader` (`hasCustomElements`/`upgradeClone`) | parse-time hyphen scan, `upgradedShell` re-creation, `upgradeClones` walk |

Defaults reproduce the no-feature paths exactly: `dispatchError` logs `[dom]` + returns null, `findBoundary`/`resolveErrorConfig` find nothing, `bindDirectHandler`/`addHook`/`queueMountWalk` no-op, `parseRawHtml` yields an empty fragment, `createDomElement` is `document.createElement`, `childNamespaceOf` returns undefined, `cloneUpgrading` is undefined (template builders resolve to a no-upgrade create path). Seam names avoid the bench rg-gated symbols (`bindDirectHandler`, not `setDirectHandler`; `drainMountQueue`, not `processMountQueue`; `parseRawHtml`, not `rawToFragment`; ForEach's `peekRegionContext`, not `peekHydrateContext`; the custom-elements seam is `setCloneUpgrader` — `upgradeClones`/`upgradedShell`/`containsCustomElement` appear only inside `lib/features/`) — gated identifiers appear only inside `lib/features/`.

## Cleanup & queues (`lib/internal/cleanup.ts`, `lib/internal/queue.ts`)

Two cooperating mechanisms share one `MutationObserver` per mount target:

- **Sync `cleanupSubtree(root)`** — called directly by `runReactiveChild` (reactive child swap), ForEach (stale-removal + list clear), Transition (leave completion), the Lazy/Portal cleanup arms. A state-carrying root takes the **overlay fast path**: `clean(root)` alone, reaching every state-carrying descendant transitively through `dirtyChildren` (each drained child is first verified still a descendant — a moved-out node's stale link just drops; after the drain the node unregisters from its own `registeredIn` and `deleteState` runs LAST so children's unregister reads survive). A stateless root keeps the `traverseDescendants` walk (iterative stack) — the external-removal safety net for stateless wrapper roots; a state-carrying descendant it reaches drains its own overlay through `clean`. Per-node `clean(node)`: `beforeDestroy` → `componentScope?.()` → `portalCleanup?.()` → `forEachCleanup?.()` → `lazyCleanup?.()` → `transitionCleanup?.()` → `suspenseCleanup?.()` → drain `effects` → `removeDirectHandlers` → `afterDestroy` → overlay drain → unregister → `deleteState`. Registration choke points keep the overlay equal to `clean`'s reach set: the `getState` creation climb with its `buildParents` build-stack fallback (`pushBuildParent`/`popBuildParent` frames every detached build that inserts into a possibly state-carrying ancestor — `resolveNode`'s flagged/function branches, `runReactiveChild`'s dynamic/node-array/error-fallback branches, ForEach's two item-build loops, hydrate's empty-container fallback, `renderEventFallback`; Lazy/Transition/Suspense/Portal post-mount insertions stay frame-free — observed containers re-register via the additions loop, Portal cleans tracked roots explicitly), observer additions re-registration, and `wireFragmentScope`'s wire-time descendant walk. After either path's clean completes, `cleanupSubtree` marks the root via `markCleanedRoot` (`queue.ts`, wired in through `setCleanedRootMarker` — the mark state lives with the observer and cleanup.ts must not import queue.ts, which imports `cleanupSubtree` from it; the standard injection pattern) so the observer's removal record for it skips the re-walk (see the observer bullet). `drainAnchorCleanup(node)` (beside `clean`) runs the same component slots minus `componentScope` and drains `effects` **without** `deleteState` — the persistent hydrate region anchor survives re-renders, only its per-run occupants are disposed.
- **Scoped observer safety net.** `registerContainer(container)` (called from `mount()`/`hydrate()`; accepts an `Element` or a shadow root) + `ensureContainerObserver` lazily create one `MutationObserver` shared across all mount targets (`observedContainers: WeakSet<Element | ShadowRoot>`), observing `{ childList: true, subtree: true }`. Removed nodes' traversed via `collectRemovedNode` (exported `@internal` from `queue.ts`; the refObserver's removal walk reuses the same collector), which collects removed nodes with state → `cleanupQueue` — a stateful node is queued WITHOUT recursing into it (`processCleanupQueue`'s `cleanupSubtree` already traverses its descendants; only stateless intermediates are walked through); state-carrying **text** nodes queue too (a fragment root's scope can ride a text child — stateless text keeps the cheap skip); a root **marked by a sync `cleanupSubtree`** (first-line `cleanedRoots.has(node)` check) skips the walk entirely — its subtree state is gone by construction, so a ForEach clear / reactive swap / unmount pays only a WeakSet lookup per removed root instead of re-walking every node the sync clean already visited; additions **unmark**: while `cleanedMarksExist` (set by the first mark, cleared only by `resetQueueState`), each added **element** node deletes itself and every `parentNode` ancestor up to the nearest observed container from `cleanedRoots` — continuing past unmarked intermediates, since a marked grandparent is stale even when the direct parent is unmarked — so a re-inserted cleaned root with fresh state mounted under it walks normally when removed again (the gate keeps first-create workloads — the common page load — out of the climb); added element nodes **with state re-register** (delete from their `registeredIn` set, re-climb from the new position — ungated, so cross-parent moves of live state land in the new ancestor's overlay); added element nodes → `mountQueue` **only while `mountHooksExist`** — the additions feed nothing else, and an ungated add retains every inserted element in the strong Set forever (hook-free apps never schedule the drain → cleared subtrees show as Detached memory); both drain on `queueMicrotask`. `processCleanupQueue` skips nodes still `isConnected` (re-attached, not removed).
- **`runHooks` element-argument rule.** `beforeMount` and `afterDestroy` are called with **no** argument; every other hook receives the element.
- **Reset (test).** `resetEventState` / `resetQueueState` / `resetSelectorState` / `resetDom` tear down listeners, observers, queues, between tests.

## Mount queue (`lib/features/hooks.ts`)

The afterMount walk (`drainMountQueue`, the queue arm the hooks feature registers into `queue.ts` — `queueMountNode`/`queueMountWalk`/the observer's `collectAdded` additions feed it) traverses each queued node's descendants; every element with state gets `isMounted = true` and `afterMount` run, **idempotently** — already-`isMounted` nodes are skipped, so re-flushing never double-fires `afterMount`. The whole walk is **skipped while no lifecycle hook has ever been registered** (`mountHooksExist` in the feature) — hook-free apps (the common case) pay nothing, and without the feature the whole arm is a no-op (the seams default to no-ops). Skips nodes not `isConnected` at flush time. The scoped `MutationObserver` only catches *later* dynamic additions (it is started by `registerContainer` after the initial `replaceChildren`, so the initial tree is never observed); the initial attach is flushed explicitly at the end of `attach()`. `afterMount` therefore fires by the time `mount()`/`hydrate()` return — **no `flush()` call is required**. The handle's `flush()` remains as an optional escape hatch (e.g. to drain the cleanup queue synchronously in tests). An `afterMount` hook registered on an already-mounted node via `registry.addHook` fires immediately (`state.isMounted`, or lazily via `element.isConnected` outside a running attach — which also sets `isMounted` so the walk does not double-fire).

## Event delegation (`lib/internal/events.ts`)

- **One Set tracks types.** `globalListeners: Set<string>` holds every type with a registered `document.body.addEventListener(type, delegatedHandler, true)` (capture) listener; it is also the fast-exit checked at the top of `delegatedHandler`. **Never decremented** — types stay registered until `resetEventState()`.
- **`delegatedHandler`** reads `event.composedPath()` and walks it target-first; for each path element with `state.handlers[type]`, invokes `handler.call(element, event)` in try/catch. The walk checks `event.cancelBubble` at each iteration — a handler calling `stopPropagation()`/`stopImmediatePropagation()` halts it (later path handlers do not fire). Errors dispatch with `phase: 'event'` and render fallback via `renderEventFallback`. **No automatic `stopPropagation`** — every handler on the path fires unless one stops it.
- **`renderEventFallback(element, fallback)`** — the shared event-side fallback renderer: `findBoundary(element) ?? element` as target, the flagged fallback built inside a build frame + `constructFresh` (mount semantics), then `target.replaceChildren(fresh)` (replaces the boundary-or-element content).
- **Direct (`e:`) handlers** (`lib/features/direct-events.ts`, registered into `internal/cleanup.ts` via `setDirectEventFeature` — the `bindDirectHandler`/`removeDirectHandlers` seams default to no-ops; cleanup.ts hosts them because `clean` reads `removeDirectHandlers` locally and events.ts sits above render.ts/cleanup.ts (an events host made cleanup → events a module cycle)) are wrapped per-instance with the same error handling, stored in `state.directHandlers` (Map of `{ handler, options }` per type), and `removeEventListener`-ed with the same options on cleanup (`capture` is the discriminating flag for removal). The `e:` value is the handler function or a `DirectListenerSpec`; options forward verbatim to `addEventListener`. Delegated `on:` stays options-less **by design** — the body-level listener is shared per type, and making it non-passive for touch/wheel would degrade scrolling for every app; browsers treat body-level touch/wheel listeners as passive by default, silently no-oping `preventDefault()` in `on:` handlers — cancelable gestures use `e:` with `passive: false`.

## Keyed reconciliation — `ForEach` (`lib/ForEach.ts`)

Returns a function with `isDynamic: true` and `fn.ssr = { kind: "forEach", props }` (the SSR descriptor consumed type-only by `@hellajs/ssr`); `child()`'s isDynamic dispatch calls it with the parent. Creates a text anchor + one effect registered on the **anchor** (anchor-owned lifecycle: `getState(anchor).forEachCleanup` removes every tracked item from its live parent via `removeAllTracked` — same bulk fast path as a list clear — and `resetTracking` clears live + temp collections; the effect disposal rides the same anchor state) holding live collections (`keyToNode`, `keyToItem`, `currentKeys`) and reusable temp collections (`newKeys`, `newExplicit`, `newKeyToNode`, `newKeyToItem`, `nodesToRemove`, `keyToOldIndex`, `toMove`).

- **Single-root item tracking.** `keyToNode` holds one raw DOM `Node` per item: the `use` renderer must resolve to a single root (element or text node) — a `DocumentFragment` result (`<>…</>`) throws `[dom] ForEach: use must return a single element` at item build (both build paths: initial render and keyed reuse; each fresh item build runs inside `constructFresh` so mount semantics hold even under an active adoption claim frame). Stale detection reads `node.parentNode`; removal runs `cleanupSubtree` + `removeChild` per item (`removeTrackedItem`, shared by stale-removal and the non-owning clear path — the owning clear inlines a parent-checked `cleanupSubtree` then one `replaceChildren`); the fresh-middle batch inserts one fragment before the boundary node; the LIS walk moves middle nodes with a rolling move anchor. Keyed reuse compares node identity — same node reference, same item. Hydrate adoption stays count-strict: the `existingNodes.length === arr.length` guard pairs one server node per item, so a fragment-item region (divergent count) takes the warned fresh-build path, whose per-item build then throws.
- **Key resolution.** Inlined at every build loop (initial render, reconcile, hydrate adoption — the former module-local key helper is gone): the `ForEach` `key` extractor (`props.key`, function-validated once per component) → the flagged build's `props.key` (spread-carried keys ride `mark`'s props metadata — the compiler re-carries them there) → the item's `id` → array index. A tier is skipped when it yields `undefined`, so an undefined build key or `id` falls through. The first three set the item's explicit flag, recorded per position in `newExplicit` and swapped with the other temp collections; the index fallback records `0`.
- **Reuse rule.** `!node || (!explicit && keyToItem.get(key) !== item)` → fresh build. Explicit-class keys (extractor, build `key`, `id`) reuse by key identity regardless of item reference; index-fallback keys require the same item reference. With the extractor present, a retained key skips the `use` call entirely — the live node is reused and no build runs; `use` runs only for keys with no live node, and its result still passes the single-root check. The initial render and hydrate adoption invoke `use` per item as before.
- **First render** (`currentKeys.length === 0`): build into a `DocumentFragment`, single `insertBefore(fragment, anchor)`.
- **Stale removal** (every non-first render): existing items absent from `newKeyToNode` (or whose tracked identity changed) are collected, then removed in a batch via `removeTrackedItem`. Items whose live parent (the node itself, or a record's anchor) is not `actualParent` (e.g. portal-moved) are skipped.
- **Prefix/suffix trim** (every non-first render, after stale removal): `prefix`/`suffix` advance while the position holds the same key, the same node, and the reuse rule's class condition — explicit-class key, or the same item reference for index-fallback keys — so a positionally-equal item replacement never trims stale content. Trimmed positions skip all diff machinery and see no DOM writes; an empty middle performs none at all.
- **Middle-only diff**: `keyToOldIndex`, `toMove`, `mapped`, and the binary-search LIS (`O(n log n)`) operate on `[prefix, newLen - suffix)` against old indices `[prefix, oldLen - suffix)`. When no middle key is retained (all `mapped` `-1`), the fresh middle nodes batch into one fragment inserted before the boundary — the first suffix node, else the region anchor. Otherwise the reverse walk moves middle nodes still in `toMove` (local indices), anchored at the boundary; fresh middle nodes are inserted by the walk. Minimal DOM moves.
- **Empty list**: `removeAllTracked` — when the region owns the parent's entire child list (tracked nodes + anchor, the common sole-content case), per-item `cleanupTrackedItem` (cleanup without removal) then ONE `replaceChildren(anchor)` (one mutation record instead of N); foreign siblings force the per-item `removeTrackedItem` fallback; `resetTracking` clears live AND temp collections (nothing may hold a node after a wipe).
- **Collection swap**: live and temp collections swap by reference; `clear()` the temps next round, never reallocate.

## `Portal` (`lib/Portal.ts`)

Returns a function with `isDynamic: true` and `fn.ssr = { kind: "portal", props }`. Renders children to a remote target. Creates a local anchor, then in one effect (guarded by `if (portalNodes.length > 0) return` → runs once) resolves `document.querySelector(to)` — a miss throws the documented target error (surfacing at mount through the direct isDynamic dispatch) — builds nodes into a fragment, applies it via the target's `appendChild`/`prepend`/`replaceChildren`/`before`/`after` (`type` prop; default `append` maps to `appendChild`), then queues each inserted root through `queueMountWalk` (`internal/queue.ts`) — the remote target is not a registered observer container, so without this the inserted subtree's `afterMount` hooks would never fire. `state.portalCleanup` (on the **anchor**) removes each tracked node from its current parent on cleanup.

## `Lazy` (`lib/Lazy.ts`)

Returns a function with `isDynamic: true` and `fn.ssr = { kind: "lazy", props }`. Async loader with cancellation. Creates an anchor; `insertBefore`s a `loading` node (skipped under hydrate when the region holds server nodes — no flash; they stay until the fresh run replaces them). Allocates an `AbortController`; `state.lazyCleanup` (on the **anchor**) sets `isCancelled = true`, `controller.abort()`s, and removes the `loading` node plus the mounted/fallback content node (tracked in a closure local). Calls `props.loader({ signal })`, then:

- **Success** — guards on `isCancelled || !anchor.parentNode`; removes loading; clears hydrate-adopted server nodes (`clearRenderedNodes(existing, parent)`); a flagged build is used directly, an unbound `ComponentFn` is called with the forwarded props; `resolveNode` + `insertBefore` at anchor. **No nested Promise unwrapping** — loader must resolve to `ComponentFn | TemplateBuildFn`.
- **Error** — same guards; removes loading; if `props.fallback`, clears the hydrate-adopted server nodes then `resolveNode` + `insertBefore` at anchor; with no `fallback` the server content stays in place (static degradation) and the error logs. **Errors do NOT bubble to `onError`** (local fallback only).
- **Cancellation** — both `.then`/`.catch` check the guard, so resolve/reject after parent removal is a no-op. Pass `signal` through to `fetch`/AbortController-aware APIs for network cancellation.

## `Transition` (`lib/Transition.ts`)

Returns a function with `isDynamic: true` and `fn.ssr = { kind: "transition", props }`. Enter/leave CSS animations. Holds `current`, `leaveTimer`, `isFirstRender`. One effect re-runs on `show`:

- **Enter** (`show=true`, no `current`, no `leaveTimer`): a single-element children array unwraps to the element first (the babel plugin's compiled component-children convention — `resolveNode` maps arrays to a parentless fragment, which would silently skip every `instanceof Element` branch below), then `resolveNode(child, parent)`, `insertBefore` at anchor. Hydrate adoption: `existingNodes[0]` becomes `current` directly (bare adopt — the server node IS the current element; no re-render). `isFirstRender && appear` → add `appear` (string) or fall back to `enter`; `!isFirstRender && enter` → add `enter`. **Without `appear`, no class is added on first mount.**
- **Rescue** (`show=true` with active `leaveTimer`): `clearTimeout`, remove `leave` class, keep the node (rapid-toggle rescue).
- **Leave with class** (`show=false`, `current`, `leave`): add `leave`, schedule `setTimeout(cleanup, duration + 50)`. The 50ms absorbs frame-timing drift; `duration` (default **300ms**) must match the CSS animation. Timer callback runs `cleanupSubtree` + `removeChild`.
- **Leave without class**: `cleanupSubtree` + `removeChild` synchronously.
- **`transitionCleanup`** (on the **anchor**) clears a pending `leaveTimer` and removes `current` (`cleanupSubtree` + `removeChild`) when the anchor is cleaned up mid-leave. The `enter` class stays on after the animation (idempotent; re-entering re-adds it).

## `Suspense` (`lib/Suspense.ts`)

Returns a function with `isDynamic: true` and `fn.ssr = { kind: "suspense", props }`. A streaming + async boundary with three render paths:

- **`ssr.stream`** (server) — `@hellajs/ssr`'s walk flushes `fallback` inline and stages the resolved children in a `<template id="hsN">` for hydrate to swap.
- **`hydrate`** — `adoptDynamicRegion` → `adoptRegion`; `swapSuspenseStage` reads the staged `<template>` id from a sentinel comment, replaces the fallback with the template's resolved children, then adopts them — the no-script/HappyDOM fallback (in a browser the inline `$hs` script from `@hellajs/ssr` swaps each region as it arrives; this runs only when that script hasn't). Adoption re-invokes the flagged child under `adoptClaimFrame` seeded at the stage head — the create fns claim and wire the stage nodes in place. A sentinel-without-template at `readyState "loading"` defers instead (selective hydration — see the hydrate section); at any later readyState it degrades via `stageMissing` (re-suspend client-side — the `stageMissing` degradation arm keeps fresh-mount semantics).
- **Fresh mount** (client, no server HTML — e.g. after client-side navigation) — evaluates the child once (`isFunction(children) ? children() : children`). A thenable suspends: render `fallback` before the anchor, await, then `insertBefore(resolveNode(resolved), anchor)`. `state.suspenseCleanup` (on the **anchor**) sets a `cancelled` flag and removes the tracked suspended nodes plus the fallback; both `.then` and `.catch` no-op on `cancelled || !anchor.parentNode` (parent removed mid-flight is safe). Sync children render directly via `resolveNode` (no fallback) and are tracked the same way.
- **Errors bubble** — on rejection the pending `fallback` is removed (pending-only) and the error is `dispatchError`-ed with `config: resolveErrorConfig(parent)`, so the nearest `error:fallback`/`error:boundary`/`onError` renders (React/Solid/Vue parity). **Unlike `Lazy`, Suspense errors bubble** (Lazy keeps them local). No `AbortController`/`{ signal }` — network-level cancellation belongs to `resource`/`fetch`, not the boundary.
- **One-shot, not reactive** — the child function runs once at mount; `<Suspense>` does not re-suspend when a signal the child reads changes (reactive async = `resource` + a reactive child branching on `isLoading()`/`data()`).

## Error system (`lib/features/errors.ts`, `lib/internal/dispatch.ts`, `lib/error.ts`)

`onError(fn)` adds to `handlers: Set<ErrorFn>`; `onError(null)` clears all; returns an unregister. With **no handlers**, `dispatchError` logs `[dom] <error>` to `console.error` and returns `null` (no UI change). Handler errors are caught (`[dom] Error handler threw:`). Handlers iterate in insertion order; **first non-null flagged build wins**.

- **Boundary detection.** `findBoundary(origin)` walks `parentElement`, returns nearest element whose `errorConfig` has `boundary || fallback`. **A `category`-only config is NOT a boundary.** Memoized on `state.cachedBoundary`, revalidated each lookup (must still be `isConnected` and still have `boundary || fallback`).
- **Config resolution.** `resolveErrorConfig(origin)` walks the same way but returns the first config of any kind (incl. `category`-only) — populates `context.config` even without a boundary.
- **Infinite-loop guard.** `handlingBoundaries: WeakSet<Element>` tracks boundaries mid-handling; a second error from one logs `[dom] Error during error handling - preventing infinite loop:` and returns `null`.
- **Reset.** `context.reset` is synthesized only when the boundary has `state.originalBuild`; `reset()` = `boundary.replaceChildren(build())` re-invoking the stored build (old children drain through the mount-target observer on removal).
- **Fallback rendering is the caller's job** — `dispatchError` only returns the flagged build:

| Error site | Phase | Fallback rendering |
|---|---|---|
| `component()` render body | render | none — returns the environment-probed empty build (flagged empty-fragment build when a document exists; the `$` vnode keeps the server pipeline consuming) |
| `beforeMount` hook | mount | none — element continues mounting |
| Reactive child effect | mount | fresh build inside `constructFresh`, `insertBefore` at anchor (**preserves siblings**) |
| Function-ref prop effect | update | `replaceChildren` on the runtime-resolved boundary (replaces siblings) |
| `beforeUpdate`/`afterUpdate` hook | update | none — bindings stay functional |
| `on:`/`e:` handler | event | `renderEventFallback`: build frame + `constructFresh`, `replaceChildren` on `findBoundary(element) ?? element` |
| Async mount rejection | mount | none — no element context |

## `element()` custom elements (`lib/element.ts`)

`customElements.define` wrapper. **Light DOM by default** — opt-in shadow DOM via the third `options` param (`ElementOptions.shadow`: `true` → `attachShadow({ mode: "open" })`, a `ShadowRootInit` object verbatim, incl. `mode: "closed"`). The root is cached on `_shadowRoot`: `attachShadow` throws on a host that already carries a root (reconnects), and `this.shadowRoot` reads `null` for closed roots. Under `shadow`, `mount` renders into the root — the observer safety net and delegated events work inside it (`registerContainer` accepts `ShadowRoot`); captured `props.children`/`props.slots` nodes are projected into the shadow render output, so native `<slot>` projection is unavailable. Per instance:

- **connectedCallback** — guards on `_isInitialized`, defers `_mount` via `Promise.resolve().then()` so children are parsed before capture.
- **Child capture** — iterates `childNodes`; nodes with a `slot` attribute → `slots[slotName]`; others (text nodes only if `textContent.trim()`) → `children`. Captured once, projected as **raw DOM nodes — not reactive** to later slot changes.
- **Props Proxy** — `props.children` → children array, `props.slots` → slots record, any other key → `() => { version(); return self.getAttribute(name); }`. Attributes reactive via an internal `_version` signal; `setAttribute`/`removeAttribute` are overridden to bump it and `flush()` for synchronous propagation. Missing attributes return `null`.
- **Render scope** — `_mount` computes the render root (`options.shadow ? cached shadow root : this`), then wraps `mount(render(props), root)` in `scope()`, storing dispose on `_dispose`. The render fn returns the flagged build (a dom-target compile); the projected slot arrays reach the build as raw DOM nodes — `child()`'s raw-Node arm appends them.
- **disconnectedCallback** — calls `_dispose()`, resets `_isInitialized` → reconnect re-runs render from scratch.

## `$ref` / `$collection` (`lib/$ref.ts`, `lib/$collection.ts`, `lib/internal/reactive.ts`, `lib/internal/selectors.ts`)

Imperative escape hatch over existing DOM. `createReactive(element)` builds the shared `DomWrapper` (`bind`/`on`/`hooks` returning the wrapper for chaining, plus a `node` getter). `bind` detects `INPUT`/`TEXTAREA`/`SELECT` (frozen `FORM_ELEMENTS`) and targets `.value` instead of `.textContent` for primitives; an object arg resolves each entry (`resolveValue`, **not** `resolveText` — stringifying pre-`renderProp` broke booleans, arrays, style objects, and CE properties) and routes it through `renderProp`, inheriting the full branch order (§renderProp) — booleans bare/removed, arrays space-joined, `StyleObject` kebab serialization, CE raw property assignment. `hooks` **fires `afterMount` immediately** if the element is already `isMounted` (handled centrally by `registry.addHook`).

- **`$ref(selector | element)`** — an element input wraps immediately and never starts watching (a runtime-null element input stays a safe queued no-op); a selector runs `document.querySelector` synchronously and wraps immediately if found. Otherwise lazily starts watching on the first `bind`/`on`/`hooks` call: registers an op in the global `multiSelectors` Map, ensures `refObserver`. The watcher's `processNode` takes the first match, drains queued ops, then runs `processMountQueue` so `afterMount` hooks fire. Returns a callable `DomRef` — `ref()` / `ref.node` returns the node; methods chain. Also exposes a `.node` getter.
- **`$collection(selector)`** — wraps every current match and registers with `registerMultiOp` so new matches auto-apply queued ops. Returns a `DomCollection`: callable `collection(index = 0)`, dynamic `length`, `forEach`, `bind`/`on`/`hooks` (all current + future), `dispose()`. Indexed `[i]` access is populated **only for the initial set** — use the callable form for dynamically-added elements.
- **`refObserver`** — separate from the container observer. Watches `document.body` `{ childList: true, subtree: true }`; removals feed `cleanupQueue` via the shared `collectRemovedNode` (same descendant walk as the container observer), any mutation schedules `checkMultiSelectors` via microtask. **The observer deliberately survives `$ref` resolution** — it is the removal-cleanup net for `$ref`-bound elements outside mount containers; `$ref`'s inline unregister (registry cleanup only) never disconnects it. Only `$collection.dispose()` → `unregisterMultiOp` → `cleanupRefObserver` disconnects, when `multiSelectors.size === 0` — same page-lifetime precedent as delegated event types.

## `registry` (`lib/registry.ts`)

Public, exported. `addEffect(node, fn)` registers `fn` as a separate effect (`effect(..., { separate: true })` — no parent link to the enclosing effect; the `effects` array owns disposal on cleanup). A registration-time gate `hooksFeatureActive` (module `let`, flipped only by `setHooksFeature`) picks the body: while the hooks feature is loaded, the body routes through the `runEffectHooks` seam — the feature's implementation brackets the body with `beforeUpdate`/`afterUpdate` — gated on `state.hooks` (two property loads, not WeakMap gets) and `state.isMounted`, which resolves lazily from `element.isConnected` so hooks registered post-mount still fire on updates; the lazy assignment is suppressed while `isMountInFlight()` — under hydrate, adopted elements are connected during the attach, and a premature `isMounted = true` here would let the flush walk's idempotence gate permanently suppress their `afterMount`. Hook errors caught, `phase: 'update'`, no fallback. Unloaded, the body registers bare — no wrapper closure — and because the gate is registration-time, effects registered before a feature load never gain the bracket at run time (features load at module init by contract, so conforming apps never hit this). `addHook(element, type, handler)` (the feature's registration) pushes onto `state.hooks[type]` (stacking) and flips `mountHooksExist`; an `afterMount` registered on an already-mounted node fires immediately. Both accumulative; without the feature, `addHook` is a no-op (`addHookNoop`).

## `renderProp` (`lib/internal/utils.ts`)

Branch order: `key` → early-out, never renders (reconciliation metadata — ForEach reads it off the flagged build's props; `data-key`/`accesskey` unaffected, strict name match); `value`/`checked`/`selected`/`innerHTML` → set the IDL property directly (falsy → `''`, never `removeAttribute`); `isFalsy` (`false`/`null`/`undefined`) → `removeAttribute`; `key === "class"` + string (`isString`) + `HTMLElement` → `className` assignment (spec-equivalent to `setAttribute("class", …)` for string values; the string guard keeps arrays/`true`/SVG on the generic paths — SVG `className` is a readonly `SVGAnimatedString` in some engines); `key === "style"` + plain object (`isPlainObject` from `./core`) → kebab-case serialization — camelCase→kebab keys, falsy declarations dropped, **no auto-px** on numbers, `"; "` join, one `setAttribute("style", …)`; custom elements (`tagName` contains `-` **and** `key in element`) → raw property assignment, objects/arrays by reference — the `in` chain check is deliberate (CE props live on prototypes as often as instances; standard tags are never hyphenated). The gate requires the element to be an UPGRADED instance at wiring time — the runtime's template create fns guarantee that (§runtime, clone-time custom-element upgrade); `true` → empty string; arrays → space-joined filtering falsy (class lists); else `setAttribute`. **`isFalsy(0)` is false** — signal `0` renders `"0"`.

## Non-obvious behaviors (gotchas)

- **Hand-built HellaNode input is rejected** at `mount`/`hydrate`/`child` with the entry-point-named throw — the compiler or the runtime module are the only construction paths.
- **`raw(html)` is an opaque child.** `ssr` wraps it in `<!--[-->…<!--]-->` markers and emits the HTML verbatim (never escaped); `hydrate` consumes the markers and adopts the existing DOM in place, binding nothing inside — no reactive scope crosses the boundary (a missing raw marker is divergence). Meta-framework renderers inject slot HTML as `props.children = [raw(slotHtml)]` (array-wrapped, so the babel `<X>{props.children}</X>` spread yields the sentinel). Bypasses escaping — sanitize untrusted input (XSS).
- **Passthrough components bypass `component()`** — `ForEach`/`Portal`/`Lazy`/`Transition`/`Suspense` set `isDynamic: true` and `fn.ssr = { kind, props }`, and are dispatched directly by `child()`'s isDynamic arm (mount) or `claimFlaggedChild`/`adoptDynamicRegion` (hydrate). The `ssr` descriptor (see `RenderFn`/`SsrMeta`) lets `@hellajs/ssr` render these without DOM access; it's write-only at mount.
- **One scoped observer covers every `mount()` target** (`observedContainers`); a second mount target adds no second observer.
- **`afterMount` fires at `mount()`/`hydrate()`.** `isMounted` (root + descendants) is set and `afterMount` fired synchronously at the end of `attach()` — no `app.flush()` needed. `flush()` on the handle is an idempotent escape hatch (drains the cleanup queue).
- **Hook element-argument rule.** `afterMount`/`beforeDestroy`/`beforeUpdate`/`afterUpdate` receive the element; `beforeMount`/`afterDestroy` do not. `beforeMount` fires synchronously during the build (the build body runs pre-insert, so registering mid-build IS before mount); `afterMount` fires at the end of `attach()`. Multiple hooks of the same type all fire in insertion order.
- **Function-ref prop effects run `beforeUpdate`/`afterUpdate`** only when `state.isMounted` is true.
- **`onError(null)` clears all handlers**; a function registers and returns an unregister. No handlers → `console.error('[dom]', error)` and no UI change.
- **Event types registered for delegation stay registered for the page lifetime** — only `resetEventState()` (called by `resetDom()` in tests) removes them. Delegated handlers never auto-stop propagation.

## Performance

- **`while` + cached `length`** on every hot path — no `for…of`/`forEach`.
- **`DocumentFragment`** for every multi-insert (ForEach first render / fresh-middle batch / empty-recovery, Portal fragment).
- **ForEach collection reuse** — temp Maps/arrays/Sets `clear()` + reference-swap, never reallocated.
- **ForEach dual-mode tracking leaves the element-item hot path untouched** — only fragment-rendered items allocate a record + anchor; element/text items stay raw `Node`s in `keyToNode`.
- **Template cache** — `template`/`fragment` parse once per distinct html string; the create path is a `cloneNode(true)` off the cached prototype (with the custom-element upgrade walk only on hyphen-tagged templates, and only when the custom-elements feature is loaded — see §runtime + §Feature gating).
- **`composedPath()`** for delegation (pre-computed ancestor chain).
- **`globalListeners` fast-exit** + inline prefix matching in `ATTR_REGEX` (single regex pass).
- **Module-level cached regexes** (`TOKEN_REGEX`, `PLACEHOLDER_REGEX`, `SKIP_REGEX`, `ATTR_REGEX`), `lastIndex = 0` before each use.
- **`WeakMap`/`WeakSet`** for `elementMap`, `observedContainers`, `handlingBoundaries`, `processedNodes` — GC with the DOM nodes.
- **Persistent text-node anchors** (`createTextNode("")`) for ForEach/Portal/Lazy/Transition/reactive children — never recreated; no comment nodes in the DOM.
- **Bulk removal** in ForEach (collect before mutating; a full clear owning the parent removes all children with one `replaceChildren`); events cleanup iterates handlers once.
- **Fast `isHellaNode`** — dom-local `isObject(v) && v.tag !== undefined`, avoiding `isPlainObject`'s `getPrototypeOf` + `Object.prototype.toString.call` on the throw-contract guards. `isPlainObject` is retained in core for cold input-validation paths (`$ref`/`$collection`).
- **`toText` vs `resolveText`** — `toText(value)` assumes an already-resolved input and skips the `resolveValue` call; `resolveText` (which keeps the call) is used only where the input may still be a function/signal (`reactive.ts` bind path). Mount-side text rendering routes through `toText`.
- **Lazy `ElementState` collections** — `handlers` / `effects` / `directHandlers` / `hooks` allocate on first use, not at `getState`. A reactive leaf pays only `{ isMounted }`.
- **Single WeakMap lookup** on hot guards — `peekState(node)?.field` replaces the `hasState` + `getState` double-lookup in boundary checks and in `delegatedHandler`'s per-path-element walk.

## Testing approach (`tests/`)

Integration-style, public API only. Runtime and type imports from **`@hellajs/dom`** (bare specifier — the JSX test transform injects the same bare instance, so scope/error/reset wiring stays on one module instance). Generic conventions (import sources/order, `mock()` tracking, `resetTestState`) are owned by `guides/tests.md` — package-specific facts: the publicly-exported introspection helpers used directly are `peekState`, `getState`, `multiSelectors`, `checkMultiSelectors`.

**Two-target harness (the hydrate-test standard).** Vitest compiles test JSX at the flipped client default (`target: "dom"`), so a server HTML fixture must come from the SAME source compiled at both plugin targets: `tests/helpers.tsx` exports `twoTargetContainer(source)` / `twoTargetAsyncContainer(source)` / `twoTargetStreamed(source)` — the server arm (ast) feeds `ssr()`/`ssr.async()`/`ssr.stream()`, the client arm (dom) yields the flagged builds `hydrate` consumes. Sources are PLAIN JS (TS annotations break babel) with signals/counters in-source, exported via `const __out = { App, … }` — the CLIENT module's exports are the live ones the test drives (`client.App as TemplateBuildFn`, in-source hit counters instead of test-side `vi.fn`, per-arm loader phasing via the `__HELLA_ARM` free variable). `tests/helpers.tsx` also exports `TWO_TARGET_MODULES` (the binding table `runCompiledModule` needs — include `@hellajs/dom/runtime`) and `ssrContainer`/`ssrAsyncContainer`/`streamContainer` for AST-shaped fixtures. Direct `vp test` invocations need `NODE_OPTIONS=--expose-gc` for the GC-canary tests (`gc?.()`); the coverage gate injects it. `rm -rf node_modules/.vitest-cache` after every `bundle.ts` rebuild — Vitest 5's fs module cache serves stale transforms otherwise.

The pointer/key event dispatchers the behavior test files use (`pointerDown`, `pressKey`, …) live in `packages/headless/tests/helpers.tsx`.
