# runtime

The DOM construction functions the babel plugin's imperative target compiles JSX into: templates, props, events, and children wired directly onto elements.

<Callout variant="info">This is a compiler contract, stable across semver; generated code imports it from `@hellajs/dom/runtime`. Hand-written apps use JSX templates; hand-author these calls only when building a custom renderer or emits tooling.</Callout>

## Basic Usage

A compiled component becomes a flagged build function: `template()` creates the element, the wiring calls attach reactive state, and `mark()` flags the result for consumers like `mount` and `ForEach`.

```typescript
import { signal } from "@hellajs/core";
import { mark, on, prop, template, text } from "@hellajs/dom/runtime";

const selected = signal(0);

const rowTemplate = template(
  `<tr><td class="col-md-1"></td><td class="col-md-4"><a class="lbl"></a></td></tr>`,
);

function Row(row: { id: number; label: string }) {
  return mark(() => {
    const root = rowTemplate();
    const idCell = root.querySelector("td") as HTMLTableCellElement;
    const label = root.querySelector("a.lbl") as HTMLAnchorElement;
    text(idCell, row.id);
    text(label, row.label);
    prop(root, "class", () => (selected() === row.id ? "danger" : ""));
    on(label, "click", () => selected(row.id));
    return root;
  }, { key: row.id });
}
```

[`component`](/reference/dom/component) wraps functions like this one (chaining the disposal scope), and [`ForEach`](/reference/dom/foreach) reads the `key` from the flagged result for keyed reconciliation.

## API

```typescript
function template(html: string, ns?: string): () => Element;
function fragment(html: string, ns?: string): () => DocumentFragment;
function mark(fn: () => Element, props?: Record<string, unknown>): TemplateBuildFn;

function text(parent: Element, value: unknown): void;
function prop(el: Element, key: string, value: unknown): void;
function on(el: Element, type: string, handler: EventListener): void;
function direct(el: Element, type: string, handler: EventListener | DirectListenerSpec): void;
function hook(el: Element, type: HookType, fn: HookFn): void;
function errorConfig(el: Element, config: ErrorConfig, build: TemplateBuildFn): void;
function child(parent: Element, value: unknown): void;

type TemplateBuildFn = (() => Element) & {
  isTemplate: true;
  props?: Record<string, unknown>;
  componentScope?: () => void;
};
```

- `html`: The html string to parse. Parsed once per distinct string; the create function is cached and reused.
- `ns`: The namespace for svg/MathML-interior templates (`"http://www.w3.org/2000/svg"` or `"http://www.w3.org/1998/Math/MathML"`). Pass it whenever the template's root only makes sense inside `<svg>` or `<math>`: a template parsed without it creates HTML-namespace elements, and inserting an HTML-namespace `<circle>` into a live `<svg>` never upgrades it.
- **Returns** (`template`, `fragment`): A create function producing a fresh clone per call.
- `fn`: The build function to flag; mutated in place and returned.
- `props`: Reconciliation metadata carried on the flagged fn; `key` is read by [`ForEach`](/reference/dom/foreach).
- `value` (`text`, `prop`, `child`): A primitive renders statically; a function registers a reactive effect.

### `template`

Parses a single-root html string and returns its cached create function. Each call returns a fresh clone, ready for wiring.

```typescript
import { template } from "@hellajs/dom/runtime";

const circle = template("<circle/>", "http://www.w3.org/2000/svg");
document.querySelector("svg")!.append(circle()); // namespaceURI is the SVG namespace
```

Clones re-create defined custom elements as upgraded instances, so wiring calls see the real accessors. `template` requires exactly one root element and throws otherwise; multi-root markup uses `fragment`, whose create function returns the content as a `DocumentFragment`.

### `fragment`

The multi-root counterpart of `template`: returns the whole parsed content as a `DocumentFragment`. Appending the fragment splays its children into the parent, matching fragment mount semantics.

### `mark`

Flags a build function and attaches reconciliation metadata. Every children consumer (mount wiring, [`ForEach`](/reference/dom/foreach), [`component`](/reference/dom/component), error boundaries) recognizes flagged functions: it invokes the fn and mounts the returned root instead of building a reactive region.

### `text`

Appends a text child. Static values render once (numbers normalized, so `0` renders `"0"`); function values register a reactive effect that keeps the text node in sync.

### `prop`

Sets one property or attribute, with the same branch order as JSX attributes: `class` handling, style objects, custom-element properties, array joins. Function values register an effect; a recompute equal to the last applied value skips the DOM write. Effect errors dispatch through the error boundary system.

Keys starting with `on:`, `e:`, `hook:`, or `error:` route to the event/hook seams below, so prefixed attrs forwarded through a component's `{...attrs}` spread land live. A function value under a prefixed key is a handler or hook, never a reactive value.

### `on`

Registers a delegated event handler (the [`on:`](/reference/dom/on) machinery): one shared capture-phase listener per event type on the document body.

### `direct`

Registers a direct, non-delegated event handler (the [`e:`](/reference/dom/e) machinery): a per-instance listener with error-boundary wrapping and native listener options forwarding.

### `hook`

Registers a lifecycle hook (the [`hook:`](/reference/dom/hook) machinery). Hooks of the same type stack and all execute.

### `errorConfig`

Attaches an error config to an element (the [`error:`](/reference/dom/error) machinery) and stores the build function as the reset target: `context.reset()` in an error handler re-runs the stored build for fresh nodes.

### `child`

Wires one child value in any compiled form: strings and numbers append text nodes; functions build reactive regions; arrays recurse in order; `raw()` html parses and inserts; flagged build functions are invoked and their root appended; raw DOM nodes append directly. Booleans, `null`, and `undefined` render nothing. A hand-built tree object throws.

## Important Considerations

### Wiring Order Is Free

The create function initializes its clone before returning it, so `text`, `prop`, `on`, and the other wiring calls register cleanly in any order. Generated code relies on this.

### Equal Reactive Values Skip Writes

`prop` memoizes the last applied value. A reactive getter that recomputes to the same value does not touch the DOM.
