# onError

Catch errors anywhere in the rendered app: one global handler receives render, mount, update, and event errors, and decides what to show instead.

## Basic Usage

Register a handler before mounting. Return a node to render fallback UI, or `null` to log only.

```jsx
import { mount, onError } from "@hellajs/dom";

onError((error, context) => {
  console.error(`[${context.phase}] ${error.message}`);
  return <div class="error">Something went wrong</div>;
});

const RiskyChild = () => <div>risky content</div>;

mount(
  <main>
    <RiskyChild />
  </main>
);
```

The returned function unregisters the handler:

```jsx
const off = onError((error) => {
  console.error(error.message);
  return null;
});

off(); // this handler no longer receives errors
```

## API

```typescript
function onError(fn: ErrorFn | null): () => void
```

- `fn`: Error handler function, or `null` to clear all handlers.
- **Returns**: A function that unregisters this handler when called.

Multiple handlers execute in registration order; the first non-null return wins.

## Key Concepts

### What the Handler Receives

The second argument carries the error's origin: the phase it threw in, the element it threw on (when one exists), the triggering event (for event errors), and the element's `error:` config when one applies.

```typescript
interface ErrorContext {
  phase: "render" | "mount" | "update" | "event";
  element?: Element;
  event?: Event;
  config?: ErrorConfig;
  reset?: () => void;
}

interface ErrorConfig {
  boundary?: boolean;
  fallback?: (error: Error) => HellaNode;
  category?: string;
}
```

### Return Values Decide the UI

| Return | Behavior |
|--------|----------|
| Node | Renders the returned node as fallback UI (errors from reactive children, bindings, and event handlers) |
| `null` or `void` | Logs the error, no UI change |

Fallback UI only renders for errors from reactive children, function-ref bindings, and event handlers. Render-phase and `hook:beforeMount` errors are logged but cannot render fallback UI.

### Error Phases

| Phase | When it occurs | Has element | Fallback UI |
|-------|----------------|-------------|-------------|
| `render` | Component function throws | No | No |
| `mount` | Error during initial mount | Yes | Yes (reactive children), No (`beforeMount`) |
| `update` | Error in reactive update | Yes | Yes (bindings), No (`beforeUpdate`/`afterUpdate`) |
| `event` | Error in event handler | Yes | Yes |

### Categories Route by Region

Tag elements with `error:category` and branch on `context.config?.category` to treat regions differently: report critical areas to a logging service while rendering inline messages elsewhere.

```jsx
const reportToService = (error: Error) => console.error(error);

onError((error, context) => {
  if (context.config?.category === "critical") {
    reportToService(error);
    return <div>Critical error occurred</div>;
  }

  return <div class="error">{error.message}</div>;
});

const Sidebar = () => <div>Sidebar</div>;

mount(
  <div error:category="critical">
    <Sidebar />
  </div>
);
```

### Element-Level Fallbacks Come First

An element's own [`error:fallback`](/reference/dom/error) handles its subtree's errors; reach it from the global handler through `context.config.fallback`. The full element-side contract (fallback, category, boundaries, config resolution) lives in the [`error:`](/reference/dom/error) doc.

```jsx
onError((error, context) =>
  context.config?.fallback?.(error)
    ?? <div class="error">Something went wrong</div>
);
```

## Important Considerations

### Nested Configs: Nearest Wins

When nested elements carry `error:` configs, the innermost one around the failing subtree applies; child configs never merge with parent configs.

```jsx
const outerFallback = (e: Error) => <div>Outer error: {e.message}</div>;
const innerFallback = (e: Error) => <div>Inner error: {e.message}</div>;

mount(
  <div error:category="outer" error:fallback={outerFallback}>
    <div error:category="inner" error:fallback={innerFallback}>
      {() => { throw new Error("oops"); }}
    </div>
  </div>
);
// Result: innerFallback is used
```

### No Handler Means console.error

With no `onError` handler registered, errors log to `console.error` and the app keeps running where it can.
