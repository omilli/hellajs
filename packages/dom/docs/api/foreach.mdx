# ForEach

Efficiently renders dynamic lists with intelligent DOM diffing and key-based optimization.

## API

```typescript
function ForEach<T>(props: {
  each: T[] | (() => T[]);
  use: (item: T, index: number) => HellaChild;
}): JSX.Element
```
- `each`: An array, a [`signal`](/reference/core/signal) containing an array, or a function that returns an array. Signals work because they are callable.
- `use`: A function that is called for each item in the array and should return a renderable node.

## Basic Usage

Use `ForEach` to render lists that change over time.

```jsx
import { signal } from "@hellajs/core";
import { ForEach } from "@hellajs/dom";

const items = signal(["Apple", "Banana", "Cherry"]);

<ul>
  <ForEach
    each={items}
    use={(fruit: string) => <li>{fruit}</li>}
  />
</ul>
```

## Key Concepts

### Key-Based Optimization

Use the `key` prop for optimal reconciliation. Explicit keys use key-only comparison: same key always reuses the DOM node, even if the item reference changes. The `key` prop is reconciliation metadata only: it never appears as a DOM attribute, in mounted or server-rendered HTML.

```jsx
import { signal } from "@hellajs/core";
import { ForEach } from "@hellajs/dom";

const items = signal([
  { unique: 1, tag: "Foo" },
  { unique: 2, tag: "Bar" }
]);

const Items = () => <ul>
  <ForEach
    each={items}
    use={(item: { unique: number; tag: string }) => <li key={item.unique}>{item.tag}</li>}
  />
</ul>
```

Items with an `id` property are automatically keyed - no explicit `key` needed.

```jsx
import { signal } from "@hellajs/core";
import { ForEach } from "@hellajs/dom";

const users = signal([
  { id: 1, name: "Alice" },
  { id: 2, name: "Bob" }
]);

// ✅ id property is used as key automatically
const Users = () =>
  <ul>
    <ForEach
      each={users}
      use={(user: { id: number; name: string }) => <li>{user.name}</li>}
    />
  </ul>
```

Key resolution order:
1. Explicit `key` prop on the rendered element
2. `id` property on the source item
3. Array index (fallback)

### Single-Root Items

Each item must render exactly one root node - an element or text node. A `use` renderer that returns multiple roots as a fragment (`<>…</>`), an array of nodes, or multi-root raw HTML throws `[dom] ForEach: use must return a single element`. A bare signal or function returned as the item root throws the same error - reactive content belongs inside an element root (see Reactive Content below).

```jsx
import { signal } from "@hellajs/core";
import { ForEach } from "@hellajs/dom";

const rows = signal([
  { id: 1, title: "Alpha", note: "first" },
  { id: 2, title: "Beta", note: "second" }
]);

// ❌ Throws: the renderer returns two roots (dt + dd)
<dl>
  <ForEach
    each={rows}
    use={(row: { id: number; title: string; note: string }) => (
      <>
        <dt>{row.title}</dt>
        <dd>{row.note}</dd>
      </>
    )}
  />
</dl>

// ✅ One root per item: wrap the row's markup in a single element
<dl>
  <ForEach
    each={rows}
    use={(row: { id: number; title: string; note: string }) => (
      <div class="row">
        <dt>{row.title}</dt>
        <dd>{row.note}</dd>
      </div>
    )}
  />
</dl>
```

When hydrating server-rendered HTML, `ForEach` adopts existing nodes only when the region's
server node count exactly matches the item count - one node per item. On mismatch the server
nodes are cleared and the list is rebuilt fresh (a warning is logged).

## Important Considerations

### Array Immutability

Always create new array instances for [`signal`](/reference/core/signal) updates - mutations don't trigger reactivity.

```jsx
// ✅ Create new array
todos([...todos(), newItem]);
// ❌ Mutation doesn't trigger updates
todos().push(newItem);
```

### Key Stability

Use stable, unique keys (like database IDs) rather than array indices. An explicit `key` (or the item's `id` property) reuses the DOM node by key identity even when the item reference changes, and the reused node's content is not re-rendered, so updates must flow through signals. Items with neither fall back to index keys, which compare by reference instead: a new item reference re-creates the DOM node. An explicit `key={index}` takes the reuse path too, keeping the old node for a new item and leaving non-signal content stale.

```jsx
// ✅ Stable keys: same key reuses DOM node regardless of reference
<ForEach
  each={items}
  use={(item) => <li key={item.id}>{item.name}</li>}
/>
// ❌ Index keys: same index reuses the old node for a new item, leaving non-signal content stale
<ForEach
  each={items}
  use={(item, index) => <li key={index}>{item.name}</li>}
/>
```

### Reactive Content

For dynamic content inside list items, use [`signal`](/reference/core/signal) children rather than deriving values in the `use` callback. Key-only reconciliation reuses DOM nodes on reference changes, so reactive signals handle content updates surgically.

```jsx
import { signal } from "@hellajs/core";
import type { Signal } from "@hellajs/core";
import { ForEach } from "@hellajs/dom";

const items = signal([
  { id: 1, name: signal("Alice") },
  { id: 2, name: signal("Bob") }
]);

// ✅ Signal children: DOM nodes reused when items reference changes
<ForEach
  each={items}
  use={(item: { id: number; name: Signal<string> }) => <li key={item.id}>{item.name}</li>}
/>
```

### Automatic Cleanup

List items are automatically cleaned when removed from the DOM. No manual cleanup needed for reactive effects or event handlers on list elements.
