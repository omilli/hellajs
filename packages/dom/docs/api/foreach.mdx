# ForEach

Render a list that tracks a signal: each item gets its own DOM node, keyed so updates reuse nodes instead of rebuilding the list.

## Basic Usage

Pass the signal to `each` and a renderer to `use`.

```jsx
import { signal } from "@hellajs/core";
import { ForEach } from "@hellajs/dom";

const items = signal(["Apple", "Banana", "Cherry"]);

<ul>
  <ForEach
    each={items}
    use={(fruit: string) => <li>{fruit}</li>}
  />
</ul>
```

When the signal changes, the list updates in place: same-key items keep their DOM nodes.

## API

```typescript
function ForEach<T>(props: {
  each: T[] | (() => T[]);
  use: (item: T, index: number) => HellaChild;
  key?: (item: T, index: number) => unknown;
}): JSX.Element
```
- `each`: An array, a [`signal`](/reference/core/signal) containing an array, or a function returning an array.
- `use`: Called per item; returns the item's rendered node.
- `key`: Optional key extractor, taking precedence over the rendered element's `key` prop, the item's `id`, and the array index. Client-side reconciliation metadata; SSR ignores it.

## Key Concepts

### Keys Decide Reuse

Keys tell `ForEach` which old item a new item replaces. A retained key keeps its live DOM node; only new items render. Resolution order:

1. The `ForEach` `key` extractor prop
2. The `key` prop on the rendered element
3. The `id` property on the source item
4. Array index (fallback)

The `key` prop is metadata only: it never appears as a DOM attribute, in mounted or server-rendered HTML.

```jsx
import { signal } from "@hellajs/core";
import { ForEach } from "@hellajs/dom";

const rows = signal([
  { id: 1, label: "Foo" },
  { id: 2, label: "Bar" },
]);

<ul>
  <ForEach
    each={rows}
    use={(row: { id: number; label: string }) => <li key={row.id}>{row.label}</li>}
  />
</ul>
```

Items with an `id` property are keyed automatically; no explicit key needed.

### One Root per Item

Each item renders exactly one root node. A `use` returning a fragment, an array, or multiple roots throws `[dom] ForEach: use must return a single element`; wrap the markup in a single element instead.

```jsx
const rows = signal([
  { id: 1, title: "Alpha", note: "first" },
  { id: 2, title: "Beta", note: "second" },
]);

// ❌ Throws: two roots (dt + dd)
<ForEach
  each={rows}
  use={(row: { id: number; title: string; note: string }) => (
    <>
      <dt>{row.title}</dt>
      <dd>{row.note}</dd>
    </>
  )}
/>

// ✅ One root: the row's markup wrapped in a single element
<ForEach
  each={rows}
  use={(row: { id: number; title: string; note: string }) => (
    <div class="row">
      <dt>{row.title}</dt>
      <dd>{row.note}</dd>
    </div>
  )}
/>
```

### Updates Flow Through Signals

A reused node is not re-rendered: `use` runs only for new items, so changing content must flow through signals inside the item, not through new item objects.

```jsx
import { signal } from "@hellajs/core";
import type { Signal } from "@hellajs/core";
import { ForEach } from "@hellajs/dom";

const items = signal([
  { id: 1, name: signal("Alice") },
  { id: 2, name: signal("Bob") },
]);

// name changes update in place, even when the array is rebuilt
<ForEach
  each={items}
  use={(item: { id: number; name: Signal<string> }) => <li key={item.id}>{item.name}</li>}
/>
```

## Important Considerations

### New Arrays, Not Mutations

Signals fire on reassignment; mutating the array in place triggers nothing.

```jsx
// ✅ Create a new array
todos([...todos(), newItem]);

// ❌ Mutation does not trigger updates
todos().push(newItem);
```

### Key Stability

Use stable, unique keys (database IDs), never array indices. Index keys compare by reference: a new item at the same index reuses the old node and leaves non-signal content stale.

```jsx
// ✅ Stable keys: same key reuses the node regardless of reference
<ForEach
  each={items}
  use={(item) => <li key={item.id}>{item.name}</li>}
/>

// ❌ Index keys: the old node survives with stale content
<ForEach
  each={items}
  use={(item, index) => <li key={index}>{item.name}</li>}
/>
```

### Hydration Adopts Matching Lists

When hydrating server-rendered HTML, `ForEach` adopts the existing nodes when the region holds exactly one node per item. On a count mismatch, the list rebuilds fresh and logs a warning.

### Automatic Cleanup

Removed items are cleaned up with their effects and handlers. No manual teardown for list elements.
