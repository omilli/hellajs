# component

The wrapper the compiler emits for every JSX component call: effects created inside the component are scoped to it, disposed when it leaves the DOM, and render errors route through the error system.

<Callout variant="info">This is a low-level API. JSX users never need it: the compiler wraps every component call automatically. Reach for it when you invoke a compiled component outside JSX, such as a loader-resolved root.</Callout>

## Basic Usage

In JSX, the wrapping is automatic. This markup:

```jsx
import { mount } from "@hellajs/dom";

const Counter = ({ initial }: { initial: number }) => (
  <div>{initial}</div>
);

mount(<Counter initial={5} />, "#app");
```

compiles to `component(Counter, { initial: 5 })`, so the scope and error handling come along on their own.

The manual use is invoking a compiled component outside JSX. A loader-resolved app root is the common case:

```typescript
import { component, mount, onError } from "@hellajs/dom";
import type { ComponentFn, TemplateBuildFn } from "@hellajs/dom";

declare const loadApp: () => Promise<{ App: ComponentFn }>;

// Registered before the mount: async-root rejections have no element
// context, so this handler (or the console) is the whole error story.
onError((error, context) => {
  console.error(context.phase, error.message); // telemetry in a real app
  return null;
});

mount(async () => {
  const mod = await loadApp();
  return component(mod.App, {}) as TemplateBuildFn;
}, "#app");
```

## API

```typescript
function component<P extends Record<string, unknown>>(
  fn: (props: P) => ComponentReturn,
  props: P
): ComponentReturn
```

- `fn`: The component function to wrap. Invoked immediately, inside the disposal scope.
- `props`: Props object passed to the component function; JSX children arrive as `props.children`.
- **Returns**: The component's build result with the disposal scope attached: a flagged build function ready for [`mount`](/reference/dom/mount) and children wiring when the result is a build function.

## Key Concepts

### One Scope per Call

`component()` invokes the component once and attaches one disposal scope to that result. Effects and [`scope()`](/reference/core/scope) calls created inside the component are disposed when its root leaves the DOM.

```jsx
import { effect, signal } from "@hellajs/core";
import { mount } from "@hellajs/dom";

const Timer = () => {
  const seconds = signal(0);

  effect(() => {
    const id = setInterval(() => seconds(seconds() + 1), 1000);
    return () => clearInterval(id);
  });

  return <span>{seconds}s</span>;
};

// The interval clears itself when Timer's DOM is removed
mount(<Timer />, "#app");
```

### Render Errors Route Through the Error System

A throw inside the component dispatches with phase `"render"` through [`onError`](/reference/dom/onerror), and the wrapper returns an empty build so the rest of the tree keeps mounting. See [Error Handling](/learn/concepts/error-handling).

### Meta-Components Pass Through

[`ForEach`](/reference/dom/foreach), [`Portal`](/reference/dom/portal), [`Lazy`](/reference/dom/lazy), [`Transition`](/reference/dom/transition), and [`Suspense`](/reference/dom/suspense) manage their own cleanup through their region anchors. Passing one to `component()` returns it unchanged with the scope chained on, so wrapping them is unnecessary.

## Important Considerations

### Component Calls Only, Not Tree Building

`component()` wraps component calls; it does not make hand-built tree objects mountable. [`mount`](/reference/dom/mount) and [`hydrate`](/reference/dom/hydrate) reject hand-built trees with the documented throw.

### The Result Is One Build, Not a Factory

The call renders the component once. A second render is a second `component()` call (or, in JSX, a second element); the result carries no component definition to re-invoke.
