# error:

Configure error behavior on an element: a fallback build for failure UI, a category for filtering, and a boundary that stops the error's walk up the tree.

## Usage

```jsx
import { mount, onError } from "@hellajs/dom";

// Element fallbacks render through the global handler: delegate to
// context.config.fallback when the failing element has one.
onError((error, context) =>
  context.config?.fallback?.(error) ?? null
);

const FlakyComponent = () => <div>Flaky content</div>;

const App = () => (
  <div
    error:fallback={(e: Error) => <span class="error">Failed: {e.message}</span>}
    error:category="sidebar"
    error:boundary={true}
  >
    <FlakyComponent />
  </div>
);

mount(App, "#app");
```

With no [`onError`](/reference/dom/onerror) handler registered, every error is logged to `console.error` and nothing renders, `error:` attributes included. See [Error Handling](/learn/concepts/error-handling) for the full flow.

## Key Concepts

### error:fallback

A function receiving the error and returning fallback UI. Its presence makes the element an error boundary: when a dispatched error's origin walks up the tree, the walk stops here, and the fallback renders within the boundary: replacing the boundary's content for event and binding errors, or standing in at the failing child's position for reactive-child errors.

```jsx
const RiskyChild = () => <div>Risky content</div>;

<div error:fallback={(e: Error) => <div class="error">Error: {e.message}</div>}>
  <RiskyChild />
</div>
```

### error:category

A string passed to the global handler through `context.config.category`, for filtering and logging. On its own it changes nothing visually: it never stops the boundary walk and renders nothing.

```jsx
const ImportantSection = () => <div>Important</div>;

<div error:category="critical">
  <ImportantSection />
</div>
```

### error:boundary

Explicitly marks the element as a boundary. When `true`, the walk up the tree stops here even with no fallback, so errors below never reach an outer boundary.

```jsx
const Child = () => <div>Child content</div>;

<div error:boundary={true}>
  {/* Errors here don't propagate to parent boundaries */}
  <Child />
</div>
```

An element with `error:fallback` is automatically a boundary. Use `error:boundary` alone to stop propagation without providing fallback UI.

## Important Considerations

### How Config Is Picked

- **Nearest qualifying boundary wins**: the walk stops at the first element whose config has `boundary` or `fallback`.
- **No merging**: a child config never inherits from a parent config.
- **Category-only elements are passed over**: they populate `context.config` for handlers, but the walk continues through them.

### What Errors Get Caught

| Error Source | Fallback UI Rendered |
|---|---|
| Reactive child functions | Yes |
| Function-ref prop callbacks | Yes |
| `on:` and `e:` event handlers | Yes |
| `hook:beforeMount` | No (logged only) |
| `hook:beforeUpdate` / `hook:afterUpdate` | No (caught, no fallback UI) |

### Reset Rebuilds the Boundary

When the boundary element is a compiled template root, the error context carries `reset()`: it re-runs the boundary's stored build and mounts fresh nodes. A retry button in a global handler's fallback uses it:

```jsx
onError((error, context) => {
  const retry = context.reset;
  if (!retry) return null; // no compiled boundary build to reset; pass

  return (
    <div class="error">
      <p>{error.message}</p>
      <button on:click={retry}>Retry</button>
    </div>
  );
});
```
