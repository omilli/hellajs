# Suspense

Show a fallback while async content loads: on the server the fallback ships immediately and the resolved content follows in the stream; on the client a pending child shows the fallback until it settles.

## Basic Usage

Wrap async data in a boundary with a `fallback`. Render with [`ssr.stream`](/reference/ssr/ssr#stream) and the shell flushes immediately while the fetch runs.

```jsx
import { Suspense } from "@hellajs/dom";
import { ssr } from "@hellajs/ssr";

const user = (id: number) => fetch(`/api/users/${id}`).then((r) => r.text());

const App = () => (
  <div>
    <h1>Profile</h1>
    <Suspense fallback={<p>Loading...</p>}>
      {() => user(1).then((name) => <p>{name}</p>)}
    </Suspense>
  </div>
);

// Server: the shell and fallback stream first; resolved content follows
const stream = ssr.stream(<App />);
```

```jsx
import { hydrate } from "@hellajs/dom";

// Client: each boundary's resolved content swaps in and goes interactive
hydrate(<App />, "#app");
```

The same tree works on a purely client [`mount`](/reference/dom/mount): the fallback shows until the Promise resolves, then the content swaps in.

## API

```typescript
function Suspense(props: SuspenseProps): JSX.Element
```

- `props.fallback`: Content rendered while children are pending: during `ssr.stream` streaming and on a client mount. Dropped under `ssr`/`ssr.async` (no streaming, children fully rendered).
- `props.children`: The boundary's content, a single child or an array. A Promise-returning child suspends on both server and client; sync children render directly.

## Key Concepts

### Out-of-Order Streaming

A Promise outside a `<Suspense>` is awaited in order by `ssr.stream`: a slow value delays everything after it. `<Suspense>` opts a subtree out of that wait: its `fallback` flushes inline, siblings continue streaming, and the resolved content follows when it is ready.

### Interrupted Streams Recover

If the stream dies before a boundary's content arrived, [`hydrate`](/reference/dom/hydrate) falls back to client-side rendering for that region: the fallback stays on screen while the child re-runs on the client, and the resolved content swaps in when it settles. A rejection bubbles to the nearest [`onError`](/reference/dom/onerror) / [`error:`](/reference/dom/error) boundary.

### Re-Fetching Needs resource

`<Suspense>` resolves a Promise child once, at mount. To re-suspend when inputs change, pair [`resource`](/reference/resource/resource) with a reactive child that branches on its getters:

```jsx
import { resource } from "@hellajs/resource";

const user = resource("/api/users/1");

// re-runs when the resource state changes
const profile = () => (
  <div>{user.isLoading() ? <p>Loading...</p> : <p>{user.data()}</p>}</div>
);
```

## Important Considerations

### Safe Under Every Renderer

Only `ssr.stream` changes behavior. Under `ssr`/`ssr.async` the children are already rendered, so `<Suspense>` renders them directly with the fallback dropped; the same tree works in every renderer.

### Nested Boundaries Resolve With Their Parent

A `<Suspense>` inside another boundary's children resolves within its parent's content: the parent's swap already contains the fully resolved subtree. Top-level boundaries stream independently.
