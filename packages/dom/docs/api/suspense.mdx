# Suspense

A streaming + async boundary. On the server, wrap async data so the shell and a `fallback` flush immediately via [`ssrStream`](/reference/ssr/ssr-stream), then [`hydrate`](/reference/dom/hydrate) swaps the resolved children in. On a client fresh mount (e.g. client-side navigation), a Promise-returning child suspends — the `fallback` shows until it resolves (or, on rejection, bubbles to the nearest `onError` / `error:fallback` boundary).

## API

```typescript
function Suspense(props: SuspenseProps): JSX.Element
```

- `props.fallback`: Content rendered while children are unresolved — shown during [`ssrStream`](/reference/ssr/ssr-stream) streaming AND on a client fresh mount while a Promise child is pending (dropped under [`ssr`](/reference/ssr/ssr)/[`ssrAsync`](/reference/ssr/ssr-async)).
- `props.children`: The boundary's content — a single child or an array. A Promise-returning child suspends on both server and client; sync children render directly. For reactive re-fetching (re-suspend on signal change), use `resource` + `Show` instead.

## Basic Usage

Render a shell with a `fallback` immediately, then resolve async data into the boundary. [`ssrStream`](/reference/ssr/ssr-stream) flushes the `fallback` inline and stages the resolved children; [`hydrate`](/reference/dom/hydrate) swaps them in.

```jsx
import { signal } from '@hellajs/core';
import { html, Suspense } from '@hellajs/dom';
import { ssrStream } from '@hellajs/ssr';

const user = (id) => fetch(`/api/users/${id}`).then(r => r.text());

const App = () => html`
  <div>
    <h1>Profile</h1>
    <${Suspense} fallback=${html`<p>Loading…</p>`}>
      ${() => user(1).then(name => html`<p>${name}</p>`)}
    </${Suspense}>
  </div>
`;

// Server — the shell + fallback stream first; resolved children stage for hydrate
const stream = ssrStream(html`<${App} />`);
```

```jsx
import { hydrate, html } from '@hellajs/dom';

// Client — hydrate swaps each boundary's resolved children in, then wires them
hydrate(html`<${App} />`, '#app');
```

## Key Concepts

### Out-of-Order Streaming Opt-In

Bare async (a Promise outside a `<Suspense>`) is awaited in-order by [`ssrStream`](/reference/ssr/ssr-stream) — a slow value delays everything after it. `<Suspense>` opts a subtree into out-of-order streaming: its `fallback` flushes inline and siblings continue, so a slow fetch no longer blocks the rest of the page.

### Hydrate Swaps, Then Adopts

The resolved children stream as a `<template>` followed by an inline `<script>$hs(id)</script>` that swaps the `fallback` for them the moment they arrive (progressive, React/Solid parity); [`hydrate`](/reference/dom/hydrate) later adopts the already-swapped nodes (its `swapSuspenseStage` is the no-script/HappyDOM fallback). Under [`ssr`](/reference/ssr/ssr)/[`ssrAsync`](/reference/ssr/ssr-async) (no streaming) the children are already present, so `<Suspense>` simply renders them directly.

### Fresh Mount Resolves Async Children

On a purely client-side [`mount`](/reference/dom/mount) (no server HTML — e.g. after client-side navigation), sync children render immediately. A Promise-returning child suspends: the `fallback` shows until the Promise resolves, then the resolved content is swapped in (the Basic Usage child shape — `${() => fetch(…).then(…)}` — works identically here). On rejection, the `fallback` is removed (it is pending-only) and the error bubbles to the nearest `onError` / `error:fallback` boundary. `<Suspense>` resolves a single Promise child at mount — for reactive re-fetching (re-suspend when a signal changes), pair `resource` with `Show`.

## Important Considerations

### Pair With `ssrStream`

`<Suspense>` only changes *streaming* behavior under [`ssrStream`](/reference/ssr/ssr-stream). Under [`ssr`](/reference/ssr/ssr)/[`ssrAsync`](/reference/ssr/ssr-async) it renders children directly (fallback dropped), so it is safe to use in trees rendered any way. On a client fresh mount, a Promise child still suspends with its `fallback` regardless of which server renderer produced the surrounding HTML.

### Nested Suspense Resolves Eagerly

A `<Suspense>` inside another boundary's children resolves eagerly within its parent's staged content (the parent's swap contains the fully-resolved subtree). Top-level boundaries stream independently.
