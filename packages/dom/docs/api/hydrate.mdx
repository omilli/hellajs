# hydrate

Attach reactivity to HTML the server rendered: the existing DOM stays on screen, and handlers, effects, and state wire onto it in place.

## Basic Usage

Render the tree to HTML on the server with [`ssr`](/reference/ssr/ssr), ship it inside the target element, then call `hydrate` on the client with the **same** tree. The [hydration concept](/learn/concepts/hydration) walks the full workflow.

```jsx
import { signal } from "@hellajs/core";
import { ssr } from "@hellajs/ssr";

const App = () => {
  const count = signal(0);
  return (
    <div id="app-root">
      <span>Count: {count}</span>
      <button on:click={() => count(count() + 1)}>Increment</button>
    </div>
  );
};

// Server: ship the serialized tree inside the target element
const body = ssr(<App />);
const page = `<div id="app">${body}</div>`;
```

```jsx
import { hydrate } from "@hellajs/dom";

// Client: wire handlers and effects onto the existing DOM; nothing is rebuilt
hydrate(<App />, "#app");
```

`afterMount` hooks fire during `hydrate`, same as during `mount`.

## API

```typescript
function hydrate(
  node:
    | TemplateBuildFn
    | (() => TemplateBuildFn)
    | (() => Promise<TemplateBuildFn | (() => TemplateBuildFn)>),
  target?: string | Element
): MountHandle
```
- `node`: The same compiled component build the server rendered: a [flagged build fn](/reference/dom/runtime), a function returning one, or an async function resolving to one. Hand-built tree objects throw the documented rejection.
- `target`: A CSS selector string or DOM Element whose existing children are the server output. Defaults to `"#app"`.
- **Returns**: A [`MountHandle`](/reference/dom/mount#mounthandle) with `flush()` and `unmount()` methods. `unmount()` removes every adopted root.

## Key Concepts

### Adopt, Don't Re-Render

Unlike [`mount`](/reference/dom/mount), which replaces the container's content and rebuilds, `hydrate` keeps the server's elements: a button the server rendered is the exact node the client binds `on:click` to. Static markup is left untouched; only handlers, hooks, effects, and reactive children are wired up.

### Server HTML Must Match

`hydrate` expects the target's children to be exactly what `ssr` produced from the same tree with the same initial state: signals must initialize to the values the server rendered. When the DOM and the tree disagree, `hydrate` warns and rebuilds just the mismatched subtree; the page still works. Compiled roots (the babel plugin's `target: "dom"` client build) are stricter: a server output that disagrees with the compiled templates throws instead of warning.

### Server-Rendered Lists

[`ForEach`](/reference/dom/foreach) items the server rendered are adopted directly: after `hydrate`, pushing, removing, and reordering items works normally. Keep keys stable between server and client; the list reads the same `each` and `use` calls on both sides.

## Important Considerations

### mount vs hydrate

Use [`mount`](/reference/dom/mount) for purely client-rendered apps; it replaces the container's content. Use `hydrate` when the server shipped HTML you want to keep. For lighter needs, [`$ref`](/reference/dom/$ref), [`$collection`](/reference/dom/$collection), and island `mount`s bind reactivity to existing or placeholder nodes without re-executing a component tree.
