# mount

Renders a compiled component tree into a container element with reactive updates and lifecycle management, replacing the container's existing content.

## API

```typescript
// With a flagged build fn (the compiled component result)
function mount(
  node: TemplateBuildFn | (() => TemplateBuildFn),
  target?: string | Element | ShadowRoot
): MountHandle

// With an async component function
function mount(
  node: () => Promise<TemplateBuildFn | (() => TemplateBuildFn)>,
  target?: string | Element | ShadowRoot
): MountHandle
```

- `node`: A [flagged build fn](/reference/dom/runtime) (the `component()` result of a compiled client build), a function returning one, or an async function resolving to one.
- `target`: A CSS selector string, DOM Element, or ShadowRoot for the container. Defaults to `"#app"`.
- **Returns**: A [`MountHandle`](#mounthandle) with `flush()` and `unmount()` methods.

### MountHandle

```typescript
interface MountHandle {
  container: Element | ShadowRoot;
  flush(): void;
  unmount(): void;
}
```

- `container`: The DOM element or shadow root the tree was mounted into.
- `flush()`: Optional escape hatch that drains the mount/cleanup queues synchronously. `afterMount` already fires during `mount()`, so this is only needed to force synchronous processing (e.g. `afterDestroy` in tests, or dynamically-added nodes).
- `unmount()`: Clean up and remove the mounted tree. For a multi-root (fragment) mount, removes and disposes every root, not just one.

## Basic Usage

Pass a component function to `mount`. The compiler lowers the JSX to imperative construction calls; `mount` invokes the build and renders the result.

```jsx
import { signal } from "@hellajs/core";
import { mount } from "@hellajs/dom";

// A simple component function
const Counter = () => {
  const count = signal(0);

  return (
    <div>
      <span>Count: {count}</span>
      <button on:click={() => count(count() + 1)}>
        Increment
      </button>
    </div>
  );
};

// Mount the component into the element with id="app"
mount(Counter, "#app");

// Defaults to #app if no selector is provided
mount(Counter);
```

## Key Concepts

### Reactive Context

`mount` establishes the reactive root where signals automatically update the DOM when values change.

```jsx
import { signal } from "@hellajs/core";
import { mount } from "@hellajs/dom";

const count = signal(0);
mount(() => <div>Count: {count}</div>, "#app");
```

### Component Functions

Components are plain functions that return their template, no classes or special syntax required. The `component()` result carries the scope wiring; `mount` invokes it exactly once through the build path.

```jsx
import { mount } from "@hellajs/dom";

const Greeting = ({ name }: { name: string }) => <h1>Hello, {name}!</h1>;
mount(<Greeting name="World" />);
```

### Fragment Roots

A template with multiple root elements mounts every root into the container. `unmount()` removes them all, disposing effects and hooks in each root.

```jsx
import { mount } from "@hellajs/dom";

const app = mount(
  <>
    <span>a</span>
    <span>b</span>
  </>
);

// Both roots removed, their effects disposed
app.unmount();
```

## Important Considerations

### Hand-Built Input Is Rejected

`mount` accepts compiled build functions only. A hand-built HellaNode (`{ tag: "div", ... }`) throws at mount time with the documented rejection (`[dom] mount: hand-built HellaNode input is not supported`). JSX sources go through the [babel plugin](/plugins/babel), which emits the build functions `mount` consumes. If you were mounting hand-built HellaNode trees, see [the v3 migration guide](/learn/concepts/migration-v3) and the [runtime](/reference/dom/runtime) reference.

### Single Mount Point

Each `mount()` call creates an independent reactive tree. Avoid multiple mounts on the same element.

```jsx
import { mount } from "@hellajs/dom";

// Avoid: mounts replace the container's content, so the second call
// unmounts the first tree's DOM
mount(App1, "#app");
mount(App2, "#app");
```

### Async Component Errors

When an async component function rejects, the error routes through [`onError`](/reference/dom/onerror). If no handler is registered, the error is logged to `console.error`.

```jsx
import { mount, onError } from "@hellajs/dom";

onError((err) => {
  console.error("Mount failed:", err.message);
  return null;
});

mount(async () => {
  const data = await fetch("/api/data").then(r => r.json());
  return <div>{data.title}</div>;
});
```

### Lifecycle Hooks

Elements support lifecycle hooks via the [`hook:`](/reference/dom/hook) prefix. `beforeMount` fires synchronously during the build, before the tree is inserted. See [`hook:`](/reference/dom/hook) for all available hooks and usage patterns.

### Memory Management

HellaJS automatically manages reactive effects and event handlers. Reactive effects and DOM events are automatically cleaned up when elements are removed from the DOM. No manual cleanup is required for standard reactive bindings.

For component-level effects, use any of these approaches. They all provide automatic cleanup:

- **JSX syntax**: the babel plugin wraps the component and chains its scope
- **`component()` helper**: manual wrapping for non-JSX sources

```jsx
import { effect, signal } from "@hellajs/core";
import { mount } from "@hellajs/dom";

const Timer = () => {
  const seconds = signal(0);

  // This effect auto-cleans when Timer is removed from DOM
  effect(() => {
    const id = setInterval(() => seconds(seconds() + 1), 1000);
    return () => clearInterval(id);
  });

  return <span>{seconds}s</span>;
};

// Using JSX, component scope is automatic
mount(<Timer />);
```
