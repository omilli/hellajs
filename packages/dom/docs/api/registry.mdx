# registry

Register effects and lifecycle hooks on DOM elements directly, with automatic cleanup when the element is removed.

<Callout variant="info">Low-level API. You only need this when building custom rendering utilities or framework integrations; normal apps get the same behavior through JSX templates, [`hook:`](/reference/dom/hook), and [`$ref`](/reference/dom/$ref).</Callout>

## Basic Usage

```typescript
import { signal } from "@hellajs/core";
import { registry } from "@hellajs/dom";

const count = signal(0);
const button = document.createElement("button");

// Reactive binding: re-runs when count changes
registry.addEffect(button, () => {
  button.setAttribute("data-count", String(count()));
});

// Lifecycle hook: fires when the element is mounted through HellaJS
registry.addHook(button, "afterMount", (el) => {
  console.log("mounted", el.tagName);
});

document.body.append(button);
count(1); // button now has data-count="1"
```

When the button is later removed from the DOM, the effect is disposed and the hooks run, with no manual teardown.

## API

```typescript
const registry: {
  addEffect(node: Node, effectFn: () => void): void;
  addHook(element: Element, type: HookType, handler: HookFn): void;
}

type HookType =
  | "beforeMount"
  | "afterMount"
  | "beforeUpdate"
  | "afterUpdate"
  | "beforeDestroy"
  | "afterDestroy";
```

### `addEffect`

Registers a reactive effect on an element, stacking with any effects already registered there. The effect is disposed when the element is removed from the DOM.

```js
import { registry } from "@hellajs/dom";

const element = document.createElement("div");

registry.addEffect(element, () => {
  element.textContent = `Count: ${count}`;
});
```

While the element is mounted, each run of the effect is bracketed by the element's `beforeUpdate` and `afterUpdate` hooks. Updates driven by dynamic components ([`ForEach`](/reference/dom/foreach), [`Transition`](/reference/dom/transition)) run on their own anchors, so a parent element's update hooks do not fire for list or visibility changes.

### `addHook`

Registers a lifecycle hook on an element. Multiple hooks of the same type stack: all execute, in registration order.

```js
registry.addHook(element, "afterMount", () => {
  console.log("Element mounted");
});

registry.addHook(element, "beforeDestroy", (node) => {
  console.log("About to remove:", node);
});
```

Direct `addHook` calls need the hooks feature loaded; any `hook:` prop or `$ref` usage loads it at startup. The hook timings:

| Hook | Timing | Receives Element |
|------|--------|------------------|
| `beforeMount` | Before element added to DOM | No |
| `afterMount` | After element added to DOM: at mount time, or immediately when registered on an already-mounted element | Yes |
| `beforeUpdate` | Before reactive effect runs | Yes |
| `afterUpdate` | After reactive effect runs | Yes |
| `beforeDestroy` | Before cleanup begins | Yes |
| `afterDestroy` | After cleanup completes | No |

## Key Concepts

### Two Cleanup Paths

- **Reactive swaps are synchronous**: when HellaJS itself replaces or removes nodes (conditional rendering, list updates), effects, handlers, and hooks are disposed immediately, before the DOM node leaves the tree.
- **External removals are batched**: when other code removes nodes from a mounted container (`el.remove()`), cleanup runs on a microtask, before the browser paints. Nodes re-appended before the microtask fires are recognized as moved and skip cleanup entirely.

```js
element.remove();
// Cleanup has not run yet

await Promise.resolve();
// Cleanup has processed
```

Only mount target containers are watched; nodes removed outside them get no automatic cleanup.

## Important Considerations

### Moved Nodes Are Not Cleaned

A node removed and re-appended before the cleanup microtask fires is treated as moved, not removed:

```js
const el = document.querySelector(".item");
el.remove();        // Queued for cleanup
parent.prepend(el); // Re-connected before processing: cleanup skips it
```

### Effects Outside a Reactive Run

`addEffect` registers with `separate` semantics: the effect does not link to an enclosing reactive owner, so its lifetime is exactly the element's DOM lifetime.
