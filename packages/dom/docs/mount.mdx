# mount

Renders HellaNodes to the DOM with reactive updates and lifecycle management.

## API

```typescript
function mount(
  hellaNode: HellaNode | (() => HellaNode), 
  rootSelector?: string
): void
```
- `hellaNode`: A JSX element ([HellaNode](/learn/concepts/templates#internal-mechanics)) object or a function that returns one.
- `rootSelector`: A CSS selector for the container element where the app will be mounted. Defaults to `"#app"`.

## Basic Usage

Typically, you'll pass a component function to `mount`. HellaJS will call this function to get the [HellaNode](/learn/concepts/templates#internal-mechanics) tree and render it.

```jsx
import { signal } from '@hellajs/core';
import { mount } from '@hellajs/dom';

// A simple component function
const Counter = () => {
  const count = signal(0);
  
  return (
    <div>
      <span>Count: {count()}</span>
      <button on:click={() => count(count() + 1)}>
        Increment
      </button>
    </div>
  );
};

// Mount the component into the element with id="app"
mount(Counter, '#app');

// Defaults to #app if no selector is provided
mount(Counter);
```

## Key Concepts

### Reactive Context

`mount` establishes the reactive root where signals automatically update the DOM when values change.

```jsx
import { signal } from '@hellajs/core';
import { mount } from '@hellajs/dom';

const count = signal(0);
mount(<div>Count: {count}</div>, '#app');
```

### Component Functions

Components are plain functions that return HellaNodes, no classes or special syntax required.

```jsx
import { mount } from '@hellajs/dom';

const Greeting = ({name}) => <h1>Hello, {name}!</h1>;
mount(<Greeting name="World" />);
```

## Important Considerations

### Single Mount Point

Each `mount()` call creates an independent reactive tree - avoid multiple mounts on the same element.

```jsx
import { mount } from '@hellajs/dom';

// ❌ Multiple mounts on same element
mount(App1, '#app');
mount(App2, '#app');
```

### Lifecycle Hooks

Elements support lifecycle hooks for executing code at specific points in their lifecycle. Hooks are passed via the `hooks` property or using the `hooks:` prefix in templates.

#### Mount Lifecycle

**`beforeMount`** - Called before the element is created, useful for initialization logic.

**`afterMount`** - Called after the element is mounted to the DOM.

```jsx
const App = () => (
  <div
    hooks={{
      beforeMount: () => console.log('About to create element'),
      afterMount: (node) => {
        console.log('Element mounted to DOM');
        // Safe to access DOM here via node
      }
    }}
  >
    Content
  </div>
);
```

Or using the `hooks:` prefix syntax:

```jsx
const App = () => (
  <div
    hooks:beforeMount={() => console.log('About to create element')}
    hooks:afterMount={(node) => console.log('Mounted:', node)}
  >
    Content
  </div>
);
```

#### Update Lifecycle

**`beforeUpdate`** - Called before reactive properties or content update.

**`afterUpdate`** - Called after reactive properties or content update.

```jsx
const App = () => {
  const count = signal(0);

  return (
    <div
      bind:data-count={count}
      hooks={{
        beforeUpdate: (node) => console.log('About to update'),
        afterUpdate: (node) => console.log('Element updated')
      }}
    >
      Count: {count}
      <button on:click={() => count(count() + 1)}>Increment</button>
    </div>
  );
};
```

#### Destroy Lifecycle

**`beforeDestroy`** - Called before the element is removed from the DOM.

**`afterDestroy`** - Called after the element is removed from the DOM and effects are cleaned up.

```jsx
const App = () => {
  const timerId = setInterval(() => console.log('Tick'), 1000);

  return (
    <div
      hooks={{
        beforeDestroy: (node) => console.log('About to be removed'),
        afterDestroy: () => {
          clearInterval(timerId);
          console.log('Cleaned up');
        }
      }}
    >
      Content
    </div>
  );
};
```

#### Lifecycle Order

Hooks execute in this order:
1. `beforeMount` - before element creation
2. `afterMount` - after element is in DOM
3. `beforeUpdate` / `afterUpdate` - on reactive updates (not during initial render)
4. `beforeDestroy` - before removal
5. `afterDestroy` - after removal and cleanup

### Memory Management

HellaJS automatically manages reactive effects and event handlers. Reactive effects and DOM events are automatically cleaned up when elements are removed from the DOM. No manual cleanup is required for standard reactive bindings.

For component-level effects, wrap your component with the `component()` helper or use JSX syntax - effects created within the component scope are automatically disposed when the component is removed.

```jsx
import { effect, signal } from '@hellajs/core';
import { mount } from '@hellajs/dom';

const Timer = () => {
  const seconds = signal(0);
  
  // This effect auto-cleans when Timer is removed from DOM
  effect(() => {
    const id = setInterval(() => seconds(s => s + 1), 1000);
    return () => clearInterval(id);
  });
  
  return <span>{seconds}s</span>;
};

// Using JSX, component scope is automatic
mount(<Timer />);
```
