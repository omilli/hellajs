# Control Flow

Conditionals and dynamic expressions in templates are reactive by default — the compiler auto-wraps any expression that reads a signal, so no manual wrapper is required (an explicit `() => …` is still accepted and behaves identically).

## Conditional Rendering

Expressions that read signals re-evaluate when their dependencies change.

```jsx
import { mount } from "@hellajs/dom";
import { signal } from "@hellajs/core";

const Counter = () => {
  const count = signal(0);

  return (
    <div>
      <h1>Count: {count}</h1>
      <h2>Doubled: {count() * 2}</h2>
      <p>Count is: {count() % 2 === 0 ? "even" : "odd"}</p>
      {count() > 5 && <p>Great job! Count is greater than 5!</p>}
      <button on:click={() => count(count() + 1)}>
        Increment
      </button>
    </div>
  );
};

mount(Counter, "#app");
```

## Lists and Iteration

Use [`ForEach`](/reference/dom/foreach) for reactive lists that change over time. Use regular array methods for static lists rendered once.

```jsx
import { mount, ForEach } from "@hellajs/dom";
import { signal } from "@hellajs/core";

const TodoList = () => {
  const todos = signal([
    { id: 1, text: "Learn HellaJS", done: false },
    { id: 2, text: "Build an app", done: false }
  ]);

  return (
    <ul>
      <ForEach each={todos} use={(todo: { id: number; text: string; done: boolean }) => (
        <li key={todo.id} class={todo.done ? "done" : ""}>
          <input
            type="checkbox"
            checked={todo.done}
            on:change={e => {
              const target = e.target as HTMLInputElement;
              const updated = todos().map(t =>
                t.id === todo.id ? { ...t, done: target.checked } : t
              );
              todos(updated);
            }}
          />
          {todo.text}
        </li>
      )} />
    </ul>
  );
};

mount(TodoList, "#app");
```

A bare `{todos().map(...)}` is reactive (it reads the signal). For a one-time static snapshot, hoist the read (`const items = todos()`) or wrap it in [`untracked`](/reference/core/untracked) — or, for lists that change, prefer [`ForEach`](/reference/dom/foreach).

See [`ForEach`](/reference/dom/foreach) for keyed reconciliation details.

## Portals

Render content to a different DOM location while maintaining reactivity — useful for modals, tooltips, and overlays that need to escape their parent's DOM tree.

```jsx
import { mount, Portal } from "@hellajs/dom";
import { signal } from "@hellajs/core";

const Modal = () => {
  const isOpen = signal(false);

  return (
    <div>
      <button on:click={() => isOpen(true)}>Open</button>
      {isOpen() && (
        <Portal to="#modal-root" type="append">
          <div class="modal">
            <button on:click={() => isOpen(false)}>Close</button>
            <p>Content rendered in modal-root</p>
          </div>
        </Portal>
      )}
    </div>
  );
};

mount(Modal, "#app");
```

**Portal types:** `append` (default), `prepend`, `replace`, `before`, `after` — controlling how content is inserted relative to the target:

```jsx
// Append as last child (default)
<Portal to="#container">
  <span>Appended</span>
</Portal>

// Replace all target content
<Portal to="#container" type="replace">
  <span>Replaces everything</span>
</Portal>
```

Portal content remains reactive — signal updates propagate to the portaled location — and is cleaned up automatically when the portal's parent element is removed. The target element must exist in the DOM when the portal renders; the target is queried by CSS selector at render time.

See [`Portal`](/reference/dom/portal) for full details.

## Lazy Loading

Load components asynchronously with automatic code splitting. [`Lazy`](/reference/dom/lazy) shows optional loading state during load and optional fallback on error.

```jsx
import { Lazy } from "@hellajs/dom";

const Dashboard = () => {
  return (
    <div>
      <h1>Dashboard</h1>
      <Lazy
        loader={() => import("./HeavyChart")}
        loading={<div>Loading chart...</div>}
        fallback={<div>Failed to load chart</div>}
      />
    </div>
  );
};
```

- `loading`: Shown during async load (optional; without it the space stays empty)
- `fallback`: Shown on loader error only (optional)

The `loader` returns a Promise resolving to a component function or HellaNode. Loader errors are caught inside `Lazy` and trigger the `fallback` directly — they do not bubble to the global [`onError`](/reference/dom/onerror) handler.

When the parent element is removed during loading, the loader is automatically cancelled. Loaders performing network requests can accept an options object with an `AbortSignal`:

```jsx
<Lazy
  loader={({ signal } = {}) =>
    fetch("/api/widget.js", { signal })
      .then(r => r.text())
      .then(html => ({ tag: "div", children: [html] }))
  }
  loading={<div>Loading widget...</div>}
  fallback={<div>Widget unavailable</div>}
/>
```

Plain `() => Promise` loaders work unchanged — the options argument is silently ignored. Pass props to the loaded component through the `props` attribute:

```jsx
<Lazy
  loader={() => import("./UserProfile")}
  props={{ userId: 123, theme: "dark" }}
/>
```

See [`Lazy`](/reference/dom/lazy) for full details.

## Transitions

Animate show/hide content with enter/leave CSS classes using [`Transition`](/reference/dom/transition).

```jsx
import { signal } from "@hellajs/core";
import { mount, Transition } from "@hellajs/dom";

const visible = signal(false);

const App = () => (
  <div>
    <button on:click={() => visible(!visible())}>Toggle</button>
    <Transition show={visible} enter="fade-in" leave="fade-out" duration={300}>
      <div class="panel">Hello</div>
    </Transition>
  </div>
);

mount(App, "#app");
```

When `show` turns `false` and a `leave` class is set, the class is added and the node is removed after `duration + 50` ms so the animation finishes; without a `leave` class, hiding removes the node synchronously. The `enter` class is suppressed on first render unless `appear` is set (`true` reuses `enter`, a string names a dedicated class). Toggling `show` back to `true` during a leave cancels the removal timer — repeated toggling is safe.

See [`Transition`](/reference/dom/transition) for full details.
