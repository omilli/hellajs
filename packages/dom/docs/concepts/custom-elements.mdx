# Custom Elements

Define reusable Web Components with reactive props, slots, and lifecycle management using [`element`](/reference/dom/element).

```jsx
import { element } from "@hellajs/dom";
import { signal } from "@hellajs/core";

element("my-counter", (props: { initial: () => string | null }) => {
  const count = signal(Number(props.initial()) || 0);

  return (
    <div>
      <span id="count">{count}</span>
      <button on:click={() => count(count() + 1)}>+</button>
    </div>
  );
});
```

## Reactive Props

Props are reactive getter functions that track attribute changes. Missing attributes return `null`, so use nullish coalescing (`??`) for defaults:

```jsx
element("my-greeter", (props: { name: () => string | null }) => (
  <div>
    {() => `Hello, ${props.name() ?? "World"}!`}
  </div>
));
```

`setAttribute` and `removeAttribute` trigger synchronous reactive updates. Effects that read props re-evaluate immediately.

## Slots

Support default and named slots for content projection. Whitespace-only text nodes are excluded from the default slot (`props.children`):

```jsx
element("my-card", (props) => (
  <article>
    <header>{props.slots?.title}</header>
    <main>{props.children}</main>
    <footer>{props.slots?.footer}</footer>
  </article>
));
```

Usage in HTML:
```html
<my-card>
  <h1 slot="title">Card Title</h1>
  <p>Default slot content</p>
  <small slot="footer">2025</small>
</my-card>
```

## Shadow DOM

By default, custom elements render to light DOM. Pass `{ shadow: true }` as the third argument to render into an open shadow root instead — page CSS no longer applies to the element's content:

```jsx
element("my-widget", (props) => (
  <div class="box">{props.children}</div>
), { shadow: true });
```

An object is passed to `attachShadow` verbatim, so `{ shadow: { mode: "closed" } }` also works: outside JavaScript cannot reach the root via `el.shadowRoot`, while the element keeps rendering and updating normally.

**Limitation:** projection uses captured `props.children` and `props.slots` nodes moved into the shadow render output — native `<slot>` element projection is **not** available under `shadow: true`. Slotted content still works through the captured-props API shown above.

## Lifecycle

When a custom element is disconnected from the DOM, all effects are disposed and internal state resets. Reconnection triggers a fresh render from scratch — the shadow root (if any) is reused.

**Important:** Custom elements render to light DOM by default; pass `{ shadow: true }` for style encapsulation (see [Shadow DOM](#shadow-dom)).

See [`element`](/reference/dom/element) for full API details.
