# Components

Components are simple functions that return elements. They compose naturally through props and children, and maintain reactivity across boundaries.

## Component Syntax

Components use uppercase names in JSX. For html template literals, use `<${Component}>` syntax.

```jsx
import type { HellaChildren } from "@hellajs/dom";

const MyComponent = ({ title, children }: { title: string; children?: HellaChildren }) => {
 return  <div>{title} - {children}</div>;
}

// JSX
<MyComponent title="Hi">Content</MyComponent>
```

In [`html`](/reference/dom/html#components) template literals, the same component uses the dynamic-tag form: `<${MyComponent} title="Hi">Content</${MyComponent}>`.

## Component Composition

Components compose through props and children, just like regular function arguments.

```jsx
import { mount } from "@hellajs/dom";

const Card = ({ title, variant = "default", children }: { title: string; variant?: string; children?: HellaChildren }) => (
  <div class={`card card-${variant}`}>
    <div class="card-header"><h2>{title}</h2></div>
    <div class="card-content">{children}</div>
  </div>
);

const Button = ({ variant = "primary", click, children }: { variant?: string; click: () => void; children?: HellaChildren }) => (
  <button class={`btn btn-${variant}`} on:click={click}>
    {children}
  </button>
);

const MyPage = () => (
  <Card title="Welcome" variant="highlighted">
    <p>Welcome to our application!</p>
    <Button click={() => alert("Hello!")}>Get Started</Button>
  </Card>
);

mount(MyPage, "#app");
```

Prefixed attrs at a call site also pass through verbatim: `<Button on:click={fn}>` arrives as `props["on:click"]`, and the component forwards prefixed attrs back onto its root element, where the runtime routes them to the matching live bucket. Plain event props like the `click` prop above remain valid: they are ordinary values the component wires itself.

In the JSX flavor, forward the whole set with rest props: declare `HTMLAttributes<"button">` in the props type and spread `{...rest}` onto the root element. TypeScript already accepts the full canonical form:

```jsx
import type { HTMLAttributes } from "@hellajs/dom";

const Button = ({ variant = "primary", children, ...rest }: HTMLAttributes<"button"> & { variant?: string }) => (
  <button class={`btn btn-${variant}`} {...rest}>{children}</button>
);

// Every prefixed key arrives verbatim and forwards:
// <Button disabled on:click={fn} on:focusin={fn} />
```

In the html flavor, the counterpart of `{...rest}` is attribute-position spread: destructure the rest object and write `...${rest}` on the root element, after any declared attributes so caller attrs win:

```js
import type { HTMLAttributes } from "@hellajs/dom";
import { html } from "@hellajs/dom";

const Button = ({ variant = "primary", children, ...rest }: HTMLAttributes<"button"> & { variant?: string }) => html`
  <button class=${`btn btn-${variant}`} ...${rest}>${children}</button>
`;

// <${Button} disabled on:click=${fn} on:focusin=${fn} /> forwards every key
```

## Component Data Flow

Pass signals as props to maintain reactivity across component boundaries. The child component reads the signal prop in a template expression; element children auto-wrap, so the binding is reactive.

```jsx
import { mount } from "@hellajs/dom";
import { signal } from "@hellajs/core";
import type { Signal } from "@hellajs/core";

type Todo = { id: number; text: string; priority: string; done: boolean };

const TodoCard = ({ todo }: { todo: Signal<Todo> }) => (
  <div class="todo-card">
    <h3>{todo().text}</h3>
    <p>Priority: {todo().priority}</p>
    <span class={`status ${todo().done ? "completed" : "pending"}`}>
      {todo().done ? "Completed" : "Pending"}
    </span>
  </div>
);

const TodoApp = () => {
  const selectedTodo = signal({
    id: 1,
    text: "Learn HellaJS",
    priority: "high",
    done: false
  });

  return (
    <div class="todo-app">
      <TodoCard todo={selectedTodo} />
      <button on:click={() => selectedTodo({
        id: 2,
        text: "Build awesome app",
        priority: "medium",
        done: true
      })}>
        Switch Todo
      </button>
    </div>
  );
};

mount(TodoApp, "#app");
```

### Component props and children are not auto-wrapped

Auto-wrapping applies to **element** children. Component props and component children are passed through as-is: a component may treat `props.children` or a prop as a plain value (not a function). So `<Comp>{expr}</Comp>` passes the eager-evaluated value; to keep a component child reactive, pass a signal reference (`<Comp>{mySignal}</Comp>`) or an explicit wrapper (`<Comp>{() => expr}</Comp>`).

## Component Scope

Effects created within components are automatically scoped and cleaned up when the component is removed from the DOM.

```jsx
import { mount } from "@hellajs/dom";
import { signal, effect } from "@hellajs/core";

const Timer = () => {
  const count = signal(0);

  effect(() => console.log(`Count: ${count}`));

  return (
    <div>
      <h1>{count}</h1>
    </div>
  );
  
  //effect auto-cleanup on unmount
};

mount(Timer, "#app");
```

The low-level [`component`](/reference/dom/component) function wraps component functions with automatic scope management. JSX and html templates wrap components automatically. Dynamic components (ForEach, Portal, Lazy, Transition, Suspense) bypass this wrapper since they manage their own scope.

Render errors (thrown during component execution) are dispatched through the error system and return an empty fragment. See [Error Handling](/learn/concepts/error-handling) for details.
