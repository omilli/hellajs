# Hydration

Make server-rendered HTML interactive without rebuilding it. The user sees the page immediately; `hydrate` attaches event handlers and reactivity to the elements already on screen.

## Hydrate a Server-Rendered Page

Render the app on the server, then run the same component on the client with [`hydrate`](/reference/dom/hydrate) instead of [`mount`](/reference/dom/mount):

```jsx
import { signal } from "@hellajs/core";
import { hydrate } from "@hellajs/dom";
import { ssr } from "@hellajs/ssr";

const App = () => {
  const count = signal(0);
  return <button on:click={() => count(count() + 1)}>Clicked {count} times</button>;
};

// Server: ship the rendered button
const body = ssr(<App />);
```

```jsx
// Client: attach the click handler to the existing button
hydrate(<App />, "#app");
```

Component bodies run again on the client (they create signals and effects that cannot be serialized), but the DOM is reused: the button the server rendered is the exact node the client binds `on:click` to. Nothing is wiped or rebuilt when the HTML matches.

## Rules for a Clean Hydrate

- **Pass the same tree.** The component you hydrate must be the same component the server rendered, with the same structure of elements.
- **Start from the same state.** Signals must initialize to the values the server rendered. A signal that starts elsewhere is a mismatch.
- **Mismatches stay usable.** When the HTML and the tree disagree, `hydrate` warns and rebuilds just the mismatched subtree; the rest of the page keeps working.

## When to Hydrate, Enhance, or Mount an Island

- [`hydrate`](/reference/dom/hydrate): the right tool when you want a fully interactive app from server-rendered HTML.
- [`$ref`](/reference/dom/$ref) / [`$collection`](/reference/dom/$collection): bind a few existing elements into reactivity, no component tree at all. Lightest option.
- Island [`mount`](/reference/dom/mount): mount a reactive component into an empty placeholder the server left. Use it when most of the page is static and only one region is interactive.

Do not run a full-tree `mount` over the server container: `mount` replaces the container's children, discarding the server HTML.

## Server-Rendered Lists

[`ForEach`](/reference/dom/foreach) items the server rendered are picked up directly: after `hydrate`, pushing, removing, and reordering items works normally. Keys are re-derived from the same `each` and `use` calls the server made, so keep keys stable between server and client.

```jsx
import { signal } from "@hellajs/core";
import { ForEach } from "@hellajs/dom";

const items = signal([{ id: 1, label: "First" }, { id: 2, label: "Second" }]);

const ItemList = () => (
  <ul>
    <ForEach
      each={items}
      use={(item: { id: number; label: string }) => <li key={item.id}>{item.label}</li>}
    />
  </ul>
);

// Server emits the two <li>s; after hydrate, list updates work normally
hydrate(<ItemList />, "#app");
```

## Hydrating a Streaming Page

When the page streams ( [`ssr`](/reference/ssr/ssr) with suspense regions), the hydrate script can run before all content has arrived. Regions whose content is still streaming are deferred: the loading fallback stays on screen, and everything else becomes interactive immediately. When the content lands, the region adopts it and goes interactive too, no reload needed.

```js
// client; placed mid-stream, so the script runs before all content arrives
import { hydrate } from "@hellajs/dom";

hydrate(page(), "#app");
// Regions still streaming stay on their fallback; they adopt when the content lands
```

Two behaviors to rely on:

- **Clicks on a pending region are replayed.** A click on a loading fallback is buffered and delivered to the resolved content once it arrives, so early interactions are not lost. Events elsewhere on the page fire normally right away.
- **A dead stream recovers.** If the stream ends before a region's content arrives, that region renders on the client instead: the fallback stays until the content is ready, then swaps in.
