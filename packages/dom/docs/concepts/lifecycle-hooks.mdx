# Lifecycle Hooks

Lifecycle hooks fire at specific points in an element's existence. They are tied directly to DOM elements using the `hook:` prefix, not to component scope.

<div role="alert" class="alert alert-info alert-soft text-base">
  <span>ℹ️</span>
  <span>Unlike other frameworks, lifecycle hooks are tied directly to elements, not component scope.</span>
</div>

**Execution order:**

- `hook:beforeMount`: Synchronously before element is inserted into DOM, before children rendered (no element argument)
- `hook:afterMount`: After element is in DOM, receives element argument (deferred via `queueMicrotask`)
- `hook:beforeUpdate`: Before reactive updates, receives element argument (not during initial render); errors caught, no fallback UI
- `hook:afterUpdate`: After reactive updates, receives element argument (not during initial render); errors caught, no fallback UI
- `hook:beforeDestroy`: Before removal, receives element argument
- `hook:afterDestroy`: After removal and effect cleanup (no element argument)

```jsx
import { mount } from '@hellajs/dom';
import { signal } from '@hellajs/core';

const Counter = () => {
  const count = signal(0);

  return (
    <div
      hook:afterMount={() => console.log('In DOM')}
      hook:beforeDestroy={() => console.log('Removing')}
    >
      <h1>{count}</h1>
      <button on:click={() => count(count() + 1)}>Increment</button>
    </div>
  );
};

mount(Counter, '#app');
```

Multiple hooks of the same type on the same element all execute in registration order.

See [`hook:`](/reference/dom/hook) for timing details and usage patterns for each hook.
