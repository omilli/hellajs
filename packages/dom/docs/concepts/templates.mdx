# Templates

Write UI as JSX: the compiler wires your signals to the DOM, and updates touch only what changed. No virtual DOM, no runtime template parsing.

## The Shape of a Template

JSX is the only template syntax. A build-time plugin (`babel-plugin-hellajs`, wired by the Vite, Rollup, and Astro integrations) compiles each component into the structures [`mount`](/reference/dom/mount) consumes. The same rules hold on the server, where [`ssr`](/reference/ssr/ssr) walks the tree to a string.

```jsx
import { mount } from "@hellajs/dom";
import { signal } from "@hellajs/core";

const count = signal(0);

const App = () => (
  <div>
    <h1>{count}</h1>
    <button on:click={() => count(count() + 1)}>Increment</button>
  </div>
);

mount(App, "#app");
```

## Reactive Bindings

A signal **reference** is the simplest reactive binding. A **compound** expression (arithmetic, conditional, method call) calls the signal, and the compiler wires the reactivity for you. Both update the DOM when their dependencies change.

```jsx
// Signal reference: updates when count changes
<h1>{count}</h1>

// Arithmetic: re-runs when count changes
<h2>{count() * 2}</h2>

// Reactive conditional: re-evaluates when count changes
{count() > 5 && <p>Great job!</p>}
```

The automatic wiring applies to element children and element attributes only. Component children and props arrive as plain values; pass an explicit function when a component documents a getter prop.

## Static Values

To read a signal once with no reactivity, hoist the read out of the template or wrap it in [`untracked`](/reference/core/untracked).

```jsx
import { untracked } from "@hellajs/core";

// Hoist: read once into a plain value
const total = count();
<h1>{total}</h1>

// untracked: read once inside the template, no dependency tracked
<h1>{untracked(() => count())}</h1>
```

`false`, `null`, and `undefined` render as nothing; `0` renders `"0"`.

```jsx
{false}      // renders nothing
{null}       // renders nothing
{undefined}  // renders nothing
{0}          // renders "0"
```

## Array Attributes

Array values for attributes join with spaces, falsy entries dropped. A call inside the array keeps the attribute reactive.

```jsx
const isActive = signal(true);

// class="base active always"; drops "active" once isActive() is false
<div class={["base", isActive() && "active", "always"]} />
```

## Static Markup Is Cheap

A fully static subtree (lowercase tag, literal props, static text) is allocated once per site and cloned on every later use, so repeating static markup costs almost nothing. Expressions, components, spreads, and prefixed attributes (`on:`, `hook:`, ...) disqualify a subtree from this treatment; static children inside a dynamic parent still benefit individually.

## SVG and MathML

SVG and MathML mount in their correct namespaces automatically: an `<svg>` root creates in the SVG namespace, descendants inherit it, and `<math>` behaves the same. No wrappers or namespace configuration needed.

```jsx
import { mount } from "@hellajs/dom";

mount(
  <svg width="24" height="24">
    <clipPath id="clip"><rect width="10" height="10" /></clipPath>
  </svg>,
  "#app"
);
```

Dynamic content works the same way: [`ForEach`](/reference/dom/foreach), [`Lazy`](/reference/dom/lazy), and reactive children under an SVG parent all create their elements in the inherited namespace.

### CamelCase Tags

Multi-word SVG and MathML tags are authored camelCase (`clipPath`, `linearGradient`, `feGaussianBlur`), exactly as in hand-written SVG. Cased attributes like `viewBox` and `patternUnits` pass through unchanged.

### foreignObject Resets to HTML

Inside `<foreignObject>` the namespace resets to HTML: its children are regular HTML elements. To re-enter SVG, open a new `<svg>` element inside.

```jsx
<svg>
  <foreignObject width="100" height="50">
    <div>HTML content here</div>
  </foreignObject>
</svg>
```

One edge: error fallback UI (from [`error:fallback`](/reference/dom/error)) always renders as HTML, even when the failing boundary sits inside an SVG subtree; keep fallback markup HTML-only.

## Only What You Use Ships

The compiler detects every prefix and namespace your templates use and loads just the matching runtime wiring: [`hook:`](/reference/dom/hook) and [`error:`](/reference/dom/error) load their features, [`e:`](/reference/dom/e) loads direct events, `<svg>`/`<math>` load namespace resolution. Features your code never uses never load and tree-shake out entirely: a hook-free, error-free app ships the mount core only.

Templates require the compiler: hand-built tree objects throw at [`mount`](/reference/dom/mount) and [`hydrate`](/reference/dom/hydrate). To build DOM without JSX, use the imperative [runtime](/reference/dom/runtime) module.
