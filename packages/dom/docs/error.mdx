# error:

Element-level error configuration for fine-grained error handling.

## Overview

Use the `error:` prefix to configure error behavior on individual elements. Works with the global [`onError`](/reference/dom/onerror) handler.

## Available Attributes

| Attribute | Type | Description |
|-----------|------|-------------|
| `error:fallback` | `(error: Error) => HellaNode` | Function returning fallback UI |
| `error:category` | `string` | Category passed to global handler |
| `error:boundary` | `boolean` | Mark element as error boundary |

## Basic Usage

### Fallback UI

```jsx
import { onError, html } from '@hellajs/dom';

// Global handler uses element's fallback
onError((error, context) => {
  return context.config?.fallback?.(error)
    ?? html`<div>Error: ${error.message}</div>`;
});

// Element with fallback
<div error:fallback=${(e) => html`<span>Error: ${e.message}</span>`}>
  <FlakyComponent />
</div>
```

### Category for Logging

```jsx
<div error:category="sidebar">
  <Sidebar />
</div>
```

### Combined

```jsx
<div error:fallback=${handleError} error:category="modal">
  <ModalContent />
</div>
```

## Resolution

- **First found wins** - Walks up DOM tree, stops at first element with `error:` config
- **No merging** - Child config doesn't inherit from parent
- **Passed to handler** - Config available in `context.config`

## What Gets Caught

Elements with `error:` config catch errors from:

- Reactive children that throw
- `bind:` callback errors
- `on:` and `e:` event handler errors
- Lifecycle hook errors

## Nested Boundaries

When nested elements have error configs, the nearest one wins:

```jsx
<div error:category="outer" error:fallback=${outerFallback}>
  <div error:category="inner" error:fallback=${innerFallback}>
    ${() => { throw new Error('oops'); }}
  </div>
</div>
// Result: innerFallback is used
```
