<headless-package-instructions>
Flat dispose-handle wiring over real DOM nodes for common UI mechanics: focus trap, Escape/outside dismissal, roving tabindex, anchor positioning, hover intent, menu typeahead, pointer gestures, layered dismissal. Zero renderer deps by design for the behaviors: raw `== null` validation (the guide's stays-raw form; never convert to `typeof` comparisons — `hella/no-raw-typeof-compare`-banned in `packages/*/lib`). State stays in caller signals. The behavior files import nothing from dom's renderer — only `@hellajs/core` (direct, e.g. `isNull`), sibling behavior files, and own internals (`internal/focusables.ts`, type-only `types/behaviors.d.ts`); the foundation layer (`modal.ts`) is the one dom importer — `registry` from the `@hellajs/dom` barrel for node-scoped disposal. The parts tier (`popover.tsx`, `menu.tsx`, `tooltip.tsx`) is the second dom importer: camelCase factories whose closure owns controlled-or-internal state and returns TitleCase members (`Popover.Trigger`, `Menu.Item`) that render structure, never styles — `data-slot`/`data-state` hooks plus spread `class`/attrs; the ui registry pastes wrap them as styled wrappers (the pastes pin their own `data-slot` through the attrs spread, which overrides the factory's generic slot). Parts `.tsx` compiles through the bundle pipeline's babel mirror (`transformRegistrySource` in `scripts/bundle/registry.ts`, reused by `esbuild-build.ts` for per-module output and a lib mirror for the bundle pass). Code/test/docs style rules live in `guides/code.md`, `guides/tests.md`, `guides/docs.md` — not duplicated here.

## Files

| File | Responsibility |
|---|---|
| `trapFocus.ts` | Document capture-phase keydown; wraps Tab/Shift+Tab when `activeElement` is exactly the first/last focusable. Focuses `initialFocus()` result or the first focusable at trap time; captures pre-trap `activeElement` and restores it on release unless `restoreFocus: false`. Focusables re-queried per keypress (dynamic children join the trap). |
| `onEscape.ts` | Bubble-phase keydown on the target itself; fires `handler` only on `key === "Escape"`. |
| `onOutside.ts` | Document capture-phase pointerdown; re-invokes the `targets` getter per event, skips `null` entries, ignores the press when any resolved node `.contains(event.target)`, else fires `handler`. |
| `rovingTabIndex.ts` | Container bubble-phase keydown over `getFocusables(container, selector)`. Init: first item `tabindex=0`, rest `-1`, never steals focus. Per key: resolve `current` via `indexOf(activeElement)` (`-1` → ignore — arrows act only with focus inside the group); orientation gates the axis; Home/End become deltas; `loop` wraps (`(target + len) % len`) or clamps at the ends; writes `tabindex=0` on the target item, `-1` on the rest. Dispose restores each init-snapshot item's original attribute (`removeAttribute` when it had none). |
| `anchorPosition.ts` | Fixed-overlay wiring over `computeAnchorPosition`: applies `position: fixed; left/top`, repositions on window `scroll` (capture — nested scrollers) + `resize`, calls `options.onUpdate?.(placement)` after each reposition. Anchor rect measured live per reposition; floating size from `offsetWidth/offsetHeight` (transform-free), with the matched width pinned and `position: fixed` applied before the box is measured (a pre-pin in-flow first layout clamps x against a stale width); `dir` defaults to the anchor's computed `direction` read once at setup. Dispose removes both window listeners. |
| `computeAnchorPosition.ts` | Pure rect math, zero DOM — the testable seam (HappyDOM rects are zeros). Placement = side + align; flip to the opposite side (vertical↔horizontal stays) when the primary doesn't fit `viewport`, then shift-clamp both axes inside it; `matchAnchorWidth` returns `width = anchor.width`; `dir` resolves `-start/-end` on the horizontal axis only (vertical alignment is direction-free). Returns `{ x, y, placement, width }`. |
| `hoverIntent.ts` | Tooltip/hover-card timing: `pointerenter`/`focus` start the open timer, `pointerleave`/`blur` the close timer, outside `pointerdown` closes immediately. Module-level `lastOpenedAt` skip-delay clock (500ms window) makes the next `onOpen` instant — shared across all consumers; reset via `resetHoverIntentState()` (`@internal`, called by `resetHeadless`). |
| `menuTypeahead.ts` | Container keydown → printable chars buffer into a query (auto-reset 500ms per keystroke); matches `resolveItems()` case-insensitively — `startsWith` from index 0, else substring wrap-around from the item after the last selection; first match → `onSelect`. Ctrl/meta/alt and non-printable keys never touch the buffer. |
| `onDrag.ts` | Pointer drag: primary-button pointerdown (skipped on `[disabled]` descendants) → guarded `setPointerCapture` → `pointermove` emits `{ dx, dy, event }` cumulative from the start → pointerup/pointercancel/lostpointercapture fire `onEnd` once. Consumers own all value math; `touch-action: none` is theirs too. |
| `onSwipe.ts` | Pointer swipe composed over `onDrag`: start/move forwarded with cumulative deltas; moves sample `(x, y, t)` via `performance.now()` into a 100ms velocity window (two rolling sample objects, the window re-anchors on the previous sample when it expires — no per-move allocation). Release: the dominant axis (larger of `|dx|`, `|dy|`; sign gives direction) commits when it crosses `threshold` (default 50) or its release velocity crosses the `velocity` floor (default 0.5px/ms, dt clamped to 1ms), else `onCancel`. No module-level state → no reset registration. |
| `onPinch.ts` | Two-pointer pinch over an owned pointer map (not `onDrag` composition — it is single-pointer and its capture model fights two-pointer tracking): primary-button + `[disabled]` guards, first two pointerdowns join (`Map<pointerId, {x, y}>`, a third is ignored), each captured. The second landing starts the gesture: baseline = pair distance + centroid. Tracked moves report `scale` (current/baseline distance) + centroid `dx`/`dy`; either tracked pointer's end (up/cancel/lostpointercapture) fires `onEnd` once, and a fresh second pointer re-baselines. No module-level state → no reset registration. |
| `onLongPress.ts` | Timed press: a primary-button `pointerdown` (skipped on `[disabled]` descendants) starts a `setTimeout(duration)` (default 500); a `pointermove` beyond `tolerance` px (default 8, squared-distance compare) from the press point, `pointerup`, or `pointercancel` clears it; expiry fires `handler` once with the originating `pointerdown` event. The timer is cleared in the dispose handle; no pointer capture is taken. No module-level state → no reset registration. |
| `onDoubleTap.ts` | Double-tap pairing over one timer per element: a qualifying tap is a primary-button `pointerdown` (skipped on `[disabled]` descendants) whose `pointerup` lands within 8px of the press point (squared-distance compare); the first tap arms `setTimeout(interval)` (default 250), a second tap inside the window clears it and fires `onDoubleTap` once with the second tap's event, expiry fires the opt-in `onSingleTap` once with the stored first tap's event. Drift beyond the tolerance or `pointercancel` voids the in-flight tap. The timer is cleared in the dispose handle; no pointer capture is taken. No module-level state → no reset registration. |
| `layerDismissal.ts` | Shared module-level layer stack: push on call, pop on dispose. Document capture keydown Escape + pointerdown outside every `nodes()` entry (getter, like `onOutside`) fire `onDismiss` only when this layer is top — stacked overlays dismiss one layer at a time. Dismissal does NOT pop — the handler must dispose. Reset via `resetLayerStack()` (`@internal`, called by `resetHeadless`). |
| `modal.ts` | The foundation layer: `registry.addEffect(node, …)` registers one re-arm effect over the `state` getter — arms `onEscape`/`onOutside`/`trapFocus` while `"open"`, disarms on the flip to `"closed"`, re-arms on reopen; the arms live in a closure the body drains at its start (the registry's effect bodies return void — no cleanup capture), and a `beforeDestroy` hook drains them at node removal. `onExited` arms a node-lifetime listener pair (`animationend` unfiltered; `transitionend` filtered to the node's own transform — the drawer's exit channel), gated on `state() === "closed"`, removed by a second `beforeDestroy` hook. Escape/outside arms take `onClose`; a missing `onClose` leaves both off (no throw). Throws on missing node/state before any registration. |
| `popover.tsx` | The parts factory: one closure per call owns the open state (controlled `open` getter or an internal signal; `onOpenChange` reports factory-driven flips only), the visible/exit machine (close-flip keeps the content mounted under `data-state="closed"` until `animationend` or the 250ms fallback budget), and the generated `aria-controls` id. `Trigger` owns the toggle + trigger aria contract and chains a user `on:click`; `Anchor` captures the positioning target; `Content` is fragment-rooted and hosts the gate as a child region OUTSIDE its `<Portal>` — the whole portal reconstructs per open (see Non-obvious). Content props carry side/align/sideOffset/alignOffset (engine defaults 4/0), an `anchor` override, and an `onExited` side-channel. Part prop types mirror the compiled shapes: `class` is the dom attribute-map union (the compose splice keeps plain arrays in the css flavor — a narrow `class?: string` fails the staged tsc gate) and `children` accepts `HellaChildren | HellaChildren[]` (multi-member JSX children nest one array level). |
| `menu.tsx` | The menu-family factories over the same closure shape as `popover`: file-local `menuOpenState` (open state + exit machine), `makeItemParts` (Item/CheckboxItem/RadioGroup/RadioItem/Label/Separator/Group/Shortcut — selection dispatches the document-level `hella:menu-select` event; `closeOnSelect: false` opts out), `makeSubParts` (hover-intent trigger with 100ms open / 300ms close timers, content anchored to its own trigger, ArrowLeft exit, pointerenter close-cancel; takes `MenuSubOptions` for the manual composition's controlled state). `menu(options)` returns the full part set; `Content` arms the anchored-layer engine with `focusTarget` (first enabled item, then the node) and an `arm` hook pushing `menuTypeahead`, the `menuKeyDown` roving model (lifted verbatim from the registry templates: wrap-around arrows, Home/End, Enter/Space, Tab close-all, RTL-flipping submenu entry, optional horizontal handoffs), and a `hella:menu-select` listener. `trigger: "contextmenu"` swaps the button for a `span` zone whose `on:contextmenu` stamps a zero-size fixed anchor at the pointer (flush `sideOffset` 0; removed + focus restored on close). `menubar(options)` returns `{ Bar, menu }`: `Bar` renders `role="menubar"` with closed-state arrow roving via `button[aria-haspopup='menu']` role lookups (override-proof where pastes re-slot data-slots) and value mirroring over document-level `hella:menubar-open`/`hella:menubar-close`; each `menu()` call announces its flips, closes on a sibling's announcement, and maps both horizontal arrows to open-then-move through the same role lookups. Internal lookups never key on data-slot (the pastes override slots). |
| `tooltip.tsx` | The hover-pair factories: file-local `hoverOpenState` (the `menuOpenState` closure shape — controlled-or-internal open + exit machine) shared by both, and `heldFocus` (the `focusTarget` resolution that refocuses the active element — a no-op satisfying the engine's open-focus contract without stealing the trigger's focus). `tooltip(options)` returns `{ Provider, Trigger, Content }`: Provider is a passthrough grouping div (skip-delay sharing is `hoverIntent`'s module clock, not provider state); Trigger arms `hoverIntent` (open `delay`, default 700) for its lifetime, disposes at `beforeDestroy`, and carries `aria-describedby` to the generated `hella-tooltip-content-N` id; Content defaults side `top`/offset 0 and arms the anchored-layer engine with `onDismiss`. `hoverCard(options)` returns `{ Trigger, Content }`: Trigger arms `hoverIntent` (200/300 defaults) plus dedicated pointerenter/leave ownership markers (a re-enter short-circuits inside `hoverIntent`'s enter before `onOpen`); the four ownership handlers (open/close from each region, each close guarded by the other region's flag) give the crossing contract; Content defaults side `bottom`/offset 4 and pushes the zero-delay content `hoverIntent` through the engine's `arm` hook so the keep-open wiring shares the armed lifecycle. |
| `internal/anchoredLayer.ts` | Internal engine, NOT exported (the `dead-exports` guard; generalized by menu as its second consumer): the non-modal `modal` sibling — anchoring, stacked dismissal, open-arm focus, exit notify, no trap. One re-arm effect over the `state` getter arms `anchorPosition` (placement from `side`/`align`), the `alignOffset` cross-axis translate, `layerDismissal` (Escape + outside, top-of-stack only), the optional `arm` hook's pushed disposers (consumer wiring that shares the armed lifecycle), and focus on the `focusTarget` resolution (the node by default) while `"open"`; `onExited` rides the node-lifetime animationend/transform-transitionend pair exactly like `modal`; a `beforeDestroy` hook drains the arms at node removal. No input guards (internal — the caller passes valid node/state). |
| `internal/focusables.ts` | `FOCUSABLE_SELECTOR` (`a[href]`, enabled `button`/`input`/`select`/`textarea`, `[tabindex]:not([tabindex="-1"])`) + `getFocusables(root, selector?)` — the shared collector for `trapFocus` (default) and `rovingTabIndex` (default + `selector` override). |
| `internal/reset.ts` | `resetHeadless()` — resets the shared hover-intent skip-delay clock and the dismissal layer stack (test/introspection; dom's `resetDom` must not import from headless — the dependency direction is headless → dom only). |

Non-obvious:

- **Dispose is REQUIRED in cleanup paths.** `trapFocus`, `onOutside`, `hoverIntent`, and `layerDismissal` listen on `document` (and `anchorPosition` on `window`) — the wiring outlives the observed element; skipping the dispose handle leaks live global listeners against detached containers.
- **Default collector vs roving's `-1` writes.** `getFocusables` excludes `tabindex="-1"`, and roving writes `-1` onto inactive items. Items collected only via their `tabindex` attribute (spans, not natively focusable) drop out of the default group after the first move; such groups must pass `selector`. Natively focusable items (buttons, links, inputs) stay collected — the selector arms match them regardless of `tabindex`.
- **`onEscape`/`rovingTabIndex` listeners take `(event: Event)`.** Generic `Node`/`ParentNode` targets only expose the string→`EventListener` overload (no keyed event map, unlike `document`), so those two closures narrow `(event as KeyboardEvent)` once at the top; `trapFocus`/`onOutside` attach to `document` and keep concrete event params.
- **Wrap only at the exact edges.** `trapFocus` intercepts when `activeElement` is the first or last focusable; focus elsewhere inside the container falls through to native Tab behavior. Pull-back from outside the container is deliberately absent.
- **`setPointerCapture` is guarded.** `onDrag` calls `el.setPointerCapture?.(id)` — HappyDOM lacks it; real browsers get capture, tests dispatch move events at the element directly.
- **Module-level state is shared across consumers.** `hoverIntent`'s `lastOpenedAt` skip-delay clock and `layerDismissal`'s layer stack live at module scope — both reset by `resetHeadless()` (via `resetHoverIntentState`/`resetLayerStack`), so test isolation holds; production code must dispose (`layerDismissal`'s stack entry pops on dispose only).
- **The exit gate sits OUTSIDE the `<Portal>`.** Portals mount once — a gated region inside a portal re-runs without a mount walk (the portaled target is not an observed container), so `hook:afterMount` never fires and the node stays `isMounted: false` forever. Host the gate as a child region of a fragment-rooted component so each flip reconstructs the whole `<Portal>` (portal mount queues the walk explicitly). The portal anchor must also stay a DESCENDANT of a mounted root: `mount`'s root set is captured at attach, so an anchor added later as a sibling of every mounted root is never cleaned and the body content leaks on unmount — render `Content` inside `Trigger`.

## Testing approach (`tests/`)

Integration-style, public API only. Runtime and type imports from **`@hellajs/headless`** (bare specifier); the `modal` foundation and the parts-factory tests (`popover`, `menu`, `menubar`, `tooltip`, `hover-card`) additionally import `@hellajs/core` (signal/flush), `@hellajs/dom` (mount/peekState), and `@utils/test-helpers.js` (delay) for the node-lifetime and portal-wait scenarios, matching their dependency direction. `tests/helpers.tsx` exports the pointer/key event dispatchers the behavior test files share: `pointerDown`, `pointerEnter`/`pointerLeave` (non-bubbling enter/leave at the target), `pointerMove(target, x?, y?)` (client-coordinate move), `pointerUp`, `pointerCancel`, `pressKey` (bubbling, **`cancelable: true`** keydown — without it `defaultPrevented` asserts fail silently), and `setupButtons` (container + labeled buttons in the body). State resets flow through `resetTestState` (`utils/test-helpers.js` calls `resetHeadless` alongside `resetDom`).
