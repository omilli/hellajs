# popover

Creates the six popover components in one call: a toggle trigger, an optional anchor span, the ported content layer, and the structural header, title, and description. The factory closure owns the open state, the exit timing, and the generated content id.

## Basic Usage

```tsx
import { signal } from "@hellajs/core";
import { mount } from "@hellajs/dom";
import { popover } from "@hellajs/headless";

const open = signal(false);

const Popover = popover({
  open: () => open(),
  onOpenChange: (next) => open(next),
});

mount(
  <div>
    <Popover.Trigger>Settings</Popover.Trigger>
    <Popover.Content side="bottom" align="start" sideOffset={6}>
      <Popover.Header>
        <Popover.Title>Dimensions</Popover.Title>
        <Popover.Description>Set the layer size.</Popover.Description>
      </Popover.Header>
    </Popover.Content>
  </div>,
  "#app",
);
// The trigger toggles the factory's open state and carries data-state plus
// aria-expanded. Content portals into document.body, anchors to the trigger,
// and closes on Escape or an outside press; closing keeps it mounted under
// data-state="closed" until its exit animation ends.
```

Omitting both `open` and `onOpenChange` keeps the state internal, so the components work standalone:

```tsx
const Popover = popover();
// <Popover.Trigger> toggles the factory's own signal.
```

## API

```typescript
function popover(options?: PopoverOptions): PopoverComponents
```

- `options.open`: Controlled open-state getter. Passing it makes the popover controlled; omitting it keeps state internal.
- `options.onOpenChange`: Called on every open-state change, owned toggle and dismissal alike.
- `options.anchor`: Resolves the positioning anchor; defaults to the `Anchor` node, then the `Trigger` node.
- **Returns**: The component set, composed as `Popover.Trigger`-style members.

### Components

| Component | Renders |
|---|---|
| `Trigger` | `button` owning the click toggle, `data-state`, `aria-expanded`, `aria-haspopup`, and `aria-controls` |
| `Anchor` | Bare `span` marking the positioning target when the trigger should not anchor |
| `Content` | `role="dialog"` panel portaled into `document.body`, carrying `data-state`, `data-side`, and `data-align` |
| `Header` | Grouping `div` carrying `data-slot="popover-header"` |
| `Title` | Heading `div` carrying `data-slot="popover-title"` |
| `Description` | Supporting `p` carrying `data-slot="popover-description"` |

Every component spreads `class` and native attributes onto its element; components own structure, styling stays in the wrapper.

### Content props

| Prop | Type | Default |
|---|---|---|
| `side` | `"top" \| "bottom" \| "left" \| "right"` | `"bottom"` |
| `align` | `"start" \| "center" \| "end"` | `"center"` |
| `sideOffset` | `number` | `4` |
| `alignOffset` | `number` | `0` |
| `anchor` | `() => Element \| undefined` | The factory's anchor resolution |
| `onExited` | `() => void` | `-` |
| `id` | `string` | The generated content id |

## Key Concepts

### Controlled or Internal State

Pass `open` and the factory never holds state: the getter is the single source of truth and `onOpenChange` reports every requested flip. Omit `open` and the factory keeps its own signal; `onOpenChange` still reports, so either shape composes with the registry's `value`/`onValueChange` contract.

### The Exit Machine

Flipping to closed starts the exit: the content stays mounted under `data-state="closed"` until its `animationend` (or a 250ms budget when no animation runs) unmounts it. Flipping back to open mid-exit cancels the unmount and re-arms in place. Call the factory in component scope so the machine's effect disposes with the component.

### Anchoring and Dismissal

While open, the content is positioned against the anchor through [`anchorPosition`](/headless/anchorposition) (fixed coordinates, collision flipping, repositioning on scroll and resize) and dismissed through [`layerDismissal`](/headless/layerdismissal): Escape and an outside pointerdown close only the top layer, so stacked popovers dismiss one at a time. Focus moves to the content on open; there is no focus trap.

## Important Considerations

### Call the Factory in Component Scope

`popover()` starts a state machine whose effect must dispose with the component that owns it. Module-level calls with an internal signal leak that effect; module-level calls are safe only with a controlled `open` getter, where the machine never subscribes to factory state.

### Controlled Getters Notify One Direction

`onOpenChange` reports transitions the factory drives (toggle, dismissal). Changing a controlled `open` signal directly is the controller's own move and notifies no one.
