Creates a desktop-style menu bar: the `Bar` root plus a `menu()` factory whose menus announce to the bar, so opening one closes its siblings and the horizontal arrows hand off between triggers.

## API

```typescript
function menubar(options?: MenubarOptions): MenubarComponents
```

- `options.value`: Controlled id of the open menu (`""` when closed). When given, the bar never writes its internal signal and `onValueChange` reports every flip.
- `options.onValueChange`: Called whenever the open menu changes.
- **Returns**: `Bar` and `menu`.

### Bar

| Prop | Type | Default |
|---|---|---|
| `value` | `() => string` | The bar's internal id signal |
| `onValueChange` | `(value: string) => void` | `-` |

`Bar` renders `role="menubar"`. With no menu open, the horizontal arrows rove focus across its triggers with wrap-around.

### menu()

```typescript
function menu(options?: MenubarMenuOptions): MenuComponents
```

- `options.value`: This menu's id in the bar's open-menu value; a generated id stands in when omitted.
- `options.open`, `options.onOpenChange`: The same controlled-or-internal open state as [`menu`](/headless/menu).
- **Returns**: The stateful menu pair (`Trigger`, `Content`); the rows come from the static `MenuRows`, and nested submenus from [`menuSub`](/headless/menu).

## Key Concepts

### Bar Coordination

Every bar menu announces its flips through the shared coordination events. A sibling's announcement closes the menu without re-announcing, and the bar mirrors the announcements into its value, so one-open-at-a-time holds across any number of `Bar.menu()` calls.

### Open-then-Move

Inside an open bar menu, both horizontal arrows hand off to the adjacent trigger in the same bar: focus moves, the neighbor opens, and the announcement closes the first menu. The direction flips with the resolved writing direction.

### Bar Menu Content Defaults

A bar menu's content drops below its trigger with a wider gap (`sideOffset` 8, `alignOffset` -4) and the same stateful pair as [`menu`](/headless/menu), with `menuSub()` for nested submenus.

## Important Considerations

### Call the Factories in Component Scope

`menubar()` and each `Bar.menu()` call start effects that must dispose with the component that owns them. Create the bar and its menus in the component that renders the `Bar`, and keep the `Trigger` and `Content` components inside the same mounted tree.

### The Value Is an Id, Not a Selection

The bar's value mirrors which menu is open (`""` when none). It is a coordination channel, not a data selection; the menu items keep their own state.
