# calendar

Creates the calendar parts in one call: the month view, its selection model, and the day grid. The closure owns the visible month, the selection in the mode's shape, the roving focus key, and the range hover preview; `Grid` renders the whole `role="grid"` table from that view model and carries the keyboard model.

## Basic Usage

```tsx
import { signal } from "@hellajs/core";
import { mount } from "@hellajs/dom";
import { calendar } from "@hellajs/headless";

const picked = signal<Date | undefined>(undefined);

const Cal = calendar({
  defaultMonth: new Date(2025, 2, 1),
  onValueChange: (next) => picked(next as Date),
});

mount(
  <Cal.Root>
    <Cal.Months>
      <Cal.Month>
        <Cal.Caption>
          <Cal.CaptionLabel />
        </Cal.Caption>
        <Cal.Nav>
          <Cal.PrevButton>{"<"}</Cal.PrevButton>
          <Cal.NextButton>{">"}</Cal.NextButton>
        </Cal.Nav>
        <Cal.Grid />
      </Cal.Month>
    </Cal.Months>
  </Cal.Root>,
  "#app",
);
// Clicking a day reports it through onValueChange; the nav buttons page
// the month, and the grid roves focus with the arrow keys.
```

## API

```typescript
function calendar(options?: CalendarOptions): CalendarParts
```

- `options.mode`: Selection behavior; defaults to `"single"`.
- `options.value`: The selection in the mode's shape: a static value seeds the internal signal; an accessor makes it controlled, so writes report through `onValueChange` only.
- `options.onValueChange`: Called with every accepted selection (defensive copies, in the mode's shape).
- `options.month`: Controlled visible-month accessor; when provided it snaps the view back on every change, winning over internal navigation.
- `options.onMonthChange`: Called with the new anchor after every month navigation: the buttons and spill-causing keys alike.
- `options.defaultMonth`: Initial visible month; defaults to the current month.
- `options.disabled`: Predicate blocking selection and keyboard activation; outside days are always disabled.
- `options.showOutsideDays`: Renders leading/trailing adjacent-month days; defaults to `true`.
- `options.fixedWeeks`: Always renders six week rows so month-to-month navigation never resizes the grid.
- `options.weekStartsOn`: First day of the week; `0` = Sunday (default) through `6` = Saturday.
- **Returns**: The part set, composed as `Cal.Root`-style members.

### Parts

| Part | Renders |
|---|---|
| `Root` | The calendar root container |
| `Months` | The months wrapper around every rendered month column |
| `Month` | One month column: composes the caption, the nav, and the grid |
| `Caption` | The caption row wrapping the live month label |
| `CaptionLabel` | The `aria-live` label rendering the visible month's `"March 2025"` text |
| `Nav` | The navigation bar wrapping the previous/next buttons |
| `PrevButton` / `NextButton` | Buttons that page the month one step, with the `aria-label`s; children replace the icon slot |
| `Grid` | The `role="grid"` table rendered from the view model (weekday header, week rows, day cells with their aria semantics) with the keyboard model wired on it |
| `DayButton` | The manual-composition day button carrying the aria semantics; the grid renders one per cell |

Every part spreads `class` and native attributes onto its element; parts own structure, styling stays in the wrapper. `Grid` additionally takes the inner class hooks (`weekdaysClass`, `weekdayClass`, `weekClass`, `dayClass`, `dayButtonClass`) for the slots it renders.

### Options

| Option | Type | Default |
|---|---|---|
| `mode` | `"single" \| "multiple" \| "range"` | `"single"` |
| `value` | `CalendarSelection \| (() => CalendarSelection)` | internal signal |
| `onValueChange` | `(value: CalendarSelection) => void` | `-` |
| `month` | `() => Date` | internal signal |
| `onMonthChange` | `(anchor: Date) => void` | `-` |
| `defaultMonth` | `Date` | the current month |
| `disabled` | `(date: Date) => boolean` | `-` |
| `showOutsideDays` | `boolean` | `true` |
| `fixedWeeks` | `boolean` | `-` |
| `weekStartsOn` | `0 \| 1 \| 2 \| 3 \| 4 \| 5 \| 6` | `0` |

## Key Concepts

### The View Model Drives the Grid

The closure derives the month grid on every view change: 31/30/28/29-day months, week-start offsets, and adjacent-month spillover. Outside days render disabled by default (`showOutsideDays: false` hides them), and `fixedWeeks` pins the grid at six rows. The caption label and the grid's `aria-label` track the visible month live.

### Selection Follows the Mode

`mode` picks the selection shape, and `onValueChange` mirrors it exactly: `"single"` reports a `Date`, `"multiple"` reports a `Date[]` in insertion order, and `"range"` reports `{ from, to }`. The first click sets `from`, a second click sets `to` (reordering automatically when it lands before `from`), and a third click starts a new span. While `from` dangles, hovering a day previews the span through the range data attributes.

### Focus and Keyboard

Exactly one day button is a tab stop at a time: the roving focus lands on today when the visible month shows it, else the first day of the month. The arrow keys move focus day to day and across month edges (changing the visible month on a spill), PageUp/PageDown jump a month, Home/End jump the week bounds, and Enter/Space select the focused day.

### Controlled-or-Internal Channels

Selection and the visible month are each controlled-or-internal: pass an accessor (`value` / `month`) and the factory never writes its internal signal; writes report through `onValueChange` / `onMonthChange`, and the accessor's own changes drive the state. Omit the accessor and a static `value` (or none) seeds the internal signal.

## Important Considerations

### Call the Factory in Component Scope

`calendar()` creates the state signals and effects that must dispose with the component that owns them; a module-level factory call leaks them. Call the factory inside the component that renders the parts.

### DayButton for Manual Composition

`DayButton` is the manual-composition day part: its state flags (`selectedSingle`, `rangeStart`/`rangeEnd`/`rangeMiddle`, `disabled`, `focused`) take plain booleans or reactive accessors, so a composed calendar drives them live while a standalone call passes static values. The grid renders its own day buttons from the view model; `DayButton` is for compositions that render cells outside `Grid`.
