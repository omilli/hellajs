# Styling

HellaJS styles apps with CSS-in-JS. You write JavaScript objects; the library registers them as real CSS rules.

Five tools cover the ground:

- [`vars`](/reference/css/vars): theme tokens as CSS variables, reactive through signals.
- [`style`](/reference/css/style): one component's look. Returns a class name.
- [`css`](/reference/css/css): global rules: resets, element defaults and more.
- [`cva`](/reference/css/cva): variant props resolved to class strings.
- [`keyframes`](/reference/css/keyframes): animations.

Every creator returns the same value on client and server. [`cssText`](/reference/css/csstext) collects the registered rules for the server's `<style>` tag.

## Scoped Styles

Reach for [`style`](/reference/css/style) first. It takes CSS declarations and returns a class name.

```jsx
import { style } from '@hellajs/css';

const card = style('card', {
  padding: '1rem',
  borderRadius: '0.5rem',
  backgroundColor: '#f8f9fa',
  'h2': {
    margin: '0 0 0.5rem 0',
  },
  '&:hover': {
    backgroundColor: '#e9ecef',
  },
});

const Card = ({ title }: { title: string }) => (
  <div class={card}>
    <h2>{title}</h2>
  </div>
);
```

The *optional* string `'card'` is a label. It keeps the class readable in DevTools: `card-{hash}`.

The hash is computed from the object's contents. The same object always produces the same class on the server and client. Two components writing the same style share one rule.

Nested keys scope under the class. `&` refers to the class itself (`&:hover` is the hover state).

Plain keys become descendants (`h2` compiles to `.card-{hash} h2`).

`@media`, `@container`, and `@supports` blocks all inherit the class.

Values follow plain rules:

- Numbers mean pixels
- Strings pass through verbatim
- Arrays join with commas
- `null` and `undefined` drop.

## Merging Style Objects

Reach for a merge when two styles are variants of one design and you want a single class that carries both. Pass an object as the first argument and an override as the second: the result is one class, and nested selector blocks merge key by key with the override winning.

```jsx
import { style } from '@hellajs/css';

// Authored once, never registered on its own: every consumer merges it
const fieldBase = {
  padding: '0.75rem',
  borderRadius: '0.5rem',
  border: '1px solid #d1d5db',
  '&:focus': {
    borderColor: '#3b82f6',
  },
};

// The red border wins; the focus block merges instead of replacing
const errorField = style(fieldBase, {
  borderColor: '#dc2626',
}, {
  label: 'field-error',
});

const successField = style(fieldBase, {
  borderColor: '#16a34a',
}, {
  label: 'field-success',
});
```

The override wins on flat keys, and a nested block such as `'&:focus'` merges with the base's block rather than replacing it. Arrays and scalars replace. A merge takes its label through the options bag, not a leading string.

Keep the base a plain object and register only the merged results. Each merged class is a complete rule: if the base is also registered on its own, its declarations are emitted twice, once under the base class and once inside every merge. When the two styles are independent concerns instead of variants of one design, join the class strings with [`cx`](/reference/css/cx) as shown next.

## Joining Classes with cx

Reach for [`cx`](/reference/css/cx) when the classes come from different places and should stay separate rules: a layout class plus a theme class, a hashed class plus an external utility, or a class plus a conditional one. It joins its arguments into one string and registers nothing.

```jsx
import { cx, style } from '@hellajs/css';

const card = style('card', {
  padding: '1rem',
  borderRadius: '0.5rem',
});

const alert = style('alert', {
  border: '1px solid #dc2626',
});

const isPinned = true;

// Two classes, two rules; cx joins the strings
const alertCard = cx(card, alert, isPinned && 'pinned');
// "card-… alert-… pinned"
```

Falsy arguments drop, so a conditional class is just `condition && 'name'`. Objects join the keys whose values are truthy, which reads well for state-driven classes:

```jsx
import { cx } from '@hellajs/css';

const isComplete = true;
const isEditing = false;

const itemClass = cx('todo', {
  done: isComplete,
  editing: isEditing,
});
// "todo done"
```

Class strings from any source compose here: [`style`](/reference/css/style) classes, [`cva`](/reference/css/cva) output, and classes from other frameworks. When the fragments depend on signals, bind them at the attribute instead so the class re-derives; the dom package covers the array and function forms in [templates](/learn/concepts/templates).

## Reusing a Class as a Recipe Base

A [`cva`](/reference/css/cva) recipe's `base` can be a class string instead of a style object. The string passes through verbatim, so the recipe output already carries your class and no second base rule is generated. Reach for this when one shared look should pair with several variant sets.

```jsx
import { cva, style } from '@hellajs/css';

// One shared look, registered once
const field = style('field', {
  padding: '0.5rem',
  borderRadius: '0.25rem',
  border: '1px solid #d1d5db',
});

// Variants add to it; the base slot passes the class through
const input = cva({
  base: field,
  variants: {
    state: {
      invalid: {
        borderColor: '#dc2626',
      },
    },
  },
});

<input class={input({
  state: 'invalid',
})} />
// "field-… state-invalid-…"
```

String values in variant and compound slots pass through the same way, which is how external classes such as utility-framework names join a recipe. See the [cva reference](/reference/css/cva) for the full rules.

## Combining Variants with compoundVariants

Reach for `compoundVariants` when one style should apply only when several variants are selected together and no single variant owns it: a large danger button gets a heavier border, but neither `size` alone nor `tone` alone should.

```jsx
import { cva } from '@hellajs/css';

const button = cva({
  base: {
    cursor: 'pointer',
  },
  variants: {
    size: {
      sm: {
        padding: '0.25rem 0.5rem',
      },
      lg: {
        padding: '0.75rem 1.5rem',
      },
    },
    tone: {
      primary: {
        background: '#3b82f6',
      },
      danger: {
        background: '#dc2626',
      },
    },
  },
  compoundVariants: [
    {
      size: 'lg',
      tone: 'danger',
      css: {
        borderWidth: 2,
      },
    },
  ],
});

<button class={button({
  size: 'lg',
  tone: 'danger',
})}>
  Delete
</button>
// "base-… size-lg-… tone-danger-… size-lg-tone-danger-…"
```

The compound contributes its own class only when every stated variant matches, so the pairing gets its own rule instead of being copied into each variant. Each piece stays an independent class on the element, which is what lets the selection change at the attribute without rebuilding a rule.

## Global Styles

[`css`](/reference/css/css) covers what belongs to no component: element defaults, `@font-face`, page-wide rules. Top-level keys are raw selectors; the call registers the rules and returns an empty string.

```jsx
import { css, reset } from '@hellajs/css';

// The shipped preflight: margins, borders, typography, form controls
// normalized to a clean baseline
css(reset);

css({
  body: {
    margin: 0,
    fontFamily: 'system-ui, sans-serif',
  },
  '@font-face': {
    fontFamily: '"Inter"',
    src: 'url("/fonts/inter.woff2") format("woff2")',
  },
});
```

Declarations must sit under a selector; a bare top-level declaration throws. Every `@` rule works as a key: conditional ones (`@media`, `@container`, `@supports`) keep the scope they are nested in, definitional ones (`@keyframes`, `@font-face`, `@layer`) stay global. Full nesting and value rules live in the [css reference](/reference/css/css).

## Variant Recipes

Components with visual variants (size, tone, state) get a [`cva`](/reference/css/cva) recipe. Call it with props, get a class string.

```jsx
import { cva } from '@hellajs/css';

const button = cva({
  base: {
    borderRadius: '0.5rem',
    cursor: 'pointer',
  },
  variants: {
    size: {
      sm: {
        padding: '0.25rem 0.5rem',
      },
      lg: {
        padding: '0.75rem 1.5rem',
      },
    },
    tone: {
      primary: {
        background: '#3b82f6',
      },
      danger: {
        background: '#dc2626',
      },
    },
  },
  defaultVariants: {
    size: 'sm',
  },
});

<button class={button({
  tone: 'danger',
  size: 'lg',
})}>
  Delete
</button>
```

Each selection resolves to its own hashed class, so variants stack on the element instead of competing in one rule. Selections you never make never generate CSS, and omitted props fall back to `defaultVariants`.

When the selection depends on state, call the recipe at the attribute; the class re-derives when the signal changes.

```jsx
import { signal } from '@hellajs/core';
import { cva } from '@hellajs/css';

const size = signal<'sm' | 'lg'>('lg');

const toggle = cva({
  base: {
    cursor: 'pointer',
  },
  variants: {
    size: {
      sm: {
        padding: '0.25rem',
      },
      lg: {
        padding: '0.75rem',
      },
    },
  },
});

<button class={toggle({
  size: size(),
})}>
  Sized by state
</button>
```

Recipes also take a `media` map for responsive selections and `compoundVariants` for combinations. See the [cva reference](/reference/css/cva).

## Reactive Theming

[`vars`](/reference/css/vars) turns an object of tokens into CSS custom properties. It returns a same-shaped proxy of `var()` references; put them in any style.

```jsx
import { signal } from '@hellajs/core';
import { style, vars } from '@hellajs/css';

const theme = signal('light');

// A plain function is enough: leaves track whatever signals they read
const isDark = () => theme() === 'dark';

const tokens = vars({
  bg: () => isDark() ? '#1a1a1a' : '#ffffff',
  text: () => isDark() ? '#e5e7eb' : '#111827',
});

const panel = style('panel', {
  background: tokens.bg,
  color: tokens.text,
  padding: '1rem',
  borderRadius: '0.5rem',
});

<button class={panel} on:click={() => theme(isDark() ? 'light' : 'dark')}>
  Toggle theme
</button>
```

Static leaves are plain values. Function leaves re-resolve when their signals change: one custom property updates, no rule is rebuilt. This is the only reactive path, and function values inside `style` and `css` objects throw.

Themes can also ride the cascade with no JavaScript state: register two sets and let CSS pick the winner.

```jsx
import { vars } from '@hellajs/css';

// Light values by default
vars({
  bg: '#ffffff',
  text: '#111827',
});

// Dark values when the OS prefers dark; no signals, no effects
vars({
  bg: '#1a1a1a',
  text: '#e5e7eb',
}, {
  media: '(prefers-color-scheme: dark)',
});
```

Scopes (`scoped: '[data-theme="dark"]'`) and prefixes (`prefix: 'app'`) are options on the call. See the [vars reference](/reference/css/vars).

## Keyframe Animations

[`keyframes`](/reference/css/keyframes) registers a `@keyframes` rule and returns its name. The name is derived from the definition's content: two animations never collide, and the same definition reuses one rule.

```jsx
import { keyframes, style } from '@hellajs/css';

const spin = keyframes({
  from: {
    transform: 'rotate(0deg)',
  },
  to: {
    transform: 'rotate(360deg)',
  },
});

const spinner = style('spinner', {
  width: '2rem',
  height: '2rem',
  border: '3px solid #e5e7eb',
  borderTopColor: '#3b82f6',
  borderRadius: '50%',
  animation: `${spin} 0.8s linear infinite`,
});
```

The name is a plain string; interpolate it into `animation` shorthands anywhere, including `css` globals and `cva` recipes.

## Server Rendering

On the server there is no DOM to inject into. Creators still register their rules; [`cssText`](/reference/css/csstext) collects the text for the response.

```typescript
import { css, cssText, style, vars } from '@hellajs/css';

const tokens = vars({
  bg: '#ffffff',
});

css({
  body: {
    margin: 0,
    backgroundColor: tokens.bg,
  },
});

const card = style('card', {
  padding: '1rem',
});

// In the response handler; one embed per response
const page = `<!DOCTYPE html><html><head><style id="hella-css">${cssText()}</style></head><body>…</body></html>`;
```

Emit the tag with the `hella-css` id and hydration adopts the delivered rules, so no duplicates ship. `cssText()` peeks, never drains: repeated calls return the same string. To mirror the client's element split, `cssText.css()` / `cssText.vars()` embed rules and variables into their own tags.

## Reactive Class Bindings

The `class` attribute also accepts a function or an array. Both re-resolve when signals change, and falsy entries drop.

```jsx
type Todo = { done: boolean; text: string; priority: string };
type TodoItemProps = {
  todo: () => Todo;
};

const TodoItem = ({ todo }: TodoItemProps) => (
  <div class={[
    'todo-item',
    todo().done && 'completed',
    todo().priority === 'high' && 'priority-high',
  ]}>
    {todo().text}
  </div>
);
```

## Web Components and Shadow DOM

The `host` option on `style`, `css`, and `vars` redirects the generated `<style>` element into any parent node, most commonly a shadow root you create:

```typescript
import { style, vars } from '@hellajs/css';

const hostElement = document.createElement('my-card');
const root = hostElement.attachShadow({
  mode: 'open',
});

// Shadow roots don't match :root; scope vars to the host element
const theme = vars({
  accent: '#3b82f6',
}, {
  host: root,
  scoped: ':host',
});

const title = style('title', {
  color: theme.accent,
}, {
  host: root,
});

hostElement.innerHTML = `<h2 class="${title}">Hello</h2>`;
```

Sheets are per host, so component instances never share. Hosted styles never reach `document.head`, and the removers ([`removeStyle`](/reference/css/removestyle), [`removeCss`](/reference/css/removecss), [`removeVars`](/reference/css/removevars)) need the same `host` option.

Custom elements the HellaJS way are [`element`](/reference/dom/element) from the dom package. Light DOM is the default, so every `style()` and `vars()` registration applies with no `host` needed:

```jsx
import { element } from '@hellajs/dom';
import { style } from '@hellajs/css';

const card = style('card', {
  padding: '1rem',
  borderRadius: '0.5rem',
});

element('info-card', (props: { children?: Node[] }) => (
  <div class={card}>{props.children}</div>
));
```

Pass `{ shadow: true }` to `element()` for encapsulation. Its render function receives props only, not the root, so pair `host` styling with a root you created yourself, as above. See [Custom Elements](/learn/concepts/custom-elements) for the element flow.
