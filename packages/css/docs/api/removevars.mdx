# removeVars

Removes CSS custom properties by decrementing the reference count. Variables are removed from the stylesheet only when the reference count reaches zero.

## API

```typescript
function removeVars<T extends CSSVarInputObject>(vars: T, options?: VarsOptions): void
```
- `vars`: Object containing CSS variable definitions. For reactive vars, must be the same reference passed to `vars`; for static vars, a structurally equal object matches by hash
- `options`: Optional configuration. Reactive entries are matched by vars reference and use the options recorded at the first `vars` call; `options` is consulted only to locate the static entry by hash
- **Returns**: `void`

## Basic Usage

```jsx
import { vars, removeVars } from '@hellajs/css';

const varsObj = vars({
  colors: { primary: 'red', secondary: 'blue' }
});

// Later, remove when no longer needed
removeVars({
  colors: { primary: 'red', secondary: 'blue' }
});
```

## Key Concepts

### Reference Counting

`removeVars` mirrors the reference counting model of [`removeCss`](/reference/css/removecss). Each [`vars`](/reference/css/vars) call increments the reference count. `removeVars` decrements it. The variables persist until all references are removed:

```jsx
import { vars, removeVars } from '@hellajs/css';

const varsObj = { theme: { color: 'red' } };

vars(varsObj);  // refCount = 1
vars(varsObj);  // refCount = 2, same scope, same vars

removeVars(varsObj);  // refCount = 1, vars still present
removeVars(varsObj);  // refCount = 0, vars removed from stylesheet
```

### Static vs Reactive Removal

For **static** vars (no signals or functions), `removeVars` uses a deterministic hash computed from the object and options. Structurally identical objects match regardless of reference identity:

```jsx
// Static objects match by structure
vars({ color: 'red' });
removeVars({ color: 'red' }); // Same hash — matches
```

For **reactive** vars (with signals or functions), `removeVars` uses the exact object reference passed to `vars`. Hold onto the original object reference:

```jsx
import { signal } from '@hellajs/core';
import { vars, removeVars } from '@hellajs/css';

const color = signal('red');
const varsObj = { primary: color };

vars(varsObj);
// Must pass the same reference to remove
removeVars(varsObj);
```

When a reactive set is removed, its effect is disposed — subsequent signal updates no longer mutate the stylesheet:

```jsx
const color = signal('red');
const varsObj = { primary: color };

vars(varsObj);
removeVars(varsObj); // Effect is now disposed

color('blue');
// Stylesheet unaffected — effect was cleaned up
```

### Shared Scopes

Multiple `vars` calls to the same scope merge their variables. `removeVars` only removes the keys from the matching call — other calls' contributions remain:

```jsx
vars({ theme: { primary: 'red' } });
vars({ spacing: { small: '8px' } });

removeVars({ theme: { primary: 'red' } });
// --spacing-small: 8px remains
```

## Important Considerations

### Unknown Input

`removeVars` is a no-op for inputs not previously registered by a `vars` call — no throw, no stylesheet change.

### Exact Options Match (Static Path)

For **static** vars, the `options` argument must match the `options` used in the original `vars` call, including `scoped`, `prefix`, and `host` — they feed the hash that locates the entry:

```jsx
vars({ color: 'red' }, { scoped: '.card', prefix: 'ui' });
removeVars({ color: 'red' }, { scoped: '.card', prefix: 'ui' }); // ✅ matches
removeVars({ color: 'red' }); // ❌ different hash — no-op
```

### Interaction with resetVars

[`resetVars`](/reference/css/resetvars) remains the nuclear option — it clears all variables, caches, reactive effects, and per-call registries in one go. `removeVars` is the granular alternative for per-call cleanup.
