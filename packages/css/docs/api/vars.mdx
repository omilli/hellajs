# vars

Creates CSS custom properties (variables) from JavaScript objects with automatic reactivity support.

## API

```typescript
function vars<T extends CSSVarInputObject>(vars: T, options?: VarsOptions): CSSVars<T>
```
- `vars`: Object containing CSS variable definitions. Can include nested objects and reactive signals.
- `options`: Optional configuration for scoping, prefixing, and media conditions
- **Returns**: A same-shaped proxy of `var()` references, on BOTH platforms — on the client the declarations are injected into the CSSOM; on the server the registration is state-only (collect it with [`cssText`](/reference/css/csstext)).

### Options

```typescript
interface VarsOptions {
  scoped?: string;   // CSS selector to scope variables to
  prefix?: string;   // Prefix for all CSS variable names
  media?: string;    // Media condition the variables live under
  host?: ParentNode; // Node the <style> element is created in
}
```

- **`scoped`**: CSS selector to limit variable scope (e.g., `.theme-container`, `#app`, `[data-theme]`)
- **`prefix`**: Prefix added to all CSS variable names for namespace organization
- **`media`**: Media condition wrapping the declarations, e.g. `(prefers-color-scheme: dark)` — interpolated verbatim into `@media (…)`
- **`host`**: Parent node the `<style>` element is created in — e.g. a `ShadowRoot`. Defaults to `document.head`. Shadow roots don't match `:root`, so pair `host` with `scoped: ':host'` to apply variables to the host element

### Types

```typescript
type CSSVarLeaf = string | number | ((...args: never[]) => string | number);

interface CSSVarInputObject {
  [key: string]: CSSVarLeaf | CSSVarInputObject;
}

type CSSVars<T> = {
  [K in keyof T]: T[K] extends CSSVarInputObject ? CSSVars<T[K]> : string;
};
```

- **`CSSVarLeaf`**: Accepted leaf value types — `string`, `number`, or a function returning `string | number` (signals, computed, plain getters)
- **`CSSVarInputObject`**: Plain object whose values are `CSSVarLeaf` or nested `CSSVarInputObject` — used as the input constraint
- **`CSSVars<T>`**: Mapped type transforming an input object into a proxy with `var()` reference strings at every leaf

## Basic Usage

```jsx
import { vars } from '@hellajs/css';

const theme = vars({
  colors: {
    primary: '#3b82f6',
    secondary: '#64748b'
  },
  spacing: {
    small: '0.5rem',
    medium: '1rem',
    large: '2rem'
  }
});

// theme.colors.primary = 'var(--colors-primary)'
// theme.colors.secondary = 'var(--colors-secondary)'
// theme.spacing.small = 'var(--spacing-small)'
```

## Key Concepts

### Using Variables in CSS

```jsx
import { style, vars } from '@hellajs/css';

const theme = vars({
  colors: {
    primary: '#3b82f6',
    background: '#ffffff'
  }
});

const buttonStyle = style({
  backgroundColor: theme.colors.primary,
  color: theme.colors.background,
  padding: '0.75rem 1.5rem',
  border: 'none',
  borderRadius: '0.5rem'
}, { label: 'btn' });
```

### Reactive CSS Variables

CSS variables automatically update when signals change. Multiple signal updates inside `batch()` flush together — the sheet updates once when the batch completes:

```jsx
import { signal } from '@hellajs/core';
import { vars, css } from '@hellajs/css';

const ThemeExample = () => {
  const isDark = signal(false);
  const primaryColor = signal('#3b82f6');

  // Reactive CSS variables - automatically update when signals change
  const theme = vars({
    colors: {
      primary: primaryColor,                                    // Direct signal
      background: () => isDark() ? '#1a1a1a' : '#ffffff',     // Computed value
      text: () => isDark() ? '#ffffff' : '#000000'
    }
  });

  const buttonStyle = css({
    backgroundColor: theme.colors.primary,
    color: theme.colors.text,
    padding: '0.75rem 1.5rem',
    border: 'none',
    borderRadius: '0.5rem'
  });

  return (
    <div>
      <button
        class={buttonStyle}
        on:click={() => isDark(!isDark())}
      >
        Toggle Theme
      </button>
      <button on:click={() => primaryColor('#059669')}>
        Change Color
      </button>
    </div>
  );
};
```

### Mixed Static and Reactive Variables

```jsx
import { signal } from '@hellajs/core';

const primaryColor = signal('#3b82f6');
const accentColor = () => '#64748b';

const mixedTheme = vars({
  // Static values (no reactivity)
  fonts: {
    body: 'system-ui, sans-serif',
    mono: 'Menlo, monospace'
  },

  // Reactive values (with signals)
  colors: {
    primary: primaryColor,                 // Direct signal
    accent: () => accentColor(),           // Computed function
    surface: '#ffffff'                     // Static value
  }
});
```

### Performance Features

CSS variables automatically optimize performance through:

- **Static Detection**: Non-reactive objects use fast static path
- **Reactive Tracking**: Only creates effects when functions are detected
- **Smart Caching**: Identical static objects are cached and reused (evicts at 100 entries to prevent unbounded growth)
- **Memory Management**: Effects are automatically cleaned up

### Identical on Both Platforms

On the client, [`vars`](/reference/css/vars) injects custom properties into the CSSOM and returns the `var()` proxy. On the server (no DOM), it returns the **same** proxy and registers the declarations state-only — function leaves resolve once to their initial values, no effects are created, and [`cssText()`](/reference/css/csstext) carries the rule text for the server's `<style>` tag:

```typescript
import { signal } from '@hellajs/core';
import { vars, cssText } from '@hellajs/css';

const color = signal('red');

// Client: { theme: { color: 'var(--theme-color)' } }, injects :root{--theme-color:red}
// Server: { theme: { color: 'var(--theme-color)' } }, cssText() === ':root{--theme-color:red}'
const theme = vars({ theme: { color } });
```

### Variable Accumulation

Multiple `vars()` calls to the same scope merge variables rather than overwrite:

```jsx
import { vars } from '@hellajs/css';

// First call sets colors
vars({
  colors: {
    primary: '#3b82f6',
    secondary: '#64748b'
  }
});

// Second call adds spacing — colors are preserved
vars({
  spacing: {
    small: '0.5rem',
    large: '2rem'
  }
});

// Both color and spacing variables are available
```

### Reactive Vars Are Keyed by Reference

A **reactive** vars object (one with any function leaf) is registered by object **reference**, not by value. A second `vars()` call passing the *same* reference returns the same result proxy and bumps its reference count. Passing the same reference a second time with *different* `scoped`/`prefix`/`media` options throws — use a distinct object per scope so each gets its own reactive effect:

```jsx
import { signal } from '@hellajs/core';
import { vars } from '@hellajs/css';

const isDark = signal(false);
const theme = { bg: () => (isDark() ? '#000' : '#fff') };

vars(theme);                             // ok — :root, reactive
vars(theme);                             // ok — same options, refCount++
vars(theme, { scoped: '.dark' });        // throws — same ref, different scope
vars({ ...theme }, { scoped: '.dark' }); // ok — separate reference, own effect
```

Static vars (no function leaves) are instead keyed by a hash of the object and its options, so structurally equal static objects collide regardless of reference identity.

### Scoping and Prefixing

Control where CSS variables are applied and how they're named:

```jsx
import { vars } from '@hellajs/css';

// Scoped to a specific selector — variables only apply within .theme-container
const themeVars = vars({
  primary: '#3b82f6',
  secondary: '#64748b'
}, { scoped: '.theme-container' });

// themeVars.primary = 'var(--primary)'
// Generated: .theme-container{--primary:#3b82f6;--secondary:#64748b}
```

```jsx
import { vars } from '@hellajs/css';

// Prefix adds a namespace to all variable names
const appVars = vars({
  fontFamily: 'system-ui, sans-serif',
  borderRadius: '0.25rem'
}, { prefix: 'app' });

// appVars.fontFamily = 'var(--app-fontFamily)'
// appVars.borderRadius = 'var(--app-borderRadius)'

// Combine both: scoped + prefixed
const themed = vars({
  primary: '#3b82f6',
  spacing: { small: '0.5rem', medium: '1rem' }
}, { scoped: '.theme-container', prefix: 'my-theme' });

// themed.primary = 'var(--my-theme-primary)'
// themed.spacing.small = 'var(--my-theme-spacing-small)'
// Only available within .theme-container
```

### Shadow DOM Hosts

`host` redirects the variables into a shadow root. The default `:root` scope doesn't match inside one — `scoped: ':host'` targets the host element itself:

```typescript
import { vars } from '@hellajs/css';

const hostElement = document.createElement('my-card');
const root = hostElement.attachShadow({ mode: 'open' });

const theme = vars(
  { accent: '#3b82f6' },
  { host: root, scoped: ':host' }
);

// Generated inside the shadow root: :host{--accent:#3b82f6}
```

Sheets are per host: the same vars injected into two hosts create independent rules with separate reference counting, and [`removeVars`](/reference/css/removevars) with the same `host` removes from that host's bucket. See [Shadow DOM Hosts](/reference/css/css#shadow-dom-hosts) for the full web-components example.

### Media-Scoped Variables

The `media` option places the declarations under a `@media` at-rule — variables that follow the environment instead of JavaScript state. The canonical case is system-driven dark mode with [`prefers-color-scheme`](https://developer.mozilla.org/en-US/docs/Web/CSS/@media/prefers-color-scheme): declare light values unscoped, dark values under the media condition, and the OS setting picks the winner with zero reactivity:

```jsx
import { vars } from '@hellajs/css';

// Default (light) values
vars({
  colors: {
    background: '#ffffff',
    text: '#111827'
  }
});

// Dark values — applied only when the OS prefers dark
vars(
  { colors: { background: '#1a1a1a', text: '#e5e7eb' } },
  { media: '(prefers-color-scheme: dark)' }
);

// Generated:
// :root{--colors-background:#ffffff;--colors-text:#111827}
// @media (prefers-color-scheme: dark){:root{--colors-background:#1a1a1a;--colors-text:#e5e7eb}}
```

`media` composes with `scoped` and `prefix`, and the same scope under different conditions coexists as separate rules — each `(scope, media)` pair is its own bucket. It interpolates verbatim (no validation), matching `scoped`'s permissive contract. For JS-driven theming (a toggle signal instead of the OS), see [Reactive CSS Variables](#reactive-css-variables) — the two modes combine freely.

### Accepted Value Types

`vars` accepts specific leaf value types at compile time. Invalid types are rejected:

```typescript
type CSSVarLeaf = string | number | ((...args: never[]) => string | number);
```

Accepted leaf values:
- **`string`**: Static text values like `'#ff0000'` or `'1rem'`
- **`number`**: Numeric values like `16` or `0.5`
- **`(...args: never[]) => string | number`**: Functions returning `string | number` — includes signals (`Signal<string>`), computed values, and plain getter functions

❌ **Rejected at compile time:**
- **`boolean`**: `vars({ flag: true })` is rejected
- **`Date`** and other class instances: `vars({ date: new Date() })` is rejected
- Functions returning `boolean` or `object`: `vars({ fn: () => true })` is rejected

✅ **Convert boolean signals explicitly:**
```typescript
const isActive = signal(true);

// ❌ Rejected — function returning boolean
vars({ flag: isActive });

// ✅ Explicit conversion
vars({ flag: () => isActive() ? '1' : '0' });
```

## Important Considerations

### Type Safety

Maintains full TypeScript support with nested object typing:

```tsx
const primary = signal('#3b82f6');

const theme = vars({
  colors: {
    primary: '#3b82f6',      // Valid
    secondary: primary       // Valid (signal)
  },
  spacing: {
    base: '1rem'            // Valid
  }
});

// theme.colors.primary: string (= 'var(--colors-primary)')
// theme.spacing.base: string (= 'var(--spacing-base)')
```

### Boolean and Object Leaves Rejected

**Breaking type-level change from v1.x:** The `vars` parameter type was tightened from `Record<string, unknown>` to `CSSVarInputObject`. Callers passing `boolean`, `Date`, class instances, or functions returning `boolean`/`object` will now get compile-time errors where they compiled before.

- Runtime behavior is unchanged — `vars` calls `String()` on values, so `true` became `"true"` at runtime
- Fix: Convert booleans explicitly with `() => flag() ? '1' : '0'`
- Fix: Replace class instances with plain values before passing to `vars`

### Memory Management

Use [`resetVars`](/reference/css/resetvars) to clean up all CSS variables and reactive effects when needed:

```jsx
import { resetVars } from '@hellajs/css';

// Clean up all CSS variables and reactive effects
resetVars();
```
