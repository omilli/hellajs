# vars

Creates CSS custom properties from an object of tokens and returns a same-shaped proxy of `var()` references. Function leaves (signals, getters) make the declarations reactive: when they change, the custom property updates without rebuilding any rule.

## Basic Usage

```jsx
import { style, vars } from '@hellajs/css';

const tokens = vars({
  color: {
    primary: '#3b82f6',
    surface: '#ffffff',
  },
  radius: '0.5rem',
});

// tokens.color.primary === 'var(--color-primary)'
// tokens.color.surface === 'var(--color-surface)'
// tokens.radius     === 'var(--radius)'

const card = style('card', {
  background: tokens.color.surface,
  color: tokens.color.primary,
  borderRadius: tokens.radius,
  padding: '1rem',
});
```

Nested objects flatten into hyphenated names (`color.primary` registers `--color-primary`); the proxy keeps the authored shape.

## API

```typescript
function vars<T extends CSSVarInputObject>(vars: T, options?: VarsOptions): CSSVars<T>
```
- `vars`: Object of CSS variable definitions. Leaves are strings, numbers, or functions returning a string or number; values can nest
- `options`: Optional configuration
- **Returns**: A same-shaped proxy of `var()` reference strings, on both platforms

```typescript
interface VarsOptions {
  scoped?: string;
  prefix?: string;
  media?: string;
  layer?: string;
  host?: ParentNode;
}
```

- **`scoped`**: CSS selector the declarations sit under (`.theme-container`, `[data-theme]`). Defaults to `:root`
- **`prefix`**: Namespace prepended to every variable name
- **`media`**: Media condition wrapping the declarations, e.g. `(prefers-color-scheme: dark)`, interpolated verbatim
- **`layer`**: Cascade layer name wrapping the declarations, interpolated verbatim. Unlayered author CSS beats layered rules, so consumer overrides win by construction; composes outermost of `media` when both apply
- **`host`**: Node the `<style>` element is created in, e.g. a `ShadowRoot`. Shadow roots don't match `:root`, so pair `host` with `scoped: ':host'`

### Types

```typescript
type CSSVarLeaf = string | number | ((...args: never[]) => string | number);

interface CSSVarInputObject {
  [key: string]: CSSVarLeaf | CSSVarInputObject;
}

type CSSVars<T> = {
  [K in keyof T]: T[K] extends CSSVarInputObject ? CSSVars<T[K]> : string;
};
```

- **`CSSVarLeaf`**: Accepted leaf: a string, a number, or a function returning a string or number (signals, computed values, plain getters)
- **`CSSVarInputObject`**: Input constraint: leaves or nested input objects
- **`CSSVars<T>`**: Output: the input shape with every leaf mapped to its `var()` reference string

## Key Concepts

### Reactive Values

A function leaf re-resolves when its dependencies change and the custom property updates in place. No rule is rebuilt, no component re-renders: every style consuming the `var()` reference follows along.

```jsx
import { signal } from '@hellajs/core';
import { style, vars } from '@hellajs/css';

const isDark = signal(false);

const tokens = vars({
  background: () => isDark() ? '#1a1a1a' : '#ffffff',
  text: () => isDark() ? '#e5e7eb' : '#111827',
  primary: '#3b82f6',  // static leaves mix in freely
});

const panel = style('panel', {
  background: tokens.background,
  color: tokens.text,
  padding: '1rem',
});

<button class={panel} on:click={() => isDark(!isDark())}>
  Toggle theme
</button>
```

Multiple signal updates in one tick drain together; the sheet updates once at the microtask boundary (core's [`flush`](/reference/core/flush) forces it synchronously).

The function wrapper is what makes a leaf reactive: without it, the expression evaluates once at registration and the token freezes at that value, silently. A signal passed bare stays reactive because a signal is itself a function; any composed expression needs the wrapper:

```jsx
import { signal } from '@hellajs/core';
import { vars } from '@hellajs/css';

const theme = signal('light');
const accent = signal('#3b82f6');
const isDark = () => theme() === 'dark';

// ❌ Frozen: the ternary runs once; the leaf is the string '#ffffff'
vars({
  bg: isDark() ? '#1a1a1a' : '#ffffff',
});

// ✅ Reactive: the wrapper defers the expression to each update
vars({
  surface: () => isDark() ? '#1a1a1a' : '#ffffff',
});

// ✅ Also reactive: a signal passed bare is a function
vars({
  accent: accent,
});
```

### Name Conversion

Flat keys convert at emission: dots fold to hyphens, camelCase and letter-digit boundaries insert a hyphen, then the name lowercases. Proxy access keeps the authored key shape.

```jsx
import { cssText, vars } from '@hellajs/css';

const tokens = vars({
  primaryForeground: 'oklch(0.985 0 0)',
  base50: '#f9fafb',
});

// tokens.primaryForeground === 'var(--primary-foreground)'
// tokens.base50 === 'var(--base-50)'
// cssText() collects:
// :root {
//   --primary-foreground: oklch(0.985 0 0);
//   --base-50: #f9fafb;
// }
```

An authored kebab key such as `'primary-foreground'` passes through byte-identically, and `prefix` prepends before the conversion: `vars({ primaryForeground: 'x' }, { prefix: 'hj' })` writes `--hj-primary-foreground`.

### Static and Reactive Registration

Objects with no function leaves are static: they register by a hash of the object and its options, so structurally equal objects share one registration regardless of reference identity. Objects with any function leaf are reactive: they register by object reference, so each object owns exactly one reactive effect.

A reactive object registered a second time with different `scoped`/`prefix`/`media`/`layer`/`host` options throws; use a separate object per scope so each gets its own effect.

```jsx
import { signal } from '@hellajs/core';
import { vars } from '@hellajs/css';

const isDark = signal(false);
const theme = {
  bg: () => isDark() ? '#000' : '#fff',
};

vars(theme);  // ok; :root, reactive
vars(theme);  // ok; same options, reference count bumps

vars(theme, {
  scoped: '.dark',
});  // ❌ throws; same reference, different options

vars({
  ...theme,
}, {
  scoped: '.dark',
});  // ✅ separate object, own effect
```

### Scoping and Prefixing

`scoped` limits where the variables apply; `prefix` namespaces the names. The two combine.

```jsx
import { vars } from '@hellajs/css';

const themeVars = vars({
  primary: '#3b82f6',
  radius: '0.5rem',
}, {
  scoped: '.theme-container',
  prefix: 'app',
});

// themeVars.primary === 'var(--app-primary)'
// themeVars.radius === 'var(--app-radius)'
// Generated:
// .theme-container {
//   --app-primary: #3b82f6;
//   --app-radius: 0.5rem;
// }
```

Values only apply within `.theme-container`; consumers outside it fall back to whatever else defines those names.

### Media-Scoped Variables

The `media` option places the declarations under a media condition: variables that follow the environment instead of JavaScript state. The canonical case is system-driven dark mode with zero reactivity:

```jsx
import { vars } from '@hellajs/css';

// Default (light) values
vars({
  bg: '#ffffff',
  text: '#111827',
});

// Dark values; applied only when the OS prefers dark
vars({
  bg: '#1a1a1a',
  text: '#e5e7eb',
}, {
  media: '(prefers-color-scheme: dark)',
});
```

`media` composes with `scoped` and `prefix`, and the same scope under different conditions coexists as separate rules. For JS-driven theming (a toggle signal), use reactive leaves; the two modes combine freely.

### Shadow DOM Hosts

`host` redirects the declarations into a shadow root. The default `:root` scope does not match inside one; `scoped: ':host'` targets the host element itself.

```typescript
import { vars } from '@hellajs/css';

const hostElement = document.createElement('my-card');
const root = hostElement.attachShadow({
  mode: 'open',
});

const theme = vars({
  accent: '#3b82f6',
}, {
  host: root,
  scoped: ':host',
});

// Generated inside the shadow root:
// :host {
//   --accent: #3b82f6;
// }
```

Sheets are per host, and [`removeVars`](/reference/css/removevars) with the same `host` removes from that host's bucket. See [Shadow DOM Hosts](/reference/css/css#shadow-dom-hosts) for the full web-components example.

### Server Behavior

The proxy and the registration are identical on both platforms. On the server no effects are created: function leaves resolve once to their initial values, and [`cssText`](/reference/css/csstext) carries the declarations for the `<style>` tag. Hydration re-registers reactively from the same object.

```typescript
import { signal } from '@hellajs/core';
import { cssText, vars } from '@hellajs/css';

const color = signal('red');
const theme = vars({
  accent: color,
});

// Client: injects ":root { --accent: red; }" and tracks the signal
// Server: same proxy, same cssText() text, no effect created
```

### Accepted Leaf Values

Leaves are typed at compile time: `string`, `number`, or a function returning `string | number`. Booleans and class instances fail to compile; convert them explicitly.

```typescript
import { signal } from '@hellajs/core';
import { vars } from '@hellajs/css';

const isActive = signal(true);

// ❌ Rejected; a boolean is not a CSS value
// vars({ flag: isActive });

// ✅ Explicit conversion
const flags = vars({
  flag: () => isActive() ? '1' : '0',
});
// flags.flag === 'var(--flag)'
```

Replace class instances (`Date`, ...) with plain values before passing them in: serialize what the CSS needs, keep the object out.

## Important Considerations

### Scopes Accumulate

Multiple `vars()` calls writing the same scope merge rather than overwrite: each call adds its own keys to the bucket. `removeVars` removes only the keys of the call it matches, so other calls' contributions survive.

```jsx
import { removeVars, vars } from '@hellajs/css';

vars({
  color: {
    primary: 'red',
  },
});
vars({
  spacing: {
    small: '0.5rem',
  },
});

removeVars({
  color: {
    primary: 'red',
  },
});
// --spacing-small remains registered
```

### Memory Management

`removeVars` decrements one registration (reactive entries dispose their effect at zero references); [`resetVars`](/reference/css/resetvars) clears every registration, cache, and reactive effect at once. Reach for `removeVars` for component-lifetime tokens and `resetVars` for teardown between test runs or app instances.
