# cssText

Collects the CSS text registered by [`css`](/reference/css/css), [`style`](/reference/css/style), [`keyframes`](/reference/css/keyframes), and [`vars`](/reference/css/vars) calls on the default host, in first-registration order (statement-leading texts, e.g. an `@import`, hoist ahead of braced-only texts). The server-side `<style>` source.

## API

```typescript
function cssText(): string
```
- **Returns**: The joined rule text of all default-host registrations

## Basic Usage

```typescript
import { css, style, vars, keyframes, cssText } from '@hellajs/css';

css({ body: { margin: 0, fontFamily: 'system-ui, sans-serif' } });
const card = style({ background: 'white' }, { label: 'card' });
const theme = vars({ color: { primary: '#3b82f6' } });
const spin = keyframes({ from: { transform: 'rotate(0deg)' }, to: { transform: 'rotate(360deg)' } });

const head = `<style id="hella-css">${cssText()}</style>`;
// "body {\n  margin: 0px;\n  font-family: system-ui, sans-serif;\n}" + "\n\n"
// + ".h-card-… {\n  background: white;\n}" + "\n\n"
// + "@keyframes h-kf-… {\n  from {\n    transform: rotate(0deg);\n  }\n  to {\n    transform: rotate(360deg);\n  }\n}" + "\n\n"
// + ":root {\n  --color-primary: #3b82f6;\n}"
```

## Key Concepts

### A Peek, Never a Drain

`cssText()` reads the registration state without consuming it; repeated calls return the same string until [`resetCss`](/reference/css/resetcss) / [`resetVars`](/reference/css/resetvars) clear it or [`removeStyle`](/reference/css/removestyle) / [`removeCss`](/reference/css/removecss) / [`removeKeyframes`](/reference/css/removekeyframes) / [`removeVars`](/reference/css/removevars) drop a registration to zero.

### Identical on Both Platforms

Registration runs without a DOM, so the collector works the same on client and server. On the server it is the only way to obtain the generated CSS: [`css`](/reference/css/css), [`style`](/reference/css/style), and [`keyframes`](/reference/css/keyframes) return `""` / the class name / the animation name on both platforms, and [`vars`](/reference/css/vars) returns its `var()` proxy everywhere.

### Vars Append After the CSS-Side Text

Two style elements exist on the client (`hella-css` for rules, `hella-vars` for custom properties), and the collector mirrors that split: css-side registrations (`css`, `style`, `keyframes`) join in call order (statement-leading texts hoist ahead of braced-only ones), then the vars contribution appends (each scope+media bucket's rule, in registration order, media-wrapped when the `media` option was set).

### Formatted Output

Every emission is pretty-printed: one declaration per line (`prop: value;` with a trailing semicolon), two-space indentation per nesting level (at-rule bodies indent their contents), and rules of one registration separated by single newlines. Separately-registered blocks join with a blank line, css side and vars buckets alike, so each `css()` / `style()` / `keyframes()` / `vars()` call reads as its own paragraph in the collected text.

### Host-Qualified Entries Are Excluded

Styles registered with a `host` (e.g. a shadow root) live in that host's own `<style>` elements, not `document.head`; `cssText()` never includes them, css side and vars side alike. The default SSR flow has no hosts, so the collector covers everything it needs.

### Adopting the Server Tag on Hydration

Emit the collected text through a tag carrying the `hella-css` id (as in [Basic Usage](#basic-usage)) and the client adopts it: the first registration after hydration finds the existing element, drains the braced rules the server shipped (the client's registration state does not know them; block-less statements such as a leading cascade-layer order declaration are preserved), and repopulates the same element from its own registrations. One `hella-css` element before and after hydration: no duplicate rules, no flash of unstyled content. The vars contribution trailing the collected text drains along with everything else and re-lands in the client's `hella-vars` element, restoring the two-element split.

## Important Considerations

### Hydration Duplicates Without the Id

Embedding `cssText()` in server HTML through a tag with no `hella-css` id gives the client nothing to adopt: hydration registers the same styles into a fresh element, and the DOM carries both rule sets. The class names agree (content-hashed), so styling is correct; the duplication is cosmetic and bounded by the number of styles. Emit the tag with the id to get adoption instead.
