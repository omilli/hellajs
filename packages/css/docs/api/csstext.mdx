# cssText

Collects the CSS text registered by [`css`](/reference/css/css), [`style`](/reference/css/style), [`keyframes`](/reference/css/keyframes), and [`vars`](/reference/css/vars), in first-registration order: the server-side `<style>` source. A callable namespace: the base call joins every contribution into one string, while `cssText.css()` and `cssText.vars()` split the contributions so each embeds into the `<style>` tag carrying its sheet id.

## Basic Usage

```typescript
import { css, cssText, keyframes, style, vars } from '@hellajs/css';

css({
  body: {
    margin: 0,
    fontFamily: 'system-ui, sans-serif',
  },
});
const card = style({
  background: 'white',
}, {
  label: 'card',
});
const spin = keyframes({
  from: {
    transform: 'rotate(0deg)',
  },
  to: {
    transform: 'rotate(360deg)',
  },
});
const tokens = vars({
  accent: '#3b82f6',
});

// In the response handler; one embed per response.
// The id lets hydration adopt the delivered rules (see below)
const head = `<style id="hella-css">${cssText()}</style>`;
// "body { … }\n\n.card-… { … }\n\n@keyframes kf-… { … }\n\n:root { --accent: #3b82f6; }"
```

## API

```typescript
declare const cssText: {
  (): string;
  css(): string;
  vars(): string;
};
```

- **Returns**: The joined rule text of all default-host registrations, css side first, then the vars contribution (statement-leading texts such as `@import` hoist ahead of braced-only ones)

### `css`

The css-side member: every [`css`](/reference/css/css), [`style`](/reference/css/style), and [`keyframes`](/reference/css/keyframes) registration, for the rules sheet.

```typescript
import { css, cssText, style } from '@hellajs/css';

css({
  body: {
    margin: 0,
  },
});
const panel = style({
  background: 'white',
}, {
  label: 'panel',
});

// Rules only; the vars half is excluded
const rulesText = cssText.css();
// "body { margin: 0px; }\n\n.panel-… { background: white; }"
```

- **Returns**: The css-side text, `""` when nothing css-side is registered

### `vars`

The vars member: the custom-property bucket rules, for the vars sheet.

```typescript
import { cssText, vars } from '@hellajs/css';

vars({
  color: {
    primary: '#3b82f6',
  },
});

// ":root { --color-primary: #3b82f6; }"; media-wrapped when set
const varsText = cssText.vars();
```

- **Returns**: The vars-side text, `""` when nothing vars-side is registered

## Key Concepts

### A Peek, Never a Drain

The collector reads the registration state without consuming it: repeated calls return the same string until [`resetCss`](/reference/css/resetcss) / [`resetVars`](/reference/css/resetvars) clear it or a `remove*` call drops a registration to zero. Host-qualified registrations (a `host` option, e.g. a shadow root) are excluded: their rules live in host sheets, not `document.head`.

### Formatted Output

Every registered text is pretty-printed: one declaration per line, two-space indentation per nesting level, and separately-registered blocks joined with a blank line so each `css()` / `style()` / `keyframes()` / `vars()` call reads as its own paragraph.

### The Two-Sheet Split

The client keeps two style elements: `hella-css` for rules, `hella-vars` for custom properties, in that order. The combined call mirrors the split (css side, then vars); the members expose it directly. Embedding the combined string through a single `hella-css` tag is correct and adopted on hydration, but lands the vars declarations on the rules sheet; emit two tags to mirror the client exactly:

```js
import { css, cssText, vars } from '@hellajs/css';

css({
  body: {
    margin: 0,
  },
});
vars({
  accent: '#3b82f6',
});

const head = `<style id="hella-css">${cssText.css()}</style>
<style id="hella-vars">${cssText.vars()}</style>`;
```

### Hydration Adopts the Delivered Tag

Emit the collected text through a tag carrying the `hella-css` id and the client claims it: the first registration after hydration finds the existing element, matches the delivered rules against its own re-registrations, and adopts each matching rule in place. No duplicate rules ship and there is no window where the stylesheet is empty. A delivery the client cannot align with falls back to clearing the delivered rules and re-registering into the same element; one `hella-css` element exists before and after hydration either way. The `hella-vars` tag adopts the same way.

## Important Considerations

### Missing Id Duplicates Rules

A tag with no `hella-css` id gives the client nothing to adopt: hydration registers the same styles into a fresh element, and the DOM carries both rule sets. The class names agree (content-hashed), so styling stays correct; the duplication is cosmetic and bounded. Emit the tag with the id to get adoption instead.

### Registration Order Is Call Order

The collected text follows first-registration order within each side (statements hoisted ahead), not source order across modules: a `vars()` call that runs before a `style()` call still collects after it, because the vars contribution always appends to the css side. The client inserts its sheets in the same fixed order, so same-specificity cross-sheet rules resolve identically on both platforms.
