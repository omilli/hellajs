# cssText

Collects the CSS text registered by [`css`](/reference/css/css), [`style`](/reference/css/style), [`keyframes`](/reference/css/keyframes), and [`vars`](/reference/css/vars) calls on the default host. A callable namespace: `cssText()` joins every contribution into one string, the server-side `<style>` source; `cssText.css()` collects the css-side half and `cssText.vars()` the vars half, so server rendering can emit each into its own `<style>` tag the client claims at hydration.

## API

```typescript
declare const cssText: {
  (): string;
  css(): string;
  vars(): string;
};
```

- **Returns**: The joined rule text of all default-host registrations, in first-registration order (statement-leading texts, e.g. an `@import`, hoist ahead of braced-only texts).

## Basic Usage

```typescript
import { css, style, vars, keyframes, cssText } from '@hellajs/css';

css({ body: { margin: 0, fontFamily: 'system-ui, sans-serif' } });
const card = style({ background: 'white' }, { label: 'card' });
const theme = vars({ color: { primary: '#3b82f6' } });
const spin = keyframes({ from: { transform: 'rotate(0deg)' }, to: { transform: 'rotate(360deg)' } });

const head = `<style id="hella-css">${cssText()}</style>`;
// "body {\n  margin: 0px;\n  font-family: system-ui, sans-serif;\n}" + "\n\n"
// + ".card-… {\n  background: white;\n}" + "\n\n"
// + "@keyframes kf-… {\n  from {\n    transform: rotate(0deg);\n  }\n  to {\n    transform: rotate(360deg);\n  }\n}" + "\n\n"
// + ":root {\n  --color-primary: #3b82f6;\n}"
```

## Members

### css

The css-side member: every registration except the vars buckets, collected for the rules sheet.

```typescript
declare namespace cssText {
  function css(): string;
}
```

- **Returns**: The css-side text ([`css`](/reference/css/css), [`style`](/reference/css/style), [`keyframes`](/reference/css/keyframes) registrations, statements hoisted ahead of braced-only texts). `""` when nothing css-side is registered.

### vars

The vars member: the custom-property bucket rules, collected for the vars sheet.

```typescript
declare namespace cssText {
  function vars(): string;
}
```

- **Returns**: The vars text ([`vars`](/reference/css/vars) bucket rules, media-wrapped when the bucket's `media` option was set). `""` when nothing vars-side is registered.

### Two Tags, One Per Sheet

The client keeps two style elements, and each member's text embeds into the tag carrying its id:

```js
import { css, vars, cssText } from '@hellajs/css';

css({ body: { margin: 0 } });
vars({ color: { primary: '#3b82f6' } });

const head = `<style id="hella-css">${cssText.css()}</style>
<style id="hella-vars">${cssText.vars()}</style>`;
// cssText.css(): "body {\n  margin: 0px;\n}"
// cssText.vars(): ":root {\n  --color-primary: #3b82f6;\n}"
```

## Key Concepts

### A Peek, Never a Drain

`cssText()` and its members read the registration state without consuming it; repeated calls return the same string (equal parts for the members) until [`resetCss`](/reference/css/resetcss) / [`resetVars`](/reference/css/resetvars) clear it or [`removeStyle`](/reference/css/removestyle) / [`removeCss`](/reference/css/removecss) / [`removeKeyframes`](/reference/css/removekeyframes) / [`removeVars`](/reference/css/removevars) drop a registration to zero. Host-qualified registrations (a `host` option, e.g. a shadow root) are excluded from the combined text and from both members.

### Identical on Both Platforms

Registration runs without a DOM, so the collector works the same on client and server. On the server it is the only way to obtain the generated CSS: [`css`](/reference/css/css), [`style`](/reference/css/style), and [`keyframes`](/reference/css/keyframes) return `""` / the class name / the animation name on both platforms, and [`vars`](/reference/css/vars) returns its `var()` proxy everywhere.

### Vars Append After the CSS-Side Text

Two style elements exist on the client (`hella-css` for rules, `hella-vars` for custom properties), and the combined call mirrors that split: css-side registrations (`css`, `style`, `keyframes`) join in call order (statement-leading texts hoist ahead of braced-only ones), then the vars contribution appends (each scope+media bucket's rule, in registration order, media-wrapped when the `media` option was set). The members expose the same split directly.

### Formatted Output

Every emission is pretty-printed: one declaration per line (`prop: value;` with a trailing semicolon), two-space indentation per nesting level (at-rule bodies indent their contents), and rules of one registration separated by single newlines. Separately-registered blocks join with a blank line, css side and vars buckets alike, so each `css()` / `style()` / `keyframes()` / `vars()` call reads as its own paragraph in the collected text.

### One Tag Per Sheet

The client keeps two style elements (`hella-css` for rules, `hella-vars` for custom properties), and the combined `cssText()` joins both sides into one string. Emitting that string through a single `hella-css` tag lands the vars declarations in the rules element, off the sheet the client keeps them on. `cssText.css()` and `cssText.vars()` restore the two-tag split: each part embeds into the tag carrying its id, so the delivered text mirrors the client's own element split.

### Adopting the Server Tag on Hydration

Emit the collected text through a tag carrying the `hella-css` id (as in [Basic Usage](#basic-usage)) and the client adopts it: the first registration after hydration finds the existing element, splits the delivered text into the same rule texts its registrations produce, verifies the split against what the platform actually parsed, and claims each matching rule in place (no duplicate insert, and no window where the stylesheet is empty; the delivery is never deleted). Rules the platform dropped at parse (e.g. vendor-prefixed selectors in another engine) align through the same check and claim without them. A delivered text the client cannot match (e.g. an altered emission) inserts a fresh copy alongside it instead. Only when the delivered text cannot be aligned with the sheet at all (a quoted blank line mis-splits a rule on platforms whose `insertRule` is strict) does the client fall back to clearing the delivered braced rules and re-registering into the same element (one `hella-css` element before and after hydration either way): no duplicate rules, no flash of unstyled content. The vars contribution trailing the collected text lands in the same element and re-lands in the client's `hella-vars` sheet. For a delivery that mirrors the client's two-element split (each side in its own adoptable tag), collect with `cssText.css()` and `cssText.vars()` (see [Two Tags, One Per Sheet](#two-tags-one-per-sheet)).

## Important Considerations

### Hydration Duplicates Without the Id

Embedding `cssText()` in server HTML through a tag with no `hella-css` id gives the client nothing to adopt: hydration registers the same styles into a fresh element, and the DOM carries both rule sets. The class names agree (content-hashed), so styling is correct; the duplication is cosmetic and bounded by the number of styles. Emit the tag with the id to get adoption instead.

### Join With a Blank Line

`cssText()`'s output equals `cssText.css() + "\n\n" + cssText.vars()` whenever both sides are non-empty; when only one side has registrations, that member alone equals `cssText()`'s output. Emit two tags rather than re-joining, so each side lands on its own sheet id.
