# cssText

Collects the CSS text registered by [`css`](/reference/css/css), [`style`](/reference/css/style), [`keyframes`](/reference/css/keyframes), and [`vars`](/reference/css/vars) calls on the default host, in first-registration order. The server-side `<style>` source.

## API

```typescript
function cssText(): string
```
- **Returns**: The joined rule text of all default-host registrations

## Basic Usage

```typescript
import { css, style, vars, keyframes, cssText } from '@hellajs/css';

css({ body: { margin: 0, fontFamily: 'system-ui, sans-serif' } });
const card = style({ background: 'white' }, { label: 'card' });
const theme = vars({ color: { primary: '#3b82f6' } });
const spin = keyframes({ from: { transform: 'rotate(0deg)' }, to: { transform: 'rotate(360deg)' } });

const head = `<style>${cssText()}</style>`;
// "body{margin:0px;font-family:system-ui,sans-serif}.h-card-…{background:white}"
// + "@keyframes h-kf-…{from{transform:rotate(0deg)}to{transform:rotate(360deg)}}"
// + ":root{--color-primary:#3b82f6}"
```

## Key Concepts

### A Peek, Never a Drain

`cssText()` reads the registration state without consuming it — repeated calls return the same string until [`resetCss`](/reference/css/resetcss) / [`resetVars`](/reference/css/resetvars) clear it or [`removeStyle`](/reference/css/removestyle) / [`removeCss`](/reference/css/removecss) / [`removeKeyframes`](/reference/css/removekeyframes) / [`removeVars`](/reference/css/removevars) drop a registration to zero.

### Identical on Both Platforms

Registration runs without a DOM, so the collector works the same on client and server. On the server it is the only way to obtain the generated CSS — [`css`](/reference/css/css), [`style`](/reference/css/style), and [`keyframes`](/reference/css/keyframes) return `""` / the class name / the animation name on both platforms, and [`vars`](/reference/css/vars) returns its `var()` proxy everywhere.

### Vars Append After the CSS-Side Text

Two style elements exist on the client — `hella-css` for rules, `hella-vars` for custom properties — and the collector mirrors that split: css-side registrations (`css`, `style`, `keyframes`) join in call order, then the vars contribution appends (each scope+media bucket's rule, in registration order, media-wrapped when the `media` option was set).

### Host-Qualified Entries Are Excluded

Styles registered with a `host` (e.g. a shadow root) live in that host's own `<style>` elements, not `document.head` — `cssText()` never includes them, css side and vars side alike. The default SSR flow has no hosts, so the collector covers everything it needs.

## Important Considerations

### Client Hydration Re-Injects

Embedding `cssText()` in server HTML and letting the client register the same styles on hydration produces duplicate rules in the DOM — accepted behavior. The class names agree (content-hashed), so styling is correct; the duplication is cosmetic and bounded by the number of styles.
