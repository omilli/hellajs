# removeCssVars

Removes CSS custom properties by decrementing the reference count. Variables are removed from the stylesheet only when the reference count reaches zero.

## API

```typescript
function removeCssVars<T extends CSSVarInputObject>(vars: T, options?: CSSVarsOptions): void
```
- `vars`: Object containing CSS variable definitions (must match the object passed to `cssVars`)
- `options`: Optional configuration (must match the options used in `cssVars`)
- **Returns**: `void`

## Basic Usage

```jsx
import { cssVars, removeCssVars } from '@hellajs/css';

const vars = cssVars({
  colors: { primary: 'red', secondary: 'blue' }
});

// Later, remove when no longer needed
removeCssVars({
  colors: { primary: 'red', secondary: 'blue' }
});
```

## Key Concepts

### Reference Counting

`removeCssVars` mirrors the reference counting model of [`removeCss`](/reference/css/removecss). Each [`cssVars`](/reference/css/cssvars) call increments the reference count. `removeCssVars` decrements it. The variables persist until all references are removed:

```jsx
import { cssVars, removeCssVars } from '@hellajs/css';

const vars = { theme: { color: 'red' } };

cssVars(vars);  // refCount = 1
cssVars(vars);  // refCount = 2, same scope, same vars

removeCssVars(vars);  // refCount = 1, vars still present
removeCssVars(vars);  // refCount = 0, vars removed from stylesheet
```

### Static vs Reactive Removal

For **static** vars (no signals or functions), `removeCssVars` uses a deterministic hash computed from the object and options. Structurally identical objects match regardless of reference identity:

```jsx
// Static objects match by structure
cssVars({ color: 'red' });
removeCssVars({ color: 'red' }); // Same hash — matches
```

For **reactive** vars (with signals or functions), `removeCssVars` uses the exact object reference passed to `cssVars`. Hold onto the original object reference:

```jsx
import { signal } from '@hellajs/core';
import { cssVars, removeCssVars } from '@hellajs/css';

const color = signal('red');
const vars = { primary: color };

cssVars(vars);
// Must pass the same reference to remove
removeCssVars(vars);
```

When a reactive set is removed, its effect is disposed — subsequent signal updates no longer mutate the stylesheet:

```jsx
const color = signal('red');
const vars = { primary: color };

cssVars(vars);
removeCssVars(vars); // Effect is now disposed

color('blue');
// Stylesheet unaffected — effect was cleaned up
```

### Shared Scopes

Multiple `cssVars` calls to the same scope merge their variables. `removeCssVars` only removes the keys from the matching call — other calls' contributions remain:

```jsx
cssVars({ theme: { primary: 'red' } });
cssVars({ spacing: { small: '8px' } });

removeCssVars({ theme: { primary: 'red' } });
// --spacing-small: 8px remains
```

## Important Considerations

### Unknown Input

`removeCssVars` is a no-op for inputs not previously registered by a `cssVars` call — no throw, no stylesheet change.

### Exact Options Match

The `options` argument must match the `options` used in the original `cssVars` call, including `scoped` and `prefix`:

```jsx
cssVars({ color: 'red' }, { scoped: '.card', prefix: 'ui' });
removeCssVars({ color: 'red' }, { scoped: '.card', prefix: 'ui' }); // ✅ matches
removeCssVars({ color: 'red' }); // ❌ different hash — no-op
```

### Interaction with resetCssVars

[`resetCssVars`](/reference/css/resetcssvars) remains the nuclear option — it clears all variables, caches, reactive effects, and per-call registries in one go. `removeCssVars` is the granular alternative for per-call cleanup.
