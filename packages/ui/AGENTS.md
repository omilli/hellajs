<ui-package-instructions>
  Copy/paste component registry and its CLI: `bunx @hellajs/ui add <component>` copies owned, editable source into the user's project; there is no importable component surface. The npm artifact IS the CLI (`bin/hellajs-ui.js` runs `main` from `dist/index.js`). `lib/` imports only `node:` builtins plus its single runtime dependency, `esbuild` (`stripTypes`; the bundle externals rule keeps the JS API external in `dist`), so the package still bundles standalone; the `@hellajs/*` peers are convention-declared, never imported here.

  ## Registry

  Copy/paste source owned by this package; there is no importable component surface. ONE canonical component file per format — `registry/<name>/<name>.tsx` (jsx) + `<name>-html.ts` (html) — carrying only markup, props, and marker regions: exactly one `// @hella:styles` (empty in the canonical; the style module's body splices here) and one `// @hella:compose` per styled part (the live css class array), each closed by `// @hella:end`. The style declarations live ONCE per flavor in real TS modules named by convention `<name>-<style>.ts` (`button-css.ts`: `style()` maps under `layer: "hella"`; `button-tailwind.ts`: plain string maps) — exported `base` plus one string map or class per styled part (lowerCamel part names: `header`, `title`, …; `variants`/`sizes` optional), never copied as files. Shared entries live in `registry/theme/` (`tokens.js` css, `theme.css` tailwind) and `registry/cn/` (`cn.ts`, tailwind only). `add` splices the chosen style module into the chosen format file through `applyStyleVariant`: package imports ride along verbatim, `export ` prefixes strip, the tailwind flavor wraps every compose array in `cn(…)` and injects `import { cn } from "./cn.js";` after the last import. Markers never ship; the CLI owns all marker processing — babel and the user's build never see one.

  Registry data schema: shared `files`/`deps` at entry level; per-style slots carry only the slot's delta (extra deps, registryDependencies). Style modules are NOT manifest data — an entry with shared files owns `<name>-<style>.ts` by convention (`resolveEntry` derives it; the registry integrity test enforces it). Style-scoped shared entries (theme, cn) keep everything in their slots — `resolveEntry` unions shared fields with the slot's.

  Gotchas — non-obvious, load-bearing:

  - **html flavor is `<name>-html.ts`, renamed to `<name>.ts` on copy.** TS 6's program builder cannot include two same-basename supported-extension files from one directory: `button.ts` shadows `button.tsx` (tsc silently drops the `.tsx` from the program — vacuous typecheck, memory 093's hazard one level deeper). The `-html` suffix keeps both flavors checked here AND unambiguous in the repo; `copyFiles`' rename map lands `button.ts` in the user's `components/` so `./components/button` resolves in both formats.
  - **Class-array members are static values.** The css flavor composes each part's `class={[partClass, props.class]}` (Button keeps `variants[…]`/`sizes[…]` lookups) — a plain array in the attribute (the `@hella:compose` region body), joined by dom's `renderProp` (`filter(Boolean).join(" ")`). A reactive member string would stringify as source, not resolve — class composition is static by design; precedence between registry CSS and user CSS is `@layer hella`'s job (unlayered author CSS always wins), not a class-name compositor's. The compose body must BE a plain array — the tailwind wrap (`[`` → `cn(`) throws without it.
  - **Dark mode is the `.dark` ancestor class, and ancestor-conditioned styling cannot use non-`&`-first selectors.** The css package's `style()` nesting replaces `&` only in `&`-FIRST keys, so `.dark &`-style ancestor selectors would emit a literal `&` (broken CSS). `.dark` conditions translate to `&:is(.dark *)` (shadcn v4's own variant definition); ancestor-attribute conditions (Tabs' trigger-under-`[data-variant=line]`-list, Card's `[.border-b]` sibling) register as raw attribute selectors under `css({ "@layer hella": … })` in the same style module, placed AFTER the `style()` calls (equal-specificity cascade resolves by registration order within the layer). Keyframes for css-flavor animations come from `keyframes()` (hashed names referenced in `animation` values), never hand-named `@keyframes`.
  - **JSX canonical components are typed `: JSX.Element`** (dom's global `JSX.Element = HellaNode & RenderFn`), not `: HellaNode` — the `.d.ts` emission and user-side JSX usage reject a bare-`HellaNode` return with TS2786. Multi-part canonicals also pass arrays through explicit `children={[...]}` props, NOT JSX child slots: a `HellaChildren`-typed value through a child slot double-wraps and fails the `HellaChild` element check.
  - **html canonical templates never bind raw array slots.** The runtime template's `cloneWithValues` does not flatten a nested array at arbitrary depth and `appendToParent` drops array children — pass-through children in pass-through parts (`TabsList`, `DialogHeader`, …) render through FUNCTION slots (`${() => props.children}`), and fixed innards (the DialogClose X + `sr-only` span) are inlined in the part's own template rather than passed as children (per-call node identity; static-subtree sharing moves nodes between clones). The JSX flavor fails one level subtler: a COMPOUND child expression (`{props.children ?? fallback}`) is not the bare `props.children` member the transform auto-wraps, so it evaluates once as a static value — an array child is then dropped and renders nothing. Arrow-wrap every conditional/compound child (`{() => props.children ?? fallback}`) exactly like the html flavor's function slot.
  - **Function-valued attribute expressions and nested function children stringify.** babel's `maybeReactive` wraps compound attribute expressions in an outer arrow; when the expression's VALUE is itself a function (a ternary yielding an accessor), the runtime receives arrow-in-arrow and `renderProp` stringifies the inner one into the attribute — observed as `style="() => props.hidden() ? …"` in compiled output. Precompute the accessor as a bare const binding (`const hiddenStyle = props.hidden ? () => … : undefined` then `style={hiddenStyle}`) in both flavors, and give a part that must render reactive children through a passthrough slot a purpose-built thunk prop instead (`portal?: () => HellaChildren`, ComboboxChips' `chips`) — `{() => props.children}` with function-valued children stringifies the same way (`resolveValue` unwraps exactly one level). Keep `<name>-html.ts` invoking parts as direct function calls (`ComboboxInput({ … })`); the `<${Component}>` embedded-tag syntax is a docs-site demo idiom, not a canonical one.
  - **A reactive structural branch must resolve to a vnode in one unwrap.** The same one-level rule hits REACTIVE FORKS: a child-slot thunk whose arm returns a render-fn (an only-dynamic `html\`\`` template — `html\`${() => cond ? a : b}\``) or an array with fn members stringifies as `[object Object]` text, because `appendToParent` → `resolveValue` unwraps the branch thunk once and `resolveNode` treats the leftover fn as reactive TEXT. Compose the fork so each arm yields a vnode: internal gate builders return the gate thunk and the branch arm CALLS it (`mobileTree()`, sidebar's `SidebarMobileSheet`), and html-format compositions/tests embed parts inside a static-root template (`html\`<div><${Part} …/></div>\``), never a raw children array of part results.
  - **The default Dialog gates its render on an internal `visible` signal, not `open()` directly.** Reading `open()` in the render template unmounts the subtree one evaluation before the open-watcher effect starts the exit (signal write vs template effect ordering); `visible` is written only by the watcher, so the exit holds the panel mounted until its `animationend` (or the 250ms fallback). The exit runs unwired: DialogContent's state effect disposes the trap/escape/outside wirings the moment `state` flips `"closed"` and re-arms them on reopen without a remount.
  - **Marker lines must stay standalone** — `// @hella:…` occupies its own line (leading whitespace fine, e.g. the compose region inside JSX attribute braces); trailing code on a marker line breaks the section parser, and any UNKNOWN `@hella:` marker throws (a stale three-region canonical fails loudly instead of shipping inert comments). The registry integrity test enforces exactly one `@hella:styles` plus at least one `@hella:compose` per canonical, with a matching `@hella:end` for each.
  - **Style modules are package-import-only.** `parseStyleModule` rejects relative/absolute specifiers — spliced output lands in a foreign flat directory, so a relative path from `registry/<name>/` would dangle. The only cross-file import a spliced file carries is the engine-injected `import { cn } from "./cn.js";` (the `.js` suffix is load-bearing: the per-module build's specifier fixup appends `.js` to extensionless relative imports — string literals included — so the constant must already hold the final form to stay identical across dist shapes; and `./cn.js` is the TS convention resolving to the copied `cn.ts` in the user's project). `export default` / `export {…}` in a style module throws; bare `export const` prefixes are stripped on splice.
  - **Runtime html has no auto-wrap pass.** babel's `maybeReactive` wraps call-containing expressions; the runtime template cannot. Compound values in `button-html.ts` are explicitly arrow-wrapped (`e:click="${() => props.onclick?.()}"`) — a bare `props.onclick` would hit `setDirectHandler` undefined and crash on `"handler" in undefined`.
  - **Delegated `on:` handlers must extract event data from `e.target`, never `e.currentTarget`.** dom's delegation runs one capture listener per event type on `document.body` and invokes `handler.call(element, event)` — `this` is the element but `currentTarget` stays the body, so `e.currentTarget.value` is `undefined` (the optional chain then silently passes it on). `currentTarget` is the element only under the direct `e:` prefix; `e.target` is correct in both flavors (`input.tsx`/`input-html.ts` shape: `(e.target as HTMLInputElement).value`).
  - **Registry files never import the theme.** Every registry file stays standalone with only `@hellajs/*` peer imports (plus `clsx`/`tailwind-merge` for `cn.ts`); the theme is added ONCE per app (user entry) — this is why `init` adds `theme` separately. Component classes reference `var(--*)` literals; without the theme anywhere the properties resolve to nothing.
  - **Tailwind flavor is theme.css-only** — zero `@hellajs/css` references anywhere in the tailwind style module or its copy output; the palette is plain CSS under `@layer hella` (whole file), read through v4 arbitrary-value shorthands (`bg-(--primary)`). Opacity modifiers on var shorthands are verified (`bg-(--primary)/90` → `color-mix(in oklab, …)` chain, probed against tailwindcss 4.1.18). Bounded open: tailwind-merge v4-syntax support for `bg-(--primary)` arbitrary-value conflict resolution is deferred (tailwind-merge ^3 in devDependencies for style-module typechecking).
  - **`clsx`/`tailwind-merge` are devDependencies, not peers.** `cn.ts` is user-owned template code importing the user's deps (`checkPeers` demands them at add time); the devDeps exist only so the lint program typechecks `cn.ts` and the style modules with real types. Never promote them to `peerDependencies` (memory 023: all-peer convention for `@hellajs/*`).
  - **`sonner` is the registry's first non-component export**: the canonical carries a module-level singleton (`toasts` signal + timer/instance state) beside the `Toaster` component, so one copied file owns one queue per app and `add` needs no engine change. Two consequences are load-bearing: per-toast live-element wiring (timers, hover pause, swipe) rides a module-level `$ref` registered once at enqueue time in `wireToast` — NOT `hook:afterMount` in the li, because lis slot into the portaled ol after its one-and-only mount walk and only mount/hydrate roots and Portal insertions deliver hooks — and the `$ref` selectors carry an `INSTANCE` nonce because ForEach's effect re-invokes `use` on every queue write (body-side registration would duplicate selectors) while four compiled flavors of the same source coexist in tests.
  - **Lint wiring for registry files**: `tsconfig.lint.json` carries `"jsx": "preserve"` (global JSX namespace, examples convention) and includes `registry/**/*.ts` + `**/*.js` — covering style modules, `cn.ts`, `tokens.js` — while the canonicals are EXCLUDED (`**/*-html.ts` via exclude; `.tsx` include line removed): they are templates referencing splice-injected names (`base`, `variants`, `sizes`) that don't resolve standalone. Their typecheck gate is the compile step's `.d.ts` emission over the spliced variants (§Compile step). eslint ignores the canonical globs (`registry/**/*.tsx`, `**/*-html.ts`) to keep the project service consistent with the tsconfig, plus `packages/ui/tests/.tmp/**` (e2e scratch).

  ## Compile step (`dist/registry`)

  `bun bundle ui` compiles the registry to `dist/registry/**` via `scripts/bundle/registry.ts` — build/verification output only, never shipped (`files` carries explicit top-level `dist/*` globs + `dist/internal`, so `dist/registry` stays out of the tarball). **Never edit `dist/registry` by hand** — `registry/` is the only truth; a registry or style-module edit invalidates the build cache (`isCacheValid` hashes the package dir) and recompiles on the next bundle.

  - **Layout**: entry-level (shared) files → `dist/registry/<name>/<style>/<file>.js`; style-scoped entries flat → `dist/registry/theme/{tokens.js,theme.css}` (verbatim copies), `dist/registry/cn/cn.js` (compiled). Tailwind variant dirs additionally carry the compiled shared dep modules (`cn.js`) so the injected `./cn.js` import resolves in dist.
  - **Docs site, the CLI consumer**: the site's `components/` section runs files vendored by `add` itself (`--dir docs`, checked in under `docs/src/components/ui/`, each `docs/src/pages/components/<name>.astro` composes them in an inline demo `<script>` and `mount()`s into its `#demo` frame) — there are no package-side demos. A `packages/ui/tests` drift guard byte-compares every vendored file against a fresh temp-dir `add` run, so a registry edit that changes `add` output without re-vendoring fails CI; re-sync with the one-liner in root `AGENTS.md`.
  - **One transform, two callers**: the build compiles through the same babel options `plugins/vite/index.mjs` applies (memory 029's transform pipeline) — what tests import from `dist/registry` is byte-faithful to what a user's Vite build produces from the copied source. Every flavor is `applyStyleVariant(canonical, styleModule, style)` run through that same path — edit canonical + style module, never dist. A component entry missing its conventional style module fails the build with a named error.
  - **`.d.ts` is the splice typecheck gate**: declarations are emitted by `bunx tsc --emitDeclarationOnly` over the staged flavor-resolved sources; a style module that produces non-compiling output fails the build. This is also the canonicals' only typecheck — they are excluded from `tsconfig.lint.json` (templates with unresolved splice-injected names; see §Registry gotchas).
  - **Coverage instruments `dist/registry/**.js`** (bunfig include) — the parity harness imports compiled variants because registry canonicals are never executed under bun test (see §Non-obvious).

  ## Non-obvious

  - **Peers are convention-declared, functionally inert.** `lib/` never imports `@hellajs/*`; the CLI bundles standalone on `node:` builtins plus `esbuild` (below). The peers exist because the COPIED source imports them in the user's project, and `checkPeers` enforces their presence there at add time. Do not "fix" the undeclared-import shape by adding dependencies (memory 023: all-peer convention, carets, zero devDeps — the `clsx`/`tailwind-merge` devDeps are the registry-canonical exception, see §Registry gotchas).
  - **`esbuild` is the package's first and only runtime `dependency`.** `stripTypes` calls its JS API (`transformSync`) at add time; the binary arrives through esbuild's own `optionalDependencies` at install. It is a real dependency, not a devDep, because the published artifact IS the CLI — a devDep would dangle for `bunx @hellajs/ui`. The bundle externals rule (`externalFlags` in `scripts/bundle/esbuild-build.ts`, peerDeps + `dependencies`) keeps the JS API external in `dist` — it must never inline. This supersedes the old "pure `node:` builtins" invariant; `@hellajs/*` peers stay convention-declared. Bun and Deno users need none of this: TS runs natively there, so `--lang js` is only for no-build browser ESM and JS-only shops.
  - **The `--lang js` rename map retargets every TS file.** `-html.ts` → `<name>.js` (not `.ts`), `.tsx` → `.jsx`, other `.ts` (`cn.ts`) → `.js`; `tokens.js` / `theme.css` pass through verbatim. `stripTypes` runs AFTER `applyStyleVariant` — the splice consumes the `@hella:` markers first, so the stripper never sees a marker line (esbuild would keep them as comments; the contract is that markers never ship). The `ts` path is byte-identical to pre-lang behavior: same renames, no strip.
  - **`import.meta.dir` anchors at the `dist/` root.** Per-module bundling inlines `internal/` imports one level up and the bundle flattens fully, so any runtime form evaluates it at `dist/` (or `lib/`) depth: anchor package-relative paths ONE level up from the file (`loadRegistry.ts`'s `REGISTRY_DIR`). A path anchored for `dist/internal/` depth resolves wrong in every runtime form. The unused `dist/internal/*.js` artifacts are not supported surfaces.
  - **Coverage instruments `dist/bundle.js`** (bunfig include-set), so every public export must be reachable from `lib/index.ts` or it silently escapes measurement. This is why `readConfig` is barrel-exported from `internal/`.
  - **Registry canonicals are never executed in this repo's tests.** Bun's test runner hijacks `.tsx` with React's JSX runtime — registry `.tsx` source under bun test is a hazard; Unit 5's parity harness runs COMPILED `dist/registry/**` output instead. In-repo verification of canonicals is structural (marker integrity, style-module binding) + the transform's byte-shape tests.
  - **A new registry entry is a four-list blast radius beyond its own files.** `registry.json` + the `§Registry` table row + `helpers/variants.ts` are the obvious three artifacts; the three ENUMERATED test lists fail otherwise: `main.test.ts`'s `listComponents()` array, `cli-e2e.test.ts`'s `list` stdout string, and `drift.test.ts`'s two `add` name lists. All five fail only at full-suite/drift time, not at scoped single-file runs.

  ## Testing

  - Run `bun coverage ui` (never bare `bun test`; stale bundles). Tests import from `@hellajs/ui/bundle`. Two suite kinds. The CLI/infra suites: `config.test.ts` (defaults/overrides, two-style + format + invalid-JSON validation), `main.test.ts` (dispatch throw contract + usage text + list + in-process init/add flag dispatch), `transform.test.ts` (splice/wrap byte shapes, import injection, export stripping, unbalance/unknown-marker/missing-region/non-array/no-specifier throws, whitespace tolerance), `registry.test.ts` (manifest ↔ disk integrity, entry-count pin, region integrity, style-module convention + binding, dependency graph), `add.test.ts` (copy semantics per style/format incl. rename + splice, collisions, peer warnings, missing/invalid package.json throws), `compile.test.ts` (dist/registry emission: declarations, plain-js output with verbatim external imports, per-style compose shapes), `plainjs.test.ts` (`--lang js`: html and jsx adds strip types, named parts stripped, rename map), `drift.test.ts` (docs-site vendoring: file-set reproduction and byte-matching against a fresh temp-dir `add`), `cli-e2e.test.ts` (spawns `bin/hellajs-ui.js` against a copy of `tests/fixtures/empty-app/` under `tests/.tmp/`, gitignored, never `/tmp`). Plus one `<name>.test.ts` parity suite per registry component (59): behavior and rendering over the compiled flavors through `helpers/variants.ts`, `assertStructuralParity` across all four style × format variants; DOM-touching suites import `@hellajs/dom`, not the bundle. Exemplars: `dialog.test.ts` (portal wiring per variant: dismissal, focus trap/restore, outside handling, disposal, structural parity), `sonner.test.ts` (toast queue per variant: enqueue/render, three-visible cap, stack depth marks, auto-dismiss with injected short durations plus one unparametrized 4000ms-default pin, hover pause/resume, action button, promise loading/success/error, swipe dismiss and spring-back, dismiss by id and blanket, position/richColors attrs, structural parity), `input-otp.test.ts` (hidden-input OTP per variant: composed slots and control-input hiding, caret placement at focus and blur, sequential typing with caret-slot tracking, backspace clear-and-move, arrow/Home/End slot moves, paste fill with length clip, pattern rejection, onChange/onComplete transitions, controlled value() re-renders, disabled blocking, wiring disposal, structural parity).
- **Tests exercising compiled components that touch dom internals (Portal, `hook:` wiring) import `@hellajs/dom`, not the bundle.** The compiled registry files import the bare specifier; `@hellajs/dom` and `@hellajs/dom/bundle` are separate instances with separate element-state maps, observer registries, and mount-walk gates — a cross-instance mount never fires `afterMount` and `peekState` sees nothing. Components whose compiled output is plain vnodes (button, card, input) are instance-agnostic and stay on the bundle import; `helpers/variants.ts` mounts through the index for the same reason. Mount-walk timing is observer-delivered: poll `peekState(panel)?.isMounted` with microtask hops, never fixed `delay()` waits. HappyDOM ships the `ResizeObserver` global but never delivers its callbacks — content-growth scenarios (message-scroller) go through the component's injectable watcher prop, never a real observer.
