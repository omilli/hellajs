## API

`SidebarProvider` owns the state and hands it to a children function; every other part receives what it needs as explicit props. Hella has no context primitive, so the provider's threaded state object (`open`, `setOpen`, `mobile`, `openMobile`, `setOpenMobile`, `onToggle`) is the single source the parts read.

The wrapper `div` carries `data-slot="sidebar-wrapper"`, the width variables, and both listeners: a `matchMedia("(max-width: 769px)")` listener that flips the `mobile` state, and a Ctrl/Cmd+B shortcut, which calls `onToggle` (the mobile sheet on mobile, the desktop open state otherwise). `open` is the standard dual-surface pair: pass `open` with `onOpenChange` for a controlled signal, or `defaultOpen` (default `true`) to let the provider own it. Cookie persistence is dropped; persist the signal yourself if you need it.

Twenty-two parts ship beside the `Sidebar` root. Layout: `SidebarHeader`, `SidebarFooter`, `SidebarSeparator`, `SidebarContent`, `SidebarInset` (the `main` that stretches beside the panel). Menu: `SidebarGroup`, `SidebarGroupLabel`, `SidebarGroupAction`, `SidebarGroupContent`, `SidebarMenu`, `SidebarMenuItem`, `SidebarMenuButton` (`variant: "default" | "outline"`, `size: "default" | "sm" | "lg"`, `active`, `tooltip`; renders `type="button"` unless a native `type` rides the attributes), `SidebarMenuAction` (`showOnHover` fades it in on item hover at `md` and up), `SidebarMenuBadge`, `SidebarMenuSkeleton` (`showIcon`), `SidebarMenuSub`, `SidebarMenuSubItem`, `SidebarMenuSubButton` (`size: "sm" | "md"`, `active`, anchor by default). Controls: `SidebarTrigger` (the panel-left icon button), `SidebarRail`. Every part carries its `data-slot` and a `data-sidebar` hook, so user CSS can target either. Every part also accepts all native attributes of its root tag (forwarded to the root element): `SidebarMenuSubButton`'s `href` and `SidebarInput`'s `value`, `placeholder`, and `aria-label` ride the spread, and a user `on:click` on the trigger, rail, or menu buttons fires alongside the owned toggles. `SidebarInput` renders the search input (`h-8`, `bg-background`) with the input entry's class maps inlined.

### SidebarProvider

| Prop | Type | Default |
| ---- | ---- | ------- |
| `open` | `() => boolean` | `-` |
| `onOpenChange` | `(open: boolean) => void` | `-` |
| `defaultOpen` | `boolean` | `true` |
| `children` | `(state) => HellaChildren` | The shell, composed from the threaded state |

Accepts all native `div` attributes (forwarded to the wrapper element).

### Sidebar

| Prop | Type | Default |
| ---- | ---- | ------- |
| `open` | `() => boolean` | `-` |
| `mobile` | `() => boolean` | `-` |
| `openMobile` | `() => boolean` | `-` |
| `onOpenMobileChange` | `(open: boolean) => void` | `-` |
| `side` | `"left" \| "right"` | `"left"` |
| `collapsible` | `"offcanvas" \| "icon" \| "none"` | `"offcanvas"` |
| `class` | `string` | `-` |
| `children` | `HellaChildren` | The panel parts |

Accepts all native `div` attributes (forwarded to the desktop panel element).

`SidebarMenuButton`'s `tooltip` composes an inline hover label (delay 0) anchored to the button; it renders only while the sidebar is collapsed to icon mode and never on mobile (the `hidden` attribute masks it otherwise). The `open` and `mobile` accessors thread that decision down.

`SidebarRail` is the clickable edge handle (`aria-label` and `title` "Toggle Sidebar") wired to `onToggle`; width dragging is out of scope, so the rail toggles on click only.

## Collapsible Modes

`collapsible` picks what the desktop panel does when `open` flips false; the root's `data-collapsible` attribute carries the mode and the CSS forks on it.

| Mode | Collapsed behavior |
|---|---|
| `"offcanvas"` (default) | The panel slides out of view; the gap closes to zero width |
| `"icon"` | The panel shrinks to `--sidebar-width-icon` (3rem); labels, badges, actions, and submenus hide, menu buttons square to icons, and a button's `tooltip` shows on hover |
| `"none"` | The panel renders as a fixed-width column and ignores the open state entirely |

## Mobile Behavior

Past the `769px` breakpoint the provider's `mobile` state flips true and `Sidebar` renders the mobile sheet instead of the desktop panel: a portaled overlay plus a `role="dialog"` panel sliding from `side`, with escape, outside-pointerdown, and focus-trap wiring and the same exit hold the sheet entry ships (the panel stays mounted under `data-state="closed"` until its exit animation ends, 350ms fallback). The mechanics are duplicated inline (registry entries are self-contained), so `add sidebar` needs no import from the sheet file. `openMobile`/`setOpenMobile` (threaded from the provider) drive it, and `onToggle` targets it while mobile.

## CSS Variables

The parts read four tokens; the first three are yours to set, the last the component generates.

| Variable | Value | Set by |
|---|---|---|
| `--sidebar-width` | `16rem` (wrapper) / `18rem` (mobile panel), both inline styles | You, on the provider wrapper and mobile panel |
| `--sidebar-width-icon` | `3rem` (wrapper inline style) | You, on the provider wrapper |
| `--sidebar`, `--sidebar-foreground`, `--sidebar-primary`, `--sidebar-primary-foreground`, `--sidebar-accent`, `--sidebar-accent-foreground`, `--sidebar-border`, `--sidebar-ring` | the sidebar oklch palette | tailwind: `theme.css` `:root` and `.dark`; css: the sidebar style module's own `vars()` registration (same values), because `tokens.ts` carries no sidebar colors |
| `--skeleton-width` | random 50% to 90% per `SidebarMenuSkeleton` | The skeleton part's inline style |

Override the widths by editing the inline `style` strings on the wrapper (and the mobile panel); override the palette through the theme entry (tailwind) or the style module's `vars()` call (css).
