## API

The composed `Select` takes its options as data and renders the trigger plus the portaled listbox; the copied file wires its positioning, dismissal, and typeahead from the `@hellajs/dom` behavior functions.

The select renders only the button and listbox: no hidden native form control, so it submits nothing by itself. Pair it with `native-select` when a form needs a submittable field.

Nine named parts ship beside the default `Select`: `SelectTrigger`, `SelectValue`, `SelectContent`, `SelectGroup`, `SelectItem`, `SelectLabel`, `SelectSeparator`, `SelectScrollUpButton`, and `SelectScrollDownButton`. Manual composition passes state explicitly: portal the content yourself, hand it a `state` accessor and an `onDismiss` callback, and thread each item its selected state.

### Select

| Prop | Type | Default |
| ---- | ---- | ------- |
| `items` | `SelectEntry[]` | `-` |
| `value` | `() => string` | `-` |
| `onValueChange` | `(value: string) => void` | `-` |
| `placeholder` | `string` | `-` |
| `size` | `"sm" \| "default"` | `"default"` |
| `clearable` | `boolean` | `-` |
| `class` | `string` | `-` |
Accepts all native `button` attributes (forwarded to the root element).

A controlled `value` stops the root from writing its internal signal; `onValueChange` reports the requested selection, including the empty string when cleared. `placeholder` shows in the trigger with `data-placeholder` while nothing is selected. `size="sm"` renders the compact `data-size="sm"` trigger variant. `clearable` renders an inline clear affordance on the trigger while a value is selected.

### SelectEntry

Each entry in the `items` array is one option row.

| Field | Type | Default |
| ----- | ---- | ------- |
| `value` | `string` | `-` |
| `label` | `HellaChildren` | `-` |
| `disabled` | `boolean` | `-` |

`value` is the selection identity (reported through `onValueChange`, matched against the controlled `value`, rendered as `data-value`); `label` is the option's text node, echoed by the trigger through `SelectValue`; `disabled` skips the row in roving and typeahead, blocks commit, and renders `aria-disabled` plus `data-disabled`.

### SelectTrigger

The trigger button carrying `aria-haspopup="listbox"`, `aria-expanded`, and the open-state `data-state`. The caller supplies `aria-controls` and `aria-label` as native attributes (the composed `Select` generates and wires the content id itself); `disabled` re-renders `disabled` and gates the open handlers.

| Prop | Type | Default |
| ---- | ---- | ------- |
| `state` | `() => "open" \| "closed"` | `-` |
| `size` | `"sm" \| "default"` | `"default"` |
| `onOpen` | `() => void` | `-` |
| `clearable` | `boolean` | `-` |
| `onClear` | `() => void` | `-` |
| `hasValue` | `() => boolean` | `-` |
Accepts all native `button` attributes (forwarded to the root element).

### SelectValue

| Prop | Type | Default |

## Keyboard and Dismissal

The trigger opens on click and on ArrowDown/ArrowUp. Inside the listbox, arrows rove the options with wrap, Home and End jump to the edges, Enter and Space commit the highlighted option, and Tab closes. Typing buffers a typeahead query (reset after 500ms) and highlights the first match: prefix matches win, then a wrapping substring scan. The highlighted option carries `data-highlighted`; the selected option carries `aria-selected="true"`, `data-state="checked"`, and the check icon, and scrolls into view on open.

Dismissal runs through [`layerDismissal`](/reference/dom/layerdismissal): Escape and a pointerdown outside the listbox close it, and focus returns to the trigger. Closing starts the exit - the listbox stays mounted under `data-state="closed"` until its animation ends, with dismissal wiring down while it leaves.

The panel positions itself through [`anchorPosition`](/reference/dom/anchorposition) with `matchAnchorWidth`: the listbox always anchors below the trigger (flipped on viewport collision) and stretches to its width. Scroll buttons render at the listbox edges; they repeat-scroll while hovered and hide at their scroll bounds.

The clear affordance is pointer-only: it lives inside the trigger button, so it cannot take keyboard focus without nesting interactive content. Keyboard users clear by re-running the composed flow (the empty string is a valid `onValueChange` report) or by pairing with `native-select`.
