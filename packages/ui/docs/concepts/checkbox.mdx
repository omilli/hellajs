# Checkbox

A checked-state control styled to shadcn's Checkbox: a button carrying `role="checkbox"` whose state lives in a signal. The root renders the `aria-checked` and `data-state` attributes and shows the check icon inside its indicator whenever the box is checked or indeterminate.

## Usage

| Prop | Type | Behavior |
|---|---|---|
| `checked` | `boolean \| (() => boolean)` | Uncontrolled seed or controlled accessor (see below) |
| `indeterminate` | `boolean \| (() => boolean)` | Mixed state. Wins over `checked` for rendering: `aria-checked="mixed"` and `data-state="indeterminate"` |
| `onCheckedChange` | `(checked: boolean) => void` | Fires on every click with the requested next value |
| `disabled` | `boolean` | Blocks clicks and renders the disabled attribute |
| `ariaInvalid` | `boolean` | Renders `aria-invalid="true"`, which the invalid ring styles key off |
| `id` | `string` | Rendered on the button for label pairing |
| `class` | `string` | Lands on the root next to the component class |

```jsx
import Checkbox from './components/checkbox';

const Settings = () => (
  <label>
    <Checkbox id="notifications" /> Email notifications
  </label>
);
```

## Controlled and Uncontrolled

Without `checked`, the root owns a signal seeded by a boolean `checked` prop and flips it on click. Pass an accessor and the checkbox becomes controlled: clicks turn into `onCheckedChange` requests without writing state, so a parent signal that ignores the request keeps the box unchanged.

```jsx
import { signal } from '@hellajs/core';
import Checkbox from './components/checkbox';

const subscribed = signal(false);

const Controlled = () => (
  <label>
    <Checkbox
      checked={() => subscribed()}
      onCheckedChange={(next) => subscribed(next)}
    />
    Subscribe
  </label>
);
```

`indeterminate` follows the same shape: a boolean seeds it, an accessor controls it. Clicking a mixed box reports `true` and clears an uncontrolled mixed state; a controlled mixed state clears only when the parent says so. The icon stays the check glyph in every state, matching the ref: only `aria-checked` and `data-state` distinguish mixed from checked.

## Accessibility

The root is a `button` element, so Space toggles it through native activation and it participates in tab order.

| Aspect | Value |
|---|---|
| Role | `checkbox` on the root button |
| State | `aria-checked` is `true`, `false`, or `mixed`; `data-state` is `checked`, `unchecked`, or `indeterminate` |
| Keyboard | Space toggles; the button is disabled for pointer and keyboard while `disabled` |
| Labeling | Pair with a `label` element or `aria-labelledby` through the `id` prop |

## Styling

Both flavors export the same names from the copied file: `base` (the root button, including the focus ring and checked palette), `indicator` (the grid-centered icon slot), and `icon` (the check glyph size). The css flavor composes [`style`](/reference/css/style) maps under the `hella` cascade layer, so unlayered author CSS always wins; the tailwind flavor wraps plain utility strings in `cn()` and keys the checked palette off the root's own `data-state` (`data-[state=checked]:bg-primary`). To restyle every checkbox at once, edit the `indicator` and `icon` maps; `props.class` lands on the root next to `base`. The indicator element stays mounted in every state; only the icon inside it appears and disappears, so adding a transition on the indicator survives state flips. Flavor choice and theme setup: [Installation](/ui/installation). Tokens and the override contract: [Theming](/ui/theming).
