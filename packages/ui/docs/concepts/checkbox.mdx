## API

### Checkbox

| Prop | Type | Default |
| ---- | ---- | ------- |
| `checked` | `boolean \| (() => boolean)` | `-` |
| `indeterminate` | `boolean \| (() => boolean)` | `-` |
| `onCheckedChange` | `(checked: boolean) => void` | `-` |
| `disabled` | `boolean` | `-` |
| `ariaInvalid` | `boolean` | `-` |
| `id` | `string` | `-` |
| `class` | `string` | `-` |

`indeterminate` wins over `checked` for rendering: `aria-checked="mixed"` and `data-state="indeterminate"`. `ariaInvalid` renders `aria-invalid="true"`, which the invalid ring styles key off, and `id` lands on the button for label pairing.

## Controlled and Uncontrolled

Without `checked`, the root owns a signal seeded by a boolean `checked` prop and flips it on click. Pass an accessor and the checkbox becomes controlled: clicks turn into `onCheckedChange` requests without writing state, so a parent signal that ignores the request keeps the box unchanged.

`indeterminate` follows the same shape: a boolean seeds it, an accessor controls it. Clicking a mixed box reports `true` and clears an uncontrolled mixed state; a controlled mixed state clears only when the parent says so. The icon stays the check glyph in every state: only `aria-checked` and `data-state` distinguish mixed from checked.

## Accessibility

The root is a `button` element, so Space toggles it through native activation and it participates in tab order.

| Aspect | Value |
|---|---|
| Role | `checkbox` on the root button |
| State | `aria-checked` is `true`, `false`, or `mixed`; `data-state` is `checked`, `unchecked`, or `indeterminate` |
| Keyboard | Space toggles; the button is disabled for pointer and keyboard while `disabled` |
| Labeling | Pair with a `label` element or `aria-labelledby` through the `id` prop |

The indicator element stays mounted in every state; only the icon inside it appears and disappears, so a transition on the indicator survives state flips.
