## API

The default mode is single selection. Click a day (or press Enter on it) and the calendar reports the picked date through `onSelect`. One month renders at a time, with roving keyboard focus over the grid and previous/next month navigation.

### Calendar

| Prop | Type | Default |
| ---- | ---- | ------- |
| `mode` | `"single" \| "multiple" \| "range"` | `"single"` |
| `selected` | `Date \| Date[] \| { from?, to? }` | `-` |
| `onSelect` | `(selected) => void` | `-` |
| `month` | `() => Date` | `-` |
| `onMonthChange` | `(month: Date) => void` | `-` |
| `defaultMonth` | `Date` | The current month |
| `disabled` | `(date: Date) => boolean` | `-` |
| `showOutsideDays` | `boolean` | `true` |
| `fixedWeeks` | `boolean` | `-` |
| `weekStartsOn` | `0..6` | `0` |
| `hideNavigation` | `boolean` | `-` |
| `classNames` | `Partial<Record<key, string>>` | `-` |
| `class` | `string` | `-` |

Selection is uncontrolled after mount: `selected` sets the initial state and `onSelect` reports every change in the mode's shape. The visible month is the one controlled prop: `month` as an accessor wins over internal navigation on every change, while `onMonthChange` still reports user navigation (buttons, arrows, page keys).

### CalendarDayButton

The manual-composition day part is exported for standalone composition. State flags take plain booleans or reactive accessors, so a composed calendar drives them live while a direct call passes static values.

| Prop | Type | Default |
| ---- | ---- | ------- |
| `day` | `Date` | `-` |
| `selectedSingle` | `boolean \| (() => boolean)` | `-` |
| `rangeStart` / `rangeEnd` / `rangeMiddle` | `boolean \| (() => boolean)` | `-` |
| `disabled` | `boolean \| (() => boolean)` | `-` |
| `focused` | `boolean \| (() => boolean)` | `-` |
| `today` | `boolean` | `-` |
| `class` | `string` | `-` |
| `onclick` / `onpointerenter` / `onpointerleave` | `(event) => void` | `-` |

`day` is also emitted as `data-day` (locale string); `selectedSingle` renders `data-selected-single` and `aria-selected`, the range flags render the `data-range-*` attributes, `disabled` renders `aria-disabled`, `focused` drives the roving `tabindex`, and `today` renders `aria-current="date"`.

## Selection Modes

`mode` picks the selection shape. `onSelect` mirrors the shape back exactly.

| Mode | `selected` shape | Behavior |
|---|---|---|
| `single` | `Date` | Click selects; clicking another day replaces it. Re-clicking the selected day keeps it |
| `multiple` | `Date[]` | Click toggles membership; order is stable, new days append |
| `range` | `{ from?, to? }` | First click sets `from`. Second click sets `to`, reordering automatically when the click lands before `from`. Third click resets and starts a new span |

While `from` dangles, hovering a day previews the span: the hovered day renders `data-range-end` and the days between render `data-range-middle`, so the range styling responds before the second click. Disabled days render `data-disabled` and `aria-disabled`, and clicks on them report nothing; adjacent-month days are always disabled.

## Intentionally Absent

The port covers the observable surface of a single-month calendar; the intentionally absent pieces match the registry's zero-dependency rule:

- `numberOfMonths` beyond one, `fromDate`/`toDate` navigation bounds, custom `formatters`, week numbers, and the dropdown caption layouts are not implemented; the caption is always the `label` layout.
- Selection is uncontrolled: there is no controlled selection accessor.
- All date math runs on local `Date` fields with no timezone conversion, and labels are fixed to `en-US` (`March 2025` captions, `Sun`-style weekday headers) so rendering is deterministic across hosts.
- The rtl navigation-button selectors are dropped; the copied file emits no `rdp-*` classes for them to target.
- The outside-day `aria-selected` color rule folds into the base outside color.

## Accessibility

The grid is a `role="grid"` table: weekday headers are column headers, cells are `role="gridcell"`, and each day button carries `aria-selected`, `aria-disabled`, and `aria-current="date"` for today.

| Key | Behavior |
|---|---|
| Arrow keys | Move focus day to day, across week boundaries (up/down by seven days) and across month edges, changing the visible month when the target spills out |
| `PageUp` / `PageDown` | Move focus to the same day one month back or forward |
| `Home` / `End` | Move focus to the first or last day of the current week |
| `Enter` / `Space` | Select the focused day (or start/reorder/reset a range) |

Exactly one day button is a tab stop at a time (roving `tabindex`); it lands on today when the visible month shows it, else the first day of the month.
