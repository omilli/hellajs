## Usage

The image owns its load state and the fallback reads it through one explicit signal you pass to both parts: `AvatarImage` hides its `img` while the signal reads false and flips it on the native `load`/`error` events, and `AvatarFallback` hides while the same signal reads true. Both parts stay mounted (the swap is attribute-driven, not conditional rendering), so a broken URL that fires `error` drops the image back out and the initial returns:

### jsx

```jsx
import { signal } from '@hellajs/core';
import Avatar, { AvatarFallback, AvatarImage } from './components/avatar';

const loaded = signal(false);

const Portrait = () => (
  <Avatar>
    <AvatarImage src="/milli.png" alt="Milli" loaded={loaded} />
    <AvatarFallback loaded={loaded}>M</AvatarFallback>
  </Avatar>
);
```
### html

The html-format (`--format html`) works the same way.

```js
html`<main>
  <${Avatar}>
    <${AvatarImage} src="/milli.png" alt="Milli" loaded=${loaded} />
    <${AvatarFallback} loaded=${loaded}>M</${AvatarFallback}>
  </${Avatar}>
</main>`
```

An `AvatarImage` without a shared signal still hides itself until its own load resolves; pass the signal only when a sibling fallback must react.

## Groups

`AvatarGroup` overlaps its avatars with a negative offset and a background ring; `AvatarGroupCount` picks up the group's size:

```jsx
import Avatar, { AvatarFallback, AvatarGroup, AvatarGroupCount } from './components/avatar';

const Team = () => (
  <AvatarGroup>
    <Avatar><AvatarFallback>M</AvatarFallback></Avatar>
    <Avatar><AvatarFallback>J</AvatarFallback></Avatar>
    <AvatarGroupCount>+5</AvatarGroupCount>
  </AvatarGroup>
);
```

## Sizes

`size` sets `data-size` (`sm`, `default`, `lg`); the root, fallback, and badge read it through group selectors, so one prop rescales the whole stack. The badge pins to the bottom-right corner:

```jsx
import Avatar, { AvatarBadge, AvatarFallback } from './components/avatar';

const Statused = () => (
  <Avatar size="lg">
    <AvatarFallback>M</AvatarFallback>
    <AvatarBadge />
  </Avatar>
);
```

## Manual Parts

`AvatarImage`, `AvatarFallback`, `AvatarBadge`, `AvatarGroup`, and `AvatarGroupCount` ship beside the default root for custom composition.

### AvatarImage

The portrait: an `img` carrying `data-slot="avatar-image"`, hidden until its load state resolves.

| Prop | Type | Behavior |
|---|---|---|
| `src` | `string` | Image URL |
| `alt` | `string` | Alternative text |
| `loaded` | `Signal<boolean>` | Shared load state: flipped to `true` on the native `load` event, back to `false` on `error`; defaults to a private signal |

### AvatarFallback

The initial: a `span` carrying `data-slot="avatar-fallback"`, hidden while the shared signal reads true.

| Prop | Type | Behavior |
|---|---|---|
| `loaded` | `() => boolean` | The image's shared signal; hides the fallback while it reads true |
| `children` | `HellaChildren` | Fallback node, typically an initial |

### AvatarBadge

The status dot: a `span` carrying `data-slot="avatar-badge"`, pinned to the bottom-right corner.

| Prop | Type | Behavior |
|---|---|---|
| `children` | `HellaChildren` | Content inside the badge |

### AvatarGroup

The overlapping row: a `div` carrying `data-slot="avatar-group"`.

| Prop | Type | Behavior |
|---|---|---|
| `children` | `HellaChildren` | The stacked avatars and count chip |

### AvatarGroupCount

The count chip: a `div` carrying `data-slot="avatar-group-count"`, scaled by the group's `data-size`.

| Prop | Type | Behavior |
|---|---|---|
| `children` | `HellaChildren` | Count label, e.g. `+5` |

Every part also takes a `class` string, landing last in its style composition.
