## API

The `Menubar` root renders the `role="menubar"` bar and owns which menu is open: an internal value signal holding the open menu's id, or the controlled `value` accessor with `onValueChange` reporting every flip. Each `MenubarMenu` wrapper owns one menu: it renders the trigger button and portals its `content` under the bar, and takes a `value` id that names it in the bar's store.

The bar and its menus coordinate through a document-level announcement: opening a menu announces its id, siblings close on a foreign announcement (the second trigger click closes the first menu), and the bar mirrors the announcement into its value store.

The content anchors against its trigger (bottom, start aligned, 8px gap, -4px cross-axis shift) and dismisses through [`layerDismissal`](/reference/dom/layerdismissal): Escape and an outside pointerdown close the top layer, item activation closes every open layer, and focus returns to the trigger.

Fourteen named parts ship beside the default `Menubar`: `MenubarMenu`, `MenubarTrigger`, `MenubarGroup`, `MenubarContent`, `MenubarItem`, `MenubarCheckboxItem`, `MenubarRadioGroup`, `MenubarRadioItem`, `MenubarLabel`, `MenubarSeparator`, `MenubarShortcut`, `MenubarSub`, `MenubarSubTrigger`, and `MenubarSubContent`. The item parts take the same explicit-state props as their dropdown-menu counterparts: the checkbox item takes a `checked` accessor, the radio group is items-driven, and each sub owns its own open signal with hover-intent timing.

### Menubar

| Prop | Type | Default |
| ---- | ---- | ------- |
| `value` | `() => string` | `-` |
| `onValueChange` | `(value: string) => void` | `-` |
| `class` | `string` | `-` |
| `children` | `HellaChildren` | The `MenubarMenu` wrappers |

A controlled `value` is the open menu's id ("" when closed); when given, the bar never writes its internal signal.

### MenubarMenu

One menu: the trigger button plus its portaled content, named in the bar's store by its `value`.

| Prop | Type | Default |
| ---- | ---- | ------- |
| `value` | `string` | Generated |
| `open` | `() => boolean` | `-` |
| `onOpenChange` | `(open: boolean) => void` | `-` |
| `children` | `HellaChildren` | The trigger label |
| `content` | `HellaChildren` | The menu items, portaled while open |

A controlled `open` accessor supports manual wiring without the bar; `onOpenChange` reports this menu's flips.

### MenubarTrigger

The menu button inside the bar, accent-highlighted while its menu is open.

| Prop | Type | Default |
| ---- | ---- | ------- |
| `children` | `HellaChildren` | The trigger label |

### MenubarContent

The `role="menu"` surface with the full keyboard model, anchored against its trigger.

| Prop | Type | Default |
| ---- | ---- | ------- |
| `state` | `() => "open" \| "closed"` | `-` |
| `id` | `string` | `-` |
| `side` | `"top" \| "bottom" \| "left" \| "right"` | `"bottom"` |
| `align` | `"start" \| "center" \| "end"` | `"start"` |
| `sideOffset` | `number` | `8` |
| `alignOffset` | `number` | `-4` |
| `anchor` | `() => Element \| undefined` | `-` |
| `onDismiss` | `() => void` | `-` |
| `onExited` | `() => void` | `-` |
| `onArrow` | `(direction: "left" \| "right") => void` | `-` |
| `children` | `HellaChildren` | The menu items |

`state` drives `data-state` and the enter/exit cycle; `closed` tears the wirings down. The anchor resolves to the element the content anchors to; positioning is skipped when undefined. `onDismiss` receives Escape and outside pointerdowns from the top layer, and item selection closes every open layer through it; `onExited` fires when the exit animation ends. Both horizontal arrows report outward through `onArrow` (bar open-then-move) when the focused item is not a sub-trigger.

### MenubarItem

A `role="menuitem"` row; activation closes every open layer.

| Prop | Type | Default |
| ---- | ---- | ------- |
| `onclick` | `() => void` | `-` |
| `destructive` | `boolean` | `-` |
| `inset` | `boolean` | `-` |
| `disabled` | `boolean` | `-` |
| `shortcut` | `string` | `-` |
| `children` | `HellaChildren` | The row's label |

`onclick` fires before the close-all activation event; `destructive` renders the destructive `data-variant` treatment; `inset` renders `data-inset="true"`; `disabled` renders `data-disabled` plus `aria-disabled` and blocks `onclick` and the close; `shortcut` renders as a trailing `MenubarShortcut` span.

Every part also takes a `class` string, landing last in its style composition. Menus keep their own open state, so a menu also composes standalone through `MenubarMenu` with explicit `open` and `onOpenChange` props, and the item parts wire manually exactly as in the dropdown-menu entry.

## Keyboard Interaction

| Key | Behavior |
|---|---|
| `ArrowLeft` / `ArrowRight` | Bar closed: moves focus between triggers with wrap. A menu open: switches to the adjacent menu (open then move), wrapping at the ends |
| `ArrowDown` / `Enter` | Opens the focused trigger's menu; inside, roves items with wrap and skips disabled entries |
| `Home` / `End` | Jumps to the first or last activatable item |
| `Enter` / `Space` | Activates the focused item; ArrowRight on a focused sub-trigger opens the submenu |
| `ArrowLeft` (in a submenu) | Closes the submenu, one layer per press |
| `Escape` | Closes the top layer and returns focus to its trigger |
| `Tab` | Closes every open layer |
| printable keys | Typeahead: selects the first item starting with the buffered keys |
