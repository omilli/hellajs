## Usage

You compose the slots yourself: group them, place the separator between groups, and give every slot its zero-based `index`. The root owns the state and wires the slots after mount, so a slot renders whatever its index holds:

### jsx

```jsx
import {
  InputOTP,
  InputOTPGroup,
  InputOTPSeparator,
  InputOTPSlot,
} from './components/input-otp';

const Verify = () => (
  <InputOTP
    length={6}
    onComplete={(code) => console.log('verifying', code)}
  >
    <InputOTPGroup>
      <InputOTPSlot index={0} />
      <InputOTPSlot index={1} />
      <InputOTPSlot index={2} />
    </InputOTPGroup>
    <InputOTPSeparator />
    <InputOTPGroup>
      <InputOTPSlot index={3} />
      <InputOTPSlot index={4} />
      <InputOTPSlot index={5} />
    </InputOTPGroup>
  </InputOTP>
);
```
### html

The html-format (`--format html`) works the same way; children sit between the part tags.

```js
html`<main>
  <${InputOTP} length=${6}>
    <${InputOTPGroup}>
      <${InputOTPSlot} index=${0} />
      <${InputOTPSlot} index=${1} />
      <${InputOTPSlot} index=${2} />
    </${InputOTPGroup}>
    <${InputOTPSeparator} />
    <${InputOTPGroup}>
      <${InputOTPSlot} index=${3} />
      <${InputOTPSlot} index=${4} />
      <${InputOTPSlot} index=${5} />
    </${InputOTPGroup}>
  </${InputOTP}>
</main>`
```

### InputOTP

| Prop | Type | Behavior |
|---|---|---|
| `length` | `number` | Slot count; fixed after mount. Defaults to `6` |
| `value` | `string \| (() => string)` | The code. A static string seeds the internal state; an accessor makes it controlled, so edits report through `onChange` only |
| `onChange` | `(value: string) => void` | Reports every accepted value change: typing, paste, and deletion |
| `onComplete` | `(value: string) => void` | Fires once per transition to a full code |
| `pattern` | `RegExp` | Whole-value gate: an edit whose result fails the test is rejected and the previous value stands. The source lands on the input's `pattern` attribute |
| `autoFocus` | `boolean` | Focuses the hidden input on mount |
| `disabled` | `boolean` | Disables the hidden input, blocks edits, and dims the group |
| `class` | `string` | Lands on the root next to the component class |
| `children` | slots and groups | The user-composed layout; the root renders them under the transparent input |

### InputOTPGroup

A `flex items-center` wrapper for related slots. Takes `children` and an optional `class`.

### InputOTPSlot

A state mirror for one position, not an input. The root drives its character text, `data-active` marker, and fake caret after mount, so the slot only carries `index` (plus an optional `class`).

| Prop | Type | Behavior |
|---|---|---|
| `index` | `number` | The position this slot mirrors |
| `class` | `string` | Lands next to the slot class |

### InputOTPSeparator

The dash divider between groups (`role="separator"` wrapping the minus glyph). Takes an optional `class`; the root's `gap-2` provides the spacing.

## The Hidden Input Technique

One real `<input>` spans the whole component (inline styles make it transparent and caret-free), so the browser owns everything textual: printable keys insert at the selection, IME composition drafts and commits work untouched, Backspace and Delete behave natively, and paste flows through the clipboard pipeline. The component only listens:

- `input` events sync the value signal from the element and report through `onChange`, clipped to `length`.
- `selectionchange` remaps the native caret onto the slot it sits in: a collapsed caret becomes a one-character selection covering that slot, which is why Backspace clears the active slot and the arrows move the highlight exactly one slot per press.
- `focus` places the selection on the next empty slot (the last filled slot when the code is full), `blur` clears the active marker.
- `paste` inserts the clipboard text at the selection, clips to `length`, and runs the same pattern gate as typing.

Slots read `(value, focused, selection)` signals, so `data-active` marks the caret slot and the blinking caret bar renders only on an active empty slot.

## Pattern Gating

Restrict the code to digits by passing a whole-value `RegExp`; a rejected edit leaves the previous code standing:

```jsx
import { InputOTP, InputOTPGroup, InputOTPSlot } from './components/input-otp';

const Digits = () => (
  <InputOTP length={4} pattern={/^\d+$/}>
    <InputOTPGroup>
      <InputOTPSlot index={0} />
      <InputOTPSlot index={1} />
      <InputOTPSlot index={2} />
      <InputOTPSlot index={3} />
    </InputOTPGroup>
  </InputOTP>
);
```

## Controlled Value

Drive the code from your own state by passing `value` as an accessor; writes from outside render straight into the slots, while user edits report through `onChange`:

```jsx
import { signal } from '@hellajs/core';
import { InputOTP, InputOTPGroup, InputOTPSlot } from './components/input-otp';

const code = signal('');

const Controlled = () => (
  <InputOTP length={6} value={code} onChange={(next) => code(next)}>
    <InputOTPGroup>
      <InputOTPSlot index={0} />
      <InputOTPSlot index={1} />
      <InputOTPSlot index={2} />
      <InputOTPSlot index={3} />
      <InputOTPSlot index={4} />
      <InputOTPSlot index={5} />
    </InputOTPGroup>
  </InputOTP>
);
```

## Intentionally Absent

Some pieces common to this component family are absent by design; they stay out rather than approximated:

- There is no context primitive. The root wires its descendant slots (by `data-index`) after mount, so composition stays user-side.
- `containerClassName`, `maxLength`, `placeholder`, `pasteTransformer`, `pushPasswordManagerStrategy`, and the `render` prop are not ported: `length` replaces `maxLength`, `class` lands on the root, and layout is user composition.
- The password-manager badge space, autofill style injection, and the `data-input-otp-mss`/`-mse` debug attributes are dropped. The css flavor folds the selection and autofill transparency into the control class; the tailwind flavor keeps only the inline hiding, so drag-selecting the invisible text can flash a selection highlight there.
- Click-to-slot caret placement is approximate. Focus always lands on the target slot, and keyboard navigation is exact.
- A slot carries no `data-filled` attribute: it exposes only the character, the fake caret, and the active flag, and a filled slot is simply one that renders a character.

## Accessibility

The hidden input carries `autocomplete="one-time-code"` and `inputmode="numeric"`, so mobile keyboards open the digit layout and password managers offer SMS codes.

| Key | Behavior |
|---|---|
| Printable keys | Insert at the caret (subject to `pattern`); the caret slot advances |
| `Backspace` | Clears the active slot, or the selection when a range is marked, and moves the highlight back |
| Arrow keys | Move the active slot one position left or right |
| `Home` / `End` | Move to the first slot or the next empty slot (the last slot when full) |
