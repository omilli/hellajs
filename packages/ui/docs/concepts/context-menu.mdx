# Context Menu

A right-click menu styled to shadcn's ContextMenu: long-pressing (right-clicking) a trigger zone opens a portaled surface of items anchored at the pointer coordinates; checkbox, radio, and submenu composition match the dropdown menu, and item selection closes the whole menu.

## Usage

The composed `ContextMenu` wraps its children in a trigger zone and takes the items through the `content` prop. A `contextmenu` event (right-click, or the long-press equivalent) preventDefaults the browser menu and opens the surface; Escape and an outside press dismiss it.

```jsx
import ContextMenu from './components/context-menu';
import { ContextMenuItem } from './components/context-menu';

const Canvas = () => (
  <ContextMenu
    content={
      <>
        <ContextMenuItem onclick={() => console.log('cut')}>Cut</ContextMenuItem>
        <ContextMenuItem shortcut="⌘C">Copy</ContextMenuItem>
      </>
    }
  >
    Right-click this zone
  </ContextMenu>
);
```

| Prop | Default | Behavior |
|---|---|---|
| `open` | - | Controlled open accessor; when given, the root never writes its internal signal |
| `onOpenChange` | - | Reports every requested open and close flip |
| `children` | - | The trigger zone content |
| `content` | - | The menu items, portaled into `document.body` while open |
| `class` | - | Extra classes on the trigger zone |

The html-format file (`context-menu.ts`, copied with `--format html`) renders through a template instead of JSX; the menu mounts as a reactive child of whatever wraps it:

```js
import { html, mount } from '@hellajs/dom';
import ContextMenu from './components/context-menu';

mount(
  html`
    <main>
      <${ContextMenu} content=${html`<p>One item.</p>`}>
        Right-click zone
      </${ContextMenu}>
    </main>
  `,
  '#app',
);
```

Coordinate anchoring: opening plants a zero-size fixed anchor node at the pointer position (`data-slot="context-menu-anchor"` in the document body) and positions the surface against it through [`anchorPosition`](/reference/dom/behaviors) on the `bottom-start` placement, so the menu's top-left corner sits at the click point with the same collision flipping and scroll or resize repositioning as every anchored overlay. Reopening moves the anchor; closing removes it and restores focus to the trigger zone.

Dismissal runs through [`layerDismissal`](/reference/dom/behaviors): Escape and a pointerdown outside the panel ask the top layer to close, so stacked menus dismiss one layer at a time. Activating an item closes every open menu layer (upstream close-on-select) through a document-level activation event, which is also how Enter and Space close from the keyboard. Focus moves to the first activatable item on open; the menu is non-modal, with no focus trap.

## Structure Parts

Thirteen named parts ship beside the default `ContextMenu`: `ContextMenuTrigger`, `ContextMenuContent`, `ContextMenuGroup`, `ContextMenuItem`, `ContextMenuCheckboxItem`, `ContextMenuRadioGroup`, `ContextMenuRadioItem`, `ContextMenuLabel`, `ContextMenuSeparator`, `ContextMenuShortcut`, `ContextMenuSub`, `ContextMenuSubTrigger`, and `ContextMenuSubContent`. The content model is the dropdown menu's, duplicated per the registry's self-contained rule; only the trigger differs (a passive zone owning the `contextmenu` listener instead of a Button-wrapped toggle).

| Part | Props beyond `children`/`class` | Renders |
|---|---|---|
| `ContextMenuTrigger` | - | The manual trigger zone (`span`) |
| `ContextMenuContent` | `state`, `id`, `side`, `align`, `anchor`, `onDismiss`, `onExited`, `onArrowLeft` | The `role="menu"` surface with the full keyboard model |
| `ContextMenuGroup` | - | A passthrough grouping div |
| `ContextMenuItem` | `destructive`, `inset`, `disabled`, `onclick`, `shortcut` | A `role="menuitem"` row; activation closes every open layer |
| `ContextMenuCheckboxItem` | `checked`, `onCheckedChange`, `disabled` | A `role="menuitemcheckbox"` row with the check indicator |
| `ContextMenuRadioGroup` | `items`, `value`, `onValueChange` | A group rendering one radio item per entry |
| `ContextMenuRadioItem` | `value`, `checked`, `onSelect`, `disabled` | A `role="menuitemradio"` row with the circle indicator |
| `ContextMenuLabel` | `inset` | A section label |
| `ContextMenuSeparator` | - | A `-mx-1` hairline |
| `ContextMenuShortcut` | - | The trailing key-hint span (also rendered by `Item`'s `shortcut` prop) |
| `ContextMenuSub` | `content` | A sub-trigger plus its portaled sub-content, open state owned here |
| `ContextMenuSubTrigger` | `inset`, `state`, `onOpen` | The manual sub-trigger row (chevron, `aria-haspopup`) |
| `ContextMenuSubContent` | `state`, `side`, `align`, `anchor`, `onDismiss`, `onExited`, `onArrowLeft`, `onPointerEnter` | The `role="menu"` sub-surface |

A representative subset over one surface - destructive action, checkbox toggle, and a submenu:

```jsx
import { signal } from '@hellajs/core';
import ContextMenu from './components/context-menu';
import {
  ContextMenuItem,
  ContextMenuCheckboxItem,
  ContextMenuSeparator,
  ContextMenuSub,
} from './components/context-menu';

const locked = signal(false);

const File = () => (
  <ContextMenu
    content={
      <>
        <ContextMenuItem>Rename</ContextMenuItem>
        <ContextMenuCheckboxItem
          checked={() => locked()}
          onCheckedChange={(next) => locked(next)}
        >
          Locked
        </ContextMenuCheckboxItem>
        <ContextMenuSeparator />
        <ContextMenuSub content={<ContextMenuItem>Compress</ContextMenuItem>}>
          Archive
        </ContextMenuSub>
        <ContextMenuItem destructive disabled={locked()}>
          Delete
        </ContextMenuItem>
      </>
    }
  >
    file-card
  </ContextMenu>
);
```

A boolean `checked` seeds the internal signal; an accessor makes the item controlled, so activation only reports through `onCheckedChange`. The sub opens on hover after roughly 100ms of rest, on click, or on ArrowRight, anchors against its trigger, and hands Escape to its own dismissal layer first.

### Keyboard Interaction

| Key | Behavior |
|---|---|
| `ArrowDown` / `ArrowUp` | Roves items with wrap, skipping disabled entries |
| `Home` / `End` | Jumps to the first or last activatable item |
| `Enter` / `Space` | Activates the focused item (toggles checkbox and radio rows) |
| `ArrowRight` / `ArrowLeft` | Enters a focused sub-trigger or exits the sub; flips with the resolved writing direction |
| `Escape` | Dismisses the top layer only |
| `Tab` | Closes every open layer |
| printable keys | Typeahead: selects the first item starting with the buffered keys |

The menu opens from the pointer, so there is no trigger-key open path: keyboard users reach a context menu through the surrounding app (for example a button that opens a controlled `ContextMenu` via its `open` accessor).

## Styling

The module exports `content` and `subContent` (the popover surface at `min-width: 8rem` with border, shadow, and enter and exit keyframes composed from fade, a 95% zoom, and the side's slide direction), `item`, `checkItem`, and `radioItem` (focus-highlighted rows with destructive, inset, and disabled selectors), `indicator`, `icon`, and `radioIcon` (the selection indicators), plus `label`, `separator`, `shortcut`, `subTrigger`, and `chevron`. The css flavor composes classes as a plain array in each part's `class` attribute, with declarations in [`style`](/reference/css/style) maps under the `hella` cascade layer, so unlayered author CSS always wins over the component's own rules; the tailwind flavor uses shadcn's literal utilities verbatim (`bg-popover`, `min-w-[8rem]`, `shadow-md`, the `data-[state=open]:animate-in` set, the `data-[side=…]` slide variants, the `data-[variant=destructive]` and `dark:` item states, and the `[&_svg]` icon sizing rules) wrapped in `cn()` so later tokens override earlier ones per utility group, with the enter and exit motion carried by `tw-animate-css`. The copied budget is 150ms both ways. The panel's look is the whole of `content` - restyle it there; the open placement is the `bottom-start` default in the composed root's anchor wiring, and manual compositions change it through the `side` and `align` passed to `ContextMenuContent`. Hold the menu open against item activation by removing the activation event dispatch from the item's click handler, and hold it against Escape and outside presses by composing `ContextMenuContent` without `onDismiss`. Flavor choice and theme setup: [Installation](/ui/installation). Tokens and the override contract: [Theming](/ui/theming).
