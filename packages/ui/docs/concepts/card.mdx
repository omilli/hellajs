# Card

A panel surface styled to shadcn's seven-part Card: a default `Card` plus named `CardHeader`, `CardTitle`, `CardDescription`, `CardAction`, `CardContent`, and `CardFooter` parts, each carrying its `data-slot` and composable in any arrangement.

## Usage

Every part takes `{ children?, class? }`, and the header automatically switches to a two-column grid when a `CardAction` is present.

```jsx
import Card, { CardAction, CardContent, CardDescription, CardFooter, CardHeader, CardTitle } from './components/card';
import Button from './components/button';

const ProfileCard = () => (
  <Card class="w-80">
    <CardHeader>
      <CardTitle>Ada Lovelace</CardTitle>
      <CardDescription>Wrote the first program.</CardDescription>
      <CardAction>
        <Button size="sm" variant="outline">Follow</Button>
      </CardAction>
    </CardHeader>
    <CardContent>
      <p>Published notes on the Analytical Engine in 1843.</p>
    </CardContent>
    <CardFooter>
      <Button>Read the paper</Button>
    </CardFooter>
  </Card>
);
```

The html-format file (`card.ts`, copied with `--format html`) renders through a template instead of JSX; each part is a plain function call:

```js
import { html, mount } from '@hellajs/dom';
import Card, { CardContent, CardDescription, CardHeader, CardTitle } from './components/card';

mount(
  html`
    <main>
      <${Card} class="w-80">
        ${CardHeader({
          children: [
            CardTitle({ children: 'Ada Lovelace' }),
            CardDescription({ children: 'Wrote the first program.' }),
          ],
        })}
        ${CardContent({ children: html`<p>Published notes on the Analytical Engine in 1843.</p>` })}
      </${Card}>
    </main>
  `,
  '#app',
);
```

## Styling

The style module exports one class per part (`base`, `header`, `title`, `description`, `action`, `content`, `footer`), and each part's compose bakes its own class plus `props.class`, which lands last. Every part renders its `data-slot` (`card`, `card-header`, `card-title`, `card-description`, `card-action`, `card-content`, `card-footer`), so one-off overrides can also target parts through the `[data-slot]` attribute selectors. The css flavor composes [`style`](/reference/css/style) maps under the `hella` cascade layer, so unlayered author CSS always wins; the tailwind flavor wraps shadcn's literal utilities (`bg-card`, `rounded-xl`) in `cn()` so later tokens override earlier ones per utility group. Edit any map in place to restyle that part everywhere. Flavor choice and theme setup: [Installation](/ui/installation). Tokens and the override contract: [Theming](/ui/theming).
