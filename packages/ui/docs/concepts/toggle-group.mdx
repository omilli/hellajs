## API

The composed root takes an items list, not children slots; items render joined into one segment strip (`data-spacing="0"`, `--gap: 0`). The `data-[spacing=...]` classes ride along in both style modules, so relaxing the joined strip into spaced buttons is an edit of the copied file away.

### ToggleGroup

| Prop | Type | Default |
| ---- | ---- | ------- |
| `items` | `{ value, label?, pressed?, disabled? }[] \| (() => { value, label?, pressed?, disabled? }[])` | `-` |
| `keyBy` | `"value"` | `-` |
| `type` | `"single" \| "multiple"` | `"single"` |
| `value` | `() => string` | `-` |
| `values` | `() => string[]` | `-` |
| `onValueChange` | `(value: string \| string[]) => void` | `-` |
| `variant` | `"default" \| "outline"` | `"default"` |
| `size` | `"default" \| "sm" \| "lg"` | `"default"` |
| `class` | `string` | `-` |

Accepts all native `div` attributes (forwarded to the root element).

`pressed` in an item seeds the uncontrolled state. Without `value` / `values`, the root owns its state seeded by the items' `pressed` flags: in single mode, clicking the active item deselects it and reports `""`; in multiple mode, clicking toggles membership and reports the full array. Pass an accessor (`value` for single, `values` for multiple) and the group becomes controlled: clicks turn into `onValueChange` requests without writing state, so a parent signal that ignores the request keeps the selection unchanged.

### ToggleGroupItem

One pressed-state button inside the group; it renders the joined-segment classes and the `data-variant` / `data-size` / `data-spacing` attributes the styles key off.

| Prop | Type | Default |
| ---- | ---- | ------- |
| `value` | `string` | `-` |
| `pressed` | `boolean \| (() => boolean)` | `-` |
| `onSelect` | `() => void` | `-` |
| `variant` | `"default" \| "outline"` | `"default"` |
| `size` | `"default" \| "sm" \| "lg"` | `"default"` |
| `children` | `HellaChildren` | `-` |

Accepts all native `button` attributes (forwarded to the button element): `disabled` gates the item and the roving walk skips it.

A boolean `pressed` reads statically, an accessor keeps the manual part reactive; it drives `aria-pressed` and `data-state` (`on` / `off`).

Every part also takes a `class` string, landing last in its style composition.

## Accessibility

| Aspect | Value |
|---|---|
| Roles | `group` on the root; each item is a toggle button carrying `aria-pressed` in both modes |
| State | `aria-pressed` plus `data-state` (`on` / `off`) per item |
| Keyboard | Arrow keys move focus (wrapping at both ends); Space and Enter toggle through native button activation; disabled items are skipped |
| Tab | Roving tabindex: `0` on the first item, `-1` on the rest; selection never steals focus |
| Labeling | Item text content names each button; icon-only items pair an `aria-label` attribute |

## Dynamic items

`items` reads once at mount when passed a plain array; pass a signal accessor and the items re-render as the array grows, shrinks, or reorders:

```jsx
import { signal } from "@hellajs/core";
import { ToggleGroup } from "./components/toggle-group";

const styles = signal([
  { value: "bold", label: "Bold" },
  { value: "italic", label: "Italic" },
]);

<ToggleGroup items={styles} keyBy="value" type="multiple" />;

// Appends a live item without remounting the existing ones.
styles([...styles(), { value: "underline", label: "Underline" }]);
```

By default items key by array index: a reorder rebuilds them, losing transient state such as focus (pressed state re-derives from the group's signal either way). `keyBy="value"` reuses each item's DOM by its entry `value` instead, so nodes move to their new positions intact through reorders and removals. Order always follows the array, never the key history. An item reused under the same `value` keeps its rendered children, so swapping an entry's `label` under a repeated value needs a getter for that content to reach the DOM.
