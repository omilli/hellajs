# Toggle Group

A set of pressed-state buttons styled to shadcn's ToggleGroup: a `role="group"` root that renders one item button per entry, in single (one active value) or multiple (a set of active values) mode. Arrow keys move focus through the same [roving tabindex](/reference/dom/behaviors) model Tabs uses, while selection changes only on click. Items render joined into one segment strip, the ref's default spacing.

## Usage

The composed root takes an items array, not children slots:

| Prop | Type | Behavior |
|---|---|---|
| `items` | `{ value, label?, pressed?, disabled? }[]` | One item button per entry; `pressed` seeds the uncontrolled state |
| `type` | `"single" \| "multiple"` | Single keeps one active value; multiple keeps a set |
| `value` | `() => string` | Controlled single selection |
| `values` | `() => string[]` | Controlled multiple selection |
| `onValueChange` | `(value: string \| string[]) => void` | Single reports the newly active value (`""` when deselected); multiple reports the full active array |
| `variant` | `"default" \| "outline"` | Visual map from the ref (`default`) |
| `size` | `"default" \| "sm" \| "lg"` | Size map from the ref (`default`) |
| `class` | `string` | Lands on the root next to the component class |

```jsx
import ToggleGroup from './components/toggle-group';

const Formats = () => (
  <ToggleGroup
    type="multiple"
    items={[
      { value: 'bold', label: 'B' },
      { value: 'italic', label: 'I', pressed: true },
      { value: 'underline', label: 'U' },
    ]}
  />
);
```

The html-format file (`toggle-group.ts`, copied with `--format html`) works the same way from a template; build the items array once and pass it in:

```js
import { html, mount } from '@hellajs/dom';
import ToggleGroup from './components/toggle-group';

const items = [
  { value: 'day', label: 'Day' },
  { value: 'week', label: 'Week' },
];

mount(html`<main><${ToggleGroup} type="single" items=${items} /></main>`, '#app');
```

## Controlled and Uncontrolled

Without `value` / `values`, the root owns its state seeded by the items' `pressed` flags. In single mode, clicking the active item deselects it and reports `""`; in multiple mode, clicking toggles membership and reports the full array. Pass an accessor (`value` for single, `values` for multiple) and the group becomes controlled: clicks turn into `onValueChange` requests without writing state, so a parent signal that ignores the request keeps the selection unchanged.

```jsx
import { signal } from '@hellajs/core';
import ToggleGroup from './components/toggle-group';

const view = signal('week');

const Controlled = () => (
  <ToggleGroup
    type="single"
    items={[
      { value: 'day', label: 'Day' },
      { value: 'week', label: 'Week' },
    ]}
    value={() => view()}
    onValueChange={(next) => view(next)}
  />
);
```

## Manual Parts

`ToggleGroupItem` ships beside the default root for custom composition. The part takes a `pressed` accessor (boolean or function), an `onSelect` callback, and the `variant` / `size` to resolve; it renders the joined-segment classes and `data-variant` / `data-size` / `data-spacing` attributes the styles key off.

```jsx
import { signal } from '@hellajs/core';
import { ToggleGroupItem } from './components/toggle-group';

const active = signal(false);

const Custom = () => (
  <ToggleGroupItem
    value="custom"
    pressed={() => active()}
    onSelect={() => active(!active())}
    variant="outline"
  >
    Custom
  </ToggleGroupItem>
);
```

## Divergences

The ref exposes a `spacing` prop that relaxes the joined segments into spaced buttons. This port pins the rendered output to the ref default (`data-spacing="0"`, `--gap: 0`): items render as one strip. The `data-[spacing=...]` classes ride along in both style modules, so restoring the prop is an edit of the copied file away. Group items also carry `aria-pressed` in both modes: each item is a toggle button, matching the Radix ref.

## Accessibility

| Aspect | Value |
|---|---|
| Roles | `group` on the root; each item is a toggle button |
| State | `aria-pressed` plus `data-state` (`on` / `off`) per item |
| Keyboard | Arrow keys move focus (wrapping at both ends); Space and Enter toggle through native button activation; disabled items are skipped |
| Tab | Roving tabindex: `0` on the first item, `-1` on the rest; selection never steals focus |
| Labeling | Item text content names each button; icon-only items pair an `aria-label` through an edited copy of the file |

## Styling

Both flavors export the same names from the copied file: `base` (the group root), `variants` and `sizes` (the toggle maps, duplicated because entries never cross-import), and `item` (the joined-segment extras, registered after the maps so its radius and shadow resets win the cascade). The css flavor composes [`style`](/reference/css/style) maps under the `hella` cascade layer, so unlayered author CSS always wins; the tailwind flavor wraps plain utility strings in `cn()`, verbatim from the ref including the `data-[spacing=0]` item conditions and the first/last rounding. To restyle every item at once, edit the `item` map; `props.class` lands on the root next to `base`. A variant tweak in the group file stays consistent with the standalone Toggle entry only if you mirror it there; the two files are intentionally independent. Flavor choice and theme setup: [Installation](/ui/installation). Tokens and the override contract: [Theming](/ui/theming).
