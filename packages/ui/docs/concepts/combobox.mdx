# Combobox

A filterable listbox styled to shadcn's Combobox: the input owns a query signal, the panel anchors to the input wrapper, and typing narrows the options case-insensitively; Enter commits the active option, and `multiple` mode toggles values into removable chips.

## Install

```bash
bunx @hellajs/ui add combobox
```

`--style css|tailwind` picks the flavor (css is the default) and `--format jsx|html` picks the canonical file; both are remembered in `hella.ui.json` once `bunx @hellajs/ui init` has run. The component copies as one editable file into `src/components/`; there is no importable package surface.

Every project adds its theme entry once, then every component reads the same properties:

```bash
bunx @hellajs/ui add theme
```

| Style | Extra peers | Theme artifact |
|---|---|---|
| css (default) | `@hellajs/css` | `tokens.js`, a [`vars`](/reference/css/vars) sheet collected by `cssText()` for SSR |
| tailwind | `clsx`, `tailwind-merge` | `theme.css` plus `cn.ts` |

The combobox copies its input-group shell inline (the entry never cross-imports), and wires its positioning, dismissal, and typeahead from the copied file using `@hellajs/dom` behavior functions.

## Composing a Combobox

The composed `Combobox` takes its options as data and renders the input shell plus the portaled panel. Focusing the input opens the panel; typing filters it.

```jsx
import Combobox from './components/combobox';

const fruits = [
  { value: 'apple', label: 'Apple' },
  { value: 'blueberry', label: 'Blueberry' },
  { value: 'canteloupe', label: 'Canteloupe' },
];

const FruitPicker = () => (
  <Combobox items={fruits} placeholder="Search fruit" onValueChange={(value) => console.log(value)} />
);
```

| Prop | Default | Behavior |
|---|---|---|
| `items` | - | `{ value, label?, disabled? }[]` rendered as options in order |
| `value` | - | Controlled selection accessor; a string in single mode, an array in multiple mode. When given, the root never writes its internal signal |
| `onValueChange` | - | Reports the requested selection (string, or array in multiple mode) |
| `multiple` | - | Toggles values in and out of an array and renders removable chips |
| `placeholder` | - | The input's placeholder text |
| `filter` | - | Replaces the default case-insensitive substring filter |
| `showClear` | - | Renders the panel's clear affordance while a value is selected (single mode) |
| `class` | - | Extra classes on the input wrapper |

## Filtering

The default filter is a case-insensitive substring match over item labels (falling back to the value when a label is missing); matching options stay visible while the rest hide in place. Options are never unmounted while filtering, so option ids stay stable for `aria-activedescendant`. When nothing matches, the panel marks itself `data-empty` and the built-in empty row shows through its `group-data-empty` styling.

Pass `filter` to replace the default entirely - it receives the full item list and the live query:

```jsx
const startsWith = (items, query) =>
  query ? items.filter((item) => item.value.startsWith(query)) : items;

const PrefixPicker = () => (
  <Combobox items={fruits} filter={startsWith} placeholder="Prefix match only" />
);
```

## Keyboard and Multiple Selection

The input keeps focus the whole time (`role="combobox"`): ArrowDown and ArrowUp move the active option (skipping disabled entries, wrapping at the edges), Enter commits it, and Escape clears the query and then closes. The active option carries `data-highlighted`, and the input's `aria-activedescendant` points at its id. Printable keystrokes also feed a [`menuTypeahead`](/reference/dom/behaviors) buffer that walks the visible options, so typing refines the filter and the highlight together.

In single mode, Enter closes the panel and clears the query. In `multiple` mode, Enter toggles the active value in or out of the array and the panel stays open; each selected value renders as a `ComboboxChip` whose remove button toggles it back out. `showClear` adds a clear affordance that wipes the whole selection.

Dismissal runs through [`layerDismissal`](/reference/dom/behaviors): Escape and a pointerdown outside the wrapper close the top layer. Closing starts the exit - the panel stays mounted under `data-state="closed"` until its animation ends, with dismissal wiring down while it leaves. The panel positions itself through [`anchorPosition`](/reference/dom/behaviors) with `matchAnchorWidth`, anchored to the input wrapper (the chips wrapper in multiple mode), flipping sides on viewport collision.

## Structure Parts

Fifteen named parts ship beside the default `Combobox`: `ComboboxTrigger`, `ComboboxInput`, `ComboboxContent`, `ComboboxList`, `ComboboxItem`, `ComboboxGroup`, `ComboboxLabel`, `ComboboxCollection`, `ComboboxEmpty`, `ComboboxSeparator`, `ComboboxValue`, `ComboboxClear`, `ComboboxChips`, `ComboboxChip`, and `ComboboxChipsInput`. hella has no base-ui-style context, so manual composition passes state explicitly: the list takes the items plus query, selection, and active resolvers; the input takes the aria wiring.

```jsx
import { signal } from '@hellajs/core';
import { Portal } from '@hellajs/dom';
import { ComboboxContent, ComboboxList, ComboboxItem } from './components/combobox';

const Manual = () => {
  const query = signal('');
  const current = signal('');
  let wrapper;

  return (
    <div hook:afterMount={(node) => { wrapper = node; }}>
      <input
        role="combobox"
        value={() => query()}
        on:input={(e) => query(e.target.value)}
      />
      {() => (
        <Portal to="body">
          <ComboboxContent anchor={() => wrapper} onDismiss={() => query('')}>
            <ComboboxList
              items={fruits}
              query={query}
              selected={(value) => current() === value}
              active={() => current()}
              onselect={(value) => { current(value); query(''); }}
            />
          </ComboboxContent>
        </Portal>
      )}
    </div>
  );
};
```

`ComboboxList({ id, items, query, filter, selected, active, onselect, empty, children, class })` renders the `role="listbox"` with one `ComboboxItem` per entry (hidden in place as the query filters) plus any static children such as `ComboboxEmpty`. `ComboboxInput({ value, onInput, onKeydown, onFocus, state, ariaControls, activeDescendant, showTrigger, showClear, onToggle, onClear, hasValue, wire, children, class })` renders the input-group shell with the chevron toggle and clear addons; `ComboboxChips`, `ComboboxChip`, and `ComboboxChipsInput` compose the multiple-mode surface, and `ComboboxContent({ state, side, align, sideOffset, anchor, chips, empty, onDismiss, onExited, children, class })` renders the positioned panel.

| Attribute | Where | Purpose |
|---|---|---|
| `role="combobox"` / `aria-expanded` / `aria-controls` / `aria-activedescendant` / `aria-autocomplete` | input | Combobox semantics; the active option is referenced by id |
| `role="listbox"` / `data-empty` | list | Options container; zero-match styling hook |
| `role="option"` / `aria-selected` / `data-state` / `data-highlighted` | item | Option semantics, the check indicator, and the active ring |
| `data-disabled` / `aria-disabled` | item | Skipped by roving and typeahead, unclickable |
| `data-chips` | content | Panel width styling in chips mode |

## Divergences from the upstream reference

- **The input owns the value display.** The selected value lives in `onValueChange` (render it through `ComboboxValue` where needed); the input always shows the query, never the selection.
- **Options hide in place.** base-ui unmounts filtered options; hella keeps every option mounted and hides non-matches, so option ids (and `aria-activedescendant` targets) stay stable across keystrokes.
- **No hidden form control.** Like the select, the combobox submits nothing by itself. Pair it with `native-select` (or a hidden input of your own) when a form needs the value.
- **`useComboboxAnchor` is gone.** The upstream hook returns a ref for the anchor; hella's composed root wires the anchor to the wrapper, and manual compositions pass `anchor={() => wrapperNode}` explicitly.

## CSS Style

The css flavor composes classes as a plain array in each part's `class` attribute; declarations live in [`style`](/reference/css/style) maps under the `hella` cascade layer, so unlayered author CSS always wins over the component's own rules. The module exports `base`, `input`, `inputFocus`, `inputInvalid`, and `inputControl` (the duplicated input-group shell under `hella-combobox` labels), `addon` (the trailing addon row), `buttonBase`, `buttonGhost`, `buttonSizeIconXs`, and `sizeIconXs` (the ghost icon-xs button pieces shared by the toggle, clear, and chip remove), `content` (the popover surface with the anchor-width sizing, ring, side-keyed keyframes at the copied 100ms budget, and the nested input-group overrides), `list` (the scrolling option container with its `data-empty` padding drop), `item` (the option row with the `data-highlighted` ring), `itemIndicator` and `icon` (the check slot and icon sizes), `label`, `separator`, `empty`, `chips`, `chip`, `chipsInput`, `trigger`, and `triggerIcon`, plus the small `triggerExtra`, `chipRemoveExtra`, and `xIcon` state helpers. `group` and `value` are empty.

```jsx
import Combobox from './components/combobox';

const Wide = () => (
  <Combobox items={fruits} multiple placeholder="Pick several" class="w-72" />
);
```

The html-format file (`combobox.ts`, copied with `--format html`) renders through a template instead of JSX; the combobox mounts as a reactive child of whatever wraps it:

```js
import { html, mount } from '@hellajs/dom';
import Combobox from './components/combobox';

mount(
  html`
    <${Combobox} items=${fruits} multiple placeholder="Pick several" />
  `,
  '#app',
);
```

## Tailwind Style

The tailwind flavor never touches `@hellajs/css`: the palette comes from `theme.css`, the copied strings use shadcn's literal utilities verbatim (`w-(--anchor-width)`, `min-w-[calc(var(--anchor-width)+--spacing(7))]`, `data-highlighted:bg-accent`, the `data-[side=…]` slide variants, the `group-data-empty/combobox-content:flex` empty reveal, and the input-group shell strings duplicated under the entry), and each part's class array wraps in `cn()` so later tokens override earlier ones per utility group. The enter and exit motion relies on the `tw-animate-css` utilities the theme's tailwind entry depends on.

## Customizing

The copied file is yours. Option rows restyle in `item`; the panel surface in `content` (its anchor-width sizing, ring, and animations live there). The empty text is the `ComboboxEmpty` children inside the composed root - edit the string or replace it. The dismissal surface is the `layerDismissal` wiring; hold the panel open against Escape and outside presses by composing `ComboboxContent` without `onDismiss`.
