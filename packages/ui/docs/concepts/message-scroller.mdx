## Usage

The composed root wraps your children in the viewport and content stack and renders the jump button (`showScrollButton={false}` opts out); it owns the state.

### jsx

```jsx
import { MessageScroller, MessageScrollerItem } from './components/message-scroller';

const Chat = () => (
  <MessageScroller class="h-96">
    <MessageScrollerItem>First message</MessageScrollerItem>
    <MessageScrollerItem>Second message</MessageScrollerItem>
  </MessageScroller>
);
```
### html

The html-format (`--format html`) works the same way.

```js
html`<main>
  <${MessageScroller} class="h-96">
    <${MessageScrollerItem}>First message</${MessageScrollerItem}>
    <${MessageScrollerItem}>Second message</${MessageScrollerItem}>
  </${MessageScroller}>
</main>`
```

## The auto-stick contract

The viewport owns an `atBottom` signal (true on mount). A scroll listener compares `scrollHeight - scrollTop - clientHeight` against `threshold` (default 80px) and flips the signal; a `ResizeObserver` on the content watches growth and scrolls back to the bottom while the state reads true. The jump button renders whenever the state reads false and hides while it reads true, driven by `data-active`.

## Manual composition

Hella has no context, so the parts take their state explicitly. Create the signal yourself, hand the same signal to the viewport and the button, and the `MessageScrollerProvider` becomes a plain passthrough kept for API parity:

```jsx
import { signal } from '@hellajs/core';
import { MessageScrollerButton, MessageScrollerContent, MessageScrollerProvider, MessageScrollerViewport } from './components/message-scroller';

const atBottom = signal(true);

const Manual = () => (
  <MessageScrollerProvider>
    <div class="relative h-96">
      <MessageScrollerViewport atBottom={atBottom} class="h-full">
        <MessageScrollerContent>{'First message'}</MessageScrollerContent>
      </MessageScrollerViewport>
      <MessageScrollerButton atBottom={atBottom} />
    </div>
  </MessageScrollerProvider>
);
```

`threshold` widens or tightens the at-bottom band, and `scrollToBottom` overrides the scroll action for both the auto-stick and the button.

## Intentionally Absent

Some pieces common to this component family are absent by design; they stay out rather than approximated:

- `MessageScrollerProvider` renders children only; hella has no context, so state lives on signals you own.
- `MessageScrollerItem` carries no per-item scroll anchor; pinning is viewport-level through the content observer.
- The `scroll-fade-b`, `scrollbar-*`, and `shimmer`-style tokens that scrollbar and animation plugins would fill stay verbatim in the tailwind flavor but carry no declarations in the vendored theme; the css flavor omits them.
- The `observe` prop (viewport and root) swaps the content watcher for testing in environments whose `ResizeObserver` never delivers; production code keeps the real observer.

## Manual Parts

All six exports are named; the composed root wraps the rest, and manual composition hands the same state to the viewport and button explicitly.

### MessageScroller

The composed root: it adopts or owns the at-bottom signal, wraps the children in the viewport and content stack, and renders the jump button.

| Prop | Type | Behavior |
|---|---|---|
| `atBottom` | `Signal<boolean>` | Shared state; the root owns an internal signal when absent |
| `showScrollButton` | `boolean` | Set `false` to omit the jump button |
| `threshold` | `number` | Distance in px from the bottom still counted as at-bottom (default `80`) |
| `scrollToBottom` | `() => void` | Overrides the scroll action for auto-stick and the button |
| `observe` | `(target: Element, onGrow: () => void) => () => void` | Swaps the content watcher; defaults to a `ResizeObserver` |
| `children` | `HellaChildren` | The message items |

### MessageScrollerViewport

The scroll container: a `div` carrying `data-slot="message-scroller-viewport"` whose passive scroll listener and content watcher drive the shared state.

| Prop | Type | Behavior |
|---|---|---|
| `atBottom` | `Signal<boolean>` | Shared state; the viewport owns an internal signal when absent |
| `threshold` | `number` | At-bottom band in px (default `80`) |
| `scrollToBottom` | `() => void` | Overrides the auto-stick scroll action |
| `observe` | `(target: Element, onGrow: () => void) => () => void` | Swaps the content watcher, attached to the content stack |
| `children` | `HellaChildren` | The content stack |

### MessageScrollerContent

The content stack: a `div` carrying `data-slot="message-scroller-content"` that the growth watcher observes.

| Prop | Type | Behavior |
|---|---|---|
| `children` | `HellaChildren` | The items |

### MessageScrollerItem

One message row: a `div` carrying `data-slot="message-scroller-item"`.

| Prop | Type | Behavior |
|---|---|---|
| `children` | `HellaChildren` | The message node |

### MessageScrollerButton

The jump button: rendered while the shared state reads false and hidden while true through `data-active`; `direction="start"` inverts the visibility semantics for jump-to-start placements.

| Prop | Type | Behavior |
|---|---|---|
| `atBottom` | `Signal<boolean>` | Drives `data-active`; the default scroll action writes it back to true |
| `direction` | `"start" \| "end"` | Which end the button jumps to (default `"end"`), rendered as `data-direction` |
| `variant` / `size` | button variant and size maps | The duplicated button declarations (defaults `"secondary"` / `"icon-sm"`) |
| `scrollToBottom` | `() => void` | Overrides the default jump action |
| `onclick` | `() => void` | A full replacement for the default click behavior |
| `children` | `HellaChildren` | Optional custom content; the default is the arrow icon plus a screen-reader label |

### MessageScrollerProvider

A passthrough kept for API parity: renders `children` only; hella has no context, so state lives on signals you own.

| Prop | Type | Behavior |
|---|---|---|
| `children` | `HellaChildren` | The composed shell |

Every part also takes a `class` string, landing last in its style composition.
