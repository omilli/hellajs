# Switch

An on/off control styled to shadcn's Switch: a `role="switch"` button whose thumb slides through pure CSS. The root renders `aria-checked` and `data-state`; the thumb carries the same `data-state` and the style layer translates it into the track palette and the thumb translation.

## Usage

| Prop | Type | Behavior |
|---|---|---|
| `checked` | `boolean \| (() => boolean)` | Uncontrolled seed or controlled accessor (see below) |
| `onCheckedChange` | `(checked: boolean) => void` | Fires on every click with the requested next value |
| `disabled` | `boolean` | Blocks clicks and renders the disabled attribute |
| `class` | `string` | Lands on the root next to the component class |

```jsx
import Switch from './components/switch';

const Settings = () => (
  <label>
    <Switch /> Airplane mode
  </label>
);
```

## Controlled and Uncontrolled

Without `checked`, the root owns a signal seeded by a boolean `checked` prop and flips it on click. Pass an accessor and the switch becomes controlled: clicks turn into `onCheckedChange` requests without writing state, so a parent signal that ignores the request keeps the switch unchanged.

```jsx
import { signal } from '@hellajs/core';
import Switch from './components/switch';

const enabled = signal(false);

const Controlled = () => (
  <label>
    <Switch checked={() => enabled()} onCheckedChange={(next) => enabled(next)} />
    Enabled
  </label>
);
```

## Divergences

The ref exposes a `size` prop (`default` and `sm`). This port pins the rendered output to the ref default: the root carries `data-size="default"` and the `sm` classes ride along in the tailwind module, where they can never match. Resizing a switch is an edit of the copied file away.

## Accessibility

The root is a `button` element, so Space toggles it through native activation and it participates in tab order.

| Aspect | Value |
|---|---|
| Role | `switch` on the root button |
| State | `aria-checked` is `true` or `false`; `data-state` is `checked` or `unchecked` on both root and thumb |
| Keyboard | Space toggles; the button is disabled for pointer and keyboard while `disabled` |
| Labeling | Pair with a `label` element or `aria-labelledby` |

## Styling

Both flavors export the same names from the copied file: `base` (the track, including the size, palette, and focus ring) and `thumb` (the sliding knob, whose `translate` carries the whole state motion). The css flavor composes [`style`](/reference/css/style) maps under the `hella` cascade layer, so unlayered author CSS always wins; the tailwind flavor wraps plain utility strings in `cn()`, verbatim from the ref including the named `group/switch` scoping that lets the thumb read the root's `data-size` and `data-state`. To restyle every switch's knob at once, edit the `thumb` map; because the thumb's motion is pure CSS keyed on `data-state`, changing the easing or distance is a one-line edit in the style module. `props.class` lands on the root next to `base`. Flavor choice and theme setup: [Installation](/ui/installation). Tokens and the override contract: [Theming](/ui/theming).
