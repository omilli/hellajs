# CLI

The `@hellajs/ui` package is its own CLI: three commands move registry source into your project, and flags override the saved config per call.

## Commands

```bash
npx @hellajs/ui init
npx @hellajs/ui add button
npx @hellajs/ui list
```

| Command | Behavior |
|---|---|
| `init` | Writes `hella.ui.json` (including `themeMode` when `--theme-mode` passes) to the project root and adds the shared `theme` entry for the configured style |
| `add <name>...` | Resolves each entry recursively, runs the peer check, and copies the format-matched files into `componentsDir` |
| `list` | Prints every entry name in the registry |

| Flag | Applies to | Behavior |
|---|---|---|
| `--style css\|tailwind` | `add` | Registry style to copy; defaults to the saved value |
| `--format jsx\|html` | `add` | Source format to copy; defaults to the saved value |
| `--lang js\|ts` | `add` | Output language; `ts` (default) copies verbatim, `js` strips types |
| `--theme-mode light\|dark` | `init`, `add` | Theme palette for the theme entry; defaults to the saved value; `dark` copies the dark-only tokens sheet (css style only) |
| `--dir <path>` | `init`, `add` | Target project root; the process cwd when absent |
| `--overwrite` | `add` | Replaces existing files instead of skipping them with a warning |
| `--force` | `init` | Rewrites an existing `hella.ui.json` |

## Project Config

```json
{
  "componentsDir": "src/components",
  "style": "css",
  "format": "jsx",
  "themeMode": "light",
  "lang": "ts"
}
```

`init` writes these defaults when the file is absent and keeps an existing file otherwise; `--force` rewrites it. `add` reads the saved values as its defaults, and the per-call flags override them.

`--lang js` also retargets the copied names: `button.tsx` becomes `button.jsx`, and `button.ts`, `cn.ts`, and `tokens.ts` become `.js`, while `theme.css` passes through unchanged. The output is plain JavaScript with the same declarations and markup. **Plain JavaScript** covers when to skip the flag entirely: Bun and Deno run TypeScript natively, so only no-build browser pages and JS-only toolchains need it.

## Dependency Resolution

Resolution is recursive: `add button` also copies every entry `button` depends on. Each dependency resolves from its own registry folder, a shared dependency resolves once, and a dependency cycle fails the add. The css style brings `tokens.ts` along; the tailwind style brings `theme.css` and `cn.ts`.

## Style Splicing

The canonical source carries marker regions the CLI consumes at copy time (and strips from the output): exactly one `// @hella:styles` region, where the style module's declarations land, and one `// @hella:compose` region per styled part, holding that part's live class array; multi-part components like Card carry seven. Each region closes with `// @hella:end`. The splice produces a different body per style:

- **css** splices [`style`](/reference/css/style) maps into the styles region and keeps every compose array in its `class` attribute; dom joins plain arrays there, and the maps emit as plain unlayered rules.
- **tailwind** inlines every class string at its use site inside `cn(...)`: compose members, static class attributes, and references from helpers or runtime code, with a non-class constant like an event name inlining the same way at its references. Only keyed variant/size maps stay at the styles region. Every compose array wraps in `cn(...)`, and `import { cn } from "./cn.js";` injects after the last import so the helper import resolves next to the copied file.

Style modules export one lowerCamel binding per styled part that carries classes (`header`, `title`, `close`); a part with no classes gets no binding, and an empty-string export appears only as a css/tailwind flavor bridge (an empty binding in one flavor mirrors a live binding in the other). `variants`/`sizes` keyed maps appear only where a component actually has them (Button's variant and size sets, TabsList's pill/line).

## Peer Checking

Copied source imports packages as regular dependencies of your project. `add` reads your `package.json` and prints an install hint naming exactly what is missing:

| What you add | Extra packages the copies import |
|---|---|
| Any component, css style | `@hellajs/css` |
| Any component, tailwind style | `clsx`, `tailwind-merge`, `tw-animate-css` |

Every component entry declares `@hellajs/core` and `@hellajs/dom` as base peers; `add` checks them in your `package.json` alongside the style's extras.

## The cn Helper

Tailwind adds copy `cn.ts`: a one-function helper that joins classes with `clsx` and resolves conflicts with `tailwind-merge`. Both packages land in your project's dependencies; the peer check names any that are missing. Conflict resolution is the override mechanism: a utility in the `class` prop wins over the same utility group baked into the component.

css projects have no `cn`: the class array composes statically, and precedence between registry CSS and your own resolves through the normal cascade (see [Theming](/ui/theming)). For joining class fragments in your own code, [`cx`](/reference/css/cx) is the css-package joiner, and [`cva`](/reference/css/cva) layers typed variant recipes over it.
