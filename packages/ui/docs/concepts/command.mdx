## API

The default `Command` takes its items as data and renders the search input, the ranked groups, and the keyboard model: the copied file composes the [`command`](/headless/command) components factory from `@hellajs/headless`, which owns the query signal, ranks matches across labels, values, and keywords, and drives the active item over a flat ranked list. Typing filters; the first match starts active. The named components compose the same factory for standalone use.

Items sharing a `group` render under one heading, in the order the groups first appear in the array; items without a `group` render above the groups. Each item renders its `label` and, when present, a right-aligned `CommandShortcut` hint.

### Command

| Prop | Type | Default |
| ---- | ---- | ------- |
| `items` | `CommandItemData[] \| (() => CommandItemData[])` | `-` |
| `filter` | `(items, query) => CommandItemData[]` | The scoring filter |
| `loop` | `boolean` | `false` |
| `value` | `() => string` | `-` |
| `onValueChange` | `(value: string) => void` | `-` |
| `children` | `HellaChildren` | `-` |
| `class` | `string` | `-` |

Accepts all native `div` attributes (forwarded to the root element).

`loop` wraps arrow movement at the edges (the default clamps); a controlled `value` stops the root from writing its internal cursor and `onValueChange` then reports each requested move and selection.

### CommandItemData

Each entry in the `items` array is one palette row.

| Field | Type | Default |
| ----- | ---- | ------- |
| `value` | `string` | `-` |
| `label` | `string` | `-` |
| `group` | `string` | `-` |
| `keywords` | `string[]` | `-` |
| `shortcut` | `string` | `-` |
| `disabled` | `boolean` | `-` |
| `onSelect` | `() => void` | `-` |

`value` is reported through `onValueChange` on Enter and rendered as `data-value`; `label` is the primary scoring target; `group` heads a group in first-appearance order; every matching `keywords` entry adds a fixed scoring bonus; `shortcut` renders through `CommandShortcut`; `disabled` rows are skipped by arrows and never commit; `onSelect` runs when Enter commits the row.

### CommandInput

The search row: the search icon plus the text input. The composed `Command` threads the query updates and the keyboard model through `on:input` and `on:keydown` on the inner input.

| Prop | Type | Default |
| ---- | ---- | ------- |
| `class` | `string` | `-` |

Accepts all native `input` attributes (forwarded to the inner input element): `placeholder`, `id`, `value`, `aria-label`, and friends ride the spread.

### CommandList

The scrolling `role="listbox"` container. The composed `Command` hands the factory its `items` and the list renders the ranked body itself; manual compositions render their rows as children.

| Prop | Type | Default |
| ---- | ---- | ------- |
| `children` | `HellaChildren` | `-` |

Accepts all native `div` attributes (forwarded to the root element).

### CommandEmpty

The zero-match row.

| Prop | Type | Default |
| ---- | ---- | ------- |
| `children` | `HellaChildren` | `-` |

Accepts all native `div` attributes (forwarded to the root element).

### CommandGroup

| Prop | Type | Default |

Accepts all native `div` attributes (forwarded to the root element).

### CommandItem

One `role="option"` row; activation runs `onSelect` on click.

| Prop | Type | Default |
| ---- | ---- | ------- |

### CommandShortcut

The right-aligned key hint inside a row.

| Prop | Type | Default |
| ---- | ---- | ------- |
| `children` | `HellaChildren` | `-` |

Accepts all native `span` attributes (forwarded to the root element).

### CommandSeparator

A `role="separator"` rule between groups. Accepts all native `div` attributes (forwarded to the root element).

### CommandDialog

The palette wrapped in the dialog surface: the overlay, the portaled panel, the focus trap with focus restore, and escape plus outside-press dismissal. The `title` and `description` render inside a screen-reader-only header and wire `aria-labelledby` and `aria-describedby` on the panel.

| Prop | Type | Default |
| ---- | ---- | ------- |
| `open` | `() => boolean` | `-` |
| `onClose` | `() => void` | `-` |
| `title` | `string` | `-` |
| `description` | `string` | `-` |
| `children` | `HellaChildren` | `-` |

Accepts all native `div` attributes (forwarded to the portaled panel element).

Every component also takes a `class` string, landing last in its style composition. The dialog surface rides the factory's `Dialog` component over the headless [`modal`](/headless/modal) foundation: the trap, escape, and outside-press wiring arm against the open state and dispose with the panel, and the panel class styles the overlay, header, close button, and command surface through descendants of the wrapper root. The entry's `dialog` registry dependency exists so standalone dialogs are one `add` away.

## Filtering

The default filter scores every item case-insensitively against its label, value, and keywords. A match scores higher when it starts earlier in the string and higher still when it starts at a word boundary (after a space, dash, slash, dot, or underscore, or at position zero); every keyword that matches adds a fixed bonus, so items hitting two keywords outrank items hitting one. A zero score drops the item out. Groups whose items all score zero render `hidden`, and when every item is filtered out the root mounts a "No results found." empty row.

Pass `filter` to replace the default entirely - it receives the full item list and the live query and returns the items to render, ranked:

```jsx
import { Command } from './components/command';

const startsWith = (items, query) =>
  query ? items.filter((item) => item.value.toLowerCase().startsWith(query.toLowerCase())) : items;

const PrefixPalette = () => (
  <Command items={commands} filter={startsWith} />
);
```

Ranking re-renders the list per keystroke: unlike the [Combobox](/ui/combobox), which hides non-matching options in place, the command re-renders its ranked order, so item elements are not stable across queries.

## Keyboard

The input keeps focus the whole time; the keydown model reads arrows, Home, End, and Enter.

| Key | Behavior |
|---|---|
| `ArrowDown` / `ArrowUp` | Moves the active item to the next or previous enabled entry; wraps when `loop` is set, clamps at the edges otherwise |
| `Home` / `End` | Jumps to the first or last enabled item |
| `Enter` | Runs the active item's `onSelect` and reports its value through `onValueChange`; disabled items never commit |

Each cursor move scrolls the newly active item to the nearest edge of the list (`scrollIntoView` with `block: "nearest"`). The active item carries `data-selected="true"` plus `aria-selected`, and `data-disabled="true"` marks the items arrows skip.

## Dynamic items

`items` reads once at mount when passed a plain array; pass a signal accessor and the ranked list rebuilds as the array grows, shrinks, or reorders - every write re-runs the same ranked body render, so a new entry is findable and selectable without a remount:

```jsx
import { signal } from "@hellajs/core";
import { Command } from "./components/command";

const commands = signal([
  { value: "copy", label: "Copy", group: "Edit" },
]);

<Command items={commands} />;

// Appends a live entry; the ranked list picks it up on the next render.
commands([...commands(), { value: "paste", label: "Paste", group: "Edit" }]);
```

The list rebuilds per change: DOM order always follows the ranked array, and there is no `keyBy` option - item rows have no cross-render identity to preserve.
