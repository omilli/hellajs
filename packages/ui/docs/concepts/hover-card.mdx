## API

A rich preview card: hovering a trigger opens an anchored panel, moving the pointer into the panel keeps it open, and leaving both closes it. Keyboard focus follows the same open and close path a pointer takes.

Two named parts ship beside the default `HoverCard`: `HoverCardTrigger` and `HoverCardContent`. State is explicit - portal the content yourself, hand it a `state` accessor, and wire both regions' hover through [`hoverIntent`](/reference/dom/hoverintent).

### HoverCard

The composed `HoverCard` wraps its children in the trigger span. It opens 200ms after the pointer rests on the trigger and closes 300ms after it leaves. Moving the pointer from the trigger into the panel keeps it open: the content carries a second [`hoverIntent`](/reference/dom/hoverintent) with zero delays that re-arms the open state the moment the pointer enters, cancelling the trigger's pending close. Leaving the content closes it immediately; returning to the trigger cancels that close in turn, so crossing between the two regions in either direction never flickers.

| Prop | Type | Default |
| ---- | ---- | ------- |
| `open` | `() => boolean` | `-` |
| `onOpenChange` | `(open: boolean) => void` | `-` |
| `content` | `HellaChildren` | The panel children, portaled into `document.body` while open |
| `class` | `string` | `-` |
| `children` | `HellaChildren` | The trigger content |

A controlled `open` stops the root from writing its internal signal; `onOpenChange` reports every requested open and close flip.

### HoverCardTrigger

The manual trigger span; the composed `HoverCard` renders the same shape wired to [`hoverIntent`](/reference/dom/hoverintent) with the 200ms/300ms delays and focus parity.

| Prop | Type | Default |
| ---- | ---- | ------- |
| `children` | `HellaChildren` | The trigger content |

### HoverCardContent

The panel `div` carrying `data-slot="hover-card-content"`, positioned through [`anchorPosition`](/reference/dom/anchorposition) at a 4px offset. When both callbacks are given, hovering the content re-arms the open state with zero delays - the keep-open contract.

| Prop | Type | Default |
| ---- | ---- | ------- |
| `state` | `() => "open" \| "closed"` | `-` |
| `side` | `"top" \| "bottom" \| "left" \| "right"` | `"bottom"` |
| `align` | `"start" \| "center" \| "end"` | `"center"` |
| `anchor` | `() => Element \| undefined` | `-` |
| `onOpen` | `() => void` | `-` |
| `onClose` | `() => void` | `-` |
| `onExited` | `() => void` | `-` |
| `children` | `HellaChildren` | The panel body |

`state` drives `data-state` and the enter/exit cycle. The anchor resolves to the element the panel anchors to; positioning is skipped when undefined. `onOpen` fires when the pointer enters the panel, re-arming the open state; `onClose` fires when it leaves; `onExited` fires when the exit animation ends under `data-state="closed"`.

Every part also takes a `class` string, landing last in its style composition. [`anchorPosition`](/reference/dom/anchorposition) fixes the coordinates against the trigger, flips on viewport collision, and repositions on scroll and resize.
