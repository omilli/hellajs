# Input Group

A fake-input wrapper that joins an input or textarea with buttons, text, and dropdowns under one border, styled byte-faithfully to shadcn's new-york-v4 InputGroup. The group owns the focus and invalid rings: its `:has` selectors light the whole composite up when the inner control receives focus or carries `aria-invalid`, while the control itself strips its own ring.

## Usage

`InputGroupInput` and `InputGroupTextarea` carry `data-slot="input-group-control"`, which is the hook the group's focus and error selectors read. Addons order themselves around the control through `align`:

```jsx
import InputGroup, { InputGroupAddon, InputGroupInput, InputGroupText } from './components/input-group';

const Search = () => (
  <InputGroup>
    <InputGroupAddon>
      <InputGroupText>Search</InputGroupText>
    </InputGroupAddon>
    <InputGroupInput placeholder="Enter query" />
    <InputGroupAddon align="inline-end">
      <InputGroupButton>Go</InputGroupButton>
    </InputGroupAddon>
  </InputGroup>
);
```

## Addon Alignment

`InputGroupAddon` takes `align` (`inline-start`, `inline-end`, `block-start`, `block-end`) to order and pad itself around the control; block alignments stack the group into a column. Clicking an addon focuses the group's input unless the click landed on a button, matching the ref's pointer behavior:

```jsx
import InputGroup, { InputGroupAddon, InputGroupButton, InputGroupTextarea, InputGroupText } from './components/input-group';

const Comment = () => (
  <InputGroup>
    <InputGroupAddon align="block-start">
      <InputGroupText>New comment</InputGroupText>
    </InputGroupAddon>
    <InputGroupTextarea placeholder="Write your reply" />
    <InputGroupAddon align="block-end">
      <InputGroupButton>Send</InputGroupButton>
    </InputGroupAddon>
  </InputGroup>
);
```

## Disabled State

Pass `disabled` to the group and it renders `data-disabled="true"`; every addon reads that attribute and drops to half opacity. Upstream takes the attribute through an untyped spread; here it is an explicit prop so the css flavor can target it with a stable selector.

## Styling

The css style module exports `base` (the border, the alignment `:has` rules, and the focus and error ring wiring), `addon` plus `addonAlign` (the four alignment maps), `buttonBase` through `sizes` (the inline duplication of the button flavor with the group's tighter size overrides), `text`, and the input and textarea blocks ending in `Control` (the ring-stripping overrides). The css flavor composes [`style`](/reference/css/style) maps under the `hella` cascade layer, so unlayered author CSS always wins; the tailwind flavor carries shadcn's literal utilities verbatim, including the focus wiring `has-[[data-slot=input-group-control]:focus-visible]:ring-[3px]` and the invalid wiring `has-[[data-slot][aria-invalid=true]]:border-destructive`, wrapped in `cn()`. Resize the group through a `class` override, or retone the error ring by editing the destructive `:has` keys in `base`. Flavor choice and theme setup: [Installation](/ui/installation). Tokens and the override contract: [Theming](/ui/theming).
