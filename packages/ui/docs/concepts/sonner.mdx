## Usage

An opinionated toast queue: `toast()` calls stack as cards on a screen edge, auto-dismiss on a pausable countdown, and swipe away past a distance threshold. The queue lives as a module-level singleton in the copied file - one copy/paste module owns one queue per app. Mount one `<Toaster />` high in the app (it portals the stack into `document.body`), then call `toast()` from anywhere that imports the same copied module.

### jsx

```jsx
import Toaster, { toast } from './components/sonner';

const App = () => (
  <>
    <Toaster />
    <button on:click={() => toast('Saved')}>Save</button>
  </>
);
```
### html

The html-format (`--format html`) works the same way.

```js
html`<main>
  <${Toaster} position=${'bottom-right'} />
  <button e:click=${() => toast('Saved')}>Save</button>
</main>`
```

`toast(message, options)` returns a `{ id, dismiss() }` handle:

| Option | Default | Behavior |
|---|---|---|
| `description` | - | Secondary line under the message |
| `type` | - | `success`, `error`, `warning`, or `info`: sets `data-type`, the tinted icon, and the rich-colors card |
| `action` | - | `{ label, onclick }` rendered as a button; firing it also dismisses the toast |
| `duration` | `4000` | Milliseconds before auto-dismiss; `Infinity` sticks |

The countdown pauses while the pointer hovers the toast and resumes from the frozen remainder on leave. `toast.dismiss(id)` retires one toast; blanket `toast.dismiss()` retires everything. The Toaster itself takes `position` (six screen edges, `"bottom-right"` default) and `richColors` (tints the whole card per flavor; without it the card stays neutral and only the icon carries the hue).

## Promise Toasts

`toast.promise(promise, messages)` shows a sticky loading toast with a spinning loader, then swaps the flavor and message on settle:

```jsx
import Toaster, { toast } from './components/sonner';

const upload = () => new Promise<string>((resolve) => resolve('report.pdf'));

const Upload = () => (
  <>
    <Toaster />
    <button
      on:click={() =>
        toast.promise(upload(), {
          loading: 'Uploading',
          success: (name) => `Uploaded ${name}`,
          error: 'Upload failed',
        })
      }
    >Upload</button>
  </>
);
```

`success` and `error` take a string or a function of the settled value. The loading phase never auto-dismisses; the settled phase arms the normal duration. Dismissing before settle keeps the toast retired: a late settle never revives it.

## Queue Semantics

| Behavior | Contract |
|---|---|
| Visible cap | Three toasts stack; a fourth retires the oldest immediately |
| Exit | `data-removed="true"` starts a fade-and-collapse; the toast unmounts after the 200ms exit budget |
| Stack look | Toasts behind the front shrink (`scale` 0.95 / 0.9 / 0.85 per depth via `data-depth`) and shift along `--stack-offset` |
| Positions | `position` on the Toaster: `top-left`, `top-center`, `top-right`, `bottom-left`, `bottom-center`, `bottom-right` (default) |
| Swipe | Horizontal drag follows the pointer (`data-dragging` suspends transitions); release past 45% of the toast width dismisses, under it springs back |
| Close | An X button appears on hover and on keyboard focus |

Buttons inside a toast (action, close) never start a swipe: the drag ignores pointerdowns on interactive elements, the same rule the drawer uses. The swipe-dismiss physics ride on [`onDrag`](/reference/dom/ondrag) from `@hellajs/dom`. Every card carries `data-type`, `data-depth`, `data-removed`, and `data-dragging`, so user CSS can key off the same state, and the thresholds live as named constants at the top of the copied file.
