# docStream

Assemble a streamed body and an optional head into a full streaming HTML document — the streaming counterpart of [`doc`](/reference/ssr/doc).

## API

```typescript
function docStream(options: DocStreamOptions): ReadableStream<string>
```

- `options`: Document assembly options.
  - `body` (`ReadableStream<string>`): Streamed HTML — the output of [`ssrStream`](/reference/ssr/ssr-stream). Placed verbatim, chunk-by-chunk — **not** re-escaped.
  - `mount?` (`string`): Mount-point selector wrapping the body — the same string [`hydrate`](/reference/dom/hydrate) targets on the client (`'#app'`, `'main#app'`, `'.wrap.x'`). One optional tag (defaults to `div`), at most one `#id`, any number of `.class` tokens (space-joined, in order). Anything else throws.
  - `head?` (`HeadOptions`): Document head contents — rendered identically to [`doc`](/reference/ssr/doc)'s head. Fields emit in declaration order: `title`, `meta`, `links`, `styles`, `scripts`, then `raw`.
  - `lang?` (`string`): Value for `<html lang="…">`; the attribute is omitted when unset.
- **Returns**: A `ReadableStream<string>` of the full HTML document — shell first, body chunks as they arrive, closing tags last.

## Basic Usage

Wrap an [`ssrStream`](/reference/ssr/ssr-stream) body in a full document without collecting it — the client receives the document shell immediately and each chunk as it renders.

```js
import { ssrStream, docStream } from '@hellajs/ssr';

const page = docStream({
  lang: 'en',
  mount: '#app',
  head: {
    title: 'Dashboard',
    scripts: [{ type: 'module', src: '/client.js' }],
  },
  body: ssrStream(App()),
});

Bun.serve({
  port: 3000,
  fetch: () => new Response(page.pipeThrough(new TextEncoderStream()), {
    headers: { 'content-type': 'text/html' },
  }),
});
```

## Key Concepts

### `mount` mirrors `hydrate`'s target

`mount: '#app'` emits `<div id="app">` before the body and `</div>` after it — so the client hydrates with the same selector the server declared: `hydrate(App(), '#app')`. A custom tag works too (`'main#app'` → `<main id="app">`), and classes join in order (`'.wrap.x'` → `<div class="wrap x">`). The closing tags are emitted by `docStream` itself, so a wrapper can never be left unclosed mid-stream.

### The closing tags flush after every staged swap

The suffix (`</div></body></html>`) is emitted only after the body stream closes. For a `ssrStream` body carrying [`<Suspense>`](/reference/dom/suspense) boundaries, that means after every staged `<template>` has streamed — progressive paint holds end-to-end, with nothing collected or re-ordered.

### Same head as `doc`

`head` runs through the same builder as [`doc`](/reference/ssr/doc)'s — identical escaping, ordering, and void-element rules. Only the body's medium differs (stream vs string).

## Important Considerations

### `mount` accepts tag, `#id`, `.class` only

A mount point is a single wrapping element. Combinators, attribute selectors, pseudo-classes, and empty strings throw `[ssr] docStream: mount supports tag/#id/.class only, received "<value>"`.

### Stream failures surface on the stream

`docStream` throws synchronously when `body` is omitted (`[ssr] docStream: body is required, received undefined`). A body-stream error (a rejected render, per [Errors Propagate](/reference/ssr/ssr#errors-propagate)) errors the document stream; cancelling the document stream cancels the body — staged `<Suspense>` swaps stop with it.
