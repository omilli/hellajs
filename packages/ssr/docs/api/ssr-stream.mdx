# ssrStream

Serialize a HellaNode AST into a streaming HTML response — yields chunks as the walk proceeds, flushing the static prefix before each awaited Promise.

## API

```typescript
function ssrStream(node: HellaNode): ReadableStream<string>
```

- `node`: A HellaNode AST (produced by [`html`](/reference/dom/html) or JSX) to serialize.
- **Returns**: A web `ReadableStream<string>` of HTML chunks. Pipe through `new TextEncoderStream()` for a `Response` body.

## Basic Usage

`ssrStream` yields HTML as the tree resolves, so the client receives the static shell before any async value settles. Pipe it into a `Response` for a streaming server handler.

```js
import { html } from '@hellajs/dom';
import { ssrStream } from '@hellajs/ssr';

const user = (id) => fetch(`/api/users/${id}`).then(r => r.text());
const page = (id) => html`<div><h1>Hello</h1><p>${() => user(id)}</p></div>`;

Bun.serve({
  port: 3000,
  fetch: (req) => {
    const id = new URL(req.url).searchParams.get('id') ?? '1';
    return new Response(
      ssrStream(page(id)).pipeThrough(new TextEncoderStream()),
      { headers: { 'content-type': 'text/html' } }
    );
  }
});
```

## Key Concepts

### Progressive Flush

The walker yields chunks as it goes. Static markup ahead of an awaited value streams immediately — the client paints the shell while async data resolves. Bare Promises are awaited in-order, consistent with [`ssrAsync`](/reference/ssr/ssr-async).

### Identical Output Contract

Collecting every chunk of `ssrStream(node)` equals `await ssrAsync(node)` (and `ssr(node)` when no value is a Promise). Marker wrapping is byte-identical to [`ssr`](/reference/ssr/ssr), so [`hydrate`](/reference/dom/hydrate) consumes streamed HTML unchanged once complete.

### Zero Runtime Dependencies

Like [`ssr`](/reference/ssr/ssr), `ssrStream` has zero runtime imports from any `@hellajs/*` package. It returns a standard web `ReadableStream`, composable with `pipeThrough` (`TextEncoderStream`), `pipeTo`, or any stream consumer.

## Important Considerations

### In-Order Streaming

Bare Promises (no [`<Suspense>`](/reference/dom/suspense)) are awaited in tree order, so a slow Promise delays everything after it. A `<Suspense>` boundary opts out: its `fallback` flushes inline immediately, then each region's resolved children stream as a `<template>` followed by an inline `<script>$hs(id)</script>` that swaps the fallback for the resolved content **the moment it arrives** — so the user sees each region fill in progressively (React/Solid parity), not all at once at hydrate. Multiple regions swap concurrently (completion order, not document order); a one-time `$hs` bootstrap precedes them. `hydrate` later adopts the already-swapped nodes (its `swapSuspenseStage` is the no-script/HappyDOM fallback). Prefer `ssrStream` when you want progressive paint; prefer [`ssr`](/reference/ssr/ssr) or [`ssrAsync`](/reference/ssr/ssr-async) when streaming isn't needed (no Promise overhead).

### Errors Error the Stream

A rejected Promise errors the `ReadableStream` — reading it throws. Handle errors at the stream consumer (your server handler).

### Throws on invalid input

`ssrStream` throws `[ssr] ssrStream: node is required, received <value>` when `node` is `null` or `undefined`.
