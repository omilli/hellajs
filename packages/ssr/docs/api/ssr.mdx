# ssr

Serialize a HellaNode AST into an HTML string — a pure stringifier with zero runtime dependencies. A callable namespace: `ssr(node)` walks synchronously, `ssr.async(node)` awaits every Promise in the tree, `ssr.stream(node)` flushes progressively.

## API

```typescript
declare const ssr: {
  (node: HellaNode): string;
  async(node: HellaNode): Promise<string>;
  stream(node: HellaNode, options?: StreamOptions): ReadableStream<string>;
};
```

- `node`: A HellaNode AST (produced by [`html`](/reference/dom/html) or JSX) to serialize.
- **Returns**: The rendered HTML string.

### async

The async member — awaits any Promise a resolved value returns, then resolves to the concatenated HTML.

```typescript
declare namespace ssr {
  function async(node: HellaNode): Promise<string>;
}
```

A component may embed server-side async data directly: a getter that returns a `Promise` is awaited, and its resolved value is placed inside a marker-bounded region identical to the sync call. A [`Lazy`](/reference/dom/lazy) loader is awaited the same way — the loaded component renders server-side, and a rejected loader renders `fallback` (or rejects this call when none is provided).

```js
import { html } from '@hellajs/dom';
import { ssr } from '@hellajs/ssr';

const user = (id) => fetch(`/api/users/${id}`).then(r => r.text());

const body = await ssr.async(html`<p>Hello ${() => user(1)}</p>`);
// body: "<p><!--[-->Ada<!--]--></p>"
```

### stream

The streaming member — yields chunks as the walk proceeds, flushing the static prefix before each awaited Promise.

```typescript
declare namespace ssr {
  function stream(node: HellaNode, options?: StreamOptions): ReadableStream<string>;
}

interface StreamOptions {
  /** CSP nonce — `nonce="…"` on every inline script the stream emits */
  nonce?: string;
}
```

The client receives the static shell before any async value settles. Pipe it into a `Response` for a streaming server handler. Bare Promises are awaited in tree order; a rejected bare Promise errors the stream, while a rejected `<Suspense>` region is isolated (see [Errors Propagate](#errors-propagate)). [`Lazy`](/reference/dom/lazy) loaders are awaited like bare Promises — in-order outside [`<Suspense>`](/reference/dom/suspense), resolved within the staged `<template>` inside one.

```js
import { html } from '@hellajs/dom';
import { ssr } from '@hellajs/ssr';

const user = (id) => fetch(`/api/users/${id}`).then(r => r.text());
const page = (id) => html`<div><h1>Hello</h1><p>${() => user(id)}</p></div>`;

Bun.serve({
  port: 3000,
  fetch: (req) => {
    const id = new URL(req.url).searchParams.get('id') ?? '1';
    return new Response(
      ssr.stream(page(id)).pipeThrough(new TextEncoderStream()),
      { headers: { 'content-type': 'text/html' } }
    );
  }
});
```

Under a strict `Content-Security-Policy` (no `unsafe-inline`), the browser blocks the inline `<Suspense>` swap scripts. Pass a per-response `nonce` and mirror it in the response header — every script the stream emits (the [`$hs` bootstrap](#in-order-streaming) and each per-region swap script) then carries `nonce="…"`:

```js
import { html } from '@hellajs/dom';
import { ssr } from '@hellajs/ssr';

const page = () => html`<div><h1>Hello</h1></div>`;

Bun.serve({
  port: 3000,
  fetch: (req) => {
    const nonce = crypto.randomUUID();   // fresh per response
    return new Response(
      ssr.stream(page(), { nonce }).pipeThrough(new TextEncoderStream()),
      {
        headers: {
          'content-type': 'text/html',
          'content-security-policy': `script-src 'self' 'nonce-${nonce}'`
        }
      }
    );
  }
});
```

Without a `nonce` — or with no options at all — the scripts are emitted unattributed, byte-identical to a stream rendered before the option existed.

## Basic Usage

Render a template to a string and assemble it into a full document. No DOM is required, so `ssr` runs in any server runtime (Bun, Node, Deno, workers).

```js
import { html } from '@hellajs/dom';
import { ssr } from '@hellajs/ssr';

const page = (title) => html`
  <section>
    <h1>${title}</h1>
    <p>Welcome.</p>
  </section>
`;

const body = ssr(page('Hello'));
// body: "<section><h1>Hello</h1><p>Welcome.</p></section>"
```

### Styled output

[`@hellajs/css`](/reference/css) returns CSS text on the server; place it in a `<style>` tag and compose it with the rendered body. `ssr` never imports `@hellajs/css` — the caller assembles both.

```js
import { html } from '@hellajs/dom';
import { css } from '@hellajs/css';
import { ssr } from '@hellajs/ssr';

const button = css({ color: 'red' }, { name: 'btn' });
// On the server, `button` is the CSS text ".btn{color:red}"

const body = ssr(html`<button class="btn">Click</button>`);
const page = `<style>${button}</style><div id="app">${body}</div>`;
```

## Key Concepts

### Works with `html` or JSX

`ssr` consumes any `HellaNode` — produced by the `html` tag or JSX — identically, whichever member renders it. The babel/vite/rollup plugin compiles JSX to the same AST, so a JSX component renders the same HTML as the equivalent `html` template.

```jsx
import { ssr } from '@hellajs/ssr';

// JSX compiles to the same HellaNode as the html tag
const App = ({ name }: { name: string }) => <div><h1>Hello {name}</h1></div>;
const body = ssr(<App name="World" />);
```

The plugin must run on the **server** entry — it is a compile-time transform, so without it JSX is not a `HellaNode`. See [Render from JSX](/learn/patterns/ssr) for a full recipe.

### Zero Runtime Dependencies

`ssr` has zero runtime imports from any `@hellajs/*` package — only a type-only [`HellaNode`](/reference/dom) import, erased at compile time. It works whether or not the other packages are installed and adds no runtime weight to the server bundle.

### Hydration markers

`ssr()` wraps every dynamic region — a reactive child, a [`ForEach`](/reference/dom/foreach) / [`Transition`](/reference/dom/transition) / [`Portal`](/reference/dom/portal) / [`Lazy`](/reference/dom/lazy) / [`Suspense`](/reference/dom/suspense), or a nested fragment — in `<!--[-->…<!--]-->` comment markers. The browser parses these to `Comment` nodes that [`hydrate`](/reference/dom/hydrate) (`@hellajs/dom`) locates to bind each region in place, without structural inference and without rebuilding coalesced text. Static elements and text are emitted unwrapped (matched by position), so the marker payload stays minimal.

```js
import { signal } from '@hellajs/core';
import { html } from '@hellajs/dom';
import { ssr } from '@hellajs/ssr';

const count = signal(5);
const body = ssr(html`<p>Count: ${count}</p>`);
// body: "<p>Count: <!--[-->5<!--]--></p>"
```

This is a **breaking** part of the output contract: if you parse or snapshot `ssr()` output, expect the markers around dynamic regions. Generate server HTML with `ssr()` rather than hand-building it.

### Awaits Promises In Place

Where the sync call reads each getter once and cannot await, `ssr.async` awaits any resolved value that is a `Promise` — a child, a function-ref prop attribute, a [`ForEach`](/reference/dom/foreach) `each`, or a [`Transition`](/reference/dom/transition) `show`. Nested thenables unwrap fully. Use `ssr.async` when a subtree needs server-fetched data; use the sync call when every value is already resolved (zero Promise overhead).

### Progressive Flush

`ssr.stream` yields chunks as the tree resolves. Static markup ahead of an awaited value streams immediately — the client paints the shell while async data resolves. Bare Promises are awaited in-order, consistent with [`ssr.async`](#async).

### Identical Output Contract

All three members emit byte-identical markers: every dynamic region is bounded by `<!--[-->…<!--]-->`, so [`hydrate`](/reference/dom/hydrate) consumes any output unchanged. Collecting every chunk of `ssr.stream(node)` equals `await ssr.async(node)` (and the sync call when no value is a Promise). Awaiting or streaming changes *when* values resolve, not the output contract.

### Resource Fetching Suppressed

[`resource`](/reference/resource/resource) is a reactive UI primitive. On the server it no-ops its fetch pipeline, so resources embedded in a server-rendered tree never trigger network calls. Fetch server-side data with direct `fetch()` and pass it in as initial values.

### Client Enhancement Model

The shipped HTML is the source of truth on the client. Bind existing static nodes into reactivity with [`$ref`](/reference/dom/$ref) / [`$collection`](/reference/dom/$collection), or mount a reactive island into an empty placeholder the template left for it.

## Important Considerations

### Portal renders nothing

[`Portal`](/reference/dom/portal) teleports content to a DOM target — there is no document on the server, so portals render as empty. Render portal content inline in the template if it must appear in the HTML.

### Lazy awaits the loader under the async members; `ssr` emits `loading`

The base `ssr` call is synchronous, so a [`Lazy`](/reference/dom/lazy) region emits its `loading` fallback (or nothing if none was provided) and never calls the loader. [`ssr.async`](#async) and [`ssr.stream`](#stream) await it instead: the loaded component renders into the HTML, and `hydrate` keeps that server content in place until the client's fresh loader run replaces it — no loading flash. The loader must be server-executable (a dynamic `import()` needs a server-resolvable module); on rejection it renders `fallback`, or rejects/errors the render when none is provided.

### Full re-mount over server HTML wipes it

Calling [`mount`](/reference/dom/mount) over the server-rendered container replaces its children and rebuilds the tree, discarding the server HTML and any user state in that subtree. Use [`$ref`](/reference/dom/$ref) / [`$collection`](/reference/dom/$collection) to bind existing nodes, or mount islands into empty placeholders. Full re-mount is only appropriate for throwaway (SEO-only) content.

### Synchronous render required

The base `ssr(node)` call walks the tree once and returns. Reactive getters are read at their current value; there is no effect scheduling, no batching, and no async resolution — use `ssr.async`/`ssr.stream` when a subtree embeds Promises. Build the tree from already-resolved data.

### Fetch Directly; Resource Is Unchanged

`ssr.async` provides a generic await mechanism — return a `Promise` from a getter. [`Lazy`](/reference/dom/lazy) loaders run server-side under the async members (see the Lazy note above), while [`resource`](/reference/resource/resource) still no-ops its fetch pipeline on the server. Fetch server-side data with direct `fetch()` and expose it through a Promise-returning getter.

### In-Order Streaming

Bare Promises (no [`<Suspense>`](/reference/dom/suspense)) are awaited in tree order under `ssr.stream`, so a slow Promise delays everything after it. A `<Suspense>` boundary opts out: its `fallback` flushes inline immediately, then each region's resolved children stream as a `<template>` followed by an inline `<script>$hs(id)</script>` that swaps the fallback for the resolved content **the moment it arrives** — so the user sees each region fill in progressively (React/Solid parity), not all at once at hydrate. Multiple regions swap concurrently (completion order, not document order); a one-time `$hs` bootstrap precedes them. `hydrate` later adopts the already-swapped nodes (its `swapSuspenseStage` is the no-script/HappyDOM fallback). A region whose Promise rejects is isolated instead of fatal: its `<template>` is skipped (the `fallback` and sentinel stay in the shell), the stream completes with its healthy siblings, and `hydrate` re-suspends that region on the client — the rejection surfaces at the nearest [`onError`](/reference/dom/onerror) / `error:fallback` boundary. Prefer `ssr.stream` when you want progressive paint; prefer the sync call or `ssr.async` when streaming isn't needed (no Promise overhead).

### Errors Propagate

The sync call throws, a rejected `Promise` rejects `ssr.async`'s returned `Promise`, and a rejected bare `Promise` in the main walk errors `ssr.stream`'s `ReadableStream` (reading it throws). A rejecting `<Suspense>` region is the exception: the stream skips its `<template>` (the `fallback` and sentinel stay in the shell) and completes with its healthy siblings — `hydrate` re-suspends that region on the client, where the rejection reaches the nearest [`onError`](/reference/dom/onerror) / `error:fallback` boundary. Wrap the render in your own error handling if a value may throw; handle stream errors at the consumer (your server handler). A throwing *component* does not propagate: `component()` catches render errors and emits an empty fragment. See [Error handling](/learn/patterns/ssr#error-handling) for a try/catch-fallback recipe.

### Throws on invalid input

Every member throws the same shape when `node` is `null` or `undefined`: `[ssr] ssr: node is required, received <value>` for the sync call (`ssr.async` rejects its Promise with the `ssr.async` prefix, `ssr.stream` throws with the `ssr.stream` prefix). A root that is not a HellaNode — any non-object, or an object without a `tag` — throws `[ssr] <member>: node must be a HellaNode (object with a tag), received <typeof>` instead of silently serializing garbage HTML: passing an uninvoked component (`ssr(App)`) throws, `ssr(App())` renders.
