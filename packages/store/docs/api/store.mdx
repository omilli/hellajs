# store

Converts a plain object into a deeply reactive store where primitives become signals, nested objects recurse into stores, arrays become signals, and functions are preserved.

## API

```typescript
import { store } from '@hellajs/store';

// All properties writable (default)
function store<T>(initial: T, options?: StoreOptions<T>): Store<T>

// All properties readonly
function store<T>(initial: T, options: { readonly: true }): Store<T, keyof T>

// Specific properties readonly
function store<T, R extends readonly (keyof T)[]>(
  initial: T,
  options: { readonly: R }
): Store<T, R[number]>

// Middleware transformations only
function store<T>(
  initial: T,
  options: { middleware: StoreMiddleware<T> }
): Store<T, never>

// Specific properties readonly + middleware
function store<T, R extends readonly (keyof T)[]>(
  initial: T,
  options: { readonly: R; middleware: StoreMiddleware<T> }
): Store<T, R[number]>

type Store<T, R extends PropertyKey = never> = {
  [K in keyof T]:
    T[K] extends (...args: unknown[]) => unknown ? T[K] :
    T[K] extends unknown[] ? K extends R ? () => T[K] : Signal<T[K]> :
    T[K] extends Record<string, unknown> ? (K extends R ? Store<T[K], keyof T[K]> : Store<T[K]>) :
    K extends R ? () => T[K] : Signal<T[K]>;
} & {
  snapshot: () => Snapshot<T>;
  update: (partial: PartialDeep<T> | ((draft: Snapshot<T>) => void)) => void;
  cleanup: () => void;
}

// Recursively unwraps composed store types so Snapshot matches the plain
// values snapshot() actually returns

type Snapshot<T> = {
  [K in keyof T]:
    T[K] extends Store<infer U, PropertyKey> ? Snapshot<U> : T[K];
}

interface StoreOptions<T> {
  readonly?: boolean | readonly (keyof T)[];
  middleware?: StoreMiddleware<T>;
}

type StoreMiddleware<T> = {
  [K in keyof T]?: T[K] extends (...args: unknown[]) => unknown
  ? (value: T[K]) => T[K]
  : T[K] extends unknown[]
  ? (value: T[K]) => T[K]
  : T[K] extends Record<string, unknown>
  ? StoreMiddleware<T[K]>
  : (value: T[K]) => T[K];
};
```

- `initial`: Plain object to transform. Functions stay as-is, primitives become signals, plain objects recurse into nested stores, arrays become signals.
- `options.readonly`: `true` for all properties readonly, or an array of keys to lock. Propagates deep — `true` locks every plain-object level; a listed object key locks its entire subtree. Composed stores keep their own readonly config.
- `options.middleware`: Per-key transform functions applied on every set.
- **Returns**: A reactive store with `snapshot`, `update`, and `cleanup` methods.

### `snapshot`

A reactive snapshot of the entire store state as a plain JavaScript object. The snapshot function is reactive and will re-compute when any store property changes.

> ⚠️ **Performance**: snapshot accesses every signal in the store. When composed stores are nested, the dependency footprint covers the full composed tree — any leaf signal change triggers re-computation. Use individual property access for targeted reactivity in wide or deeply composed stores.

```typescript
import { store } from '@hellajs/store';

const appStore = store({ count: 0, user: { name: 'Alice' } });

const snapshot = appStore.snapshot();
console.log(snapshot); // { count: 0, user: { name: 'Alice' } }
```

The snapshot is reactive across composed store boundaries. When one store is nested inside another, mutating a leaf signal in either store triggers re-computation of the outer snapshot, and composed leaves unwrap to their plain values:

```typescript
import { effect } from '@hellajs/core';
import { store } from '@hellajs/store';

const userStore = store({ name: 'Alice' });
const appStore = store({ user: userStore });

effect(() => {
  console.log(appStore.snapshot()); // { user: { name: 'Alice' } }
});

userStore.name('Bob'); // triggers the effect — snapshot is reactive across composed stores
```

### `update`

Partial deep updates to the store state. Accepts either a partial object or a function that receives the current state.

For single property updates, set the property directly. For multiple properties or nested merges, use `update()`.

```typescript
import { store } from '@hellajs/store';

const appStore = store({ count: 0, step: 1, user: { name: 'Alice' } });

appStore.count(5);

appStore.update({
  step: 2,
  user: { name: 'Bob' },
});

console.log(appStore.count());       // 5
console.log(appStore.step());        // 2
console.log(appStore.user.name());   // Bob
```

> ⚠️ `update()` writes only signal-backed properties — unknown keys, function-valued properties, and reserved keys are silently ignored. Swap functions by assigning directly: `appStore.onSave = newHandler`.

### `cleanup`

Recursively invokes `cleanup` on each nested store. Individual signals are not disposed — they remain functional after cleanup, and the store object stays intact. Effects that read individual signals continue to fire.

```typescript
import { store } from '@hellajs/store';

const appStore = store({ count: 0, user: { name: 'Alice' } });
appStore.cleanup();

appStore.count(10);
console.log(appStore.count()); // 10
```

## Basic Usage

```typescript
import { store } from '@hellajs/store';

const appStore = store({
  count: 0,
  user: { name: 'Alice' }
});

appStore.count(5);
appStore.user.name('Bob');

console.log(appStore.count());       // 5
console.log(appStore.user.name());   // Bob
```

## Key Concepts

### Deep Reactivity

All nested objects become stores, arrays become signals, and functions stay as-is — a fully reactive state tree. Middleware transforms or validates values on every set; `readonly` restricts which properties can be modified. See [State](/learn/concepts/state) for the deep walk, effect examples, [middleware](/learn/concepts/state#middleware), and [readonly](/learn/concepts/state#readonly) configuration.

### Nested Stores

Existing stores can be passed as values to create hierarchical state with shared signal references.

```typescript
import { store } from '@hellajs/store';

const userStore = store({
  name: 'John Doe',
  preferences: { theme: 'dark' }
});

const uiStore = store({
  sidebarOpen: false,
  activeTab: 'dashboard'
});

const appStore = store({
  user: userStore,
  ui: uiStore
});

appStore.user.name('Jane');
userStore.name(); // 'Jane' — same signal reference
```

### Partial Updates

Pass a partial object to `update()` for deep merging nested properties — unknown keys are ignored. See [State](/learn/concepts/state) for the pattern.

### Mutable Updates

Pass a function to `update()` for ergonomic mutations on a mutable draft of the state. See [State](/learn/concepts/state) for array-operation examples.

### Function Preservation

Functions in the initial object are preserved as-is — not wrapped in signals, functional in snapshots. See [State](/learn/concepts/state) for `computed`-in-store examples.

### `PartialDeep<T>`

Recursive optional mapping used by [`update()`](#update). Arrays and functions are preserved as leaf values — a partial update to `{ items: [...] }` is a full replacement, not a deep merge.

```typescript
type PartialDeep<T> = {
  [K in keyof T]?: T[K] extends (...args: unknown[]) => unknown
  ? T[K]
  : T[K] extends unknown[]
  ? T[K]
  : T[K] extends Record<string, unknown>
  ? PartialDeep<T[K]>
  : T[K];
};
```

- **`T`**: The object type to make partially optional.

```typescript
import type { PartialDeep } from '@hellajs/store';

type Config = {
  apiUrl: string;
  features: { darkMode: boolean; beta: boolean };
  items: number[];
  log: () => void;
};

type PartialConfig = PartialDeep<Config>;
```

> ⚠️ `PartialDeep` preserves arrays and functions without recursing into them. Calling `update({ items: [...] })` replaces the entire array — it does not merge individual elements.

### `ReadonlyKeys<T, O>`

Extracts the readonly property key set from a `StoreOptions` value. Useful for deriving the readonly keys of a store at the type level. See [readonly](/learn/concepts/state#readonly) for usage.

```typescript
type ReadonlyKeys<T, O extends StoreOptions<T> | undefined> =
  O extends { readonly: true }
  ? keyof T
  : O extends { readonly: readonly (keyof T)[] }
  ? O["readonly"][number]
  : never;
```

- **`T`**: The store's value type.
- **`O`**: The `StoreOptions<T>` or `undefined`.

```typescript
import type { ReadonlyKeys } from '@hellajs/store';

type Config = { apiUrl: string; theme: string; debug: boolean };

type R1 = ReadonlyKeys<Config, { readonly: ['apiUrl'] }>;
// R1: 'apiUrl'

type R2 = ReadonlyKeys<Config, { readonly: true }>;
// R2: keyof Config — 'apiUrl' | 'theme' | 'debug'

type R3 = ReadonlyKeys<Config, undefined>;
// R3: never
```

## Important Considerations

### Draft Updates Compare Structurally

The `update(fn)` draft path diffs by content, not reference. Untouched `Date`, `Map`, `Set`, `RegExp`, and array values are not rewritten — their signals keep the same value and subscribers do not fire. Mutated class instances keep their prototype:

```typescript
import { store } from '@hellajs/store';

class Point {
  x: number;
  constructor(x: number) { this.x = x; }
}

const data = store({ point: new Point(1), count: 0 });

data.update(draft => {
  draft.count = 1; // point is untouched — no write, no subscriber wakeups
});

data.update(draft => {
  draft.point.x = 5; // written back as a Point, not a plain object
});
```

### Reserved Keys

The keys `snapshot`, `update`, and `cleanup` are reserved by the store implementation. Passing them as properties in the initial object throws an error.

```typescript
import { store } from '@hellajs/store';

store({ snapshot: 1 }); // Throws: Error '[store] store: reserved key collision, received "snapshot"'
```

### Memory Management

`cleanup()` propagates teardown through the store tree, invoking each nested store's `cleanup`. Assign a custom `cleanup` method to release external resources (timers, listeners, subscriptions); the call recurses through the whole tree.

```typescript
import { store } from '@hellajs/store';

const userStore = store({ name: 'John' });
userStore.cleanup();
```

### Readonly Propagates Deep

`readonly: true` locks every plain-object level of the store tree, and a listed object key locks its entire subtree. Composed stores are the exception: adoption preserves their signals, so a composed store keeps its own readonly configuration regardless of the parent's. See [readonly](/learn/concepts/state#readonly) for the full explanation and examples.

### Signals Survive Cleanup

`cleanup()` recursively invokes `cleanup` on nested stores but does not dispose individual signals or null the store object. This is intentional: signals owned by other contexts (composed stores, external effects) keep working.

### Effects vs Middleware

- **Effects** run after changes — use for logging, persistence, derived state.
- **Middleware** runs before changes — use for validation, transformation.

```typescript
import { effect } from '@hellajs/core';
import { store } from '@hellajs/store';

const data = store({ count: 0 }, {
  middleware: { count: (v) => Math.max(0, v) }
});

effect(() => {
  console.log('Count changed:', data.count());
});
```
