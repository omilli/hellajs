# store

Converts a plain object into a deeply reactive store where each property is an independently reactive signal.

## API

```typescript
import { store } from '@hellajs/store';

function store<T>(initial: T, options?: StoreOptions<T>): Store<T>
function store<T>(initial: T, options: { readonly: true }): Store<T, keyof T>
function store<T, R extends readonly (keyof T)[]>(
  initial: T,
  options: { readonly: R }
): Store<T, R[number]>
function store<T>(
  initial: T,
  options: { middleware: StoreMiddleware<T> }
): Store<T, never>
function store<T, R extends readonly (keyof T)[]>(
  initial: T,
  options: { readonly: R; middleware: StoreMiddleware<T> }
): Store<T, R[number]>

type Store<T, R extends PropertyKey = never> = {
  [K in keyof T]:
    T[K] extends (...args: unknown[]) => unknown ? T[K] :
    T[K] extends unknown[] ? K extends R ? () => T[K] : Signal<T[K]> :
    T[K] extends Record<string, unknown> ? Store<T[K], R> :
    K extends R ? () => T[K] : Signal<T[K]>;
} & {
  snapshot: () => T;
  update: (partial: PartialDeep<T> | ((draft: T) => void)) => void;
  cleanup: () => void;
}

interface StoreOptions<T> {
  readonly?: boolean | readonly (keyof T)[];
  middleware?: StoreMiddleware<T>;
}

type StoreMiddleware<T> = {
  [K in keyof T]?: T[K] extends Record<string, unknown>
    ? StoreMiddleware<T[K]> | ((value: T[K]) => T[K])
    : (value: T[K]) => T[K];
};
```

- `initial`: Plain object to transform. Functions stay as-is, primitives become signals, plain objects recurse into nested stores, arrays become signals.
- `options.readonly`: `true` for all properties readonly, or an array of keys to lock.
- `options.middleware`: Per-key transform functions applied on every set.
- **Returns**: A reactive store with `snapshot`, `update`, and `cleanup` methods.

## Basic Usage

```typescript
import { store } from '@hellajs/store';

const appStore = store({
  count: 0,
  user: { name: 'Alice' }
});

appStore.count(5);
appStore.user.name('Bob');

console.log(appStore.count());       // 5
console.log(appStore.user.name());   // Bob
```

### `snapshot`

A reactive snapshot of the entire store state as a plain JavaScript object. The returned object is a plain snapshot at call time, not a live reference; store it and it won't update.

> ⚠️ **Performance**: snapshot accesses every signal in the store. Any property change triggers re-computation. Use individual property access for targeted reactivity.

```typescript
import { store } from '@hellajs/store';

const appStore = store({ count: 0, user: { name: 'Alice' } });

const snapshot = appStore.snapshot();
console.log(snapshot); // { count: 0, user: { name: 'Alice' } }
```

### `update`

Partial deep updates to the store state. Accepts either a partial object or a function that receives the current state.

For single property updates, set the property directly. For multiple properties or nested merges, use `update()`.

```typescript
import { store } from '@hellajs/store';

const appStore = store({ count: 0, step: 1, user: { name: 'Alice' } });

appStore.count(5);

appStore.update({
  step: 2,
  user: { name: 'Bob' },
});

console.log(appStore.count());       // 5
console.log(appStore.step());        // 2
console.log(appStore.user.name());   // Bob
```

> ⚠️ `update()` only applies changes for properties that exist in the initial object. Unknown keys are silently ignored.

#### Mutable Update

```typescript
import { store } from '@hellajs/store';

const appStore = store({ count: 0, user: { name: 'Alice' } });

appStore.update(draft => {
  draft.count = 5;
  draft.user.name = 'Jane';
});

console.log(appStore.count());       // 5
console.log(appStore.user.name());   // Jane
```

### `cleanup`

Recursively disposes nested stores and their reactive subscriptions. Individual signals remain accessible after cleanup; they are not disposed, only the store structure is torn down.

```typescript
import { store } from '@hellajs/store';

const appStore = store({ count: 0, user: { name: 'Alice' } });
appStore.cleanup();

appStore.count(10);
console.log(appStore.count()); // 10
```

## Key Concepts

### Deep Reactivity

All nested objects are automatically converted to reactive stores, arrays become signals, and functions remain unchanged, creating a fully reactive state tree.

```typescript
import { effect } from '@hellajs/core';
import { store } from '@hellajs/store';

const userStore = store({
  profile: { name: 'John', age: 30 },
  settings: { theme: 'dark' }
});

effect(() => {
  console.log(userStore.profile.name());
  console.log(userStore.settings.theme());
});
```

### Middleware

Transform or validate values before they are stored. Middleware runs synchronously on every set operation for the configured properties.

```typescript
import { store } from '@hellajs/store';

const user = store({
  name: '',
  email: '',
  age: 0
}, {
  middleware: {
    name: (v) => v.trim(),
    email: (v) => v.toLowerCase(),
    age: (v) => {
      if (v < 0) throw new Error('Age cannot be negative');
      return v;
    }
  }
});

user.name('John');              // stored as 'John'
user.email('john@example.com'); // stored as 'john@example.com'
user.age(-5);                   // throws Error
```

Middleware also applies through `update()`:

```typescript
user.update({ name: 'Jane', age: 30 });
user.update(draft => { draft.email = 'jane@example.com'; });
```

Middleware works with nested stores too:

```typescript
const app = store({
  user: { name: '', email: '' },
  settings: { theme: 'light' }
}, {
  middleware: {
    user: {
      name: (v) => v.trim(),
      email: (v) => v.toLowerCase()
    },
    settings: {
      theme: (v) => {
        if (!['light', 'dark'].includes(v)) throw new Error('Invalid theme');
        return v;
      }
    }
  }
});
```

### Readonly Options

Granular control over which properties can be modified, enforced at the type level.

```typescript
import { store } from '@hellajs/store';

const configStore = store(
  { apiUrl: 'https://api.com', theme: 'light', debug: false },
  { readonly: ['apiUrl'] }
);

configStore.theme('dark');           // Updates normally
configStore.apiUrl('new-url');       // Silently ignored at runtime, type error at compile time
```

Readonly keys do not propagate to nested stores. Each nested store requires its own readonly configuration.

### Nested Stores

Existing stores can be passed as values to create hierarchical state with shared signal references.

```typescript
import { store } from '@hellajs/store';

const userStore = store({
  name: 'John Doe',
  preferences: { theme: 'dark' }
});

const uiStore = store({
  sidebarOpen: false,
  activeTab: 'dashboard'
});

const appStore = store({
  user: userStore,
  ui: uiStore
});

appStore.user.name('Jane');
userStore.name(); // 'Jane' — same signal reference
```

### Partial Updates

Pass a partial object to `update` for deep merging nested properties.

```typescript
import { store } from '@hellajs/store';

const user = store({
  profile: { name: 'John', email: 'john@example.com' },
  settings: { theme: 'light', notifications: true }
});

user.update({
  profile: { name: 'Jane', email: 'jane@example.com' }
});

console.log(user.profile.name()); // Jane
console.log(user.settings.theme()); // light (unchanged)
```

### Mutable Updates

Pass a function to `update` for ergonomic mutations on arrays and complex nested transforms. The function receives a mutable draft.

```typescript
import { store } from '@hellajs/store';

const todos = store({
  items: [
    { id: 1, text: 'Learn HellaJS', done: false },
    { id: 2, text: 'Build app', done: false }
  ],
  count: 2
});

todos.update(draft => {
  draft.items.push({ id: 3, text: 'Ship it', done: false });
  draft.items[0].done = true;
  draft.count = draft.items.length;
});

console.log(todos.items().length); // 3
console.log(todos.items()[0].done); // true
```

### Function Preservation

Functions in the initial object are preserved as-is. They are not wrapped in signals and remain unchanged in the store and snapshot.

```typescript
import { computed } from '@hellajs/core';
import { store, type Store } from '@hellajs/store';

type DataStore = Store<{
  count: number;
  double: () => number;
  logCount: () => void;
}>;

const data: DataStore = store({
  count: 0,
  double: computed(() => data.count() * 2),
  logCount: () => console.log('Count is', data.count()),
});

data.count(1);
data.logCount(); // Count is 1
data.double();   // 2
```

## Important Considerations

### Reserved Keys

The keys `snapshot`, `update`, and `cleanup` are reserved by the store implementation. Passing them as properties in the initial object throws an error.

```typescript
store({ snapshot: 1 }); // throws: Reserved key "snapshot"
```

### Memory Management

Call `cleanup()` when stores are no longer needed to prevent memory leaks from nested store subscriptions.

```typescript
const userStore = store({ name: 'John' });
userStore.cleanup();
```

### Nested Stores Do Not Inherit Readonly

Readonly configuration applies to the current store level only. Nested stores passed in retain their own readonly settings.

### Signals Survive Cleanup

`cleanup()` disposes the store structure and nested computed dependencies, but individual signals remain functional. This is intentional: signals owned by other contexts (composed stores, external effects) keep working.

### Effects vs Middleware

- **Effects** run after changes — use for logging, persistence, derived state.
- **Middleware** runs before changes — use for validation, transformation.

```typescript
import { effect } from '@hellajs/core';
import { store } from '@hellajs/store';

const data = store({ count: 0 }, {
  middleware: { count: (v) => Math.max(0, v) }
});

effect(() => {
  console.log('Count changed:', data.count());
});
```
