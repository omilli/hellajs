# store

A deeply reactive store for managing application state, with full type safety and flexible readonly controls.

## API

```typescript
import { store } from '@hellajs/store';

function store<T>(initial: T, options?: StoreOptions<T>): Store<T>

type Store<T, R = never> = {
  [K in keyof T]: T[K] extends (...args: unknown[]) => unknown
    ? T[K]
    : T[K] extends unknown[]
    ? K extends R ? () => T[K] : Signal<T[K]>
    : T[K] extends Record<string, unknown>
    ? Store<T[K]>
    : K extends R ? () => T[K] : Signal<T[K]>;
} & {
  snapshot: () => T;
  update(partial: PartialDeep<T> | ((draft: T) => void)): void;
  cleanup(): void;
}

interface StoreOptions<T> {
  readonly?: boolean | readonly (keyof T)[]; // true = all readonly, array = specific keys
  middleware?: StoreMiddleware<T>;
}

type StoreMiddleware<T> = {
  [K in keyof T]?: T[K] extends Record<string, unknown>
    ? StoreMiddleware<T[K]> | ((value: T[K]) => T[K])
    : (value: T[K]) => T[K];
};
```

### `snapshot`

A reactive snapshot of the entire store state as a plain JavaScript object. The returned object is a plain snapshot at call time, not a live reference; store it and it won't update.

> ⚠️ **Performance**: snapshot accesses every signal in the store. Any property change triggers re-computation. Use individual property access for targeted reactivity.

```typescript
import { store } from '@hellajs/store';

const appStore = store({ count: 0, user: { name: 'Alice' } });

// Get a reactive snapshot of the entire store
const snapshot = appStore.snapshot();
console.log(snapshot); // { count: 0, user: { name: 'Alice' } }
```

### `update`

Partial deep updates to the store state. Accepts either a partial object or a function that receives the current state.

For single property updates, set the property directly. For multiple properties or nested merges, use `update()`.

**Partial object update:**
```typescript
import { store } from '@hellajs/store';

const appStore = store({ count: 0, step: 1, user: { name: 'Alice' } });

// Single property: set directly
appStore.count(5);

// Multiple properties: use update
appStore.update({
  step: 2,
  user: { name: 'Bob' },
});

console.log(appStore.count());       // 5
console.log(appStore.step());        // 2
console.log(appStore.user.name()); // Bob
```

> ⚠️ `update()` only applies changes for properties that exist in the initial object. Unknown keys are silently ignored.

**Mutable update:**
```typescript
import { store } from '@hellajs/store';

const appStore = store({ count: 0, user: { name: 'Alice' } });

appStore.update(draft => {
  draft.count = 5;
  draft.user.name = 'Jane';
});

console.log(appStore.count()); // 5
console.log(appStore.user.name()); // Jane
```

### `cleanup`

Recursively disposes nested stores and their reactive subscriptions. Individual signals remain accessible after cleanup; they are not disposed, only the store structure is torn down.

```typescript
import { store } from '@hellajs/store';

const appStore = store({ count: 0, user: { name: 'Alice' } });
// Later, when done with the store
appStore.cleanup();

// Signals still work after cleanup
appStore.count(10);
console.log(appStore.count()); // 10
```

### `middleware`

Transform or validate values before they are stored. Middleware runs synchronously on every set operation for the configured properties.

- `initial`: Initial object to create the store from
- `options.middleware`: Map of property keys to transform functions; can be nested for nested stores

```typescript
import { store } from '@hellajs/store';

const user = store({
  name: '',
  email: '',
  age: 0
}, {
  middleware: {
    name: (v) => v.trim(),
    email: (v) => v.toLowerCase(),
    age: (v) => {
      if (v < 0) throw new Error('Age cannot be negative');
      return v;
    }
  }
});

user.name('John');          // stored as 'John'
user.email('john@example.com'); // stored as 'john@example.com'
user.age(-5);                   // ❌ throws Error
```

Middleware also applies through `update()`:

```typescript
user.update({ name: 'Jane', age: 30 }); // name stored as 'Jane'
user.update(draft => { draft.email = 'jane@example.com'; }); // stored as 'jane@example.com'
```

## Key Concepts

### Deep Reactivity

All nested objects are automatically converted to reactive stores, arrays become signals, and functions remain unchanged, creating a fully reactive state tree.

```typescript
import { effect } from '@hellajs/core';
import { store } from '@hellajs/store';

const userStore = store({
  profile: {
    name: 'John',
    age: 30
  },
  settings: {
    theme: 'dark'
  }
});

// All nested properties are reactive
effect(() => {
  console.log(userStore.profile.name()); // Reactive to name changes
  console.log(userStore.settings.theme()); // Reactive to theme changes
});
```

### Readonly Options

Granular control over which properties can be modified, with full TypeScript support.

```typescript
import { store } from '@hellajs/store';

const configStore = store(
  { apiUrl: 'https://api.com', theme: 'light', debug: false },
  { readonly: ['apiUrl'] } // apiUrl cannot be modified
);

configStore.theme('dark'); // ✅ Works
configStore.apiUrl('new-url'); // ❌ Doesn't update

// TypeScript enforces readonly at compile time
const readonlyConfig: Store<{ apiUrl: string; theme: string }, 'apiUrl'> = configStore;
```

### Nested Stores

Existing stores can be passed as values to create hierarchical state with shared signal references.

```typescript
import { store } from '@hellajs/store';

const userStore = store({
  name: 'John Doe',
  preferences: { theme: 'dark' }
});

const uiStore = store({
  sidebarOpen: false,
  activeTab: 'dashboard'
});

// Compose stores into a single app store
const appStore = store({
  user: userStore,
  ui: uiStore
});

// Access deeply nested properties
appStore.user.name(); // 'John Doe'
appStore.user.preferences.theme(); // 'dark'

// Updates sync bidirectionally (same signal references)
appStore.user.name('Jane');
userStore.name(); // 'Jane' - original store reflects change
```

### Partial Updates

Pass a partial object to `update` for deep merging nested properties. This is ideal for simple property updates and deep object merges.

```typescript
import { store } from '@hellajs/store';

const user = store({
  profile: {
    name: 'John',
    email: 'john@example.com'
  },
  settings: {
    theme: 'light',
    notifications: true
  }
});

// Deep merge nested properties
user.update({
  profile: {
    name: 'Jane',
    email: 'jane@example.com'
  }
});

console.log(user.profile.name()); // Jane
console.log(user.profile.email()); // jane@example.com
console.log(user.settings.theme()); // light (unchanged)
```

### Mutable Updates

Pass a function to `update` for ergonomic mutations on arrays and complex nested transforms. The function receives a mutable draft you can modify directly.

```typescript
import { store } from '@hellajs/store';

const todos = store({
  items: [
    { id: 1, text: 'Learn HellaJS', done: false },
    { id: 2, text: 'Build app', done: false }
  ],
  count: 2
});

// Mutate arrays directly
todos.update(draft => {
  draft.items.push({ id: 3, text: 'Ship it', done: false });
  draft.items[0].done = true;
  draft.count = draft.items.length;
});

console.log(todos.items()); // 3 items
console.log(todos.items()[0].done); // true

// Complex coordinated mutations
const cart = store({
  items: [
    { id: 1, price: 10, qty: 2 },
    { id: 2, price: 5, qty: 1 }
  ],
  total: 25
});

cart.update(draft => {
  // Remove item and recalculate
  draft.items = draft.items.filter(item => item.id !== 2);
  // Update quantity and recalculate
  draft.items[0].qty = 3;
  draft.total = draft.items.reduce((sum, item) => sum + item.price * item.qty, 0);
});

console.log(cart.total()); // 30
```

### Function Preservation

Functions in the initial object are preserved as-is. They are not wrapped in signals and remain unchanged in the store and snapshot.

```typescript
import { store } from '@hellajs/store';

const data = store({
  count: 0,
  double: () => 2
});

data.double(); // 2 (called directly, not a signal)

const snap = data.snapshot();
snap.double(); // 2 (preserved in snapshot)
```

### Middleware for Validation and Transformation

Middleware intercepts values before they're stored, enabling validation and transformation.

```typescript
import { store } from '@hellajs/store';

const user = store({
  name: '',
  email: '',
  age: 0
}, {
  middleware: {
    // Transform: normalize input
    name: (v) => v.trim(),
    email: (v) => v.toLowerCase(),

    // Validate: throw to reject
    age: (v) => {
      if (v < 0) throw new Error('Age cannot be negative');
      if (v > 150) throw new Error('Age seems invalid');
      return v;
    }
  }
});

user.name('John');      // stored as 'John'
user.email('john@example.com'); // stored as 'john@example.com'
user.age(-5);              // throws Error: Age cannot be negative
```

Middleware works with nested stores too:

```typescript
const app = store({
  user: {
    name: '',
    email: ''
  },
  settings: {
    theme: 'light'
  }
}, {
  middleware: {
    user: {
      name: (v) => v.trim(),
      email: (v) => v.toLowerCase()
    },
    settings: {
      theme: (v) => {
        if (!['light', 'dark'].includes(v)) {
          throw new Error('Invalid theme');
        }
        return v;
      }
    }
  }
});
```

## Important Considerations

### Memory Management

Call `cleanup()` when stores are no longer needed to prevent memory leaks.

```typescript
import { store } from '@hellajs/store';

// ✅ Clean up when done
const userStore = store({ name: 'John' });
// Later...
userStore.cleanup();
```

### Effects vs Middleware

- **Effects** run *after* changes - use for logging, persistence, derived state
- **Middleware** runs *before* changes - use for validation, transformation

```typescript
import { effect } from '@hellajs/core';
import { store } from '@hellajs/store';

const data = store({ count: 0 }, {
  middleware: {
    count: (v) => Math.max(0, v) // Transform before storing
  }
});

// Effect runs after change
effect(() => {
  console.log('Count changed:', data.count());
});
```
