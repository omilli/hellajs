# State

Short, copy-pasteable patterns for common state management tasks using [`store`](/reference/store/store). Each pattern is self-contained with imports.

### Store with Validation

Use middleware to trim strings and clamp numbers before storing values. Middleware runs synchronously on every set operation and should return the transformed value.

```typescript
import { store } from '@hellajs/store';

const form = store({
  name: '',
  email: '',
  age: 0,
}, {
  middleware: {
    // Middleware for primitive values receives the new value and returns transformed value
    // Type: (value: string) => string for name and email
    // Type: (value: number) => number for age
    name: (v) => v.trim(),
    email: (v) => v.toLowerCase().trim(),
    age: (v) => Math.min(150, Math.max(0, v)), // clamp between 0-150
  },
});

form.name('John');  // stored as 'John'
// form.age(-5);   // stored as 0 (clamped by middleware)
```

### Partial Deep Updates

Update nested properties without replacing the entire object using `$update()` with a partial. The update applies to properties of the initial object and materializes unknown keys, returning the store typed with them.

```typescript
import { store } from '@hellajs/store';

const app = store({
  user: { name: 'Alice', role: 'viewer' },
  theme: 'light',
});

app.$update({
  user: { name: 'Bob' }, // Only updates the name property
  theme: 'dark',
});

app.user.name(); // 'Bob'
app.user.role(); // 'viewer' (unchanged - not included in update)
app.theme();     // 'dark'
// Adding new properties works the same way: const grown = app.$update({ newProp: 'value' })
// materializes newProp and types it on the returned store
```

### Declaring Future Keys

Grow a store on the same binding by declaring keys that arrive later as optional in the type parameter; the first `$update()` write materializes them.

```typescript
import { effect } from '@hellajs/core';
import { store } from '@hellajs/store';

const app = store<{ count: number; tags?: string[] }>({ count: 0 });

effect(() => {
  // Snapshot reads see the add; direct app.tags?.() reads track nothing
  // until the key exists, so snapshot is the cross-materialization seam
  console.log('tags:', app.$snapshot().tags);
});

app.$update({ tags: ['a'] }); // materializes tags
// Logs: "tags: undefined", then "tags: [ 'a' ]"

app.tags?.(); // [ 'a' ] - optional-chained, typed string[] | undefined
```

### Mutable Draft Updates

Pass a function to `$update()` for ergonomic array operations and coordinated mutations. The function receives a mutable draft copy of the state, and changes are extracted via diff and applied per key: collection values reconcile through their containers, so changed positions patch their element stores and untouched positions write nothing. This is particularly useful for array operations.

```typescript
import { store } from '@hellajs/store';

const todos = store({
  items: [
    { id: 1, text: 'Write tests', done: false },
    { id: 2, text: 'Ship it', done: false },
  ],
  count: 2,
});

todos.$update(draft => {
  // draft is a mutable copy - changes won't affect original until function completes
  draft.items.push({ id: 3, text: 'Refactor', done: false });
  draft.items = draft.items.filter(item => item.id !== 1);
  draft.count = draft.items.length; // updates derived state
});

todos.items(); // [{ id: 2, ... }, { id: 3, ... }]
todos.count(); // 2
// The draft function runs synchronously and all changes are applied as individual writes; wrap the call in [`batch`](/reference/core/batch)`()` to fire effects once
```

### Structural Array Equality

Silence content-equal writes with the `'structural'` write-equality preset, useful when a big collection key is rewritten wholesale on every save and the content usually hasn't changed. For collection keys the comparator applies per element: equal elements write nothing and wake no one.

```typescript
import { effect } from '@hellajs/core';
import { store } from '@hellajs/store';

const board = store({
  columns: ['todo', 'doing', 'done'],
}, {
  equals: { columns: 'structural' },
});

effect(() => {
  console.log(board.columns().join(',')); // Logs: todo,doing,done
});

board.columns(['todo', 'doing', 'done']); // same content; no element write, effect stays asleep
board.columns(['todo', 'blocked', 'done']); // changed; effect re-runs
```

### Deep Todo Lists

Collection keys give the todo shape field-precise updates without the draft indirection: object elements are element stores, so a write to one field of one todo wakes only that field's readers.

```typescript
import { effect } from '@hellajs/core';
import { store } from '@hellajs/store';

const todos = store({
  todos: [{ id: 1, text: 'write plans', completed: false }]
});

effect(() => todos.todos.get(0)!.completed());  // Subscribes to ONE field
todos.todos.get(0)!.completed(true);            // Wakes only that effect
todos.todos.set(0, { completed: true });        // Patch: text kept, completed-readers only
todos.todos.push({ id: 2, text: 'ship', completed: false }); // Structural: positional readers wake
console.log(todos.$snapshot().todos.length);     // 2, deep-plain
```
### Collections in ForEach

Pass the container callable to `ForEach` and close over the element stores for field-precise bindings: each row reads its own element store's fields, so a field write re-renders nothing but the bound text.

```typescript
import { ForEach, html } from '@hellajs/dom';
import { store } from '@hellajs/store';
import type { Store } from '@hellajs/store';

type Todo = { id: number; text: string; completed: boolean };

const todos = store({
  todos: [{ id: 1, text: 'write plans', completed: false }] as Todo[]
});

html`
  <ul>
    <${ForEach} each=${() => todos.todos()}>
      ${(todo: Store<Todo>) => html`<li class=${() => (todo.completed() ? 'done' : '')}>${() => todo.text()}</li>`}
    <//>
  </ul>
`;
```

Element references are stable across calls (`todos.todos()[0] === todos.todos()[0]`), which is what the keyed reconciliation relies on.

### Patch Semantics vs Whole-Array Reconcile

`set(i, partial)` patches the element store in place: untouched fields keep their values and their readers stay asleep. Writing the whole array through the callable reconciles position-wise with the same patch semantics, and equal positions write nothing. Only structural differences (length, Map membership, Set membership) wake positional readers.

```typescript
import { effect } from '@hellajs/core';
import { store } from '@hellajs/store';

const todos = store({
  todos: [{ id: 1, text: 'write plans', completed: false }]
});

effect(() => todos.todos.get(0)!.text());      // The text reader
todos.todos.set(0, { completed: true });       // never re-runs: patch keeps text
todos.todos([{ id: 1, text: 'write plans', completed: true }]); // Same: position 0 patches, no structural wake
console.log(todos.todos.get(0)!.text());        // write plans, untouched
```

### Nested Grids

Collections inside collections recurse: each inner collection is its own container, fully granular.

```typescript
import { effect } from '@hellajs/core';
import { store } from '@hellajs/store';

const grid = store({ grid: [[1, 2], [3, 4]] });

effect(() => grid.grid.get(0)!.get(0)); // Tracks one inner cell
grid.grid.get(0)!.set(0, 9);            // Wakes only inner-index-0 readers
console.log(grid.$snapshot().grid);      // [[9, 2], [3, 4]], deep-plain
```

### Readonly Properties

Lock specific keys to read-only access using the `readonly` option. Object keys lock their whole subtree: every nested level below a listed key is readonly too.

```typescript
import { store } from '@hellajs/store';

const config = store({
  apiUrl: 'https://api.example.com',
  theme: 'light',
  limits: { maxItems: 100 },
}, {
  readonly: ['apiUrl', 'limits'] as const,
});

config.theme('dark');       // Updates normally
// ❌ config.apiUrl('localhost'); throws: [store] readonly key "apiUrl"
// ❌ config.limits.maxItems(50); throws: object keys lock their whole subtree
config.limits.maxItems();   // 100
config.apiUrl();            // 'https://api.example.com'
```

### Store Composition

Nest existing stores inside a parent store for hierarchical state with shared references.

```typescript
import { store } from '@hellajs/store';

const userStore = store({
  name: 'Alice',
  role: 'admin',
});

const uiStore = store({
  sidebar: true,
  theme: 'dark',
});

const appStore = store({
  user: userStore,
  ui: uiStore,
});

appStore.user.name('Bob');
userStore.name(); // 'Bob': same signal reference

appStore.ui.theme(); // 'dark'
```

### Subscribe to Property Changes

Observe a single property with `$subscribe()` for logging, analytics, or any side effect that needs the previous value. The callback receives `(next, prev)`, does not fire on subscribe, and the returned function stops notifications.

```typescript
import { store } from '@hellajs/store';

const cart = store({
  items: [{ id: 1, price: 10 }],
  discount: 0.1,
});

const trackDiscount = cart.$subscribe('discount', (next, prev) => {
  console.log(`discount: ${prev} → ${next}`);
  // analytics: report(prev, next); reads here stay untracked
});

cart.discount(0.2); // Logs: discount: 0.1 → 0.2
trackDiscount();
cart.discount(0.3); // silent; unsubscribed
```

### Store Snapshot

Get a plain object snapshot of the entire store. Snapshots are reactive: use them in [`computed`](/reference/core/computed) for derived state.

```typescript
import { computed } from '@hellajs/core';
import { store } from '@hellajs/store';

const cart = store({
  items: [{ id: 1, price: 10 }, { id: 2, price: 20 }],
  discount: 0.1,
});

const total = computed(() => {
  const state = cart.$snapshot();
  const subtotal = state.items.reduce((sum, item) => sum + item.price, 0);
  return subtotal * (1 - state.discount);
});

total(); // 27
cart.discount(0.2);
total(); // 24
```
