

# Resources

Reactive data fetching with automatic loading states, caching, and error handling.

Resources wrap async operations in reactive primitives: [`computed`](/reference/core/computed) for data (so transforms stay in sync), [`signal`](/reference/core/signal) for error and loading flags. When data changes, only the affected parts of the UI update. No manual subscription management, no stale closures.

## Resource Creation

Resources are created with the [`resource`](/reference/resource/resource) function. The first argument is either a URL string or an async fetcher function. The returned object exposes reactive getters (`data`, `error`, `isLoading`, etc.) and methods (`fetch`, `abort`, `invalidate`, etc.).

### Function-Based Resources

Pass an async function that returns data, then trigger with `fetch`.

```typescript
const todos = resource(() =>
  fetch('/api/todos').then(r => r.json())
);

todos.fetch({ force: true });

console.log(todos.isLoading()); // true
console.log(todos.status());    // 'loading'

// After completion:
// todos.data() -> [{ id: 1, text: "Learn resources", completed: false }]
// todos.status() -> 'success'

// fetch() is awaitable: resolves the fetched data (or undefined on error), never rejects
const todosData = await todos.fetch();
console.log(todosData);
```

### URL-Based Resources

For simple GET requests, pass a URL directly. The URL is used as both the fetch target and the cache key.

```typescript
const users = resource('/api/users');

users.fetch({ force: true });
```

### Reactive Keys

Use the `key` option to parameterize resources with reactive values. Changing the key dependency does not trigger a refetch by itself; call `invalidate()` or `fetch()` to use the new key value.

```typescript
import { signal } from '@hellajs/core';

const userId = signal(1);

const posts = resource(
  id => fetch(`/api/users/${id}/posts`).then(r => r.json()),
  { key: () => userId() }
);

posts.fetch({ force: true });

userId(2);
posts.invalidate(); // Refetch with new userId
```

Set `refetchOnKeyChange: true` to eliminate manual `invalidate()` calls: the resource automatically refetches when key dependencies change.

```typescript
const posts = resource(
  id => fetch(`/api/users/${id}/posts`).then(r => r.json()),
  {
    key: () => userId(),
    refetchOnKeyChange: true
  }
);

userId(2); // Automatically fetches posts for user 2
```

When the key resolves to `null` or `undefined`, the fetch is skipped. This prevents premature requests when key dependencies haven't loaded yet.

For the full API surface including `initialData`, `enabled`, `timeout`, `deduplicate`, and all reactive getters, see [`resource`](/reference/resource/resource).

## Mutations

Resources include a built-in mutation system with lifecycle hooks for optimistic updates and error rollback. The pattern uses two resources: one for reading data, one for writing.

```typescript
import { resource } from '@hellajs/resource';

type Todo = { id: number; text: string; completed: boolean; pending?: boolean };

// Read resource
const todosResource = resource<Todo[]>(
  () => fetch('/api/todos').then(r => r.json())
);

// Write resource with optimistic update
const addTodoResource = resource(
  async (todoData: Omit<Todo, 'id'>) => {
    const response = await fetch('/api/todos', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify(todoData)
    });
    return response.json() as Promise<Todo>;
  },
  {
    onMutate: async (variables) => {
      const tempTodo: Todo = { id: Date.now(), ...(variables as Omit<Todo, "id">), pending: true };
      todosResource.setData(todos => [...(todos || []), tempTodo]);
      return { tempTodo };
    },
    onSettled: async (newTodo, error, variables, context) => {
      const temp = (context as { tempTodo: Todo } | undefined)?.tempTodo;
      if (error && temp) {
        todosResource.setData(todos =>
          (todos || []).filter(todo => todo.id !== temp.id)
        );
      }
      todosResource.invalidate();
    }
  }
);

addTodoResource.mutate({ text: 'Learn mutations', completed: false });
```

The mutation lifecycle (`onMutate`, `onSettled`) provides the hooks needed for optimistic updates with rollback. See [`resource`](/reference/resource/resource) for the full lifecycle API.

### Concurrent Mutations

Each `mutate()` call runs independently — a second call never aborts the first. Both fetchers run, both settle with their own `variables` and `onMutate` context, and `retry`/`retryDelay` apply to mutations just like reads. Reads and mutations never abort each other either; `abort()` is the cancel-all — it aborts the active read and every in-flight mutation, resetting the resource to its `initialData`.

Double-clicks fire two mutations. For operations that must not overlap (payments, duplicate row creation), guard the trigger while a mutation is in flight:

```typescript
const submitTodo = () => {
  if (addTodoResource.isFetching()) return; // single-flight guard: ignore double-submits
  addTodoResource.mutate({ text: 'Learn mutations', completed: false });
};
```

## Features

Resources provide several built-in features for production data fetching. Each is documented in full detail in the [`resource`](/reference/resource/resource) reference.

### Stale-While-Revalidate (SWR)

Control data freshness with `staleTime`. When data becomes "stale" but is still cached, `.fetch()` returns it immediately while fetching fresh data in the background.

```typescript
import { resource } from '@hellajs/resource';

// Fresh: 0-30s, Stale: 30s-5min, Expired: 5min+
const user = resource(
  () => fetch('/api/user').then(r => r.json()),
  { staleTime: 30000, cacheTime: 300000 }
);

user.fetch();
```

| Time | State | `fetch()` behavior |
|------|-------|--------------------|
| 0-30s | Fresh | Returns cached data instantly |
| 30s-5min | Stale | Returns cached data + background fetch |
| 5min+ | Expired | Fresh network request |

After `staleTime` passes, `fetch()` returns stale data immediately and triggers a background refetch: `isLoading()` stays false, `isFetching()` turns true, `data()` returns the previous value.

`staleTime` options: `0` (always stale, triggers background fetch on every `fetch()`), `Infinity` (never stale, default). Set `revalidateOnStale: false` to disable background refetch when stale.

### Automatic Retry

Configure retry behavior with count, conditional logic, and custom delays. Retries respect abort signals.

```typescript
// Simple retry count with fixed delay
const userResource = resource(
  () => fetch('/api/user').then(r => r.json()),
  { retry: 3, retryDelay: 1000 }
);

// Boolean shorthand: true = retry once, false = no retries (default)
// e.g. resource(fetcher, { retry: true })

// Conditional retry based on error category + exponential backoff
const resilient = resource(
  () => fetch('/api/data').then(r => r.json()),
  {
    retry: (count, error) => error.category !== 'not_found' && count < 3,
    retryDelay: (attempt) => Math.min(1000 * Math.pow(2, attempt - 1), 30000)
  }
);
```

Retries can be cancelled at any point during the delay:

```typescript
const r = resource(() => fetch('/api/slow').then(r => r.json()),
  { retry: 10, retryDelay: 5000 }
);
r.fetch({ force: true });
setTimeout(() => r.abort(), 2000); // Cancel during retry delay
```

### Polling / Interval Refetch

Periodically refresh data for real-time updates. Polling requires `refetchOnKeyChange: true`. Without it, the polling cycle never starts. Polling arms when `enabled` first evaluates `true` — including a later flip from `false` — and key changes never reset the cadence. `abort()`/`reset()` stop polling until the resource is recreated.

```typescript
// Fixed interval: every 5 seconds
const stockPrice = resource(
  () => fetch('/api/stock/price').then(r => r.json()),
  { refetchInterval: 5000, refetchOnKeyChange: true }
);
```

Dynamic interval based on data:

```typescript
const health = resource(
  () => fetch('/api/health').then(r => r.json()),
  {
    refetchInterval: (data) => data?.status === 'unhealthy' ? 1000 : 30000,
    refetchOnKeyChange: true
  }
);
```

Continue polling when tab is hidden:

```typescript
const stats = resource(
  () => fetch('/api/stats').then(r => r.json()),
  { refetchInterval: 10000, refetchIntervalInBackground: true, refetchOnKeyChange: true }
);
```

Always call `dispose()` to stop polling and clean up timers.

### Window Focus / Reconnect Refetch

Automatically refetch when the user returns to the tab, focuses the browser window (switching back from another app), or when the browser reconnects. Both require `refetchOnKeyChange: true` for automatic initial fetch.

```typescript
const session = resource(
  () => fetch('/api/session').then(r => r.json()),
  { refetchOnWindowFocus: true, refetchOnReconnect: true, refetchOnKeyChange: true }
);
```

`refetchOnWindowFocus` fires on both `visibilitychange` (the tab becomes visible) and the window `focus` event, so switching between OS windows without hiding the tab also refetches. The browser fires `focus` once at page load — expect one extra fetch on load. When a tab return fires both events back-to-back, request deduplication collapses them into a single network call.

Without `refetchOnKeyChange: true`, call `fetch()` manually first; the focus/reconnect listeners still work for subsequent refetches.

### Data Transformation

Transform data before returning while caching the original. Multiple resources with different `transform` functions can share the same cache entry by using the same fetcher function.

```typescript
// Same fetcher function → shared cache scope for "user-1"
const fetchUser = () => fetch('/api/user').then(r => r.json());

const userName = resource(fetchUser,
  { key: () => 'user-1', cacheTime: 60000, transform: (d) => d.name });

const userEmail = resource(fetchUser,
  { key: () => 'user-1', cacheTime: 60000, transform: (d) => d.email });

userName.fetch();
userEmail.fetch(); // Joins the same request via deduplication
```

Resources are automatically cache-isolated by their fetcher identity, so sharing the fetcher is required for shared caching.

### Structural Sharing

Preserve object/array references for structurally unchanged subtrees so dependent computeds and effects that shallow-compare references skip redundant re-evaluation. Opt in per resource with `structuralSharing: true`.

Plain objects and arrays are compared element/key-wise; primitives use `Object.is`; `Map`, `Set`, `Date`, and class instances use reference equality and are never merged. A changed subtree builds a new container along the changed path while sibling subtrees keep their previous references. Applies to the fetch-success path only — `setData` and `mutate` are unaffected. See [Structural Sharing](/learn/patterns/resource#structural-sharing) for a runnable reference-stability recipe.

### Request Deduplication

Identical concurrent requests share a single network call by default. Disable with `deduplicate: false`.

Deduplication rules:

- Same cache key + concurrent requests = shared network request
- Different cache keys = separate requests
- `fetch({ force: true })` skips joining an existing in-flight request but still registers itself, so later fetches can join it while it runs
- Sequential requests with caching = cache-based deduplication

### Timeout and Abort Control

Request timeout and external abort signals for coordinated cancellation.

```typescript
const slowResource = resource(
  () => new Promise(resolve => setTimeout(() => resolve({ data: 'Slow' }), 10000)),
  {
    timeout: 5000,
    initialData: { data: 'Initial' }
  }
);

slowResource.fetch({ force: true });
// After 5s timeout: abort fires, isLoading/isFetching -> false,
// error() stays undefined, data() -> { data: 'Initial' }
```

External abort controller for coordinated cancellation:

```typescript
const controller = new AbortController();

const r = resource(
  () => fetch('/api/long-operation').then(r => r.json()),
  { abortSignal: controller.signal }
);

r.fetch({ force: true });

// Cancel externally: affects all resources using this controller
controller.abort();
```

### Batch Invalidation

Pattern-based cache clearing for logout and bulk resets — see [`resourceCache`](/reference/resource/resourcecache) for the invalidate methods. The `invalidates` option wires them to a successful mutation:

```typescript
import { resource, resourceCache } from '@hellajs/resource';

resourceCache.set('user:1', { id: 1 }, 60000);

const saveUser = resource(async () => ({ ok: true }), {
  invalidates: ['user:', /^posts:\d+$/],
});

await saveUser.mutate({ action: 'save' });
// on success: invalidateByPrefix('user:') + invalidateByPattern(/^posts:\d+$/)
```

`invalidates` deletes cache entries only — a resource currently displaying a matched key keeps its data; only the next fetch for that key hits the network. Call `invalidate()` or `fetch()` on any resource that must refresh immediately.

<summary>Internal Mechanics</summary>

Resources coordinate reactive primitives, caching systems, and async operations to provide predictable data management patterns.

#### Resource State Machine

Resources maintain a simple state machine with four states.

- **idle** - No active request
- **loading** - Request in progress
- **success** - Data available
- **error** - Request failed

```
idle -> loading -> success
  ^      |    ^      |
  |    abort()|  invalidate()
  |      |    +------+ (if data available, stays in success)
  |   abort()  error
  +------+
```

`abort()` resets to idle, restores `initialData`, and clears errors. `reset()` does the same but also clears mutation context. `invalidate()` clears cache and triggers a fresh request.

#### Loading vs Fetching

`isLoading()` is true only when no data exists (full spinner); `isFetching()` is true during any network activity including background refetches. See the SWR section above for a worked example.

</details>
