# resource

Reactive async data fetching with caching, abort, and mutation.

## API

```typescript
// Overload for simple URL fetching
function resource<T, TTransformed = T>(url: string, options?: ResourceOptions<T, string, TTransformed>): Resource<TTransformed, T>;

// Overload for custom fetcher functions
function resource<T, K = undefined, TTransformed = T>(fetcher: (key: K) => Promise<T>, options?: ResourceOptions<T, K, TTransformed>): Resource<TTransformed, T>;

// The returned resource object
interface Resource<TTransformed, T = TTransformed> {
  data: () => (TTransformed | undefined);
  error: () => (ResourceError | undefined);
  isLoading: () => boolean;
  isFetching: () => boolean;
  isIdle: () => boolean;
  status: () => ResourceStatus;
  fetch(options?: FetchOptions): void;
  abort(): void;
  invalidate(): void;
  setData: (updater: T | ((old: T | undefined) => T)) => void;
  cacheKey: () => unknown;
  mutate: <TVariables = unknown>(variables: TVariables) => Promise<T>;
  reset(): void;
  dispose(): void;
}

type ResourceStatus = "idle" | "loading" | "success" | "error";

type ResourceErrorCategory = 'not_found' | 'server' | 'client' | 'abort' | 'unknown';

interface ResourceError {
  /** Human-readable error message */
  message: string;
  /** Categorized error type for structured handling */
  category: ResourceErrorCategory;
  /** HTTP status code if available */
  statusCode?: number;
  /** Original error object for debugging */
  originalError?: unknown;
}

interface ResourceOptions<T, K, TTransformed = T> {
  /** Function to generate cache key or static key value */
  key?: (() => K) | K;
  /** Whether the resource is enabled, or a getter re-evaluated reactively for automatic fetches (default: true) */
  enabled?: boolean | (() => boolean);
  /** Auto-refetch when key dependencies change (default: false). Skips fetch while key resolves to null or undefined. */
  refetchOnKeyChange?: boolean;
  /** Initial data before first request completes */
  initialData?: T;
  /** Cache TTL in milliseconds (0 = no caching) */
  cacheTime?: number;
  /** Duration in ms data is considered fresh before background revalidation (default: Infinity = never stale, 0 = always stale) */
  staleTime?: number;
  /** Whether to auto-refetch when data becomes stale (default: true) */
  revalidateOnStale?: boolean;
  /** Request timeout in milliseconds */
  timeout?: number;
  /** External abort signal for cancellation */
  abortSignal?: AbortSignal;
  /** Deduplicate concurrent requests with same key (default: true) */
  deduplicate?: boolean;
  /** Preserve object/array references for structurally unchanged subtrees on fetch success, preventing redundant reactive cascades (default: false) */
  structuralSharing?: boolean;
  /** Retry count on failure, boolean for simple on/off, or function for conditional retry */
  retry?: number | boolean | ((failureCount: number, error: ResourceError) => boolean);
  /** Delay between retries in ms, or function returning delay based on attempt number */
  retryDelay?: number | ((attempt: number, error: ResourceError) => number);
  /** Transform data before returning; cache stores original data */
  transform?: (data: T) => TTransformed;
  /** Callback when request succeeds */
  onSuccess?: (data: T) => void;
  /** Callback when request fails */
  onError?: (err: unknown) => void;
  /** Refetch interval in ms, false to disable, or function returning interval based on data (arms when enabled first evaluates true, including a later flip from false; not reset by key changes) */
  refetchInterval?: number | false | ((data: TTransformed | undefined) => number | false);
  /** Continue polling when tab is hidden (default: false) */
  refetchIntervalInBackground?: boolean;
  /** Refetch when window regains focus (default: false) */
  refetchOnWindowFocus?: boolean;
  /** Refetch when browser reconnects after going offline (default: false) */
  refetchOnReconnect?: boolean;
  /** Hook for optimistic updates before mutation */
  onMutate?: (variables: unknown) => Promise<unknown> | unknown;
  /** Hook after mutation completion (success or error) */
  onSettled?: (data?: T, error?: unknown, variables?: unknown, context?: unknown) => Promise<void> | void;
  /** After a successful mutation, invalidate matching cache entries: strings dispatch to `invalidateByPrefix`, RegExp to `invalidateByPattern`. Deletes cache entries only — mounted resources do not auto-refetch. No invalidation on error or abort. */
  invalidates?: Array<string | RegExp>;
}
```

### `data`

Reactive signal containing the fetched data or undefined if not yet loaded.

```typescript
import { resource } from '@hellajs/resource';
import { effect } from '@hellajs/core';

const userResource = resource(() =>
  fetch('/api/user').then(r => r.json())
);
effect(() => {
  if (userResource.data()) console.log('Name:', userResource.data().name);
});
userResource.fetch();
```

### `error`

Reactive signal containing error information if the request failed.

```typescript
const userResource = resource(() =>
  fetch('/api/user').then(r => r.json())
);
userResource.fetch();
const error = userResource.error();
if (error) console.log('Category:', error.category);
```

### `isLoading`

Reactive signal indicating if an **initial** request is in progress. Only true when there's no data at all (not even `initialData`).

```typescript
const userResource = resource(() =>
  fetch('/api/user').then(r => r.json())
);
userResource.fetch();
console.log(userResource.isLoading()); // true during first load only
```

### `isFetching`

Reactive signal indicating if **any** network request is in progress, including background refetches.

```typescript
const userResource = resource(() =>
  fetch('/api/user').then(r => r.json())
);
userResource.fetch();
console.log(userResource.isFetching()); // true
userResource.invalidate(); // background refetch
```

### `isIdle`

Reactive signal indicating if no fetch has occurred yet.

```typescript
const userResource = resource(() =>
  fetch('/api/user').then(r => r.json())
);
console.log(userResource.isIdle()); // true - no fetch yet
userResource.fetch();
console.log(userResource.isIdle()); // false
```

### `status`

Computed signal showing the current resource status: `'idle'`, `'loading'`, `'success'`, or `'error'`.

```typescript
const userResource = resource(() =>
  fetch('/api/user').then(r => r.json())
);
userResource.fetch();
console.log(userResource.status()); // 'loading', then 'success' or 'error'
```

### `fetch`

Fetches data using a cache-first strategy by default. Pass `{ force: true }` to bypass the cache lookup and skip joining in-flight requests for the same key. A force fetch still registers itself in the dedup map, so subsequent non-force fetches can join it while it is in flight.

```typescript
const userResource = resource(
  () => fetch('/api/user').then(r => r.json()),
  { cacheTime: 300000 } // 5 minutes
);
userResource.fetch(); // Cache-first - uses cached data if valid
userResource.fetch({ force: true }); // Bypasses cache lookup and dedup check
```

### `abort`

Cancels the ongoing request and resets resource to initial state.

```typescript
const userResource = resource(
  () => fetch('/api/slow-endpoint').then(r => r.json()),
  { initialData: null }
);
userResource.fetch();
userResource.abort();
console.log(userResource.data()); // null - back to initialData
```

### `invalidate`

Clears the cache entry and triggers a fresh request.

```typescript
const userResource = resource(
  () => fetch('/api/user').then(r => r.json()),
  { cacheTime: 300000 }
);
userResource.invalidate(); // Cache cleared - next fetch goes to the network
```

### `setData`

Updates the resource data with a new value or updater function. When `cacheTime` is greater than 0, also writes to the cache.

```typescript
type User = { id: number; name: string; lastSeen?: number };

const userResource = resource<User>(
  () => fetch('/api/user').then(r => r.json()),
  { cacheTime: 300000 }
);
userResource.setData({ id: 1, name: 'Updated Name' });
userResource.setData(old => ({ ...old, lastSeen: Date.now() }) as User);
```

When `cacheTime` is `0` (the default), `setData` updates the reactive signal but does not write to cache. The updater function still receives the current signal value, not a cached value.

### `cacheKey`

Returns the current cache key used for this resource.

```typescript
import { signal } from '@hellajs/core';

const userId = signal(1);
const keyed = resource(
  (key) => fetch(`/api/users/${key}`).then(r => r.json()),
  { key: () => userId() }
);
console.log(keyed.cacheKey()); // 1
userId(2);
console.log(keyed.cacheKey()); // 2
```

### `mutate`

Executes a mutation with given variables, supporting optimistic updates via the `onMutate`/`onSettled` hooks. See [Resources](/learn/concepts/resources#mutations) for the optimistic-update lifecycle and rollback pattern.

```typescript
const saveUser = resource(
  async (data) => fetch('/api/user', {
    method: 'PUT', body: JSON.stringify(data)
  }).then(r => r.json())
);

await saveUser.mutate({ name: 'John Doe' });
```

When a mutation succeeds, `onSuccess` fires with the result data, just like a regular fetch. If a mutation is aborted (via `abort()`, `timeout`, or external signal), `onSettled` is **not** called, even if `onMutate` already ran.

### `reset`

Resets resource state to initial values, clearing data and errors.

```typescript
const userResource = resource(
  () => fetch('/api/user').then(r => r.json()),
  { initialData: null }
);
userResource.fetch();
userResource.reset();
console.log(userResource.status()); // 'idle'
console.log(userResource.data()); // null (initialData)
```

### `dispose`

Cleans up all resource effects, polling timers, and subscriptions. Call this when the resource is no longer needed to prevent memory leaks.

```typescript
const pollResource = resource(
  () => fetch('/api/user').then(r => r.json()),
  { refetchOnKeyChange: true, refetchInterval: 5000 }
);
pollResource.dispose(); // Stops polling, cleans up timers and effects
```

## Basic Usage

```typescript
import { resource } from '@hellajs/resource';

const userResource = resource(
  () => fetch('/api/user').then(r => r.json())
);

userResource.fetch();
console.log(userResource.status()); // 'loading', then 'success' or 'error'
```

## Key Concepts

### Stale-While-Revalidate (SWR)

Control data freshness with `staleTime`. When data is stale but cached, `.fetch()` returns it immediately while fetching fresh data in the background. See [Resources](/learn/concepts/resources#stale-while-revalidate-swr) for `staleTime` options and refresh indicator patterns.

### Automatic Retry

Configure retry behavior with count, conditional logic, and custom delays. The `retry` predicate receives the failure count starting at `1` on the first failure. See [Resources](/learn/concepts/resources#automatic-retry) for conditional retry and delay configuration.

### Polling / Interval Refetch

Periodically refresh data for real-time updates. See [Resources](/learn/concepts/resources#polling--interval-refetch) for dynamic intervals and background polling.

### Window Focus / Reconnect Refetch

Automatically refetch when the user returns to the tab or when the browser reconnects. See [Resources](/learn/concepts/resources#window-focus--reconnect-refetch) for setup details.

### Data Transformation

Transform data before returning while caching the original. See [Resources](/learn/concepts/resources#data-transformation) for shared cache scope patterns.

### Structural Sharing

Preserve object/array references for structurally unchanged subtrees so dependent computeds and effects that shallow-compare references skip redundant re-evaluation. Opt in per resource with `structuralSharing: true`. See [Resources](/learn/concepts/resources#structural-sharing) for the merge semantics and the [Resource patterns](/learn/patterns/resource#structural-sharing) for a runnable example.

### Request Deduplication

Identical concurrent requests share a single network call by default. Disable with `deduplicate: false`. See [Resources](/learn/concepts/resources#request-deduplication) for deduplication rules.

### Timeout and Abort Control

Request timeout and external abort signals for coordinated cancellation. See [Resources](/learn/concepts/resources#timeout-and-abort-control) for external abort controller patterns.

### Mutation invalidation

Declare cache entries to invalidate after a successful mutation with `invalidates` — string prefixes dispatch to [`invalidateByPrefix`](/reference/resource/resourcecache#invalidatebyprefix), `RegExp` patterns to [`invalidateByPattern`](/reference/resource/resourcecache#invalidatebypattern). Invalidation runs only on the success path — on error or abort nothing is invalidated. See [Resources](/learn/concepts/resources#batch-invalidation) for the seed example and the mounted-resources caveat.

## Important Considerations

### AbortError Does Not Set Error State

When a request is aborted (via `.abort()`, `timeout`, or an external `abortSignal`), the error state is **not** set. The resource returns to `idle` status with the original `initialData`, not `error` status.

```typescript
// ❌ Don't rely on error() being set after abort
const r = resource(fetchData, { timeout: 5000 });
r.fetch();
// ...timeout fires... error() is NOT set

// ✅ Check status instead
if (r.isIdle() && !r.isFetching()) {
  console.log('Request was aborted or never started');
}
```

### Manual vs Key-Change Fetching

By default, resources don't auto-fetch on creation. Call `.fetch()` explicitly, or set `refetchOnKeyChange: true` for automatic fetching when key dependencies change. With an explicit `key`, fetching is skipped while the key resolves to `null` or `undefined` — see [Reactive Keys](/learn/concepts/resources#reactive-keys).

```typescript
// Manual: must call fetch() explicitly
const manual = resource(() => fetch('/api/user'));
manual.fetch();

// Auto: refetch when key dependencies change
const auto = resource(() => fetch('/api/user'), { refetchOnKeyChange: true });
```

### enabled: Static vs Reactive

A static `boolean` is captured once at creation and cannot be toggled — a static `enabled: false` blocks even manual `fetch()`. A getter `() => boolean` is re-evaluated reactively inside the `refetchOnKeyChange` effect: transitions from `false` to `true` trigger a fetch automatically, and manual `fetch()` bypasses the getter. For the toggling pattern, see [Conditional Fetching](/learn/patterns/resource#conditional-fetching).

```typescript
import { signal } from '@hellajs/core';
import { resource } from '@hellajs/resource';

const userId = signal<string | null>(null);

const r = resource(
  (id) => fetch(`/api/users/${id}`).then(r => r.json()),
  { key: () => userId(), enabled: () => userId() !== null, refetchOnKeyChange: true }
);

userId("7"); // getter re-evaluates to true -> fetch triggers automatically
r.fetch();   // manual fetch bypasses the getter, executes regardless
```

### Memory Management

Each unique key creates a separate cache entry within the resource's fetcher scope — favor stable, meaningful keys for large datasets. See [`resourceCache`](/reference/resource/resourcecache) for key-design patterns.

### Server-Side Rendering

On the server (no `window`), `run()` exits before fetching — resources embedded in a server-rendered tree never trigger network calls. Fetch server-side data with direct `fetch()` and pass it in as `initialData`; do not rely on resources for server-side data loading.
