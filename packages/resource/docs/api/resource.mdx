# resource

Reactive async data fetching with caching, deduplication, abort control, and mutations.

## Basic Usage

```typescript
import { effect } from '@hellajs/core';
import { resource } from '@hellajs/resource';

const userResource = resource(() => fetch('/api/user').then(r => r.json()));
userResource.fetch();

effect(() => {
  if (userResource.isLoading()) {
    console.log('Loading user...');
  } else if (userResource.error()) {
    console.error('Failed:', userResource.error()?.message);
  } else if (userResource.data()) {
    console.log('User name:', userResource.data()?.name);
  }
});
```

Resources never auto-fetch on creation: call `fetch()` explicitly, or opt into automatic fetching with `refetchOnKeyChange` (see [Manual vs Key-Change Fetching](#manual-vs-key-change-fetching)).

## API

```typescript
// Overload for simple URL fetching
function resource<T = unknown, TTransformed = T>(url: string, options?: ResourceOptions<T, string, TTransformed>): Resource<TTransformed, T>;

// Overload for custom fetcher functions
function resource<T, K = undefined, TTransformed = T>(fetcher: (key: K) => Promise<T>, options?: ResourceOptions<T, K, TTransformed>): Resource<TTransformed, T>;

// The returned resource object
interface Resource<TTransformed, T = TTransformed> {
  data: () => (TTransformed | undefined);
  error: () => (ResourceError | undefined);
  isLoading: () => boolean;
  isFetching: () => boolean;
  isIdle: () => boolean;
  isPaused: () => boolean;
  status: () => ResourceStatus;
  fetch(options?: FetchOptions): Promise<T | undefined>;
  abort(): void;
  invalidate(): void;
  setData: (updater: T | ((old: T | undefined) => T)) => void;
  cacheKey: () => unknown;
  mutate: <TVariables = unknown>(variables: TVariables) => Promise<T>;
  reset(): void;
  dispose(): void;
}

type ResourceStatus = "idle" | "loading" | "success" | "error";

type ResourceErrorCategory = 'not_found' | 'server' | 'client' | 'unknown';

interface ResourceError {
  /** Human-readable error message */
  message: string;
  /** Categorized error type for structured handling */
  category: ResourceErrorCategory;
  /** HTTP status code if available */
  statusCode?: number;
  /** Original error object for debugging */
  originalError?: unknown;
}

interface ResourceOptions<T, K, TTransformed = T> {
  /**
   * Function to generate cache key or static key value. Plain objects and arrays compare
   * structurally (key order insensitive, nested dates as ISO strings); other object shapes by reference.
   */
  key?: (() => K) | K;
  /** Whether the resource is enabled, or a getter re-evaluated reactively for automatic fetches (default: true) */
  enabled?: boolean | (() => boolean);
  /** Auto-refetch when key dependencies change (default: false). Skips fetch while key resolves to null or undefined. */
  refetchOnKeyChange?: boolean;
  /** Keep the previous key's data visible while a key-change refetch is in flight (default: true). When false, a key change clears data (isLoading() true, data() undefined, status() 'loading') until the new key's fetch settles; initialData is not re-applied. */
  keepPreviousData?: boolean;
  /** Initial data before first request completes */
  initialData?: T;
  /** Cache TTL in milliseconds (0 = no caching) */
  cacheTime?: number;
  /** Duration in ms data is considered fresh before background revalidation (default: Infinity = never stale, 0 = always stale) */
  staleTime?: number;
  /** Whether to auto-refetch when data becomes stale (default: true) */
  revalidateOnStale?: boolean;
  /** Request timeout in milliseconds */
  timeout?: number;
  /** External abort signal for cancellation */
  abortSignal?: AbortSignal;
  /** Deduplicate concurrent requests with same key (default: true) */
  deduplicate?: boolean;
  /** Preserve object/array references for structurally unchanged subtrees on fetch success, preventing redundant reactive cascades (default: false) */
  structuralSharing?: boolean;
  /** Retry count on failure (fetches and mutations alike), boolean for simple on/off, or function for conditional retry */
  retry?: number | boolean | ((failureCount: number, error: ResourceError) => boolean);
  /** Delay between retries in ms, or function returning delay based on attempt number */
  retryDelay?: number | ((attempt: number, error: ResourceError) => number);
  /** Transform data before returning; cache stores original data */
  transform?: (data: T) => TTransformed;
  /** Callback when request succeeds */
  onSuccess?: (data: T) => void;
  /** Callback when request fails */
  onError?: (err: unknown) => void;
  /** Refetch interval in ms, false to disable, or function returning interval based on data; works standalone (arms when enabled first evaluates true, including a later flip from false; key changes never reset the cadence; reset() re-arms, abort() does not) */
  refetchInterval?: number | false | ((data: TTransformed | undefined) => number | false);
  /** Continue polling when tab is hidden (default: false) */
  refetchIntervalInBackground?: boolean;
  /** Refetch on tab return or window focus; both visibilitychange and focus events (default: false) */
  refetchOnWindowFocus?: boolean;
  /** Refetch when browser reconnects after going offline (default: false) */
  refetchOnReconnect?: boolean;
  /** Defer fetches while the browser is offline; the deferred fetch resumes on reconnect with its original force flag, reflected by isPaused() (default: false). Mutations are not paused. */
  pauseWhenOffline?: boolean;
  /** Hook for optimistic updates before mutation */
  onMutate?: (variables: unknown) => unknown;
  /** Hook after mutation completion (success or error) */
  onSettled?: (data?: T, error?: unknown, variables?: unknown, context?: unknown) => Promise<void> | void;
  /** After a successful mutation, invalidate matching cache entries: strings dispatch to `invalidateByPrefix`, RegExp to `invalidateByPattern`. Deletes cache entries only; mounted resources do not auto-refetch. No invalidation on error or abort. */
  invalidates?: Array<string | RegExp>;
}
```

### Reactive State

### `data`

Reactive getter for the fetched data, or `undefined` before the first successful fetch. With a `transform`, returns the transformed value.

```typescript
import { effect } from '@hellajs/core';
const userResource = resource(() => fetch('/api/user').then(r => r.json()));
userResource.fetch();
effect(() => {
  const user = userResource.data();
  if (user) console.log('Name:', user.name);
});
```

### `error`

Reactive getter for error details when a request fails. Aborts and timeouts never set it (see [AbortError Does Not Set Error State](#aborterror-does-not-set-error-state)).

```typescript
const userResource = resource(() => fetch('/api/user').then(r => r.json()));
userResource.fetch();
// After a failed request:
const error = userResource.error();
if (error) {
  console.log(error.category); // 'server', 'client', 'not_found', or 'unknown'
  console.log(error.statusCode); // e.g. 500, when the server reported one
}
```

### `isLoading`

True only while an **initial** fetch is in flight: no data at all (a non-`undefined` `initialData` keeps it `false`).

```typescript
const userResource = resource(() => fetch('/api/user').then(r => r.json()));
userResource.fetch();
console.log(userResource.isLoading()); // true during the first load only
```

### `isFetching`

True while **any** request is in flight, including background refetches and mutations.

```typescript
const userResource = resource(() => fetch('/api/user').then(r => r.json()));
userResource.fetch();
console.log(userResource.isFetching()); // true
userResource.invalidate(); // background refetch keeps isFetching() true
```

### `isIdle`

True when no fetch has run yet, or after `abort()`/`reset()` returned the resource to its initial state.

```typescript
const userResource = resource(() => fetch('/api/user').then(r => r.json()));
console.log(userResource.isIdle()); // true - no fetch yet
userResource.fetch();
console.log(userResource.isIdle()); // false
```

### `isPaused`

True while a fetch is deferred because the browser is offline. Requires the `pauseWhenOffline` option; without it, offline fetches attempt the network and fail into `error()` as usual.

```typescript
window.dispatchEvent(new Event('offline')); // The connection has dropped

const feed = resource(() => fetch('/api/feed').then(r => r.json()),
  { pauseWhenOffline: true, refetchOnKeyChange: true });
console.log(feed.isPaused()); // Logs: true; the initial fetch defers, no request attempted
window.dispatchEvent(new Event('online')); // The connection returns
console.log(feed.isPaused()); // Logs: false; the deferred fetch runs
```

The deferred fetch replays on reconnect with the force flag it was called with: a paused `fetch({ force: true })` resumes as a force fetch. The pause listener follows the focus/reconnect listener lifecycle: `abort()`, `reset()`, and `dispose()` clear it; `reset()` does not re-arm it. Mutations are never paused. See [Offline Pausing](/learn/concepts/resources#offline-pausing) for the pause/resume behavior and the `refetchOnReconnect` interplay.

### `status`

Reactive getter for the combined status: `'idle'`, `'loading'`, `'success'`, or `'error'`.

```typescript
const userResource = resource(() => fetch('/api/user').then(r => r.json()));
userResource.fetch();
console.log(userResource.status()); // 'loading', then 'success' or 'error'
```

### Fetching

### `fetch`

Fetches data with a cache-first strategy by default. Pass `{ force: true }` to bypass the cache lookup and skip joining in-flight requests; a force fetch still registers itself in the dedup map, so later non-force fetches can join it while it runs.

`fetch()` is awaitable: it resolves with the fetched data (raw type, before `transform`) on success or cache hit, and `undefined` on error, skip, or abort; it never rejects. Errors surface through `error()` and `onError` as usual, so fire-and-forget callers stay source-compatible.

```typescript
const user = resource(() => fetch('/api/user').then(r => r.json()), { cacheTime: 60000 });
await user.fetch(); // Network request
await user.fetch(); // Cache hit within cacheTime - no network
user.fetch({ force: true }); // Bypasses cache lookup and dedup lookup

const bad = resource(() => fetch('/api/broken').then(r => r.json()));
await bad.fetch(); // Resolves undefined; the failure surfaces in bad.error()
console.log(bad.error()?.category);
```

On key-change refetches (`refetchOnKeyChange`), the previous key's data stays visible while the new fetch is in flight. Pass `keepPreviousData: false` for a loading-state transition instead; see [Keep Previous Data](#keep-previous-data).

### `invalidate`

Clears this resource's cache entry for the current key, then triggers a fresh request.

```typescript
const userResource = resource(() => fetch('/api/user').then(r => r.json()), { cacheTime: 300000 });
userResource.invalidate(); // Cache cleared - the fetch goes to the network
```

### `abort`

Cancels the ongoing fetch and every in-flight mutation, and resets the resource to its initial state.

```typescript
const userResource = resource(() => fetch('/api/slow-endpoint').then(r => r.json()), { initialData: null });
userResource.fetch();
userResource.abort();
console.log(userResource.data()); // null - back to initialData
```

### Data and Mutations

### `setData`

Sets the resource data to a new value or updates it with an updater function (raw type, before `transform`). When `cacheTime` is greater than 0, also writes the cache entry.

```typescript
type User = { id: number; name: string; lastSeen?: number };
const userResource = resource<User>(() => fetch('/api/user').then(r => r.json()), { cacheTime: 300000 });
userResource.setData({ id: 1, name: 'Updated Name' });
userResource.setData(old => ({ ...old, lastSeen: Date.now() }) as User);
```

When `cacheTime` is `0` (the default), `setData` updates the reactive data but writes nothing to the cache. The updater receives the current data value; with a cache present it reads the cached value first.

### `cacheKey`

Returns the current raw cache key: the resolved `key` option value, not its normalized cache form. Structurally-hashed object keys come back as the original object.

```typescript
import { signal } from '@hellajs/core';

const userId = signal(1);
const keyed = resource((key) => fetch(`/api/users/${key}`).then(r => r.json()), { key: () => userId() });
console.log(keyed.cacheKey()); // 1
userId(2);
console.log(keyed.cacheKey()); // 2
```

### `mutate`

Executes a mutation with the given variables, bypassing cache and deduplication. Supports optimistic updates via the `onMutate`/`onSettled` hooks; see [Resources](/learn/concepts/resources#mutations) for the optimistic-update lifecycle and rollback pattern.

```typescript
const saveUser = resource((data) =>
  fetch('/api/user', { method: 'PUT', body: JSON.stringify(data) }).then(r => r.json()));

await saveUser.mutate({ name: 'John Doe' });
```

When a mutation succeeds, `onSuccess` fires with the result data, just like a regular fetch. If a mutation is aborted (via `abort()`, `timeout`, or an external signal), `onSettled` is **not** called, even if `onMutate` already ran.

`mutate()` rejects where `fetch()` never does: with the mutation error on failure, with a `DOMException` (AbortError) on abort, or with the callback's own error when `onSettled` throws. A success-path `onSettled` throw keeps the committed data and `success` status: `onSettled` is not re-invoked, and `invalidates` is skipped on incomplete settlement. Fire-and-forget callers need `.catch` on the returned promise; without it the rejection goes unhandled.

Concurrent mutations run independently: each `mutate()` call owns its abort controller and `onMutate` context, so a second call never aborts the first; both settle individually with their own `(variables, context)` pair. Mutations honor `retry`/`retryDelay` just like reads, and reads never abort mutations; `abort()` is the cancel-all: it aborts the active read and every in-flight mutation. For operations that must not overlap, guard the trigger with `isFetching()` (see [Concurrent Mutations](/learn/concepts/resources#concurrent-mutations)).

### Lifecycle

### `reset`

Returns the resource to its initial state: data back to `initialData`, error cleared, polling restarted at its interval. In-flight requests are not cancelled: unlike `abort()`, which stops polling permanently (recreate the resource to resume) and cancels the active fetch, a request that resolves after `reset()` still writes its data.

```typescript
const userResource = resource(() => fetch('/api/user').then(r => r.json()), { initialData: null });
userResource.fetch();
userResource.reset();
console.log(userResource.status()); // 'idle'
console.log(userResource.data()); // null (initialData)
```

### `dispose`

One-way teardown: clears the key-change effect, polling timers, and focus/reconnect/pause listeners. The resource cannot be reused. Call it when a polling or focus-refetching resource leaves the page to prevent leaks.

```typescript
const pollResource = resource(() => fetch('/api/user').then(r => r.json()),
  { refetchInterval: 5000 });
pollResource.fetch();
pollResource.dispose(); // Stops polling, cleans up timers and effects
```

`dispose()` does not abort in-flight requests and does not touch the cache: a fetch that resolves after `dispose()` still writes its data. Use `abort()` to cancel.

## Key Concepts

### Cache Scope Is per Fetcher

Cache and deduplication entries are scoped by the fetcher function: two resources share cache only when they use the *same fetcher reference*. Each `resource('/api/users')` call builds its own fetcher, so two URL resources never share cache. Share a named fetcher function when resources must see the same entries. See [Data Transformation](/learn/concepts/resources#data-transformation) for the pattern.

### Stale-While-Revalidate (SWR)

Control data freshness with `staleTime`: stale-but-cached data returns immediately while a background fetch refreshes it. See [Resources](/learn/concepts/resources#stale-while-revalidate-swr) for options and refresh indicator patterns.

### Keep Previous Data

On a key-change refetch, the previous key's data stays visible by default: `data()` returns the old value, `isLoading()` stays false, `isFetching()` flips true. With `keepPreviousData: false`, `data()` is `undefined`, `isLoading()` is `true`, and `status()` is `'loading'` until the new key's fetch settles: the transition pagination and search UIs need. `initialData` is not re-applied; a key change is a refetch, not a return to the never-fetched state.

```typescript
const user = resource((id) => fetch(`/api/users/${id}`).then(r => r.json()),
  { key: () => userId(), refetchOnKeyChange: true, keepPreviousData: false });
userId(2); // data() undefined + isLoading() true until User 2 lands
```

### Automatic Retry

Configure retry with count, conditional logic, and custom delays; the `retry` predicate receives the failure count starting at `1`. Applies to reads and mutations alike. See [Resources](/learn/concepts/resources#automatic-retry) for configuration.

### Polling / Interval Refetch

Periodically refresh data for real-time updates. `refetchInterval` works standalone, with no auto-fetch opt-in. See [Resources](/learn/concepts/resources#polling--interval-refetch) for dynamic intervals and background polling.

### Window Focus / Reconnect Refetch

Automatically refetch when the user returns to the tab or window, or when the browser reconnects. See [Resources](/learn/concepts/resources#window-focus--reconnect-refetch) for setup details.

### Data Transformation

Transform data for `data()` reads while caching the original; `setData` and `mutate` keep operating on the raw shape. See [Resources](/learn/concepts/resources#data-transformation) for the shared-cache pattern.

### Structural Sharing

Preserve object/array references for structurally unchanged subtrees so dependent computeds and effects that shallow-compare references skip redundant re-evaluation; opt in with `structuralSharing: true`. See [Resources](/learn/concepts/resources#structural-sharing) for merge semantics and [Resource patterns](/learn/patterns/resource#structural-sharing) for a runnable example.

### Request Deduplication

Identical concurrent requests share a single network call by default; disable with `deduplicate: false`. See [Resources](/learn/concepts/resources#request-deduplication) for the rules.

### Timeout and Abort Control

Request timeout and external abort signals for coordinated cancellation. See [Resources](/learn/concepts/resources#timeout-and-abort-control) for external abort controller patterns.

### Mutation Invalidation

Declare cache entries to invalidate after a successful mutation with `invalidates`: string prefixes dispatch to [`invalidateByPrefix`](/reference/resource/resourcecache#invalidatebyprefix), `RegExp` patterns to [`invalidateByPattern`](/reference/resource/resourcecache#invalidatebypattern). Runs only on the success path: on error or abort nothing is invalidated. See [Resources](/learn/concepts/resources#batch-invalidation) for the seed example and the mounted-resources caveat.

## Important Considerations

### Never Mutate data() In Place

`data()` returns the stored value directly. Mutating it in place keeps the same reference, so no signal fires and dependent UI never updates.

```typescript
const todos = resource<string[]>(() => fetch('/api/todos').then(r => r.json()));
todos.fetch();

// ❌ Same reference; nothing re-renders
todos.data()?.push('New item');

// ✅ New value through setData; the signal fires and the cache follows
todos.setData(old => [...(old || []), 'New item']);
```

### AbortError Does Not Set Error State

When a request is aborted (via `abort()`, `timeout`, or an external `abortSignal`), the error state is **not** set. The resource returns to `idle` status with the original `initialData`, not `error` status.

```typescript
// ❌ After abort, error() is NOT set
const aborted = resource(() => fetch('/api/user').then(r => r.json()), { timeout: 5000 });
aborted.fetch(); // ...timeout fires...

// ✅ Check status instead
if (aborted.isIdle() && !aborted.isFetching()) {
  console.log('Request was aborted or never started');
}
```

### Manual vs Key-Change Fetching

By default, resources don't auto-fetch on creation. Call `.fetch()` explicitly, or set `refetchOnKeyChange: true` for automatic fetching when key dependencies change. With an explicit `key`, fetching is skipped while the key resolves to `null` or `undefined`; see [Reactive Keys](/learn/concepts/resources#reactive-keys).

```typescript
// Manual: must call fetch() explicitly
const manual = resource(() => fetch('/api/user').then(r => r.json()));
manual.fetch();
// Auto: refetch when key dependencies change
const auto = resource(() => fetch('/api/user').then(r => r.json()), { refetchOnKeyChange: true });
```

### enabled: Static vs Reactive

A static `boolean` is captured once at creation and cannot be toggled; a static `enabled: false` blocks even manual `fetch()`. A getter `() => boolean` re-evaluates reactively inside the `refetchOnKeyChange` effect: `false`-to-`true` transitions trigger a fetch automatically, and manual `fetch()` bypasses the getter. For the toggling pattern, see [Conditional Fetching](/learn/patterns/resource#conditional-fetching).

```typescript
const userId = signal<string | null>(null);
const conditional = resource((id) => fetch(`/api/users/${id}`).then(r => r.json()),
  { key: () => userId(), enabled: () => userId() !== null, refetchOnKeyChange: true });

userId("7"); // Getter re-evaluates to true -> fetch triggers automatically
conditional.fetch(); // Manual fetch bypasses the getter, executes regardless
```

### Server-Side Rendering

Reads are no-ops on the server: resources in a server-rendered tree never trigger network calls. Fetch server-side data with direct `fetch()` and pass it as `initialData`.

`mutate()` is deliberately **not** guarded: calling it from a render path (a component body or an effect that runs during server rendering) fires a real network write from the server. Keep `mutate()` in event handlers and other client-only code paths.

```typescript
// ❌ Runs during server rendering; POSTs for real, once per render
function NoteEditor() {
  saveNote.mutate({ text: 'hello' });
}

// ✅ Event handlers run client-side only
function onSave() {
  saveNote.mutate({ text: 'hello' }).catch(() => { /* handled in onSettled */ });
}
```

### Memory Management

Each unique key creates a separate cache entry within the resource's fetcher scope; favor stable, meaningful keys for large datasets. See [`resourceCache`](/reference/resource/resourcecache) for key-design patterns.
