# resource

Reactive async data fetching with caching, abort, and mutation.

## API

```typescript
// Overload for simple URL fetching
function resource<T, TTransformed = T>(url: string, options?: ResourceOptions<T, string, TTransformed>): Resource<TTransformed, T>;

// Overload for custom fetcher functions
function resource<T, K = undefined, TTransformed = T>(fetcher: (key: K) => Promise<T>, options?: ResourceOptions<T, K, TTransformed>): Resource<TTransformed, T>;

// The returned resource object
// - TTransformed: the type returned by data() (after transform, defaults to T)
// - T: the raw data type used by setData() and mutate()
interface Resource<TTransformed, T = TTransformed> {
  data: () => (TTransformed | undefined);
  error: () => (ResourceError | undefined);
  isLoading: () => boolean;
  isFetching: () => boolean;
  isIdle: () => boolean;
  status: () => ResourceStatus;
  fetch(options?: FetchOptions): void;
  abort(): void;
  invalidate(): void;
  setData: (updater: T | ((old: T | undefined) => T)) => void;
  cacheKey: () => unknown;
  mutate: <TVariables = unknown>(variables: TVariables) => Promise<T>;
  reset(): void;
  dispose(): void;
}

type ResourceStatus = "idle" | "loading" | "success" | "error";

type ResourceErrorCategory =
  | 'not_found'     // Resource not found (404)
  | 'server'        // Server errors (5xx)
  | 'client'        // Client errors (4xx)
  | 'abort'         // Request was cancelled
  | 'unknown';      // Unclassified errors (including network failures)

interface ResourceError {
  /** Human-readable error message */
  message: string;
  /** Categorized error type for structured handling */
  category: ResourceErrorCategory;
  /** HTTP status code if available */
  statusCode?: number;
  /** Original error object for debugging */
  originalError?: unknown;
}

interface ResourceOptions<T, K, TTransformed = T> {
  /** Function to generate cache key or static key value */
  key?: (() => K) | K;
  /** Whether the resource can make requests (default: true) */
  enabled?: boolean;
  /** Auto-refetch when key dependencies change (default: false) */
  refetchOnKeyChange?: boolean;
  /** Initial data before first request completes */
  initialData?: T;
  /** Cache TTL in milliseconds (0 = no caching) */
  cacheTime?: number;
  /** Duration in ms data is considered fresh before background revalidation (default: Infinity = never stale, 0 = always stale) */
  staleTime?: number;
  /** Whether to auto-refetch when data becomes stale (default: true) */
  revalidateOnStale?: boolean;
  /** Request timeout in milliseconds */
  timeout?: number;
  /** External abort signal for cancellation */
  abortSignal?: AbortSignal;
  /** Deduplicate concurrent requests with same key (default: true) */
  deduplicate?: boolean;
  /** Retry count on failure, boolean for simple on/off, or function for conditional retry */
  retry?: number | boolean | ((failureCount: number, error: ResourceError) => boolean);
  /** Delay between retries in ms, or function returning delay based on attempt number */
  retryDelay?: number | ((attempt: number, error: ResourceError) => number);
  /** Transform data before returning; cache stores original data */
  transform?: (data: T) => TTransformed;
  /** Callback when request succeeds */
  onSuccess?: (data: T) => void;
  /** Callback when request fails */
  onError?: (err: unknown) => void;
  /** Refetch interval in ms, false to disable, or function returning interval based on data */
  refetchInterval?: number | false | ((data: TTransformed | undefined) => number | false);
  /** Continue polling when tab is hidden (default: false) */
  refetchIntervalInBackground?: boolean;
  /** Refetch when window regains focus (default: false) */
  refetchOnWindowFocus?: boolean;
  /** Refetch when browser reconnects after going offline (default: false) */
  refetchOnReconnect?: boolean;
  /** Hook for optimistic updates before mutation */
  onMutate?: <TVariables, TContext = unknown>(variables: TVariables) => Promise<TContext> | TContext;
  /** Hook after mutation completion (success or error) */
  onSettled?: <TVariables, TContext = unknown>(data?: T, error?: unknown, variables?: TVariables, context?: TContext) => Promise<void> | void;
}
```

### `data`

Reactive signal containing the fetched data or undefined if not yet loaded.

```typescript
import { resource } from '@hellajs/resource';
import { effect } from '@hellajs/core';

const userResource = resource(() =>
  fetch('/api/user').then(r => r.json())
);

effect(() => {
  const data = userResource.data();
  if (data) {
    console.log('User name:', data.name);
  }
});

userResource.fetch();
```

### `error`

Reactive signal containing error information if the request failed.

```typescript
import { resource } from '@hellajs/resource';

const userResource = resource(() =>
  fetch('/api/user').then(r => r.json())
);

effect(() => {
  const error = userResource.error();
  if (error) {
    console.log('Error category:', error.category);
    console.log('Error message:', error.message);
    if (error.statusCode) {
      console.log('HTTP status:', error.statusCode);
    }
  }
});

userResource.fetch();
```

### `isLoading`

Reactive signal indicating if an **initial** request is in progress. Only true when there's no data at all (not even `initialData`).

```typescript
import { resource } from '@hellajs/resource';

const userResource = resource(() =>
  fetch('/api/user').then(r => r.json())
);

effect(() => {
  if (userResource.isLoading()) {
    console.log('Loading user data for the first time...');
  }
});

userResource.fetch();
```

### `isFetching`

Reactive signal indicating if **any** network request is in progress, including background refetches.

```typescript
import { resource } from '@hellajs/resource';

const userResource = resource(() =>
  fetch('/api/user').then(r => r.json())
);

effect(() => {
  if (userResource.isFetching()) {
    console.log('Fetching data...');
  }
});

userResource.fetch();
// Later, during background refetch:
userResource.invalidate();
// isFetching() is true, but isLoading() may be false if data already exists
```

### `isIdle`

Reactive signal indicating if no fetch has occurred yet.

```typescript
import { resource } from '@hellajs/resource';

const userResource = resource(() =>
  fetch('/api/user').then(r => r.json())
);

console.log(userResource.isIdle()); // true - no fetch yet

userResource.fetch();
console.log(userResource.isIdle()); // false - fetch started

userResource.reset();
console.log(userResource.isIdle()); // true - back to initial state
```

### `status`

Computed signal showing the current resource status.

```typescript
import { resource } from '@hellajs/resource';

const userResource = resource(() =>
  fetch('/api/user').then(r => r.json())
);

effect(() => {
  const status = userResource.status();
  switch (status) {
    case 'idle':
      console.log('Resource not fetched yet');
      break;
    case 'loading':
      console.log('Fetching data...');
      break;
    case 'success':
      console.log('Data loaded successfully');
      break;
    case 'error':
      console.log('Failed to load data');
      break;
  }
});

userResource.fetch();
```

### `fetch`

Fetches data using a cache-first strategy by default. Pass `{ force: true }` to bypass cache and force a fresh network request.

```typescript
import { resource } from '@hellajs/resource';

const userResource = resource(
  () => fetch('/api/user').then(r => r.json()),
  { cacheTime: 300000 } // 5 minutes
);

// Cache-first - uses cached data if valid
userResource.fetch();

// Force fresh - bypasses cache
userResource.fetch({ force: true });
```

### `abort`

Cancels the ongoing request and resets resource to initial state.

```typescript
import { resource } from '@hellajs/resource';

const userResource = resource(
  () => fetch('/api/slow-endpoint').then(r => r.json()),
  { initialData: null }
);

userResource.fetch();

// Cancel the request after 1 second
setTimeout(() => {
  userResource.abort();
  console.log('Request cancelled');
  console.log('Data:', userResource.data()); // Back to initialData
}, 1000);
```

### `invalidate`

Clears the cache entry and triggers a fresh request.

```typescript
import { resource } from '@hellajs/resource';

const userResource = resource(
  () => fetch('/api/user').then(r => r.json()),
  { cacheTime: 300000 }
);

// After updating user data elsewhere
async function updateUser(data) {
  await fetch('/api/user', {
    method: 'PUT',
    body: JSON.stringify(data)
  });

  // Invalidate cache and refetch fresh data
  userResource.invalidate();
}
```

### `setData`

Updates cached data with a new value or updater function.

```typescript
import { resource } from '@hellajs/resource';

const userResource = resource(
  () => fetch('/api/user').then(r => r.json()),
  { cacheTime: 300000 }
);

// Update with new value
userResource.setData({ id: 1, name: 'Updated Name' });

// Update with function
userResource.setData(old => ({
  ...old,
  lastSeen: Date.now()
}));
```

When `cacheTime` is `0` (the default), `setData` updates the reactive signal but does not write to cache. The updater function still receives the current signal value, not a cached value.

### `cacheKey`

Returns the current cache key used for this resource.

```typescript
import { resource } from '@hellajs/resource';
import { signal } from '@hellajs/core';

const userId = signal(1);
const userResource = resource(
  (id) => fetch(`/api/users/${id}`).then(r => r.json()),
  { key: () => `user:${userId()}` }
);

console.log(userResource.cacheKey()); // 'user:1'

userId(2);
console.log(userResource.cacheKey()); // 'user:2'
```

### `mutate`

Executes a mutation with given variables, supporting optimistic updates.

```typescript
import { resource } from '@hellajs/resource';

const userResource = resource(
  async (userData) => {
    const response = await fetch('/api/user', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify(userData)
    });
    return response.json();
  },
  {
    onMutate: async (variables) => {
      // Optimistic update
      console.log('Starting mutation with:', variables);
      return { previousData: userResource.data() };
    },
    onSettled: async (data, error, variables, context) => {
      if (error) {
        console.log('Mutation failed, rollback if needed');
        // Could restore context.previousData here
      } else {
        console.log('Mutation succeeded:', data);
      }
    }
  }
);

// Execute mutation
try {
  const result = await userResource.mutate({
    name: 'John Doe',
    email: 'john@example.com'
  });
  console.log('Created user:', result);
} catch (error) {
  console.error('Mutation failed:', error);
}
```

### `reset`

Resets resource state to initial values, clearing data and errors.

```typescript
import { resource } from '@hellajs/resource';

const userResource = resource(
  () => fetch('/api/user').then(r => r.json()),
  { initialData: null }
);

userResource.fetch();
// ... resource has data or error

// Reset to clean state
userResource.reset();
console.log(userResource.data()); // null (initialData)
console.log(userResource.error()); // undefined
console.log(userResource.status()); // 'idle'
```

### `dispose`

Cleans up all resource effects, polling timers, and subscriptions. Call this when the resource is no longer needed to prevent memory leaks.

```typescript
import { resource } from '@hellajs/resource';

const userResource = resource(
  () => fetch('/api/user').then(r => r.json()),
  {
    refetchOnKeyChange: true,
    refetchInterval: 5000 // Polling every 5 seconds
  }
);

// When component unmounts or resource is no longer needed:
userResource.dispose();
// All timers and effects are cleaned up
```

## Key Concepts

### Polling / Interval Refetch

Resources can automatically refetch data at regular intervals using the `refetchInterval` option. This is useful for real-time data like stock prices, notifications, or live updates.

#### Fixed Interval Polling

```typescript
// Poll every 5 seconds
const stockPrice = resource(
  () => fetch('/api/stock/price').then(r => r.json()),
  {
    refetchInterval: 5000,
    refetchOnKeyChange: true
  }
);

// Polling starts automatically with refetchOnKeyChange: true
// Data refreshes every 5 seconds
```

#### Dynamic Interval Polling

Use a function to adjust the polling interval based on the current data:

```typescript
// Poll faster when data indicates an issue
const health = resource(
  () => fetch('/api/health').then(r => r.json()),
  {
    refetchInterval: (data) => {
      // Poll every second when unhealthy, every 30 seconds when healthy
      return data?.status === 'unhealthy' ? 1000 : 30000;
    },
    refetchOnKeyChange: true
  }
);
```

#### Background Polling Control

By default, polling pauses when the browser tab is hidden. Use `refetchIntervalInBackground: true` to continue polling even when the tab is not visible:

```typescript
// Continue polling even when tab is hidden
const notifications = resource(
  () => fetch('/api/notifications').then(r => r.json()),
  {
    refetchInterval: 10000,
    refetchIntervalInBackground: true, // Continue when tab hidden
    refetchOnKeyChange: true
  }
);
```

#### Cleanup

Always call `dispose()` when the resource is no longer needed to stop polling and clean up timers:

```typescript
// In a component cleanup or when navigating away:
health.dispose();
// Polling stopped, all timers cleared
```

### Window Focus Refetch

Resources can automatically refetch data when the user returns to the tab. This is useful for keeping session data, notifications, or any time-sensitive data fresh.

```typescript
// Refetch when tab regains focus
const session = resource(
  () => fetch('/api/session').then(r => r.json()),
  {
    refetchOnWindowFocus: true,
    refetchOnKeyChange: true
  }
);

// Data automatically refreshes when user switches back to this tab
```

#### When to Use

- Session/authentication state that should stay fresh
- Notification counts that need updating
- Real-time data that should be current when user returns

#### Cleanup

The focus listener is automatically cleaned up when calling `dispose()`:

```typescript
// In a component cleanup:
session.dispose();
// Focus listener removed
```

### Reconnect Refetch

Resources can automatically refetch data when the browser reconnects after going offline. This ensures users see fresh data after network interruptions.

```typescript
// Refetch when browser reconnects
const data = resource(
  () => fetch('/api/data').then(r => r.json()),
  {
    refetchOnReconnect: true,
    refetchOnKeyChange: true
  }
);

// Data automatically refreshes when network comes back online
```

#### Global Network Status

Access network status globally through the cache API:

```typescript
import { resourceCache } from '@hellajs/resource';

// Check current online status
if (resourceCache.isOnline()) {
  data.fetch({ force: true });
}

// Subscribe to online/offline changes
const unsubscribe = resourceCache.onOnlineChange((online) => {
  console.log(online ? 'Back online' : 'Gone offline');
});

// Cleanup subscription
unsubscribe();
```

#### Cleanup

The reconnect listener is automatically cleaned up when calling `dispose()`:

```typescript
// In a component cleanup:
data.dispose();
// Reconnect listener removed
```

### Retry Logic

Resources support automatic retry on failure with configurable strategies for both retry count and delay.

#### Simple Retry

```typescript
// Retry up to 3 times on failure
const userResource = resource(
  () => fetch('/api/user').then(r => r.json()),
  { retry: 3 }
);

// Boolean shorthand: true = 1 retry, false = 0 retries
const dataResource = resource(fetchData, { retry: true });
```

#### Conditional Retry

Use a function to conditionally retry based on error type:

```typescript
const userResource = resource(
  () => fetch('/api/user').then(r => r.json()),
  {
    // Only retry on server errors (5xx), not client errors (4xx)
    retry: (count, error) => {
      if (error.category === 'client' || error.category === 'not_found') {
        return false; // Don't retry 4xx errors
      }
      return count < 3; // Retry up to 3 times for server/network errors
    }
  }
);
```

#### Retry Delay

Control the delay between retries with fixed values or exponential backoff:

```typescript
// Fixed delay: 1 second between each retry
const fixedDelay = resource(fetchData, {
  retry: 3,
  retryDelay: 1000
});

// Exponential backoff: 1s, 2s, 4s, 8s...
const exponentialBackoff = resource(fetchData, {
  retry: 3,
  retryDelay: (attempt) => Math.min(1000 * Math.pow(2, attempt - 1), 30000)
});

// Jittered exponential backoff (recommended for distributed systems)
const jitteredBackoff = resource(fetchData, {
  retry: 3,
  retryDelay: (attempt) => {
    const base = Math.min(1000 * Math.pow(2, attempt - 1), 30000);
    return base * (0.5 + Math.random() * 0.5); // 50-100% of base
  }
});
```

#### Error Categories

The `ResourceError` object passed to retry functions includes a `category` field for conditional logic:

| Category | Description |
|----------|-------------|
| `abort` | Request was aborted (DOMException AbortError) |
| `not_found` | Resource not found (HTTP 404) |
| `server` | Server errors (HTTP 5xx) |
| `client` | Client errors (HTTP 4xx) |
| `unknown` | All other errors (including network failures and unclassified errors) |

```typescript
const resilientResource = resource(fetchData, {
  retry: (count, error) => {
    // Retry server errors and unknowns (network), not client errors
    return ['server', 'unknown'].includes(error.category) && count < 3;
  },
  retryDelay: (attempt, error) => {
    // Longer delays for server errors
    return error.category === 'server' ? attempt * 2000 : attempt * 1000;
  }
});
```

### Data Transformation

Use the `transform` option to transform data before it's returned, while keeping the original data in cache. This is useful for selecting specific fields, computing derived values, or reshaping API responses.

#### Basic Transformation

```typescript
import { resource } from '@hellajs/resource';

interface UserResponse {
  id: number;
  name: string;
  email: string;
  permissions: string[];
  metadata: Record<string, unknown>;
}

// Transform to extract only needed fields
interface UserSummary {
  name: string;
  email: string;
}

const userResource = resource<UserResponse, undefined, UserSummary>(
  () => fetch('/api/user').then(r => r.json()),
  {
    transform: (data): UserSummary => ({
      name: data.name,
      email: data.email
    })
  }
);

userResource.fetch();
// userResource.data() returns { name, email } not full UserResponse
```

#### Derived Computations

Transform arrays into aggregated statistics or computed values:

```typescript
interface Todo {
  id: number;
  text: string;
  completed: boolean;
}

interface TodoStats {
  total: number;
  completed: number;
  pending: number;
}

const todosResource = resource<Todo[], undefined, TodoStats>(
  () => fetch('/api/todos').then(r => r.json()),
  {
    transform: (todos): TodoStats => ({
      total: todos.length,
      completed: todos.filter(t => t.completed).length,
      pending: todos.filter(t => !t.completed).length
    })
  }
);

todosResource.fetch();
// todosResource.data() returns { total, completed, pending }
```

#### TypeScript Support

The `transform` option adds a third generic parameter for the transformed type:

```typescript
// T = raw data type, K = key type, TTransformed = transformed data type
const resource = resource<TRaw, TKey, TTransformed>(
  fetcher,
  { transform: (data): TTransformed => ... }
);
```

#### Cache Behavior

The cache always stores the original (untransformed) data. This means:

- Multiple resources with different `transform` functions share the same cache
- `setData` and `mutate` work with the raw data type
- Transform is reapplied when cache is reused

```typescript
// Both resources share the same cache entry for 'user-1'
const userName = resource(
  () => fetch('/api/user/1').then(r => r.json()),
  {
    key: () => 'user-1',
    cacheTime: 60000,
    transform: (data) => data.name
  }
);

const userEmail = resource(
  () => fetch('/api/user/1').then(r => r.json()),
  {
    key: () => 'user-1',
    cacheTime: 60000,
    transform: (data) => data.email
  }
);

// Concurrent fetch() calls share one request via deduplication
userName.fetch(); // Fetches and caches
userEmail.fetch(); // Joins the same request (deduplication)

// After completion:
// userName.data() → "John"
// userEmail.data() → "john@example.com"
```

### Stale-While-Revalidate (SWR)

The `staleTime` option controls how long cached data is considered fresh. When data becomes stale, calling `.fetch()` returns the stale data immediately while triggering a background refresh.

#### Basic SWR

```typescript
// Data is fresh for 30 seconds, cached for 5 minutes
const userResource = resource(
  () => fetch('/api/user').then(r => r.json()),
  {
    staleTime: 30000,  // Fresh: 0-30s
    cacheTime: 300000  // Cached: 0-5min
  }
);

userResource.fetch();

// Within 30 seconds: returns cached data instantly (fresh)
// After 30 seconds: returns cached data + background refresh (stale)
// After 5 minutes: fresh network request (expired)
```

#### Timeline Behavior

| Time | State | `.fetch()` Behavior |
|------|-------|-------------------|
| 0-30s | Fresh | Returns cached data instantly |
| 30s-5min | Stale | Returns cached data + background fetch |
| 5min+ | Expired | Fresh network request |

#### Stale State Indicators

Use `isFetching()` to show background refresh indicators while keeping stale data visible:

```typescript
const todos = resource(
  () => fetch('/api/todos').then(r => r.json()),
  {
    staleTime: 10000,  // 10 seconds
    cacheTime: 60000   // 1 minute
  }
);

todos.fetch();

// After 10+ seconds, when user navigates back:
todos.fetch();

// UI can show refresh indicator while keeping data visible
if (todos.isFetching() && todos.data()) {
  console.log('Refreshing in background...');
  console.log('Still showing:', todos.data()); // Stale data still available
}
```

#### StaleTime Options

```typescript
// Always stale - always triggers background fetch on .fetch()
const realtime = resource(fetchPrice, {
  staleTime: 0
});

// Never stale - never refetches unless manually invalidated
const offline = resource(fetchConfig, {
  staleTime: Infinity
});

// Disable automatic revalidation when stale
const manual = resource(fetchData, {
  staleTime: 30000,
  revalidateOnStale: false  // Don't auto-refetch when stale
});
```

#### SWR vs Cache Expiration

| Option | Purpose | Default |
|--------|---------|---------|
| `staleTime` | When to start background refresh | `Infinity` |
| `cacheTime` | When to remove from cache entirely | `0` |

- **staleTime**: Data exists but should be refreshed (SWR active)
- **cacheTime**: Data removed, requires fresh network request

```typescript
const data = resource(fetchData, {
  staleTime: 30000,  // After 30s: background refresh
  cacheTime: 300000  // After 5min: cache cleared, fresh fetch
});

// 0-30s: Fresh data, instant return
// 30s-5min: Stale data + background refresh
// 5min+: Cache miss, fresh network request
```

### Cache Keys
The `key` option is used for caching and deduplication. You can provide either a static value for simple cases or a function for reactive behavior.

#### Static Keys
For resources that don't depend on changing parameters, use a static string or value:

```typescript
const configResource = resource(
  () => fetch('/api/config').then(r => r.json()),
  { key: 'app-config' } // Static string key
);

const userProfileResource = resource(
  () => fetch('/api/me').then(r => r.json()),
  { key: 'current-user' } // Another static key
);
```

#### Reactive Keys
For dynamic resources that depend on other reactive state, use a function that returns the key:

```typescript
const userId = signal(1);

const userResource = resource(
  (id) => fetch(`/api/users/${id}`).then(r => r.json()),
  { key: () => userId() } // Reactive function key
);

// Fetch user 1
userResource.fetch();

// To fetch a different user, change the key and call get again
userId(2);
userResource.fetch();
```

### Key-Change Refetch
Set `refetchOnKeyChange: true` to automatically refetch when reactive key dependencies change. This eliminates the need to manually call `.fetch()` after key changes.

```typescript
const userId = signal(1);

const userResource = resource(
  (id) => fetch(`/api/users/${id}`).then(r => r.json()),
  { 
    key: () => userId(), // Reactive key function
    refetchOnKeyChange: true // Automatically refetch when userId changes
  }
);

// Initial fetch happens automatically on first effect run
// No need to call userResource.fetch()

// Changing userId automatically triggers a new fetch
userId(2); // Resource automatically fetches user 2
userId(3); // Resource automatically fetches user 3
```

  <span>ℹ️</span>
  <span>Auto-fetch only works with reactive key functions. Static key values won't trigger automatic refetches since they don't change. If your key function uses signals or computed values, the resource will automatically track those dependencies and refetch when they change.</span>
</div>

### Caching
Set `cacheTime` (in milliseconds) to enable caching. Each unique key gets its own cache entry.

```typescript
const postsResource = resource(
  (id) => fetch(`/api/posts/${id}`).then(r => r.json()),
  { 
    key: () => postId(),
    cacheTime: 60000 // Cache for 1 minute
  }
);
```

### Data Mutations
To update data after a mutation (e.g., a POST or PUT request), perform the mutation and then call `.invalidate()` on the relevant resource to refetch the fresh data.

```typescript
async function updateUser(data) {
  await fetch(`/api/users/${userId()}`, { method: 'PUT', body: JSON.stringify(data) });
  
  // Invalidate the user resource to get the updated data
  userResource.invalidate();
}
```

## Important Considerations

### AbortError Does Not Set Error State

When a request is aborted (via `.abort()`, `timeout`, or an external `abortSignal`), the error state is **not** set. The resource returns to `idle` status with the original `initialData`, not `error` status.

```typescript
// ❌ Don't rely on error() being set after abort
const r = resource(fetchData, { timeout: 5000 });
r.fetch();
// ...timeout fires...
if (r.error()) { /* ⚠️ won't enter here */ }

// ✅ Check status instead
if (r.isIdle() && !r.isFetching()) {
  console.log('Request was aborted or never started');
}
```

### Manual vs Key-Change Fetching

By default, resources don't auto-fetch on creation - you must explicitly call `.fetch()` or `.fetch({ force: true })`. Set `refetchOnKeyChange: true` for automatic fetching when key dependencies change.

```typescript
// ❌ No data fetched yet (manual mode)
const userResource = resource(() => fetch('/api/user'));
console.log(userResource.data()); // undefined
// ✅ Explicitly fetch data
userResource.fetch();

// ✅ Key-change refetch mode
const reactiveResource = resource(() => fetch('/api/user'), { refetchOnKeyChange: true });
// Data fetches automatically when effect runs
```

### enabled Is Static, Not Reactive

The `enabled` option is evaluated once at creation time and stored as a boolean. It does not reactively update when signals change.

```typescript
const userId = signal(null);

// enabled is evaluated NOW — if userId() is null, it's false forever
const r = resource(
  (id) => fetch(`/api/users/${id}`).then(r => r.json()),
  {
    key: () => userId(),
    enabled: !!userId()
  }
);

// Changing userId later does NOT re-evaluate enabled
userId(123); // enabled is still false from creation time
```

### Dynamic refetchInterval Receives undefined Initially

When using a function for `refetchInterval`, the first scheduling call receives `undefined` as data (no data has been fetched yet). Handle this in your function:

```typescript
const r = resource(fetchHealth, {
  refetchInterval: (data) => {
    // data is undefined on first call before any fetch completes
    return !data ? 1000 : data.status === 'unhealthy' ? 1000 : 30000;
  },
  refetchOnKeyChange: true
});
```

### Memory Management

Each unique key creates a separate cache entry - consider key design for large datasets.

```typescript
// ❌ Too many cache entries
{ key: () => Math.random() }
// ✅ Stable, meaningful keys
{ key: () => `user-${userId()}` }
```

### Error Handling

Always check both `error()` and `status()` states for proper error handling.

```typescript
// ✅ Proper error handling
effect(() => {
  if (resource.error()) {
    console.error('Failed:', resource.error());
  }
  if (resource.status() === 'success') {
    console.log('Data:', resource.data());
  }
});
```
