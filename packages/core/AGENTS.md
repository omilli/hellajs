<core-package-instructions>

Reactive primitives over a doubly-linked dependency DAG. Signals are sources, computeds are transforms, effects are sinks. Updates propagate via depth-first traversal in topological order — glitch-free, each node executes at most once per update cycle. Rebased onto the alien-signals 3.2.1 machinery, vendored into `lib/internal/system.ts` ([Alien Signals](https://github.com/stackblitz/alien-signals), MIT); every behavioral decision (queueing, disposal, node kinds) lives in the host layer, and the public API + runtime behavior are byte-identical to the pre-rebase engine.

## Public exports (`lib/index.ts`)

| Export | Kind | Source |
|---|---|---|

| `signalArray`, `signalMap`, `signalSet` | Collection primitives | `lib/signalArray.ts` (`signalArray`), `lib/signalMap.ts` (`signalMap`), `lib/signalSet.ts` (`signalSet`) |
| `flush` | Scheduler drain (advanced/testing) | `lib/internal/scheduler.ts` |
| `isFunction`, `isString`, `isPlainObject`, `isNumber`, `isBoolean`, `isNull`, `isFalsy`, `isObject`, `objectLoop` | Utils | `lib/internal/utils.ts` |
| `hasWindow`, `hasDocument`, `hasNavigator` | Env probes | `lib/internal/env.ts` |
| `Signal` | Type-only | `lib/types.d.ts` |

`computed`, `effect`, `batch`, `untracked`, and `scope` throw `[core] <name>: <argName> must be a function, received <typeof>` on a non-function callback (arg names: `computedFn`, `effectFn`, `batchFn`, `untrackedFn`, `fn`). `signal` takes a value, not a function, and validates only its optional `options.equals` (`[core] signal: equals must be a function, received <typeof>`); `computed(fn, options)` validates the same way. The collection factories validate structural input at every public entry point: `signalArray` throws `[core] signalArray: initial must be an array, received <typeof>` on a non-array seed and `[core] signalArray: value must be an array, received <typeof>` on a non-array reconcile call; `signalMap` throws `[core] signalMap: initial must be iterable, received <typeof>` / `[core] signalMap: value must be a Map, received <typeof>`; `signalSet` throws `[core] signalSet: initial must be iterable, received <typeof>` / `[core] signalSet: value must be a Set, received <typeof>`. A rejected input never mutates the container (the reconcile throw precedes every membership pass). An equal `equals` result skips the update entirely — old value/reference kept, no propagation; on `computed`, the comparator is skipped on the first evaluation (prev is `undefined`).

## Collection signals (`signalArray` / `signalMap` / `signalSet`)

Pure composition over `signal`/`computed`: one child signal per element plus one version signal per container (`signal(0)`, incremented per structural change). No new node kinds, no scheduler/system/flags changes. Shared machinery: `lib/internal/collections.ts` (`createVersion`, `createHooks`, `peekSignal`, `writeValue`, `CollectionHooks`).

- Tracking: value ops (`set` on an existing target) write exactly one child; structural ops reorder/drop nodes + bump the version (zero child writes). `get(i)`/`get(k)`/`has(k)`(map)/`length`/`size`/`keys` track the version; `map`/`forEach`/`values`/whole-callable additionally track every element read. Set `has(v)` tracks only its value's membership signal (lazily created on first probe); map `entry(k)` is a memoized `computed` over `[version, key signal]`, so unrelated structural wakes re-evaluate to the same value and stop at the computed's equality gate.
- Set wrap threading (store's deep-collection entry point): `signalSet` accepts `CollectionOptions<T>`; `wrap` runs on initial values, `add`, and the reconcile setter. The set reconcile must pre-wrap the incoming diff into a converted `Set` before both passes — the add pass and the delete pass compare against wrapped membership, never the raw input (wrapping only on the add side deletes every existing member). `equals`/`merge` are validated for options-shape parity but inert (no keyed positions, no value writes).
- The container interfaces are asymmetric (`SignalArray<T, W = T>`, `SignalMap<K, V, W = V>`, `SignalSet<T, W = T>`): write/insert methods take `W`, reads return `T`, and set `has`/`delete` accept `T | W` (raw identity probes stay legal). `W` defaults to `T` (standalone usage is symmetric); store instantiates `W` with the raw element form so its usage (`set(0, partial)`, `push(raw)`, `has(raw)`) typechecks. The callable's write overload is `(value: W[])`/`(Map<K, W>)`/`(Set<W>)`, spelled as explicit call signatures instead of `extends Signal<T[]>`.
- Write pipeline (`writeValue`): `merge(prev, next)` returns true = handled (no child write); else `wrap(next)` then the child write, whose per-element `options.equals` gates propagation. Merge-before-wrap is load-bearing (store matches raw input against converted nodes). New targets (init, push/insert/splice-insert, reconcile-add) skip merge: `wrap` then store.
- Map delete is structural only (version bump, zero child writes — symmetric with array removals); `entry(k)` handles read `undefined` via the computed, never by writing `undefined` through a user `(V, V)` comparator.
- `signalArray.length()` must attach via `Object.defineProperty` — `Function.prototype.length` is non-writable, plain assignment throws in strict mode.
- Internal reads on write paths (pop return, splice removed values, merge's `prev`) go through `peekSignal` (untracked) so mutations inside effects never leak subscriptions.

## Node types & initialization

Every node extends `ReactiveNode` (`lib/internal/system.ts`): `deps` (tracking bookmark — last-linked dependency), `depsTail` (dependency-list tail; links past it are stale), `subs` (first subscriber link), `subsTail` (subscriber-list tail — new links append), `flags` (bitmask).

| Node | Created by | Initial `flags` | Extra fields |
|---|---|---|---|
| Signal | `signal()` | `MUTABLE` (1) | `currentValue` (committed), `pendingValue` (staged write) |
| Computed | `computed()` | `NONE` (0) | `value` (cached), `getter` (compute fn, receives prev), `ce` (optional equals comparator) |
| Effect | `effect()` | `WATCHING \| RECURSED_CHECK \| SIGNAL_DEPS` (134) | `fn` (effect fn), `cleanup` (cleanup fn or undefined) |

A `Link` (`lib/internal/system.ts`) is the doubly-linked edge: `version` (tracking stamp — recursion dedup compares it), `dep` (subscribed-to node), `sub` (subscriber), `prevDep`/`nextDep` (threading the subscriber's dependency list), `prevSub`/`nextSub` (threading the dependency's subscriber list). Each link is shared by both adjacency lists. DFS algorithms allocate stack frames `{value, prev}` (`Stack<T>`, `lib/internal/system.ts`).

- **Computed starts `NONE`** so the first read routes through the getter's fresh-evaluation arm (`!rf` → `updateComputed`) — which also re-marks `MUTABLE | DIRTY` when that first evaluation throws, so a throwing computed never serves a stale cache.
- **Effect starts `WATCHING | RECURSED_CHECK | SIGNAL_DEPS`**: `WATCHING` arms it for queueing, `RECURSED_CHECK` marks the first factory run as executing (re-entrant propagation defers, identical to re-runs), and `SIGNAL_DEPS` assumes signals-only deps until a computed link clears the fast-path bit.

## Flags (`lib/internal/flags.ts`)

Values 0-32 are the vendored system's contract — do not renumber; `SIGNAL_DEPS` is a host-owned extension.

| Flag | Value | Meaning |
|---|---|---|
| `NONE` | 0 | No pending work |
| `MUTABLE` | 1 | Value node (signal or computed) — propagation descends into its subscribers |
| `WATCHING` | 2 | Armed effect — `notify` queues it and clears the bit (the bit means "awaiting notification"; queue dedup) |
| `RECURSED_CHECK` | 4 | Node is currently executing — re-entrant propagation defers via the recursion check |
| `RECURSED` | 8 | Recursive notification landed while the node was executing (vendored propagation only; the host never sets it) |
| `DIRTY` | 16 | Definitely needs re-execution |
| `PENDING` | 32 | Might need re-execution (validate via `checkDirty` before deciding) |
| `SIGNAL_DEPS` | 128 | Effect's deps are all signals — `notify` marks it DIRTY directly (a write proved change), flush runs it without validation |

`MUTABLE` is a permanent type bit on value nodes (rebuilt by `updateSignal`/`updateComputed`); `WATCHING`/`SIGNAL_DEPS` are sticky effect bits (rebuilt by `executeEffect` from the entry snapshot — a computed link clears `SIGNAL_DEPS` permanently, locking in the conservative validation path); `RECURSED_CHECK`/`DIRTY`/`PENDING` are transient state bits.

## Execution context (`lib/internal/context.ts`)

Module-level singletons that drive tracking and scope registration:
- **`currentValue`** / `setCurrentSub(sub)`: the reactive node currently executing (an effect or computed). Signal/computed getters call `link(source, currentValue, 0)` only when this is set — this is how dependencies get recorded. `setCurrentSub` returns the previous value so callers can save/restore (used by `updateComputed`, `executeEffect`, `runCleanup`, `untracked`, `effect`).
- **`activeScope`** / `setActiveScope(scope)`: the innermost `scope()` in effect. `addScopeEffect(cleanup)` lazily allocates a `Set` on the scope and registers an effect's disposer; no-op when no scope is active.

## Core algorithms

**Vendored machinery (`lib/internal/system.ts`).** `createReactiveSystem({ update, notify, unwatched })` builds and exports the five graph functions; the module instantiates it over the scheduler's callbacks (the package's one intentional import cycle — safe because both sides touch each other's bindings only inside hoisted function declarations; keep the scheduler callbacks as `function` declarations).

- **`link(dep, sub, version)`**: appends the edge with three reuse fast-paths — the bookmark dep (`depsTail.dep === dep`), the next-in-line dep (version refresh + `depsTail` advance: zero allocation when a computation re-reads the same signals in the same order), and the last-subscriber dedup (`subsTail.version === version && subsTail.sub === sub` — the host passes version `0` throughout). The host never re-arms versions, so the stamp is constant; `isValidLink` (below) is what consumes live-span membership.
- **`unlink(link, sub)`**: O(1) DLL surgery on both lists, returns `nextDep` so callers keep walking. Detaching a dependency's last subscriber calls the host's `unwatched(dep)` — the computed auto-GC trigger.
- **`propagate(link, innerWrite)`**: the setter's DFS. Per subscriber: clean nodes get `PENDING` (+ `RECURSED` under `innerWrite`, which the host never sets — writes are only ever top-level or batch-deferred); nodes already `DIRTY`/`PENDING` short-circuit without re-queueing; an executing node (`RECURSED_CHECK`) takes the recursion check — `isValidLink` walks the live dependency span and marks `RECURSED | PENDING` when the written dep is tracked (self-write deferred), otherwise leaves it untouched. Armed (`WATCHING`) nodes go to `notify`. `MUTABLE` nodes are descended into; siblings stack in `{value, prev}` frames for backtracking.
- **`checkDirty(link, sub)`**: the skip-update validation for `PENDING` nodes. Walks the subscriber's deps; a `MUTABLE | DIRTY` dep is re-committed via the host's `update` — changed → `shallowPropagate` its other subscribers + dirty; a `MUTABLE | PENDING` dep dives (stacked). A subscriber marked `DIRTY` mid-walk (its own shallow mark landed) short-circuits dirty. On unwind, a dirty intermediate recomputes via `update` — equal results clear `PENDING` and stop; the walk continues to sibling deps at each level. This is the mechanism behind "computed returns the same value → downstream effects don't fire".
- **`shallowPropagate(link)`**: the confirmation pass — linear walk upgrading `PENDING` subscribers to `DIRTY`, queueing armed effects via `notify`. Called after a confirmed value change (signal/computed getters, `checkDirty`'s commits).

**Host layer (`lib/internal/scheduler.ts`).** Owns the queue and every queueing/disposal decision:

- **`update(node)`**: host dispatch — `"getter" in node` → `updateComputed`, else `updateSignal`. Effects never carry `MUTABLE`, so only value kinds arrive.
- **`notify(effect)`**: appends to `effectQueue`, clears `WATCHING` (the queue-dedup bit — callers only notify `WATCHING` nodes, so an effect is never queued twice), and marks `SIGNAL_DEPS` effects `DIRTY` (pin: a signal write already proved change — flush runs them without `checkDirty`; this is why a canceling batch `s(1); s(0)` still runs a signals-only effect once). No ancestor walk: parents order through their own dependency writes (a write inside the parent's run nests a flush after the direct subscribers). The vendored walk fits vendored's own disposal semantics, not this host's — it would run a parent gate ahead of same-write direct subscribers sitting later in the subscription list.
- **`unwatched(node)`**: computed auto-GC only — mark `MUTABLE | DIRTY` (lazy rebuild) and unlink **all** its dependencies (cascading into dep computeds that lose their own last subscriber). Signals hold nothing to release. Effects deliberately no-op: a nested effect whose parent unlinked it stays alive and keeps firing on its own dependencies until explicitly disposed (accumulation pin).
- **`flush`**: drains `effectQueue` — each dequeue clears its slot (GC) and runs `executeEffect` with the entry flag snapshot. Effects queued during the drain append and run in the same pass. Indices reset only on a completed pass: a throw aborts the drain with the remaining entries intact, and a bare `flush()` recovers them.
- **`executeEffect(effect, flags)`**: runs if `DIRTY`, or `PENDING` with stale deps (`checkDirty`). Run path: prior `cleanup` first (tracking suspended via `setCurrentSub(undefined)`); if the cleanup disposed the effect (`flags` zeroed), return without re-running. Otherwise rebuild the flag word from constants — `WATCHING | RECURSED_CHECK | (flags & SIGNAL_DEPS)` — run `fn` under `setCurrentSub`, capture the cleanup only when `isFunction(result)`, then restore context, clear `RECURSED_CHECK`, and `purgeDeps`. Skip path: re-arm `WATCHING | (flags & SIGNAL_DEPS)`, dropping `PENDING`.
- **`disposeEffect(effect)`**: runs `cleanup`, unlinks every dependency (forward walk via `unlink`'s `nextDep` return), unlinks the incoming parent subscription (`subs`), sets `NONE`.

**Tracking (`lib/internal/tracking.ts`).** There is no start/end pair — the execute paths reset `depsTail = undefined` inline and `purgeDeps(sub)` unlinks every dependency after it (the ones not re-accessed this run). This rebuild is what makes conditional dependencies work — the graph is re-derived each execution.

**Value commits (`lib/internal/execution.ts`).** `updateSignal` resets `flags = MUTABLE`, moves `pendingValue → currentValue`, and reports `!isEqual(previous, pending)` (reference equality, NaN self-equal). `updateComputed` resets the bookmark, sets `MUTABLE | RECURSED_CHECK`, runs `getter(previousValue)`, applies the `ce` equality gate (skipped while `previousValue` is `undefined` — first evaluation), commits, and in `finally` restores context, clears `RECURSED_CHECK`, and purges. The `catch` arm re-marks `MUTABLE | DIRTY` before rethrowing — a throwing computed re-executes on every read instead of serving the stale cache.

## Getter / setter mechanics

- **Signal getter (`signal.ts`):** `rf & DIRTY && updateSignal(node) && subs !== undefined && shallowPropagate(subs)` — commit a staged write, then dirt-mark subscribers. Then `currentValue && link(node, currentValue, 0)` tracks; the link leaves the subscriber's `SIGNAL_DEPS` set (signals-only fast path stays armed). Returns `currentValue` — committed by this point, or never dirty.
- **Signal setter:** dispatched by `arguments.length > 0` (NOT `value !== undefined` — so you can store `undefined`). Equality gate first: closure `se` or `isEqual` against `pendingValue` (the last staged value); equal → no work. Changed: stage `pendingValue`, set `flags = MUTABLE | DIRTY`, and only if `subs` exists call `propagate(subs, false)` then `!batchDepth && flush()`. No subscribers → no work.
- **Computed getter (`computed.ts`):** `rf & DIRTY || (rf & PENDING && (checkDirty(deps, node) || ((node.flags = rf & ~PENDING), false)))` decides staleness → `updateComputed` + `shallowPropagate(subs)` on change. The PENDING clear is folded into the condition — the comma arm only runs when validation says not-stale, and that snapshot never carries `DIRTY` (the first arm short-circuits), so a fresh-clean flag word is never clobbered back to stale. `!rf` (first read) routes through `updateComputed` too — same path, so a throwing first evaluation re-marks `DIRTY` and rethrows on every later read. Then `link(node, sub, 0)` and `sub.flags &= ~SIGNAL_DEPS` — a computed link permanently disables the subscriber's signals-only fast path (its value may come out equal, forcing flush-time validation; conservative by design, never re-armed).
- **`effect` (`effect.ts`):** if `currentValue` is active, `link(node, parent, 0)` runs *before* `setCurrentSub` — note the argument order: **the parent subscribes to this child** (the edge lands in `parent.deps` / `child.subs`, not the reverse); a parent disposal consumes that edge, and the child survives it (accumulation pin). The factory then runs `fn` synchronously under `setCurrentSub(node)` with `RECURSED_CHECK` already set, captures `cleanup` if `fn` returns a function, and clears `RECURSED_CHECK` in `finally`. A throw on that first run self-disposes: the `catch` arm runs `disposeEffect` (while the sub context still points at the effect) and rethrows before any disposer is captured or scope-registered — an effect that never started leaves no subscribed state. Returns a `disposeEffect` closure and registers it with the active scope via `addScopeEffect`.

## Non-obvious behaviors

- **Getter/setter discriminator is `arguments.length`, not value identity.** `s(undefined)` is a setter call, not a getter — storing `undefined` is supported and tested.
- **Reference equality with `NaN` self-equal by default** for change detection (`isEqual` in `lib/internal/utils.ts`: `a === b || (a !== a && b !== b)`), overridable per node via `signal(v, { equals })` / `computed(fn, { equals })`. Primitives compare by value; new object/array references always propagate; writing `NaN` over `NaN` is treated as unchanged and never fires (`+0`/`-0` compare equal — `Object.is` as `equals` distinguishes them). An equal comparator result skips the write block entirely — the old reference stays visible. In-place mutation never fires — replace the reference.
- **Self-writes do not infinite-loop.** An executing node holds `RECURSED_CHECK`, and `propagate`'s recursion check defers it: a write to a dep the running node has re-linked marks `RECURSED | PENDING` (suppressed now, validated on the next external write's flush); a write to a not-yet-re-linked dep marks nothing. Either way the running pass completes — an effect writing a signal it reads runs at most twice across two external triggers then stabilizes (`packages/core/tests/propagation.test.ts` pins write-before-read, read-then-write, and already-tracked variants). `untracked` exists to read without establishing a dependency, not to prevent loops.
- **Errors abort the flush.** An uncaught throw in an effect propagates out of the signal setter that triggered it; the queue indices are untouched, so the remaining entries — still queued, `WATCHING` cleared — survive. A bare `flush()` (or any later write's flush) recovers them; each survivor runs exactly once. Signal state is not corrupted: a committed value stays committed.
- **A throwing computed rethrows on every read.** `updateComputed`'s catch re-marks `MUTABLE | DIRTY` (the flag rebuild cleared it), so every read retries `getter` and rethrows — never a silent `undefined`, never the stale cached value — until a dependency change allows success. The fresh-evaluation arm shares the path, so a first-read throw behaves identically.
- **Errors defeat tracking past the throw point.** A throw in a computed/effect means dependencies read after the throw point aren't tracked (the `finally` still calls `purgeDeps`, pruning everything after `depsTail`). `try/catch` *inside* the reactive function preserves tracking — read deps before branching.
- **Effects must be synchronous.** `async` effect functions break dependency tracking (the body returns before deps are read); start async work via `.then` / `fetch` inside a sync effect body.
- **Nested effects accumulate.** Re-running a parent effect creates new child effects but does NOT dispose old ones — `unwatched` no-ops on effects (the accumulation pin), so old children keep firing on their own dependencies until explicitly disposed. The stale child-effect links a re-run leaves behind splice out naturally as new links append past the bookmark.
- **A cleanup can dispose its own effect.** `executeEffect` runs the prior cleanup before rebuilding flags; if the cleanup called the disposer (`flags` zeroed), the re-run is skipped and the effect stays dead (`packages/core/tests/effect-lifecycle.test.ts`).
- **Scope cleanup is idempotent.** The returned function `forEach`-calls cleanups then clears the set; subsequent calls iterate an empty set (no-op). Empty scopes return a shared `NOOP` singleton (reference-equal across calls).
- **`untracked` nests correctly:** saves/restores the prior `currentValue`, so it composes inside `computed`/`effect` and reads multiple signals in one call.
- **Batch is a depth counter.** `++batchDepth` on entry, `!--batchDepth` triggers `flush()`. Nested batches drain at outermost exit. Async work scheduled inside escapes the boundary.
- **Signals-only effects skip flush-time validation; computed-mediated ones never do.** `notify` marks `SIGNAL_DEPS` effects `DIRTY` at queue time — a signal write already proved the change, so flush runs them without `checkDirty`. Consequence: a batch whose writes cancel out (`s(1); s(0)`) re-runs a signals-only effect once (pinned in `batch.test.ts`), while computed-mediated effects still skip (the computed's equal-value check stays authoritative). A single computed link disables the fast path for that effect forever — conservative by design.
- **Parents order through their own writes, not a queue walk.** When a parent effect's own dependency changes, its write flush nests inside the child-notification flush, so the parent re-runs before effects subscribed to it — without `notify` reordering the queue. An ancestor-queued-ahead scheme would run a parent gate ahead of same-write direct subscribers sitting later in the subscription list (the failure mode that removed the walk).
- **Computed auto-GC.** When a computed's last subscriber link is removed, `unwatched` drops **all** of its dependency links (cascading into dep computeds that lose their own last subscriber) and marks it `MUTABLE | DIRTY`. The next read rebuilds the graph and recomputes from scratch.
