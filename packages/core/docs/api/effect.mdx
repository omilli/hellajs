# effect

Runs automatically when reactive dependencies change.

## API

```typescript
function effect(effectFn: () => void | (() => void)): () => void
```
- `effectFn`: Re-executed whenever a signal read inside it changes. Return a cleanup function to run before re-execution and on disposal.
- **Returns**: A function that stops the effect and prevents further executions

## Basic Usage

Runs immediately, then again whenever a dependency changes.

Call the returned function to stop the effect when no longer needed.

```typescript
import { signal, effect } from '@hellajs/core';

const count = signal(0);

// This effect runs immediately, then whenever `count` changes.
const cleanup = effect(() => {
  console.log(`The count is: ${count()}`);
});

count(1); // Logs: "The count is: 1"
count(2); // Logs: "The count is: 2"

// Stop the effect. Future changes to `count` will not be logged.
cleanup();
count(3); // (nothing is logged)
```

## Key Concepts

### Conditional Effects

Only reacts to the signals that are read during the ***last*** execution.

```typescript
import { signal, effect } from '@hellajs/core';

const showData = signal(true);
const data = signal('value');
const backup = signal('backup');

effect(() => {
  if (showData()) {
    console.log(data()); // Only tracks data when showData is true
  } else {
    console.log(backup()); // Tracks backup when showData is false
  }
});

// Initially tracks showData and data
data('updated'); // Effect re-runs
backup('fallback'); // Effect does NOT re-run: backup is not a dependency yet

showData(false); // Effect re-runs, now tracks showData and backup instead of data
backup('new fallback'); // Effect re-runs: backup is now a dependency
data('still updated'); // Effect does NOT re-run: data is no longer a dependency
```

## Important Considerations

### Avoid Async

The effect function itself must be synchronous (not `async`). Async operations can be started inside via `.then()` or `fetch()`, but the reactive system needs synchronous dependency tracking.

```typescript
import { effect } from '@hellajs/core';

// ❌ Async function directly
effect(async () => { /* ... */ });

// ✅ Handle async operations inside
effect(() => {
  fetch('/api/data').then(data => {
    // Handle the data here
    console.log(data);
  });
});
```

### Infinite Loops

Writing to a signal that the effect also reads creates infinite loops.

Use [`untracked`](/reference/core/untracked) for non-reactive reads or [`batch`](/reference/core/batch) to group the read and write into a single update cycle.

```typescript
import { signal, effect, untracked } from '@hellajs/core';

const count = signal(0);

// ❌ Effect reads and writes the same signal
effect(() => {
  count(count() + 1); // Triggers itself infinitely
});

// ✅ Use untracked to read without creating dependency
effect(() => {
  const current = untracked(() => count());
  console.log(`Count: ${current}`);
});
```

### Error Propagation

Errors thrown inside an effect propagate to the signal setter that triggered it and abort the current flush (remaining queued effects are skipped). Subsequent signal changes start a fresh flush and the reactive system continues normally.

```typescript
import { signal, effect } from '@hellajs/core';

const count = signal(0);
const shouldThrow = signal(false);

const cleanup = effect(() => {
  const value = count();
  if (shouldThrow()) throw new Error("boom");
  console.log(value);
});

// Error throws from the signal setter call
shouldThrow(true); // throws Error: "boom"

// Signal state is not corrupted
shouldThrow(false); // Effect recovers and re-runs normally

cleanup();
```
