# Reactivity

Declare data and track dependencies, only computations affected by a change re-run.

Every value computes at most once per update, and effects never observe partially updated state.

<Callout variant="info"><p style="margin:0">The core package is a heavily modified fork of the excellent <strong>Alien Signals</strong> library.</p></Callout>

## Reactive Primitives

Reactive data starts with a [`signal`](/reference/core/signal) which holds a value, writing to it triggers an update.

A [`computed`](/reference/core/computed) function derives a new value from whatever signals it reads.

An [`effect`](/reference/core/effect) runs and re-runs whenever any signals it reads changes.

### Reactive State

Call a `signal` with no argument to read the current value, or call it with an argument to write a new one.

```typescript
import { signal } from '@hellajs/core';

const count = signal(0);

console.log(count()); // 0

count(5); // Write a new value

console.log(count()); // 5
```

New values are compared by reference. See [Objects and Arrays](#working-with-objects-and-arrays) for working with those data types.

### Derived Values

`computed` is a read-only function that derives its value from other signals, re-evaluating only when one of them changes. The getter runs lazily, on read, not every write. 

```typescript
import { signal, computed } from '@hellajs/core';

const count = signal(0);
const doubled = computed(() => count() * 2);

console.log(doubled()); // 0

count(5);

console.log(doubled()); // 10
```

### Side Effects

`effect` runs a function that re-runs whenever a `signal` it read changes. Dependencies are collected automatically on every run: whatever the function reads, it subscribes to.

```typescript
import { signal, computed, effect } from '@hellajs/core';

const count = signal(0);
const doubled = computed(() => count() * 2);

effect(() => {
  console.log(`Count: ${count()}, Doubled: ${doubled()}`);
});

count(5); // Logs: "Count: 5, Doubled: 10"
```

`effect` re-runs whenever a `signal` it read changes. Dependencies are collected automatically on every run, and whatever the function reads, it subscribes to.

## Objects and Arrays

Signals compare using reference equality. Mutating objects and arrays changes no reference, so nothing updates.

### Replace, Don't Mutate

Always replace the value with a new reference to trigger updates.

```typescript
import { signal } from '@hellajs/core';

const todos = signal([
  { id: 1, text: 'Learn HellaJS', done: false },
  { id: 2, text: 'Build an app', done: false },
]);

// ❌ Mutation does not trigger reactivity
todos().push({ id: 3, text: 'New todo', done: false }); // No update
todos()[0].done = true; // No update

// ✅ Replace with a new reference to trigger updates
todos([
  { id: 1, text: 'Learn HellaJS', done: true }, // done flipped
  { id: 2, text: 'Build an app', done: false },
]); // Updates: new array reference
```

### Signal Collections

Collection signals split the collection into one child `signal` per element: [`signalArray`](/reference/core/signalarray), [`signalMap`](/reference/core/signalmap), and [`signalSet`](/reference/core/signalset).

Writing one element wakes only that element's readers; structural operations (`push`, `splice`, adding keys) wake readers of the collection shape, without cloning anything.

```typescript
import { signalArray, effect } from '@hellajs/core';

const items = signalArray([1, 2, 3]);

// Tracks element 0, not the whole array
effect(() => console.log('First:', items.get(0))); // Initial run: "First: 1"

items.push(4); // "First: 1"; the shape changed, element 0 did not
items.set(0, 9); // "First: 9"; only index-0 readers wake
items([9, 2, 3, 4]); // Equal elements write nothing; nothing wakes
```

## Dependency Tracking

A dependency exists only when a `signal` is actually read, and the dependency set refreshes on every run.

### Conditional Dependencies

A `computed` that reads different signals on different branches tracks only what its last run actually read.

```typescript
import { signal, computed } from '@hellajs/core';

type Todo = {
  id: number;
  text: string;
  done: boolean;
};

const view = signal('counter');
const count = signal(0);
const todos = signal<Todo[]>([]);

const currentTitle = computed(() => {
  if (view() === 'counter') {
    // Tracks only count while the view is 'counter'
    return `Count: ${count()}`;
  }
  // Tracks only todos when the view is something else
  return `Todos: ${todos().length}`;
});

todos([...todos(), { id: 1, text: 'New todo', done: false }]);
// No update: currentTitle does not track todos yet

view('todos'); // Updates; now tracks todos, drops count

count(10); // No update: count is no longer a dependency
```

### Transformation Chains

A change to chained computeds propagates through every level, each level computing at most once.

```typescript
import { signal, computed } from '@hellajs/core';

const todos = signal([
  { id: 1, text: 'Learn HellaJS', done: false },
  { id: 2, text: 'Build an app', done: false },
  { id: 3, text: 'Write docs', done: true },
]);

const activeTodos = computed(() => todos().filter(todo => !todo.done));

const todoTotals = computed(() => ({
  total: todos().length,
  active: activeTodos().length,
}));

console.log(todoTotals()); // { total: 3, active: 2 }

todos([...todos(), { id: 4, text: 'New task', done: false }]);
console.log(todoTotals()); // { total: 4, active: 3 }: the whole chain updated
```

## How Effects Run

Effects are optimized to run only once per update, even if multiple dependencies change.

### Automatic Batching

All `signal` writes schedule one pass at the end of the current synchronous code. Consecutive writes batch together so every `effect` runs only once against the final state.

Reading a `signal` or `computed` always returns the freshest value, even before effects run.

```typescript
import { signal, computed, effect } from '@hellajs/core';

const count = signal(0);
const multiplier = signal(1);
const result = computed(() => count() * multiplier());

effect(() => console.log(`Result: ${result()}`)); // Initial run: "Result: 0"

count(10); // No log yet: effects wait for the batch
multiplier(3); // Batches into the same pass
console.log(result()); // 30: reads are never deferred
// The synchronous code ends, the batch runs: one log, "Result: 30"
```
### Glitch Free Updates

When one change reaches an `effect` through several paths, the `effect` still sees a single consistent update: each value computes once, and the `effect` runs once.

```typescript
import { signal, computed, effect } from '@hellajs/core';

const count = signal(1);
const doubled = computed(() => count() * 2);
const tripled = computed(() => count() * 3);

// Reads two derivations of the same signal
effect(() => console.log(`${doubled()} x ${tripled()}`)); // Initial run: "2 x 3"

count(2); // Logs: "4 x 6"
// Never a half-updated "4 x 3", and the effect runs once
// however many of its dependencies changed
```

### Draining Effects Early

When the next line needs the effects already run, reading a log written by an `effect`, or handing control to non-reactive code, call [`flush`](/reference/core/flush) to run the queued effects synchronously.

```typescript
import { signal, effect, flush } from '@hellajs/core';

const count = signal(0);
const runs: number[] = [];

effect(() => runs.push(count())); // Initial run: runs is [0]

count(5);
count(6);
console.log(runs); // [0]: both writes wait for the batch

flush(); // Runs the queued effects now
console.log(runs); // [0, 6]: one run, final value only
```

## Reducing Unnecessary Work

Every re-run costs. These patterns keep recomputation proportional to what actually changed.

### Fine-Grained Signals

Split independent concerns into separate signals so a change wakes only the readers of the value that changed.

```typescript
import { signal, computed } from '@hellajs/core';

// ❌ One signal for the whole object: any write dirties every reader
const counter = signal({ value: 0, max: 10, multiplier: 1 });
const displayText = computed(() => `Count: ${counter().value}`);
counter({ ...counter(), multiplier: 2 });
// displayText recomputes on its next read although value did not change

// ✅ One signal per independent value: readers wake only for what they read
const counterValue = signal(0);
const counterMultiplier = signal(1);
const display = computed(() => `Count: ${counterValue()}`);

counterMultiplier(2); // display does not recompute
counterValue(1); // display recomputes

console.log(display()); // "Count: 1"
```

### Custom Equality

Both `signal` and `computed` accept an optional `{ equals }` comparator that replaces the default reference check. An equal value skips the update entirely: the old reference is kept and nothing propagates.

```typescript
import { signal, effect } from '@hellajs/core';

const username = signal('ada', {
  equals: (previous, next) => previous.toLowerCase() === next.toLowerCase(),
});

effect(() => console.log('Username changed:', username())); // Initial run: "Username changed: ada"

username('ADA'); // Same name, different casing: effect does not re-run
```

### Untracked Reads

Read a `signal` inside [`untracked`](/reference/core/untracked) to use its value without subscribing to it.

```typescript
import { signal, computed, untracked } from '@hellajs/core';

const count = signal(0);
const multiplier = signal(10);

// Recomputes only when count changes: multiplier is untracked
const result = computed(() => count() * untracked(() => multiplier()));

count(5);
console.log(result()); // 50

multiplier(20);
// No recompute: multiplier is not a dependency
```

### Building on the Previous Value

The `computed` getter receives its previous result as an optional parameter, `undefined` on the first run.

```typescript
import { signal, computed } from '@hellajs/core';

const deposit = signal(100);
const balance = computed<number>((previous = 0) => previous + deposit());

console.log(balance()); // 100

deposit(50);
console.log(balance()); // 150: 50 added to the previous result

deposit(30);
console.log(balance()); // 180
```

## Handling Errors

An error thrown inside an `effect` aborts the current pass. The error surfaces at the caller of `flush`, or the scheduled pass when it runs on its own. Queued effects stay queued and the next `signal` change drains them again.

Catch expected failures with `try/catch` inside the `effect` so it keeps running. See [error propagation](/reference/core/effect#error-propagation) and [error recovery](/reference/core/computed#error-recovery) for the full usage rules.

```typescript
import { signal, effect } from '@hellajs/core';

const raw = signal('{"count":1}');

effect(() => {
  try {
    console.log('count:', JSON.parse(raw()).count);
  } catch {
    console.log('invalid JSON, skipped');
  }
});

raw('oops'); // Logs: "invalid JSON, skipped"; the effect survives, tracking preserved
raw('{"count":5}'); // Logs: "count: 5"
```

## Stopping Effects with scope

Effects keep running until disposed. [`scope`](/reference/core/scope) collects every `effect` created inside its callback and returns a cleanup that disposes them. See the `scope` reference for nested scopes, lazy scopes, and cleanup edge cases.

```typescript
import { signal, effect, scope } from '@hellajs/core';

const query = signal('');

const dispose = scope(() => {
  effect(() => console.log(`Query: ${query()}`));
  effect(() => console.log(`Results for: ${query()}`));
});

query('hella'); // Logs: "Query: hella" and "Results for: hella"

dispose(); // One call stops both effects
query('js'); // Nothing logged
```
