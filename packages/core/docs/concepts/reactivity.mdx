# Reactivity

HellaJS implements a directed acyclic graph where signals are sources, computed values are transforms, and effects are sinks. Updates propagate through the graph via depth-first traversal with glitch-free guarantees. Each node executes at most once per update cycle.

  <span>The core package is a heavily modified fork of the excellent Alien Signals library.</span>
</div>

## Reactive Primitives

### Signals - Reactive State

A [`signal`](/reference/core/signal) notifies dependent computations when its value changes.

```typescript
import { signal } from '@hellajs/core';

const count = signal(0);

console.log(count()); // 0

count(5); // Update value

console.log(count()); // 5
```

### Computed - Derived Values

A [`computed`](/reference/core/computed) signal derives its value from other signals.

```typescript
import { signal, computed } from '@hellajs/core';

const count = signal(0);
const doubled = computed(() => count() * 2);

console.log(doubled()); // 0

count(5);

console.log(doubled()); // 10
```

### Effects - Reactive Side Effects

An [`effect`](/reference/core/effect) runs when reactive dependencies change.

```typescript
import { signal, computed, effect } from '@hellajs/core';

const count = signal(0);
const doubled = computed(() => count() * 2);

// Effect automatically tracks dependencies
effect(() => {
  console.log(`Count: ${count()}, Doubled: ${doubled()}`);
});

count(5); // Logs: "Count: 5, Doubled: 10"
```

## Working with Complex Data

[`signal`](/reference/core/signal) and [`computed`](/reference/core/computed) use reference equality to detect changes in objects and arrays. Direct mutation does not trigger reactive updates; always replace the value with a new reference.

```typescript
import { signal } from '@hellajs/core';

const todos = signal([
  { id: 1, text: 'Learn HellaJS', done: false },
  { id: 2, text: 'Build an app', done: false }
]);

// ❌ Mutation doesn't trigger reactivity
todos().push({ id: 3, text: 'New todo', done: false }); // No reactive update
todos()[0].done = true;                                 // No reactive update

// ✅ Replace with new reference to trigger updates
todos([
  { id: 1, text: 'Learn HellaJS', done: false },
  { id: 2, text: 'Build an app', done: true }  // Changed done to true
]);  // Triggers update: new array reference
```

## Granular Collection Signals

[`signalArray`](/reference/core/signalarray), [`signalMap`](/reference/core/signalmap), and [`signalSet`](/reference/core/signalset) replace immutable spreads for collection state. Each element or key lives in its own child signal plus one structural version per container: a value write wakes only that element's readers, and an in-place structural operation (`push`, `splice`, `set.add`) wakes positional readers without cloning anything.

```typescript
import { signalArray, effect } from '@hellajs/core';

const items = signalArray([1, 2, 3]);

effect(() => console.log('First:', items.get(0))); // Logs: "First: 1"

items.push(4);   // Logs: "First: 1" - in-place structural op, positional readers wake
items.set(0, 9); // Logs: "First: 9" - only index-0 readers wake
items([9, 2, 3, 4]); // Reconcile: equal elements write nothing, nothing wakes
```

Each container is still a [`signal`](/reference/core/signal): calling it reads a fresh plain snapshot that tracks everything, and calling it with a collection reconciles element-wise. See the `signalArray`, `signalMap`, and `signalSet` reference pages for the full method surface and wake tables.

## Advanced Patterns

### Conditional Dependencies

A dependency is only established when a signal is actually read during execution. This means the dependency graph adjusts dynamically based on control flow.

```typescript
import { signal, computed } from '@hellajs/core';

type Todo = { id: number; text: string; done: boolean };

const view = signal('counter');
const count = signal(0);
const todos = signal<Todo[]>([]);

const currentTitle = computed(() => {
  if (view() === 'counter') {
    return `Count: ${count()}`;  // Only tracks count when view is 'counter'
  }
  return `Todos: ${todos().length}`;  // Only tracks todos when view is 'todos'
});

// Initially tracks count and view, not todos
todos([...todos(), { id: 1, text: 'New todo', done: false }]); // currentTitle doesn't update
view('todos'); // currentTitle updates, now tracks todos instead of count
count(10); // currentTitle doesn't update: count is no longer a dependency
```

### Transformation Chains

[`computed`](/reference/core/computed) values create pipelines that propagate changes through complex data flows.

```typescript
import { signal, computed } from '@hellajs/core';

const todos = signal([
  { id: 1, text: 'Learn HellaJS', done: false },
  { id: 2, text: 'Build an app', done: false },
  { id: 3, text: 'Write docs', done: true }
]);

const activeTodos = computed(() => todos().filter(t => !t.done));

const todoTotals = computed(() => ({
  total: todos().length,
  active: activeTodos().length,
}));

console.log(todoTotals()); // { total: 3, active: 2 }

todos([...todos(), { id: 4, text: 'New task', done: false }]);
console.log(todoTotals()); // { total: 4, active: 3 }: entire chain updates
```

## Optimization Strategies

### Batching Updates

Group multiple signal writes into a single execution with [`batch`](/reference/core/batch). Effects are deferred until the batch completes.

```typescript
import { signal, computed, effect, batch } from '@hellajs/core';

const count = signal(0);
const multiplier = signal(1);
const result = computed(() => count() * multiplier());

effect(() => {
  console.log(`Result: ${result()}`);
});

// Without batching: effect runs twice
count(5);        // Logs: "Result: 5"
multiplier(2);   // Logs: "Result: 10"

// With batching: effect runs once
batch(() => {
  count(10);     // No effect execution yet
  multiplier(3); // No effect execution yet
});              // Logs: "Result: 30"
```

### Fine-grained Updates

Separate independent concerns into individual [`signal`](/reference/core/signal) references to avoid unnecessary recomputation.

```typescript
import { signal, computed } from '@hellajs/core';

// ❌ Over-reactive: any property change updates everything
const counter = signal({ value: 0, max: 10, multiplier: 1 });
const displayText = computed(() => `Count: ${counter().value}`);
counter({ ...counter(), priority: 'medium' }); // displayText recomputes but returns same value: downstream effects not triggered

// ✅ Fine-grained: separate signals for independent concerns
const counterValue = signal(0);
const counterMax = signal(10);
const counterMultiplier = signal(1);

const display = computed(() => `Count: ${counterValue()}`);
counterMultiplier(2); // display unaffected
counterValue(1);      // display recalculates

console.log(display()); // "Count: 1"
```

### Custom Equality

Both [`signal`](/reference/core/signal) and [`computed`](/reference/core/computed) accept an optional `{ equals }` comparator that replaces the default reference check. An equal value skips the update entirely; the old reference is kept and nothing propagates.

```typescript
import { signal, effect } from '@hellajs/core';

const todos = signal([{ id: 1 }], {
  equals: (a, b) => a.length === b.length && a.every((t, i) => t.id === b[i]?.id)
});

effect(() => console.log('Todos changed:', todos()));

todos([{ id: 1 }]); // Content-equal by id: effect does not re-run
```

### Untracked Reads

Use [`untracked`](/reference/core/untracked) to read a [`signal`](/reference/core/signal) without establishing a dependency.

```typescript
import { signal, computed, untracked } from '@hellajs/core';

const count = signal(0);
const multiplier = signal(10);

// Only recomputes when count changes: multiplier is untracked
const result = computed(() => count() * untracked(() => multiplier()));

count(5);
console.log(result()); // 50

multiplier(20);
// result does not recompute: multiplier is not tracked
```

### Error Handling

Errors thrown inside an effect propagate to the signal setter that triggered them and abort the current flush; remaining queued effects are skipped, and the next signal change starts a fresh flush with no corrupted state. Catching errors with `try/catch` inside the effect preserves dependency tracking. See [error propagation](/reference/core/effect#error-propagation) for the effect rules and [error recovery](/reference/core/computed#error-recovery) for computed behavior.

### Previous Computed Value

A [`computed`](/reference/core/computed) function receives the previously computed value as an optional parameter, useful for incremental calculations. See the [`computed`](/reference/core/computed) reference for details.

### Lifecycle Management

Use [`scope`](/reference/core/scope) to group multiple effects and clean them up together: one `cleanup()` stops every effect created inside the scope. See the [`scope`](/reference/core/scope) reference for nested scopes, lazy scopes, and cleanup edge cases.
