# Reactivity

HellaJS implements a directed acyclic graph with glitch-free guarantees. Nodes executes at most once per update cycle, and effects never observe a half-updated state.

<Callout variant="info">The core package is a heavily modified fork of the excellent Alien Signals library.</Callout>

## Reactive Primitives

### Reactive State

A [`signal`](/reference/core/signal) notifies dependencies when its value changes.

```typescript
import { signal } from '@hellajs/core';

const count = signal(0);

console.log(count()); // 0

count(5); // Update value

console.log(count()); // 5
```

### Derived Values

A [`computed`](/reference/core/computed) signal derives its value from other signals.

```typescript
import { signal, computed } from '@hellajs/core';

const count = signal(0);
const doubled = computed(() => count() * 2);

console.log(doubled()); // 0

count(5);

console.log(doubled()); // 10
```

### Side Effects

An [`effect`](/reference/core/effect) runs when reactive dependencies change.

```typescript
import { signal, computed, effect } from '@hellajs/core';

const count = signal(0);
const doubled = computed(() => count() * 2);

// Effect automatically tracks dependencies
effect(() => {
  console.log(`Count: ${count()}, Doubled: ${doubled()}`);
});

count(5); // Logs: "Count: 5, Doubled: 10"
```

## Working with Complex Data

### Signal References

[`signal`](/reference/core/signal) and [`computed`](/reference/core/computed) use reference equality to detect changes in objects and arrays. Direct mutation does not trigger reactive updates; always replace the value with a new reference.

```typescript
import { signal } from '@hellajs/core';

const todos = signal([
  { id: 1, text: 'Learn HellaJS', done: false },
  { id: 2, text: 'Build an app', done: false }
]);

// ❌ Mutation doesn't trigger reactivity
todos().push({ id: 3, text: 'New todo', done: false }); // No reactive update
todos()[0].done = true; // No reactive update

// ✅ Replace with new reference to trigger updates
todos([
  { id: 1, text: 'Learn HellaJS', done: false },
  { id: 2, text: 'Build an app', done: true } // Changed done to true
]); // Triggers update: new array reference
```

### Signal Collections

[`signalArray`](/reference/core/signalarray), [`signalMap`](/reference/core/signalmap), and [`signalSet`](/reference/core/signalset) replace immutable spreads and each item lives in its own child signal. A value write wakes only that element's readers and in-place structural operations (`push`, `splice`, `set.add`) wakes positional readers without cloning anything.

```typescript
import { signalArray, effect } from '@hellajs/core';

const items = signalArray([1, 2, 3]);

effect(() => console.log('First:', items.get(0))); // Logs: "First: 1"

items.push(4); // Logs: "First: 1" - in-place structural op, positional readers wake
items.set(0, 9); // Logs: "First: 9" - only index-0 readers wake
items([9, 2, 3, 4]); // Reconcile: equal elements write nothing, nothing wakes
```

## Advanced Patterns

### Conditional Dependencies

A dependency is only established when a signal is actually read during execution.

```typescript
import { signal, computed } from '@hellajs/core';

type Todo = {
  id: number;
  text: string;
  done: boolean
};

const view = signal('counter');
const count = signal(0);
const todos = signal<Todo[]>([]);

const currentTitle = computed(() => {
  if (view() === 'counter') {
    return `Count: ${count()}`; // Only tracks count when view is 'counter'
  }
  return `Todos: ${todos().length}`; // Only tracks todos when view is 'todos'
});

// Initially tracks count and view, not todos
todos([...todos(), {
  id: 1,
  text: 'New todo',
  done: false
}]); // currentTitle doesn't update
view('todos'); // currentTitle updates, now tracks todos instead of count
count(10); // currentTitle doesn't update: count is no longer a dependency
```

### Transformation Chains

[`computed`](/reference/core/computed) values create pipelines that propagate changes through complex data flows.

```typescript
import { signal, computed } from '@hellajs/core';

const todos = signal([
  { id: 1, text: 'Learn HellaJS', done: false },
  { id: 2, text: 'Build an app', done: false },
  { id: 3, text: 'Write docs', done: true }
]);

const activeTodos = computed(() => todos().filter(t => !t.done));

const todoTotals = computed(() => ({
  total: todos().length,
  active: activeTodos().length,
}));

console.log(todoTotals()); // { total: 3, active: 2 }

todos([...todos(), { id: 4, text: 'New task', done: false }]);
console.log(todoTotals()); // { total: 4, active: 3 }: entire chain updates
```

## Optimization Strategies

### Effect Timing

Signal writes defer effects to the next microtask. Consecutive synchronous writes coalesce, and every effect runs once against final state. Signals always observe the freshest value, even between write and drain.

```typescript
import { signal, computed, effect } from '@hellajs/core';

const count = signal(0);
const multiplier = signal(1);
const result = computed(() => count() * multiplier());

effect(() => console.log(`Result: ${result()}`)); // Initial run: "Result: 0"

count(10); // No effect run yet: the drain is scheduled
multiplier(3); // Coalesced into the same pass
console.log(result()); // 30: reads are synchronous
// Script ends, the boundary fires: one run logs "Result: 30"
```

When the next line needs the effects already run (checking a log after an update, handing control to non-reactive code), call [`flush`](/reference/core/flush) to drain synchronously:

```typescript
import { signal, effect, flush } from '@hellajs/core';

const count = signal(0);
const runs: number[] = [];

effect(() => runs.push(count())); // Initial run: runs is [0]

count(5);
count(6);
console.log(runs); // [0]: both writes wait for the drain

flush(); // Drains now, ahead of the microtask
console.log(runs); // [0, 6]: one run for both writes, final state only
```

### Fine-grained Updates

Separate independent concerns into individual [`signal`](/reference/core/signal) references to avoid unnecessary recomputation.

```typescript
import { signal, computed } from '@hellajs/core';

// ❌ Over-reactive: any property change updates everything
const counter = signal({ value: 0, max: 10, multiplier: 1 });
const displayText = computed(() => `Count: ${counter().value}`);
counter({ ...counter(), priority: 'medium' }); // displayText recomputes but returns same value: downstream effects not triggered

// ✅ Fine-grained: separate signals for independent concerns
const counterValue = signal(0);
const counterMax = signal(10);
const counterMultiplier = signal(1);

const display = computed(() => `Count: ${counterValue()}`);
counterMultiplier(2); // display unaffected
counterValue(1); // display recalculates

console.log(display()); // "Count: 1"
```

### Custom Equality

Both [`signal`](/reference/core/signal) and [`computed`](/reference/core/computed) accept an optional `{ equals }` comparator that replaces the default reference check. An equal value skips the update entirely; the old reference is kept and nothing propagates.

```typescript
import { signal, effect } from '@hellajs/core';

const username = signal('ada', {
  equals: (previous, next) => previous.toLowerCase() === next.toLowerCase()
});

effect(() => console.log('Username changed:', username()));

username('ADA'); // Same name, different casing: effect does not re-run
```

### Untracked Reads

Use [`untracked`](/reference/core/untracked) to read a [`signal`](/reference/core/signal) without establishing a dependency.

```typescript
import { signal, computed, untracked } from '@hellajs/core';

const count = signal(0);
const multiplier = signal(10);

// Only recomputes when count changes: multiplier is untracked
const result = computed(() => count() * untracked(() => multiplier()));

count(5);
console.log(result()); // 50

multiplier(20);
// result does not recompute: multiplier is not tracked
```

### Error Handling

An error thrown inside an [`effect`](/reference/core/effect) aborts the current drain and surfaces at the [`flush`](/reference/core/flush) caller or from the scheduled drain. Queued effects stay queued, and the next signal change starts a fresh drain.

Catch expected failures with `try/catch` inside the effect so it keeps running. See [error propagation](/reference/core/effect#error-propagation) and [error recovery](/reference/core/computed#error-recovery) for the full rules.

```typescript
import { signal, effect } from '@hellajs/core';

const raw = signal('{"count":1}');

effect(() => {
  try {
    console.log('count:', JSON.parse(raw()).count);
  } catch {
    console.log('invalid JSON, skipped');
  }
});

raw('oops'); // Logs: "invalid JSON, skipped" - the effect survives, tracking preserved
raw('{"count":5}'); // Logs: "count: 5"
```

### Previous Computed Value

A [`computed`](/reference/core/computed) function receives its previous result as an optional parameter (`undefined` on the first run), so an incremental calculation can build on the last result instead of re-deriving it.

```typescript
import { signal, computed } from '@hellajs/core';

const deposit = signal(100);
const balance = computed<number>((previous = 0) => previous + deposit());

console.log(balance()); // 100

deposit(50);
console.log(balance()); // 150: 50 added to the previous result

deposit(30);
console.log(balance()); // 180
```

### Lifecycle Management

Use [`scope`](/reference/core/scope) to stop many effects with one call: the returned cleanup disposes every effect created inside the scope callback. See the [`scope`](/reference/core/scope) reference for nested scopes, lazy scopes, and cleanup edge cases.

```typescript
import { signal, effect, scope } from '@hellajs/core';

const query = signal('');

const dispose = scope(() => {
  effect(() => console.log(`Query: ${query()}`));
  effect(() => console.log(`Results for: ${query()}`));
});

query('hella'); // Logs: "Query: hella" and "Results for: hella"

dispose(); // One call stops both effects
query('js'); // Nothing logged
```
