# Why

This convention was re-derived from scratch during an SSR-examples planning run, then corrected the
same day when a worker followed the entry's own (wrong) verification advice and shipped an example
with stray `file:` deps. It governs three classes of future rework on `examples/`:

1. **Wrong "broken" finding** — an audit/critic run greps an example, sees `import "@hellajs/dom"`
   with no matching package.json entry + empty `node_modules/@hellajs`, and flags it as a broken
   dependency. It is not broken; it resolves via root walk-up (see Evidence). (Contrast memory 022:
   dom's test import of `@hellajs/ssr` is a test-only cross-package dep with no clean home under the
   all-peerDeps convention — a different shape. Examples are apps/consumers; the install step lives
   in the tutorial, not package.json.)
2. **Wrong "fix"** — a worker "helpfully" adds `@hellajs/*` to an example's `dependencies` to make
   it runnable. That diverges from all the other examples and creates an inconsistent example. (This
   happened: `bun add @hellajs/*@file:../../packages/*` wrote `file:` deps into
   `examples/ssr-islands/package.json`; the deletion of node_modules/bun.lock did NOT revert them,
   so the committed example diverged until caught.) The fix is the tutorial's install line, not the
   committed package.json.
3. **Wrong verification method (CORRECTED)** — the prior version of this entry advised "verify
   runtime via a local uncommitted `bun add` + restore." That advice IS the trap: `bun add` installs
   into the example's own `node_modules`, which (a) shadows the root symlinks with stale npm
   versions — `dom@1.4.2` predates `$ref`, `css@1.1.1` predates the server-safe `css()` return, so
   the example then looks like it depends on unpublished features; and (b) mutates `package.json`
   with `file:`/version deps that survive a `node_modules`/`bun.lock` deletion and must be reverted
   separately. The correct verification is to just RUN the example — `bun src/server.js` resolves
   `@hellajs/*` from root with no install at all (current source).

The boundary vs memory 023 (packages/* all-peerDeps, zero devDeps): 023 is about *library* packages;
examples are *apps*. Apps would normally declare their runtime deps — the examples convention
deliberately does not, offloading install to the tutorial and relying on root walk-up in-repo. Do
not collapse the two.

# Evidence

- `examples/{blog,counter,todo,theme-switcher,ssr-islands,ssr-routing,ssr-streaming}/package.json`: `dependencies: null`; bench is the exception (`dependencies` holds rollup build tooling) but still no @hellajs/* entry.
  devDeps are typescript/vite only (ssr-islands: typescript only — it bundles the client with
  `Bun.build`, no Vite).
- ROOT `node_modules/@hellajs/*` ARE symlinks → `packages/*`, created by the root `bun install`
  (root `workspaces` = `["packages/*","plugins/*"]`): `ls -la node_modules/@hellajs/` →
  `dom -> ../../packages/dom`, `ssr -> ../../packages/ssr`, `core`, `css`, `router`, `store`,
  `resource`, `ui`. `examples/` is NOT a workspace, but Node/Bun resolution walks UP from
  `examples/<x>/src` → `examples/<x>/node_modules` (no @hellajs) → … → root `node_modules/@hellajs/*`
  (found). So an empty `examples/<x>/node_modules/@hellajs` is normal, not broken.
- PROVEN run with zero local install (2026-07-28): `cd examples/ssr-islands && bun src/server.js`
  with NO `node_modules` and NO deps in `package.json` → `curl -s localhost:3000` returns the
  server-rendered HTML (`<span id="count">0</span>` + empty `#slot`); `/client.js` HTTP 200.
  `@hellajs/{core,dom,ssr,css}` all resolved from root.
- The shadowing trap (confirmed): `bun add @hellajs/*@file:../../packages/*` into the example
  installed local copies that shadowed root; once removed (node_modules deleted + package.json
  reverted to no-deps), the example ran cleanly via root hoisting. The npm-installed `css@1.1.1`
  had crashed server-side (`document is not defined` — predates the `!hasDocument()` guard at
  css.ts:37) and `dom@1.4.2`'s bundle omitted `$ref` — both false signals that vanished under root
  hoisting.

Re-verify before trusting if an example's package.json gains a `dependencies` field or the root
workspaces field grows an `examples/*` glob — either would flip this convention.
