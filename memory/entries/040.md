# Why

The comparison skill's Step 3 says "Use WebFetch" for competitor facts. This session (core-comparison rewrite) `api.bundlephobia.com` returned empty for every package and no WebFetch tool was available in the harness — the documented path can dead-end mid-skill. The npm registry itself was reachable via `curl`: version metadata from `https://registry.npmjs.org/<pkg>/latest` (jq-extractable), and full published source from the `dist.tarball` URL (`https://registry.npmjs.org/<pkg>/-/<name>-<version>.tgz`, scoped packages URL-encode as `@scope%2Fname`). Tarballs beat docs pages for the skill's purpose: every claim lands on the exact shipped code (e.g. Solid's array-based `sources`/`observers` in `dist/solid.js`, Angular's `producer`/`consumer` graph in `fesm2022/_effect-chunk.mjs`, Svelte's `reactions`/version counters in `src/internal/client/reactivity/`), which is what "every competitor claim cites a fetched source" actually wants. Dependency facts (`dependencies`, `peerDependencies`) come straight from the tarball's `package.json` — no third-party API needed.

# Evidence

Verified 2026-08-21 generating `packages/core/core-comparison.md`: Bundlephobia returned empty bodies for all seven queried packages; tarball download + read succeeded for `solid-js@1.9.15`, `@vue/reactivity@3.5.41`, `@vue/runtime-core@3.5.41`, `svelte@5.56.10`, `@angular/core@22.1.3`, `react@19.2.8`, `react-dom@19.2.8`. Gotchas confirmed on the same run: scoped-package tarball URLs must be URL-encoded (`@vue%2Freactivity`) or curl 404s; extract into a scratch dir inside the repo and `rm -rf` it after — an earlier scratch dir vanished when named `.tmp-comparison` (dot-prefixed), the non-dot `tmp-comparison` survived. Tarballs carry no install step — read `dist/`, `fesm2022/`, `src/` directly.
