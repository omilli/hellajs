# Why

core's own AGENTS.md scopes its responsibility to "Reactive primitives over a doubly-linked dependency DAG," so a critic (or reviewer) seeing `isFunction`, `isPlainObject`, `hasNavigator`, etc. in `lib/index.ts` will reflexively flag it as responsibility drift / god-package coupling. It is not. `guides/code.md:35` explicitly blesses the pattern — "Barrel re-export from internal/ (utils, env) → stays in `lib/internal/`, re-exported by `index.ts`" — and `:94d` lists "cross-package foundation — re-exported via an `internal/core.ts` barrel to other packages" as a valid criterion for promoting an internal helper to `lib/internal/`. All six sibling packages consume these helpers (every css/dom/router/store/resource `lib/internal/core.ts` shim re-exports them from `@hellajs/core`).

Under the bundle model (see entry 001), each consuming package bundles `@hellajs/core` wholesale; the util/env code rides along inside that bundle at zero extra dependency cost. So the "every package takes a core dep for `isString`" coupling argument is a misread — there is no separate runtime dependency to add. A `brain-critic` run on `packages/core/lib/` did raise this as a candidate Major finding and correctly dropped it after checking the guide; recording the verdict here so the next run skips the detour.

# Evidence

- `guides/code.md:35` — "Barrel re-export from internal/ (utils, env) → stays in `lib/internal/`, re-exported by `index.ts`."
- `guides/code.md:94` criterion (d) — "cross-package foundation — re-exported via an `internal/core.ts` barrel to other packages."
- `packages/core/lib/index.ts:11-23` — exports `flush`, the type guards, and the env probes as the sanctioned shared surface.
- Grep across `packages/**` + `plugins/**` (dist excluded): `isFunction`/`isPlainObject`/`hasWindow`/`hasDocument`/`hasNavigator` are imported by css, dom, router, store, resource — each via its own `lib/internal/core.ts` shim.
- Bundle model: see `memory/entries/001.md` — consuming packages bundle `@hellajs/core` wholesale; the `internal/core.ts` shim dedupes the resulting esbuild imports.
- Counter-example that proves the gate still bites: `isUndefined` had zero external consumers, so it was dropped from the barrel this run (kept internally for `isFalsy`). The kernel pattern sanctions *shared* helpers, not unused ones.
