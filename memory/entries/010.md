# Why

> **⚠ RESOLVED 2026-07-11** by the marker rework (entry 013). `ssr()` now bounds every reactive value in its own `<!--[-->…<!--]-->` region, so adjacent text no longer coalesces and `hydrate` adopts regions directly — no rebuild. The marker-free behavior below is historical.

The design doc asserted `ssr()` output is "already hydration-compatible." It is NOT, unconditionally: the two backends produce different DOM structures whenever reactive text is adjacent to static text without an element boundary between them. Any future SSR or hydration work that assumes the contract holds everywhere will ship incorrect hydration (duplicated or orphaned nodes). Recalling this prevents re-deriving it (it took an empirical probe mid-build to catch).

The contract holds for: tag names, attribute names/values/order, and **element-bounded** structure (elements don't coalesce). It breaks for: reactive text adjacent to static text (the server merges them into one node; the client can't split it without rebuilding).

# Evidence

Measured against the `dist/` bundles (2026-07-10), same template:

| Template | `ssr()` parsed DOM | `mount()` DOM |
|---|---|---|
| `a${sig}b` | 1 node: `TEXT("axb")` | 4 nodes: `TEXT("a"),TEXT("x"),TEXT(""),TEXT("b")` |
| `before${false}${null}after` | 1 node: `TEXT("beforeafter")` | 2 nodes |
| `<span>s</span>${sig}` | 2 nodes: `SPAN, TEXT("x")` | 3 nodes (element-bounded → matches, modulo the anchor) |

- `packages/ssr/lib/ssr.ts` `walkChildren` concatenates `walkChild` results (no separator) — the coalescing cause.
- `packages/dom/lib/internal/render.ts` `appendToParent` appends a separate `createTextNode` per string child + a persistent `createTextNode("")` anchor per reactive child — the separation cause.
- hydrate resolution: `packages/dom/lib/internal/hydrate.ts` `hydrateSequence` groups consecutive static-text + reactive-text children into an element-bounded "text run"; a run with any reactive child has its one merged server text node removed and is re-mounted fresh (`mountRunBefore`/`mountReactiveAt`); all-static runs consume the one text node. Element-resolving reactive children break the run and are rebuilt individually.
