# Why

Memory 033 shipped progressive *content* reveal ($hs inline swaps) but left α-style per-segment *interactivity* as "the gap": a region whose stage hadn't arrived when hydrate ran immediately degraded to client-side re-suspension — re-running the async work and discarding the server's pending content, and any click on the fallback was lost. This closes the gap React-19-style: hydrate what's present, adopt late regions when their content lands, replay events that hit un-hydrated regions.

Design decisions (each rejected an alternative):

1. **Defer gate `readyState === "loading"`, not `!== "complete"`** — only a script parsed mid-document can still receive later stages; once parsing completes nothing more arrives. The `!== "complete"` form was falsified by the test env being `"interactive"` (memory 076) — it would defer in every test run and break the ssr degrade contract. `complete` keeps the unchanged `stageMissing` degrade path (back-compat for end-of-stream scripts and every pre-existing test).
2. **Observer-based detection, not a `$hs` callback** — one mechanism (container `MutationObserver` → `recheckDeferredRegions`) covers both the scripted `$hs` swap and the raw `<template>` arrival (tests/HappyDOM); zero coupling into `@hellajs/ssr`, which shipped no code change.
3. **Positional replay, not original-target re-dispatch** — a click's original target may be inside the swapped-out fallback, i.e. detached; a detached node's re-dispatched event can never reach the delegated body listener where HellaJS handlers live. So: original target if still connected, else the adopted node at the same top-level index (subtree-root mapping via the region's recorded nodes), else the entry is dropped. First-cut React shape, honestly scoped: synthesized re-dispatch (no coordinate fidelity), no dedup against natively re-fired events, buffer discarded on adoption.
