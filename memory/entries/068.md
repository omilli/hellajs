# Why

Same root cause as 019 (about:blank document URL) but a different actionable surface: 019 covers `replaceState`-can't-seed-`/` at init (→ mockClear/notFound-count guidance); this entry covers that `pushState` is equally a no-op for `pathname`, which kills any test that simulates browser back/forward. A test doing `history.pushState(null, "", "/about"); window.dispatchEvent(new Event("popstate"))` against a `blank` document URL makes the router's popstate handler resolve the literal path `"blank"` — guards never run, `notFound` commits instead, and assertions on the pop target fail (`route().path === "blank"`). Assigning `window.location.href = "http://localhost/"` first (save orig in `beforeEach`, restore in `afterEach` — guards.test.ts pattern) gives the document a real URL; from then on pushState/replaceState move `pathname` normally and pop simulations behave. Side effect to remember: with a real `/` URL, `router()` init now MATCHES `/` instead of resolving `"blank"`, so a `navigate("/")` first-step becomes a `from === to` no-op (scroll/early-return surfaces) — order first-navigations to a different path (scroll.test.ts reordered two existing tests for exactly this).

# Evidence

Probed 2026-08-31 in the 07-popstate-scroll run: bare `GlobalRegistrator.register()` + `history.replaceState({}, "", "/")` + `pushState(null, "", "/about")` → `window.location.pathname` stays `"blank"` after each (same under the `bun test` preload). Failed cycle: scroll.test.ts "custom scroll fn receives null on push and the saved position on back" received `backTo === "blank"`; fixed by the href beforeEach pattern → `bun coverage router` 234 pass / 0 fail. guards.test.ts:259-291 is the original href-pattern precedent.
