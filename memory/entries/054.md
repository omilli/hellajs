# Why

User decision 2026-08-27: A–Z was rejected for the API reference — sections are small (≤19 entries), the primary exports (signal, mount, css, router, resource, ssr) are what users scan for, and Vue/Solid references are curated-grouped too. The match target is the per-package `docs/index.mdx` "### API" list because that is what `docs/src/pages/reference/index.mdx` actually renders (it imports `@{pkg}/index.mdx`); the sidebar must land on the page it mirrors. Package-level order (core, dom, css, store, router, resource, ssr) is usefulness order and already matches the reference page's section order.

History: nav.ts had drifted into a half-finished alphabetical mix that disagreed with every rendered index list (e.g. `resetresource` listed first, `router` last, dom prefixes e:/error:/hook:/on: instead of on:-first) — the drift itself was the reported problem. User correction same session: `component` is low-level and sits directly above `registry`, forming a low-level tier ($ref, $collection, component, registry) at the bottom of the dom list — not third position.

Learn section analog: Patterns group order mirrors the Concepts pedagogical order (rendering track, then app track: State, Routing, Resources, then advanced, SSR, Hydration) — Concepts has Styling before State, so Patterns must too (nav.ts group + learn/index.mdx enumeration + learn/patterns/index.mdx cards all swap together).
