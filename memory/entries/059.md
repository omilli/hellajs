# Why

A coverage reading is a point-in-time snapshot of `dist/`; attributing a delta (e.g. new uncovered lines) to your edit requires measuring the pre-change state. Mid-plan worktrees typically carry whole uncommitted feature units (this repo's plans land that way), so `git checkout -- <file>` reverts to a HEAD that **never was** the baseline — it silently strips the user's in-flight changes, can break unrelated untracked tests against the stale HEAD build, and any measurement from it is wrong. The worker's read-before-write rule guarantees the true pre-edit content exists in-session: reconstruct from it.

Method: `cp` the edited file to a backup → write the pre-edit content back → `bun bundle <package>` (explicit rebuild honors the no-stale-dist rule) → `bun test packages/<package>/tests --coverage` (the command coverage runs internally) → restore the backup → rebuild. The pre/post uncovered-line sets give exact delta arithmetic (this session: baseline 1 uncovered line, post-fix 2 — proving the new uncovered line is the one added line, not a regression elsewhere).

Bonus: the reconstructed pre-fix bundle failing exactly the new regression tests is direct proof the tests pin the bug rather than a tautology.
