# Why

The marker-free cursor-walk hydration (the original v1 design) carried a recurring complexity tax that surfaced as concrete bugs under audit: the coalescing rebuild (010), the isDynamic-resolved adoption limit (012), undiagnosable ForEach count divergence, and ~120 lines of bug-prone structural inference in `internal/hydrate.ts`. Verified against source that every major framework emits comment markers (Vue confirmed this session: `vuejs/core` `packages/server-renderer/src/render.ts` emits `<!--[-->`/`<!--]-->`/`<!---->`). Adopted Vue-style markers and reverted the walk.

# Evidence

- `packages/ssr/lib/ssr.ts`: `MARK_OPEN`/`MARK_CLOSE` constants; `walkChild` wraps every dynamic region (reactive + isDynamic + nested fragment) in `<!--[-->…<!--]-->`; `renderDynamic` (shared by direct-isDynamic and reactive-resolved-isDynamic dispatch) fixes the C1 adoption limit at the source.
- `packages/dom/lib/internal/hydrate.ts`: marker-reader `hydrateSequence` (`isMarkOpen`/`gatherRegion`/`consumeRegion`); `mountRunBefore`/`mountReactiveAt`/count-gather DELETED; `adoptReactiveRegion` adopts text/element regions on first run (isDynamic-resolved regions always run so the component registers its effects); `HydrateCtx` stack retained for the walker→ForEach/Transition adoption handoff.
- `ForEach.ts`: count-strict adoption (`existingNodes.length === arr.length` else warn + fresh rebuild) — count divergence is now detected, not silent.
- Verified: `bun coverage ssr` (33/33, 100%), `bun coverage dom` (302/302), `bun visibility` clean. The ssr→hydrate integration test passes, including the C1 case end-to-end.
- **Resolves 010** (coalescing — eliminated; each reactive value is its own bounded region, no rebuild) and **012** (isDynamic-resolved adoption limit — `renderDynamic` + `adoptReactiveRegion`'s Proxy branch handle it).
- **Breaking:** `ssr()` output now contains markers; `hydrate()` requires marker-bearing server HTML (generate it with `ssr()`, don't hand-build). Major bump for `@hellajs/ssr` + `@hellajs/dom`.
