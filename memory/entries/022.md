> **Naming superseded 2026-08-22 (entry 045):** `ssrAsync`→`ssr.async`, `ssrStream`→`ssr.stream`, `docStream`→`doc` (stream overload) — the old names below are the pre-v2 API, kept for history.

# Why

011 framed the undeclared `@hellajs/ssr` import as a "residual undeclared devDep" inviting a fix. On 2026-07-17 a plan to declare it hit the worker, which discovered the monorepo convention: every `packages/*` declares cross-pkg HellaJS deps ONLY as `peerDependencies` with caret ranges, and `devDependencies` are `null` across the board (`dependencies` is null too except css → csstype, a legitimate runtime dep whose CSS.Properties flows into the public `.d.ts` — see 023). So "mirror the sibling convention" for a new cross-pkg dep means a peerDependency with a caret — NOT a `devDependency` or `workspace:*`.

But `@hellajs/ssr` is a TEST-only dep of dom (hydrate/streaming tests need real `ssr()`/`ssrStream()` output). Declaring it a `peerDependency` is semantically wrong — it tells every dom consumer to install ssr (a server package); dom is client-side and never imports ssr at runtime. Declaring it a `devDependency` would be semantically correct but the first `devDependencies` entry in the monorepo, breaking the all-peer uniformity. Neither option is clean; the user chose to leave it undocumented, accepting that the only cost is publish-hygiene (an out-of-workspace clean install wouldn't resolve the test import — but consumers don't run dom's tests, and in-repo `bun install` links the workspace so `bun coverage dom` is green). Future audits should NOT re-flag this as a finding — it is a reviewed, accepted state.

# Evidence

- `jq '{dependencies,devDependencies,peerDependencies}' packages/dom/package.json` (2026-07-17) → `dependencies: null`, `devDependencies: null`, `peerDependencies: {"@hellajs/core":"^1.0.6"}`. No ssr dep declared.
- Convention check (2026-07-17): `jq .devDependencies packages/*/package.json` → `null` for every package; cross-pkg deps appear only under `peerDependencies` (ssr→dom `^1.4.2`; dom/router/css/store/resource→core `^1.0.6`).
- `packages/dom/tests/helpers.ts` + `tests/ssr-meta.test.ts` import `@hellajs/ssr/bundle`; `bun coverage dom` → 317 pass / 0 fail (workspace-linked resolution).
- User decision (2026-07-17): chose "Leave as-is (undocumented)" over devDep / optional-peer alternatives.
