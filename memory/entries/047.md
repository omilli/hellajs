# Why

`delegatedHandler` (`packages/dom/lib/internal/events.ts`) halts its `composedPath()` walk on `event.cancelBubble`. Per the DOM spec, the `cancelBubble` getter reflects the stop-propagation flag, which BOTH `stopPropagation()` and `stopImmediatePropagation()` set — so in real browsers either call halts the walk (Solid relies on the same check). HappyDOM implements only the spec's `stopPropagation` → `cancelBubble` aliasing; `stopImmediatePropagation()` sets its own immediate flag without flipping `cancelBubble`. A test whose handler calls only `stopImmediatePropagation()` therefore sees the delegated walk continue (ancestor handlers fire) — a green-in-browser behavior fails only under HappyDOM. The shipped `delegated-events.test.ts` stop-immediate test calls both methods with a why-comment; keep that shape.

# Evidence

Verified 2026-08-21 empirically under `utils/happydom.js` preload: `new MouseEvent("click")` → `stopImmediatePropagation()` → `cancelBubble === false`; → `stopPropagation()` → `cancelBubble === true`. The stop-immediate test failed (`backdropHandler` called) with the single call, passed with both; `bun coverage dom` exit 0 (360 pass).
