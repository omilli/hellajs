# Why

Extends memory 026 (examples resolve `@hellajs/*` via root node_modules symlinks). The resolution
TARGET is `packages/*/dist`, not `lib/`:

- Root `node_modules/@hellajs/*` → `packages/*`, and every package's `package.json` declares
  `"main": "./dist/index.js"` — an example bundler (rollup) bundles the BUILT ARTIFACTS.
- `dist` is gitignored (root `.gitignore`, `# output` section) → `git checkout <ref>` (and `git
  stash`) never touches it; nothing invalidates it on ref switch.
- Consequence: any workflow that switches refs and builds an example — perf A/B, bisect, stale-build
  debugging — silently bundles the PREVIOUS ref's dist unless a root `bun bundle` runs first, in each
  checkout. The measurement/build looks valid; the code under test is not.

Caught while planning the internal bench harness: the original stash-based `--base` design rebuilt
neither arm's packages, so both arms would have measured pre-stash dist. The harness now runs
`bun bundle` (no package arg → `buildAllPackagesFromOrder` rebuilds every package) before the example
build on every run; the manual checkout A/B protocol relies on the same step.

# Evidence

- `packages/dom/package.json`: `"main": "./dist/index.js"` (same shape across all packages).
- Root `.gitignore`: `dist` under `# output`.
- `examples/bench/package.json`: rollup scripts emit `examples/bench/dist/main.js` from `@hellajs/*`
  imports (resolved via memory-026 walk-up to root symlinks).
- `scripts/bundle.ts`: no-package-arg mode → `buildAllPackagesFromOrder` rebuilds all
  `packages/*/dist` in dependency order.

Re-verify before trusting if a package's `main`/`exports` starts pointing at `lib/` source, or if
the bundler switches to source resolution (tsconfig paths / rollup aliasing into `lib/`).
