# Why

> **⚠ RESOLVED 2026-07-11** by the marker rework (entry 013). `renderDynamic` (ssr) now dispatches a reactive getter that resolves to an isDynamic component, and `adoptReactiveRegion`'s Proxy branch handles it on hydrate — the input is now supported end-to-end. The "unsupported" claim below is historical.

The marker-free cursor-walk hydration design matches server DOM to the AST by structural position. It adopts element-bounded regions reliably (a direct ForEach child, an element-resolving signal) but has no mechanism for a reactive getter that returns a **bare isDynamic `RenderFn`**:

- **`ssr` has no DOM.** `walkChild` resolves a non-dynamic function child; if the value is an isDynamic `RenderFn` (not an object with `tag`), it falls through to `escapeText(\`${resolved}\`)` → the function's source as text. The server ships garbage, not adoptable nodes.
- **`hydrate` cannot adopt what the server never rendered.** `mountReactiveAt` has no isDynamic-resolved branch; `resolveNode` treats the fn as a text signal and crashes (`fn(undefined)` → `undefined.appendChild`).
- **The obvious fix is net-negative.** Mirroring `appendToParent`'s `Proxy` parent branch (`render.ts:198-215`) into `mountReactiveAt` was traced and rejected: on hydrate, `clearRenderedNodes` starts empty so server items are NOT removed, then the Proxy mounts fresh items before them → duplication (fresh + stale). Worse than the current error-dispatch.

This is an instance of the broader marker-free adoption limit (entry 010 is the coalesced-text instance): regions whose boundaries are not element-delimited cannot be reliably matched without hydration markers, which the design rejects. The supported forms — `<${ForEach} .../>` as a direct child, or `() => show() ? html\`<ul>…\` : null` (wrapped in a HellaNode) — work because `walkChild` recurses into a real node with element boundaries.

# Evidence

- `packages/ssr/lib/ssr.ts` `walkChild`: a non-dynamic function child resolves via `resolveValue`; an isDynamic `RenderFn` result has no `tag`, so it is stringified, not rendered.
- `packages/dom/lib/internal/render.ts:198-215` (`appendToParent`): the mount path's `Proxy`-parent branch is the ONLY path that renders a bare isDynamic return correctly, and it requires a live DOM parent.
- `packages/dom/lib/internal/hydrate.ts` `mountReactiveAt`: no isDynamic-resolved branch; `resolveNode` mis-handles the fn.
