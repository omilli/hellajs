> **Naming superseded 2026-08-22 (entry 045):** `ssrAsync`→`ssr.async`, `ssrStream`→`ssr.stream`, `docStream`→`doc` (stream overload) — the old names below are the pre-v2 API, kept for history.

# Why

The SSR walkers have TWO array-classification paths that must each handle arrays independently:

1. **Direct child** (`walkChild`/`walkChildGen` top-level guard) — memory 028: JSX compiles
   `<Comp>{child}</Comp>` to `children: [child]` (an array). Fixed by `if (Array.isArray(child))`.
2. **Resolved getter** (inside the `typeof child === "function"` branch, after `resolveValue`/
   `resolveAsync`) — THIS concept. A non-dynamic function child is resolved and reclassified; if it
   returns a HellaNode[] the resolved-value classification must walk each, not stringify.

The `.map()` idiom (`<ul>{items.map(t => <li>{t}</li>)}</ul>`) compiles to `children: [() => items.map(...)]`
— a getter returning a HellaNode[] (babel and the `html\`\`` parser emit the same shape for an element
child). Before the fix, the resolved-value classification only recursed when `resolved.tag !== undefined`;
an array has no `.tag`, so it hit the escape branch → `` `${[node, node, node]}` `` →
`[object Object],[object Object],...`. The DOM client rendered the identical node correctly because
`resolveNode` (`packages/dom/lib/internal/render.ts`) checks `Array.isArray` FIRST and mounts each into a
DocumentFragment — so this was a silent client/server divergence: `.map()` worked on the client, emitted
`[object Object]` in `ssr`/`ssrAsync`/`ssrStream`. A `<Suspense>`-streamed card using `.map()` thus shipped
broken markup under a green build (no test asserted on it — see memory 034's generalization).

`ForEach` sidesteps it (its SSR dispatch iterates `use(item)` per element), but `.map()` is a legitimately
supported pattern on the client; the fix restores parity. Recall this before editing the SSR walkers'
resolved-value classification, before assuming `.map()` is unsupported, or when chasing `[object Object]`
in streamed/ssr output. Generalizes memory 034 (hydrate tests must scan for stringification artifacts) to
the serializer itself: every resolved-value path must mirror dom's `resolveNode` array handling.

# Evidence

- `packages/ssr/lib/internal/walk.ts` `walkChildGen` — added `else if (Array.isArray(resolved)) { yield*
  walkChildrenGen(resolved, pending); }` inside the function-child branch, before the `resolved.tag` check.
- `packages/ssr/lib/ssr.ts` `walkChild` — mirrored `else if (Array.isArray(resolved)) { body =
  walkChildren(resolved); }` (parity invariant between sync/async walkers, enforced by ssr-async +
  ssr-stream `test.each(parityCases)`).
- `packages/ssr/tests/helpers.ts` — new `parityCase` "reactive getter returning an array of nodes"
  (`html\`<ul>${() => [1,2,3].map(n => html\`<li>${n}</li>\`)}\``), shared by both async parity suites.
- `packages/ssr/tests/ssr.test.ts` — direct assertion, byte-identical to the ForEach case:
  `<ul><!--[--><li>1</li><li>2</li><li>3</li><!--]--></ul>`.
- `packages/ssr/AGENTS.md` §"The walk" — reactive-child line updated to record the array sub-case.
- `bun coverage ssr` → 145 pass, 100% lines; lint green (tsc + eslint + 4 guards).
- Empirical (pre-fix): `html\`<ul>${() => ["a","b"].map(t => html\`<li>${t}</li>\`)}\`` → `children[0]` is a
  function; `ssr(node)` = `<ul><!--[-->[object Object],[object Object]<!--]--></ul>`; DOM `mount` =
  `<ul><li>a</li><li>b</li></ul>`. Post-fix: SSR matches DOM.
- Example `examples/ssr-streaming` rebuilt: Activity/Top `<template>`s now stream real `<li>`s; `[object Object]` gone.
- Related: memory 028 (direct-child array path — distinct), 030 (Suspense fresh-mount `[object Object]` via
  resolveNode — DOM side), 034 (assert full container text to catch stringification). None covers the SSR
