# Why

A streaming-SSR design session initially framed an inline swap `<script>` (the React/Solid mechanism for placing out-of-order streamed content) as a conflict with a "HellaJS zero-runtime-in-HTML stance," and nearly built a load-bearing crux on that conflict. Grepping the repo showed no such stance exists: the zero-runtime property is about the `@hellajs/ssr` *bundle's imports* (`lib/ssr.ts` has one type-only import, erased), not about HTML *content*. Recalling the invariant's actual scope prevents re-deriving it — and re-asserting the wrong claim — on any future SSR / streaming / Suspense / selective-hydration work. The distinction matters because it keeps the proven inline-swap technique available for streaming without a false fight against an invariant that doesn't govern HTML output.

# Evidence

- `packages/ssr/AGENTS.md` Non-obvious behaviors: "Zero runtime imports. `lib/` has only `import type` from `@hellajs/dom` (erased). Adding a runtime `@hellajs/*` import violates the package's core invariant." — scoped to `lib/` *imports*.
- `packages/ssr/ssr-comparison.md` §2/§3: "Zero runtime imports… the only import is `import type…` erased at compile time"; §3 frames zero-runtime as zero runtime *dependencies* + bundle size (~1.15 KB).
- `rg -n -i "inline|<script|swap|suspense|stream|runtime.*markup"` across `packages/ssr`, `packages/dom/lib`, both AGENTS.md → no stance against scripts/inline content in shipped HTML.
- Confirmed 2026-07-12 during the streaming-SSR design session (`plans/ssr/code/streaming/design.md`).
