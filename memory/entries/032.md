# Why

Previously `ssrStream` drained staged `<Suspense>` swaps **sequentially in tree order** (a `while` loop awaiting each `swap.childGen` fully before starting the next). A slow region placed above a fast one held the fast region's resolved `<template>` back until the slow one resolved — the fallback-vs-resolved swap was already out-of-order, but inter-region *resolution* was not, which understated the streaming claim. Concurrent collection (`Promise.all` over per-swap drains) fixes it: each region streams on its own completion.

The load-bearing enabler is hydrate's lookup contract: `swapSuspenseStage` finds a staged template via `document.getElementById(sentinel.nodeValue)` — keyed by the `hsN` id, **not** by document position. So the `<template id="hsN">` blocks appended at stream end may arrive in **any** order and hydrate still matches each to its inline sentinel. This is why concurrent completion-order emission needs no reorder buffer.

Recalling this prevents a future change from (a) re-imposing sequential tree-order collection (a regression — slow blocks fast again), or (b) adding a wasteful reorder buffer under the false assumption that hydrate resolves templates positionally. Rejected alternative: buffer all swaps then emit in tree order — re-imposes the slow-blocks-fast problem the fix exists to remove. Error/cancel races: a `done` flag shared by `start()`/`cancel()` suppresses late concurrent enqueues into a closed/errored stream; a rejecting `childGen` rejects `Promise.all` → outer `catch` → `controller.error`. The main walk (shell + fallbacks + sentinels) still drains fully before any swap collection begins, so the TTFB win is unchanged.

Refines **memory 033** (the progressive streaming model): 033 records the inline-`$hs` swap + hydrate-adopts model; this entry records the collection *semantics* (concurrent, completion-order, id-safe) within that model. Does **not** supersede 033.

# Evidence

- `packages/ssr/lib/ssrStream.ts` — `start()` drains `pending` via `Promise.all`; each swap's `<template>` enqueued on its own completion, guarded by `if (!done)`; `cancel()` and the `catch` set `done = true`.
- `packages/dom/lib/internal/hydrate.ts` → `swapSuspenseStage`: `document.getElementById(n.nodeValue)` (id-based template lookup — the fact that makes order-independent emission safe; no reorder buffer needed).
- `packages/ssr/tests/ssr-stream.test.ts`: "concurrent swaps: a slow region above a fast one does not hold the fast region's `<template>` back (completion order)" — fails under the prior sequential drain; "concurrent swaps: a rejecting region errors the stream; a still-pending sibling's late enqueue is skipped (done guard)".
