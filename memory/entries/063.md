# Why

`dist/bundle.js` is a rollup that inlines every `lib/` module; `dist/{file}.js` (the `./*` exports-map subpath target) is a separate compiled copy with its own module-level state. A test mixing the two silently observes the wrong instance — assertions on the subpath's state pass or fail against an empty/unrelated copy. The `plans/resource/code/behavior-gaps/01-cache-scope-gc.md` plan prescribed importing `cacheMap` from `@hellajs/resource/cache` while resources under test came from `@hellajs/resource/bundle` — the scope-reap assertion would have inspected bundle-external `cacheMap` and **false-passed with or without the fix**. `dist/index.js` re-exports from `./cache.js` etc., so bare-package and subpath imports DO share an instance — but neither shares with `/bundle`.

# Evidence

Verified 2026-08-30 against `packages/resource/dist/`: `bundle.js` carries inlined compiled copies (`rg -c 'cacheMap'` → 22 hits in `dist/bundle.js`, 21 in `dist/cache.js` — two distinct copies) and exports only `resetResource, resource, resourceCache`; `dist/index.js` re-exports from `./resource.js`/`./cache.js`. Probes this session confirmed the instance split empirically. Consequence for tests: scope/entry counts via `resourceCache.map.size` (a `/bundle` value) remain the observable seam; internal `cacheMap` scope membership is not publicly observable and WeakRef release is the behavioral proxy (see 064).
