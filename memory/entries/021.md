# Why

`ssrStream` stages a `<Suspense>` swap by yielding its sentinel comment and then running `pending.push({ id, childGen })` as the very next statement (`packages/ssr/lib/internal/walk.ts`, `renderDynamicGen` → `case "suspense"`). But `start()` drives the generator with `for await`, which resumes the generator on a *separate microtask* from each `yield`, and `reader.read()` resolves on its own microtask. So a test that breaks its read loop as soon as the fallback `<i>…</i>` chunk appears is canceling while `start()` is still suspended between yields — before the push. `pending.length === 0` at cancel time → the swap-`return` loop body in `cancel()` never runs → those lines stay uncovered.

General lesson: generator output and consumer-side reads interleave at microtask granularity. To act on "the producer has reached stage X," witness stage X's *output* (the sentinel) AND yield a tick (`await delay(0)`) for the producer's post-output synchronous continuation (`pending.push`, then unwind into the flush await). Reading the sentinel alone is insufficient — the generator is suspended at that yield and only runs the push when `for await` calls `.next()` again.

Ignored → streaming/cancel/Suspense tests silently fail to exercise the swap path; `bun coverage ssr` shows the `cancel()` swap-return loop (and any later staged-state branch) as uncovered lines with all assertions green.

# Evidence

`packages/ssr/lib/ssrStream.ts` — `start()` drives `for await (const chunk of gen)`, then the deferred-swap flush loop; `cancel()` iterates `pending` calling `swap.childGen.return()`. `packages/ssr/lib/internal/walk.ts` — `renderDynamicGen` `case "suspense"`: `yield \`<!--${id}-->\`; pending.push({ id, childGen }); return;`.

Verified 2026-07-17: a cancel-against-`<Suspense>` test whose read loop broke on the fallback chunk (`pre.includes("<i>wait</i>")`) left `packages/ssr/dist/bundle.js:320-321` — the `while (si < sLen) { void pending[si]!.childGen.return(undefined); si++; }` body in `cancel()` — uncovered, because `pending.length` was 0 at cancel (the push hadn't run). Changing the break to `pre.includes("<!--hs")` (witness the sentinel) + `await delay(0)` (from `@utils/test-helpers.js`) before `reader.cancel()` brought the package to 100% line+func coverage — `bun coverage ssr` → 132 pass / 0 fail, exit 0.
