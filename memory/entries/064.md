# Why

Three independent failure modes make naive WeakRef/GC tests lie in this runtime:

1. **Microtask-checkpoint sensitivity.** `Bun.gc(true)` cannot collect objects still reachable from scheduled-but-unprocessed promise/async machinery. A plain drop-then-double-GC probe collected only 1/6 runs; inserting one macrotask turn (`await delay(0)`) after dropping the refs and before GC collected 6/6. Memory 039's "two full GCs" cadence is necessary but not sufficient once async machinery is in play — the turn boundary is the missing half.
2. **Suspended-activation retention (not a hellajs leak — refuted 2026-08-30 second session).** An earlier session recorded "ANY post-settle method access on a fetched resource pins its whole closure graph for process life" as an open bug. Refuted: the pin exists only while the async function that called the method is still live — `r.data()` (or any method) inside a test body, followed by nulling every reference, still false-pins at an in-body GC; the identical access inside a helper that RETURNS collects deterministically (bun:test and bare bun, ×3 each). No hellajs module state holds the graph (post-return collection proves it), and a pure no-hellajs closure graph with the same shape collects — the trigger is JSC's conservative retention of a suspended async activation's saved state, shape-sensitive to the callee's closure graph (every stripped factory skeleton variant pins — without effect, without signals, without any async function — while a minimal same-module closure graph does not). Production impact: none — retention is bounded by the accessing function's lifetime.
3. **Consequence for test shape.** Assert settlement via module state (e.g. `resourceCache.map.size`), never via the resource; create/access the object in one function, return, then turn+GC+deref in the caller. `packages/resource/tests/cache-scope-gc.test.ts` is the canonical passing shape (block-scope drop + `await delay(0)` + `Bun.gc(true)`×3, no post-settle access).

# Evidence

Verified 2026-08-30 across two sessions (unit 01-cache-scope-gc + resource-graph-pin diagnosis): flake split 1/6 vs 6/6 with/without the `delay(0)` turn (fresh-process ×6); pin matrix from session 1 reproduced unrolled (none collects; data/dispose pin ×3) and then bracketed — in-live-activation GC pins even with `r`/`fetcher` both nulled (×3), helper-return-then-GC collects under bun:test and in bare bun (×3 each), bare-bun cached+invalidateAll collects (×3), pure no-hellajs closure-graph repro collects under both environments (×3), and all six stripped-factory skeletons (S0–S5: minus effect / computed / signals / async-decl / any async) still pin (×3) — no single construct isolates, attributing the retention to JSC's suspended-activation machinery.
