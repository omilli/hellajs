> **Naming superseded 2026-08-22 (entry 045):** `ssrAsync`→`ssr.async`, `ssrStream`→`ssr.stream`, `docStream`→`doc` (stream overload) — the old names below are the pre-v2 API, kept for history.

# Why

`for await (const chunk of stream)` consumes a ReadableStream through its async iterator, which **acquires the stream lock** for the iterator's lifetime. Two consequences for any wrapper stream (docStream-style: prefix + chunks + suffix around a body stream):

1. The wrapper's own `cancel(reason)` callback cannot call `source.cancel(reason)` — the source is locked to the async iterator, and cancel on a locked stream throws `TypeError: Invalid state: ReadableStream is locked` (`ERR_INVALID_STATE`) — surfaced in HappyDOM/Bun exactly as in browsers.
2. There is no handle to cancel *through*: the iterator is internal to the `for await`.

The correct shape: `const reader = body.getReader()` **before** constructing the wrapper (the stream is then locked to *our* reader, deliberately), drain with `let chunk = await reader.read(); while (!chunk.done) { enqueue; chunk = await reader.read(); }`, and propagate cancel as `return reader.cancel(reason)` — cancelling through a reader still invokes the source's `cancel()` callback (e.g. ssrStream's generator-return + pending-swap teardown), which is the whole point of propagation.

Reading order note: this is the same read-loop idiom `tests/helpers.ts`'s `collect()` and dom's stream consumers already use — the trap is specific to *wrappers* that also own a `cancel()` callback.

# Evidence

- Failure observed 2026-08-21: `packages/ssr/tests/doc-stream.test.ts` "cancels the body stream when the document stream is cancelled" — `await stream.getReader().cancel("gone")` → `TypeError: Invalid state: ReadableStream is locked, code: "ERR_INVALID_STATE"` at the `options.body.cancel(reason)` call in the first docStream draft (`for await` + `body.cancel`).
- Fix in `packages/ssr/lib/docStream.ts`: reader acquired up front, manual read-loop in `start()`, `cancel(reason) { done = true; return reader.cancel(reason); }` — test green; `bun coverage ssr` exit 0 (157 pass, 100.00% lines) same day.
- The cancel test's `cancel: mock(() => {})` body source confirms the reason reaches the source's cancel callback through the reader.
