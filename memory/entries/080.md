# Why

`bun doc-snippets` reports tutorial findings informationally (strict tier gates the exit code; tutorials never fail the run), and plans in this repo carry DoDs of the form "tutorials report informationally, zero new snippet errors". Two mechanics make a raw count comparison useless:

1. **Byte-parity Complete Code redeclares.** `lint:structure` requires each `### src/...` block to byte-match the real file, and doc-snippets hoists every block containing an `export ` line to module scope (`scripts/doc-snippets.ts` emitModules — `/^(declare|export) /m` filter). A tutorial that shows a file in a progressive section AND in Complete Code therefore emits TS2451 ("Cannot redeclare") ×2 for EVERY exported const — e.g. blog's 14 pre-existing exported names. Adding a legitimately new export (blog v3's `card`/`cardTitle`/`cardBody`) mechanically adds new TS2451 findings of that same benign class; refusing them would mean refusing the export. Meanwhile the edit also REMOVES real findings (e.g. `cssVars`-specifier errors once the import is fixed), so the net count can drop while individual new lines appear (observed: 48 → 47 with +6 benign / −7 real).

2. **Line numbers shift.** Emitted-module coordinates change with any block edit, so textual diffs of findings are noise; only the error-kind × doc × count set is meaningful.

# Evidence

- Unit 04 (css api-v3, 2026-09-03): HEAD-swap experiment — `git show HEAD:examples/{counter,todo}/tutorial.mdx` temporarily restored, `bun doc-snippets` re-run, error sets compared: counter 9 (8× TS2552 'count', 1× TS2304 'doubled' — all from a `//... derived values unchanged` marker block) and todo 2 (TS1109/TS1005 from a `( //...` parse hole) byte-identical pre/post → edit introduced zero new findings there. Blog attribution (file user-modified pre-session, no HEAD state): 6 new TS2451s for the 3 new exported consts, same class as 14 sibling pre-existing names, offset by removed cssVars-specifier errors.
- Swap limit: HEAD-swap only reconstructs pre-state for files CLEAN at HEAD; for uncommitted user-modified files, attribute by error-shape reasoning against the pre-edit block contents read in-session.
