# Why

The intuitive framing "seed `resource(url, { initialData })` to kill the client refetch" (used by the
ssr-behavior-gaps 03 plan, corrected during execution) is wrong twice:

1. There is no refetch to kill by default — a resource created without `refetchOnKeyChange` issues
   no request at creation; the only auto-fetch path is the `refetchOnKeyChange` effect, and its
   first evaluation (creation) calls `run(false)` too.
2. `initialData` does not suppress any fetch — `run()` has no `rawData`/initialData guard before
   initiating a request. What `initialData` actually does: `data()` returns the server value
   immediately, `isLoading()` stays false ("only true when there's no data at all, not even
   initialData"), and `status()` reads `'idle'` while data equals initialData.

Docs, patterns, and plans describing the `doc({ data })` → `resource(url, { initialData })` wiring
must claim what happens: no initial request + no loading flash because the resource never
auto-fetches and is pre-seeded — not "initialData prevents a refetch". A reader switching on
`refetchOnKeyChange: true` still gets a creation fetch even with initialData set.

# Evidence

- `packages/resource/lib/resource.ts` — the creation effect calls `run(false)` only inside
  `if (refetchOnKeyChange)` (the `cleanupEffect = effect(...)` block); `run()` (async function) has
  no initialData/`rawData` check before the request-initiation phase. Read 2026-09-01 during unit
  03 (`doc({ data })` data-serialization).
- `packages/resource/docs/api/resource.mdx:429` — "By default, resources don't auto-fetch on
  creation. Call `.fetch()` explicitly, or set `refetchOnKeyChange: true` for automatic fetching
  when key dependencies change."
- `packages/resource/docs/api/resource.mdx:136` — `isLoading`: "Only true when there's no data at
  all (not even `initialData`)."
- Applied in `packages/ssr/docs/patterns/ssr.mdx` ("Ship server data to the client") and
  `packages/ssr/docs/api/doc.mdx` ("The `data` payload script") — phrased as the server's fetch
  being the fetch; `bun doc-snippets` strict tier clean.
