# Why

`consumeRegion` is the shared helper every marker-bounded hydrate path uses to (a) gather the region's existing server nodes, (b) strip the `<!--[-->`/`<!--]-->` markers, (c) insert a persistent text anchor, and (d) hand back the DOM pointer past the region (`next`) so the walker continues correctly. Returning `null` for `next` whenever the region had a following sibling silently corrupted hydration: the next AST child's `hydrateNode`/`consumeRegion` ran against the wrong node (null), triggered `"[dom] hydrate mismatch: expected element node"`, and `replaceMismatch` mounted a fresh node that got `appendChild`ed — leaving the original server node in place AND a duplicate. Reactive bindings on the real server node were never established.

This was invisible in the existing suite because every region-adoption test either had the region as the last child or was followed only by another region (whose own `consumeRegion` happened to re-anchor correctly from the misaligned pointer). The Unit-A `raw` region test was the first to pair a region with a following **element** sibling (`<span>`), exposing it.

# Evidence

- **Root cause** — `packages/dom/lib/internal/hydrate.ts` `consumeRegion`: original `return { anchor, existing, next: close.nextSibling };` ran after `parent.removeChild(open)` + `parent.removeChild(close)`.
- **HappyDOM is spec-compliant** — empirical test (`packages/dom/tests/_debug_next.test.ts`, since removed): `<a><b><c>` → `b.nextSibling` is `C` before `removeChild(b)`, `null` after; `a.nextSibling` still `C`. So a detached node's `nextSibling` is `null`.
- **Failure signature** — dom raw test scenario 5: `ssr` output `<main><!--[--><h1/><p/><!--]--><span><!--[-->A<!--]--></span></main>`; after `hydrate`, `main.childNodes` = `[ ""(anchor), H1, P, SPAN, SPAN ]` — two spans, the original unbound + a fresh-appended one; `querySelector("span")` returned the unbound original so `label("B"); flush()` showed stale `"A"`.
- **Fix** — `const next = close.nextSibling;` captured immediately after `gatherRegion`, before any `removeChild`; return uses the captured `next`. (`packages/dom/lib/internal/hydrate.ts`.)
- **Re-verification** — `bun coverage dom` → 317 pass / 0 fail, including `"preserves siblings outside a ForEach region on count-mismatch"`, all `hydrate adoption` (ForEach/Transition/Portal/Lazy), `hydrate <Suspense>`, and the raw scenarios. No behavior change for region-as-last-child (null → null).
