# Why

> **⚠ RESOLVED 2026-07-11** — `bun install` ran during the marker rework (Unit 3), so `@hellajs/ssr` is now in `bun.lock` and linked into `node_modules/@hellajs/`. The `serverContainer` workaround below is also retired (replaced by a real-`ssr()` `ssrContainer` helper). Kept for historical context.

A run writing dom (or any non-ssr) tests that import `@hellajs/ssr/bundle` hits `Cannot find module '@hellajs/ssr/bundle'` and wastes a round-trip discovering the link is missing. The fix is environment-shaped (`bun install` to link the workspace, which touches `bun.lock` — off-limits without explicit request) or dep-shaped (add `@hellajs/ssr` as a devDependency of the consuming package). The workaround used here avoids both: build server HTML without importing ssr.

The `serverContainer` workaround (`packages/dom/tests/helpers.ts`) mounts the tree and serializes `innerHTML`. The browser's `innerHTML` serialization reproduces `ssr()`'s text coalescing (adjacent text nodes serialize concatenated), so it is faithful for structure. BUT mount has side effects ssr does not: it populates a Portal's remote target, fires a Lazy loader, and runs sync `beforeMount` hooks during the mount — so tests asserting on those (target-empty pre-hydrate, loader call count, hook call count) must use manual `container.innerHTML = "..."` instead.

# Evidence

- `ls node_modules/@hellajs/` lists core/css/dom/resource/router/store/ui but NOT ssr (2026-07-10).
- `rg '"@hellajs/ssr"' bun.lock` → no matches (ssr absent from the lockfile).
- `packages/dom/tests/hydrate*.test.ts` import `ssr` from neither; they use `serverContainer` (structure/ForEach/Transition cases) or manual `container.innerHTML` (Portal/Lazy/beforeMount/count-mismatch cases). Error reproduced: `Cannot find module '@hellajs/ssr/bundle' from '.../hydrate.test.ts'`.
- `packages/dom/tests/helpers.ts` `serverContainer` — mount, capture `innerHTML`, `resetTestState`, fresh container.
- Workspaces config (`package.json`): `"packages/*"` includes ssr; the link is simply missing because `bun install` was not re-run after ssr was added.
