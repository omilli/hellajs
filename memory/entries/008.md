# Why

A transient full-suite failure of this test is not a regression signal — it passes in isolation and on immediate re-run within the same session, pointing to cross-suite ordering or microtask timing in dom's error dispatch (the test throws `render failed` from a `BrokenComp`; under certain full-suite state the throw propagates uncaught instead of being routed through `dispatchError`/`onError`). Treating it as a real failure wastes a run; re-run first.

# Evidence

- This run (2026-07-10): full `bun coverage` → 1111 pass / 1 fail; the failure was `dom > component > multiple components isolation` with an uncaught `Error: render failed`.
- Same session: `bun coverage dom` → 270 pass / 0 fail (the test passes in isolation).
- Same session: full `bun coverage` re-run → 1112 pass / 0 fail (non-reproducing).
- `packages/dom/tests/component.test.ts` constructs a throwing `BrokenComp`; dom normally routes the throw via `dispatchError`.
