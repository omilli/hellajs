# Why

`@hellajs/core`'s reactive graph (link lists `rd`/`rs`, cached value `cbc`) lives behind function closures — there is no public accessor to inspect whether a supposedly-GC'd node still holds edges. Any future leak or auto-GC regression test must therefore observe retention *transitively*: a leaked node keeps its `cbf` closure alive, which keeps the canary alive. Two failure modes make a naive probe lie:

1. **Dead-statement false negative.** `const held = {...}; computed(() => { held; return a() + b(); })` — the bare `held;` expression statement contributes nothing to the result, engines treat the capture as dead, and the canary is collected *even when the node leaks*. The canary must flow into the observable output: `return { sum: a() + b(), tag: held }` — `cbc` then genuinely retains it.
2. **Premature collection.** The probe must keep the source signals alive in outer scope (they are the roots that retain a leaked node via their `rs` subscriber lists) and drop only the computed + its subscriber (dispose the effect). One `Bun.gc(true)` pass can leave weak targets un-swept; two consecutive full GCs before `deref()` is the reliable cadence.

The differential shape is the actual test: a known-leaky graph (multi-dep computed after last-subscriber dispose, 2026-08-21 `removeLink` bug) must retain the canary while a known-clean one (single-dep computed) must not. If both read the same, the probe is optimizing out the capture — trust neither result.

# Evidence

- Verified 2026-08-21 against `packages/core/lib/internal/links.ts` `removeLink`: first probe with a dead `held;` statement reported both canaries collected (false negative); corrected probe returning `{ sum: a() + b(), tag: held }` reported the 2-dep computed's canary **retained** after disposing its only subscriber while the 1-dep control was collected — matching the code trace (GC branch removes only `ls.rd`, dep 2..n survive).
- Probe skeleton (bun --eval): build computed returning the canary inside the value, `effect(() => c())` then `stop()` (triggers auto-GC), keep `a`/`b` signals in outer scope, `Bun.gc(true); Bun.gc(true);`, assert `ref.deref()` expectations.
