# Why

`bun doc-snippets` emits one module per doc: `splitImports` pulls each block's import statements into a doc-level union (`mergeImports`), and block bodies are nested `{ }` scopes inside one async IIFE — a later block can read names an earlier block declared, and same-name redeclaration across blocks shadows instead of colliding (scripts/doc-snippets.ts:298–335).

Consequence for section moves: a moved block silently carried two dependencies that don't travel with its text.

1. **Source doc strands references.** If the moved block was the only one importing a name (`route`, `navigate` after moving Route Metadata out of router.mdx), every remaining block using that name fails TS2552 — the doc's merged import union lost its supplier. Fix is 0-net-lines: widen an existing import line in a surviving block.
2. **Target doc type-collides.** A moved block referencing names it never declared (`currentView`, `checkAuth`) now resolves against the target doc's earlier declarations, which may have incompatible types (route-hooks' `currentView = signal(<div>…)` is `Signal<JSX.Element>`; the moved snippet calls `currentView('About')`) or different semantics (`checkAuth` async vs sync). Fix: prepend the block's own imports + local declarations matching its original context.

# Evidence

u8 docs split (2026-08-26): after moving `### Route Metadata` from packages/router/docs/api/router.mdx to concepts/route-hooks.mdx, `bun doc-snippets` failed with `packages_router_docs_api_router_mdx.ts(82,20) TS2552: Cannot find name 'route'` and `(125,39) TS2552: Cannot find name 'navigate'` — fixed by widening the Basic Usage block's import to `{ router, route, navigate }`; the moved block got its own `import` + `const checkAuth = () => true; const currentView = signal("")` preamble. Both failures were invisible until the audit tool ran; `bun lint:structure`/`lint:guards` stay green through them, so run `bun doc-snippets` after any doc block move, not just after edits.
