# Why

These five facts are the evidence base for the SSR architecture (string renderer in a new `@hellajs/ssr` package + core-owned render-context slot + resource fetch-suppression via that slot). Recalling them prevents three classes of rework on any SSR run: (1) re-auditing each package's DOM surface from scratch, (2) re-deriving the css drain point, and (3) re-falling-for the wrong claim that resource's listeners are unguarded. This is a point-in-time snapshot — re-verify against `lib/` source before trusting if a package's internals shift.

# Evidence

Verified 2026-07-03 against `lib/` source (`rg 'document\.|window\.|MutationObserver|customElements'` per package, plus targeted reads):

- **core** (`packages/core/lib/`): zero grep matches. Pure reactive primitives; runs as-is on server.
- **store** (`packages/store/lib/`): zero grep matches. Wraps core; SSR-safe.
- **css** (`packages/css/lib/`): server-runnable, unified registration (v3 — see 079, which supersedes the former platform-dependent text return this entry originally recorded). All creators register on both platforms and return `""`/class/name/proxy everywhere; sheet ops are the only DOM-gated step; `cssText()` collects the server `<style>` text (css-side rules, then vars buckets). The `<style>` babel transform is deleted (only `jsx.mjs` + `component.mjs` remain). Tests: `tests/ssr.test.ts`.
- **resource** (`packages/resource/lib/`): ALREADY server-import-safe. `createFocus` guards at `internal/lifecycle.ts:32` (`if (!hasDocument()) return;` before `visibilitychange` attaches). `cache.ts:19-42` guards online/offline: `onlineStatus = hasNavigator() ? navigator.onLine : true` (defaults online), `if (hasWindow()) { window.addEventListener("online"…) }`. An initial grep-only "unguarded" read was WRONG — corrected by reading the guard context around the matching lines, not just the matches. (Lesson: grep matches don't confirm guard context; read the surrounding lines before asserting a call is unguarded.)
- **dom** (`packages/dom/lib/`): importable server-side — no module-scope `document.`/`window.`/`new MutationObserver`/`customElements.define`. Every touch point sits inside a function body (`$ref.ts:16`, `internal/render.ts:55,61,86`, `events.ts:20`, `queue.ts:58`, `selectors.ts:47,66`, `element.ts:101`). But every call path requires a live DOM; `mountNode` is hardwired to `document.createElement(tag)` at `internal/render.ts:88`. The string backend is `@hellajs/ssr` (BUILT — see 013; 007/009 archived); `mountNode` and `ssr()` are the two backends over one HellaNode AST.
- **html`` / babel**: `lib/html.ts` + `lib/internal/template.ts` have zero `document.`/`window.` refs (parser is DOM-free, builds HellaNode AST by tokenization). babel plugin (`plugins/babel/src/transformers/{component,jsx,style}.mjs`) is build-time-only and emits the same HellaNode AST shape. This AST is the DOM-free seam a string renderer walks — two backends (mountNode + ssr), one input.

The "planned second backend" framing below is historical. Re-verify against `lib/` before trusting any package-specific detail if internals shift.

**Update 2026-07-17:** Sharpened the dom claim for meta-framework (Astro renderer) SSR. dom is importable-but-inert for its *mount/render* runtime, BUT `component()` — the single symbol the babel transform auto-injects (`import { component } from "@hellajs/dom"`) into every compiled component file — is server-EXECUTABLE. Verified: `packages/dom/lib/component.ts` body is `scope(() => result = fn(props))` + `dispatchError` on catch only; zero `mountNode`/`document`/`window` refs (rg). `scope()` is core (`packages/core/lib/scope.ts:22`), DOM-free. Therefore an Astro-style `renderToStaticMarkup(Component, props)` can run `Component(props)` on the server: nested `<Child/>` compile to `component(Child, props)` calls that execute (establishing the reactive scope, returning a HellaNode) without ever touching the DOM. `mountNode` — the one hardwired to `document.createElement` — is never on the `component()` call path. This is the load-bearing fact for any SSR renderer that imports a compiled hellajs component.
