# Why

These five facts are the evidence base for the SSR architecture (string renderer in a new `@hellajs/ssr` package + core-owned render-context slot + resource fetch-suppression via that slot). Recalling them prevents three classes of rework on any SSR run: (1) re-auditing each package's DOM surface from scratch, (2) re-deriving the css drain point, and (3) re-falling-for the wrong claim that resource's listeners are unguarded. This is a point-in-time snapshot — re-verify against `lib/` source before trusting if a package's internals shift.

# Evidence

Verified 2026-07-03 against `lib/` source (`rg 'document\.|window\.|MutationObserver|customElements'` per package, plus targeted reads):

- **core** (`packages/core/lib/`): zero grep matches. Pure reactive primitives; runs as-is on server.
- **store** (`packages/store/lib/`): zero grep matches. Wraps core; SSR-safe.
- **css** (`packages/css/lib/`): platform-dependent return (BUILT). `css()` early-returns text on server at `css.ts:37` (before any `injectedMap` access); `cssVars()` early-returns text at `cssVars.ts:27-41` (before any state/effects). Server path is fully stateless. Client-side textContent mirrors: `syncTextContent()` (`cssStore.ts:31-36`) and `syncVarsTextContent()` (`varsStore.ts:145-168`) both guard with `hasDocument()`. Former 4 css-side maps collapsed to 1 (`injectedMap`, `cssStore.ts:24`). The `<style>` babel transform is deleted (only `jsx.mjs` + `component.mjs` remain). Tests: `tests/ssr.test.ts` (14 tests).
- **resource** (`packages/resource/lib/`): ALREADY server-import-safe. `createFocus` guards at `internal/lifecycle.ts:32` (`if (!hasDocument()) return;` before `visibilitychange` attaches). `cache.ts:19-42` guards online/offline: `onlineStatus = hasNavigator() ? navigator.onLine : true` (defaults online), `if (hasWindow()) { window.addEventListener("online"…) }`. An initial grep-only "unguarded" read was WRONG — corrected by reading the guard context around the matching lines, not just the matches. (Lesson: grep matches don't confirm guard context; read the surrounding lines before asserting a call is unguarded.)
- **dom** (`packages/dom/lib/`): importable server-side — no module-scope `document.`/`window.`/`new MutationObserver`/`customElements.define`. Every touch point sits inside a function body (`$ref.ts:16`, `internal/render.ts:55,61,86`, `events.ts:20`, `queue.ts:58`, `selectors.ts:47,66`, `element.ts:101`). But every call path requires a live DOM; `mountNode` is hardwired to `document.createElement(tag)` at `internal/render.ts:86`. No string backend exists today — the planned `@hellajs/ssr` (entry 007, UNBUILT) would fill it.
- **html`` / babel**: `lib/html.ts` + `lib/internal/template.ts` have zero `document.`/`window.` refs (parser is DOM-free, builds HellaNode AST by tokenization). babel plugin (`plugins/babel/src/transformers/{component,jsx,style}.mjs`) is build-time-only and emits the same HellaNode AST shape. This AST is the DOM-free seam a string renderer walks — two backends (mountNode + ssr), one input.

**Update 2026-07-10:** The platform-dependent return (entry 006) is now BUILT. `css()`/`cssVars()` return text on server with zero state mutation; the former 4 css-side maps are now 1 (`injectedMap`); the `<style>` babel transform is deleted. The `@hellajs/ssr` package (entry 007) remains UNBUILT — only its plans exist. Re-verify against `lib/` before trusting any package-specific detail if internals shift.
