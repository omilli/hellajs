> **Naming superseded 2026-08-22 (entry 045):** `ssrAsync`→`ssr.async`, `ssrStream`→`ssr.stream`, `docStream`→`doc` (stream overload) — the old names below are the pre-v2 API, kept for history.

# Why

Memory 015 chose β (stage templates, swap at hydrate, **no inline scripts**) over α (per-segment hydration), citing HappyDOM testability (HappyDOM won't execute innerHTML-inserted scripts) and that α's selective-hydration complexity was unjustified given HellaJS's cheap hydrate. But β gave up the most *visible* streaming benefit — resolved content all swapped together at hydrate, so the user never saw cards fill in one-by-one (the user flagged "everything loads at the same time"). React/Solid get progressive reveal via per-chunk inline scripts (React `$RC`, Solid `_$HY`); memory 014 confirmed inline scripts in streamed HTML violate NO HellaJS invariant (the zero-runtime rule is about `@hellajs/ssr`'s bundle *imports*, not HTML *content*). So the sole blocker was testability — solvable by unit-testing `$hs` directly + string-testing emission + relying on the `swapSuspenseStage` fallback in HappyDOM integration tests (exactly how React tests `$RC`).

Decision: ship progressive inline-swap scripts. `ssrStream` emits the `$hs` bootstrap once (only when there are staged swaps), then each `<template id="hsN">…</template>` is followed by `<script>$hs("hsN")</script>`. The browser runs `$hs` on parse → swaps the fallback for the resolved content the moment that chunk arrives. `hydrate` later adopts the already-swapped nodes; `swapSuspenseStage` is the no-script/HappyDOM fallback.

**What did NOT change (still true from 015):** hydrate still runs once; α-style per-segment *selective hydration of interactivity* (event handlers going live per-segment as they arrive — React's selective hydration) is STILL not adopted — HellaJS does progressive *content* reveal, not progressive *interactivity* hydration. So the "α future option" note is retired for CONTENT (we did it) but remains for INTERACTIVITY hydration.

**Load-bearing implementation detail (the [object Promise] bug):** `$hs` wraps the inserted content in an EXTRA `<!--[->…<!--]-&gt;` pair. hydrate's `hydrateDynamic`→`consumeRegion` eats the region's OUTER marker pair; the inner pair the wrapper leaves becomes the resolved getter's reactive-region markers (matching what β's `swapSuspenseStage` returned — marker-including childNodes). WITHOUT the wrapper, hydrate re-evaluates the getter → a fresh Promise stringified to `[object Promise]`. The wrapper is what keeps "dom needs no change" true.

# Evidence

- `packages/ssr/lib/ssrStream.ts` — `HS_SWAP_SCRIPT` const (`$hs(id)`); `start()` emits `<script>HS_SWAP_SCRIPT</script>` once before the flush (only when `pending.length`), then each template as `<template id="hsN">…</template><script>$hs("hsN")</script>` (concurrent collection per memory 032).
- `packages/dom/lib/internal/hydrate.ts` — `swapSuspenseStage` UNCHANGED (the no-script fallback; `if (!template) return existing` adopts pre-swapped regions). No dom code change.
- Viability: raw-HTTP test — Vite dev server delivers each template as a distinct chunk at a distinct time (bun's `fetch` coalesces them and is misleading — use `node:http`/`curl`).
- Browser-verified by the user: cards pop in one-by-one; the `[object Promise]` hydrate bug (from the missing marker wrapper) was found + fixed.
- `bun coverage ssr` 142 pass / 0 fail, 100% funcs/lines; the `$hs swap + hydrate … no [object Promise]` regression test proven to fail without the wrapper.
- Supersedes memory 015 (β no-inline-script framing). Memory 014 (inline scripts OK) and 032 (concurrent collection) still hold.
