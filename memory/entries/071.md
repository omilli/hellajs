# Why

`html`'s declared return type is the union `HellaNode | (() => HellaNode)` (`packages/dom/lib/html.ts:15` — a template whose root interpolates a dynamic value can legitimately return a function). The ssr members type their param as plain `HellaNode` (`SsrFn` in `packages/ssr/lib/ssr.ts`: `(node: HellaNode): string`, `async(node: HellaNode): Promise<string>`, `stream(node: HellaNode): ReadableStream<string>`), so `ssr.async(html`<${App} />`)` fails tsc with TS2345 — "Value of type '() => HellaNode' has no properties in common with type 'HellaNode'. Did you mean to call it?". The asymmetry that misleads: `hydrate(node, target)` widens its param to `HellaNode | (() => HellaNode) | (() => Promise<…>)` (`packages/dom/lib/hydrate.ts:25-26`), so the SAME expression compiles uncast there — a test that copies the hydrate line shape onto an ssr line goes red only at the coverage tsc stage. Same root cause fires a second way: passing `html`…`` where a callback expects `() => HellaNode` (e.g. a hand-rolled loader resolver `resolveLoader(() => html`<b/>`)`) fails TS2322 until the template expression carries `as HellaNode`.

# Evidence

Two tsc errors in unit 02 (Lazy server render), both fixed by appending the cast: `packages/ssr/tests/hydrate-integration.test.ts:96` TS2345 on `ssr.async(html`<${App} />`)` and `packages/dom/tests/hydrate-foreach.test.ts:170` TS2322 on `resolveLoader(() => html`…`)` — gate green after `as HellaNode` on each (bun coverage ssr 173 pass / dom 402 pass, 2026-09-01). Every pre-existing test in `packages/ssr/tests/` already writes `ssr(html`…` as HellaNode)`; the convention exists precisely for this union. The `ComponentReturn` union itself is declared at `packages/dom/lib/types/nodes.d.ts:134`.
