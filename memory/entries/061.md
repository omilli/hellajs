# Why

Mid-unit, the main tree routinely holds whole uncommitted feature slices (this repo's plans land that way — see 059 for the mirror rule). A `git worktree add` cuts from HEAD, so it *lacks* those uncommitted changes — yet committed tests may already depend on them (a sibling unit committed its test but not the shared-helper change it reads). Any HEAD checkout is then red on a package outside yours, and "baseline red → stop" deadlocks the whole task. The attribution rule (AGENTS.md §Gate failure attribution) correctly blames the foreign file; the resolution is to replicate the user's working state: copy the current helper file verbatim into the worktree as an uncommitted carry. Never edit or "fix" it — it is the user's in-flight work; the carry is a replica, and it must be reported and dropped at merge time (or the merge will conflict with the owning unit's real change). Without the carry, every `bun coverage <pkg>` in the worktree dies in the repo-wide tsc stage before the scoped tests can validate your own work.

# Evidence

Session 2026-08-30 (worktree `../hellajs-shadow-dom`, unit `plans/dom/code/behavior-gaps/03-shadow-dom-element.md`): fresh worktree from `fe0fdcb6` → `bun coverage dom` failed repo-wide tsc with TS2724 `getHostStylesheet` in `packages/css/tests/style-host.test.ts:2`; main-tree `git diff utils/test-helpers.js` showed the export exists only uncommitted (in-flight css style-host unit — 059's session saw the same unit uncommitted). `cp` of the main tree's `utils/test-helpers.js` into the worktree → `bun coverage dom` exit 0 (373 pass), establishing the green baseline; post-change gate exit 0 (380 pass). Carry recorded in the plan's Worker notes as not-part-of-this-unit, to be dropped when the css unit lands. This is a justified deviation from "off-limits: the user's existing changes" — copied verbatim, never modified.
