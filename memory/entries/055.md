# Why

The docs site renders MDX that lives OUTSIDE the site: package docs via the
`@{pkg}/...` aliases (`astro.config.mjs` → `../packages/*/docs/*`) and tutorials via
`@examples/{name}/tutorial.mdx`. Tailwind v4's automatic content detection only scans
inside the Vite root (`docs/`), and daisyUI 5 — though it registers components through
`addComponents` — has Tailwind v4 emit each component class only when its candidate is
detected in a scanned file. Net effect: any daisyUI class used ONLY in imported MDX
(`alert-info`, `alert-soft`, `btn-success`, …) is silently dropped from the built CSS.
The bug looks MDX/import-specific because classes that also appear in site-authored
pages (`badge`, `btn-primary`) keep working; base `.alert` even survived by accident —
the bare word "alert" occurs in `docs/AGENTS.md` prose inside the scanned root.

Fix in `docs/src/global.css`:

    @source "../../packages/*/docs/**/*";
    @source "../../examples/*/tutorial.mdx";

Two resolution rules, each verified empirically (first two attempts were both wrong):

1. **`@source` paths are relative to the stylesheet's directory** (`docs/src/`), NOT
   the Vite root — hence `../../`. Confirmed by build A/B: `../../packages/*/docs/**/*`
   → classes present; `packages/*/docs/**/*` (repo-root-relative) and
   `../packages/*/docs/**/*` → zero. (A compiled-dist read of `new F(l, e.root, …)` in
   `@tailwindcss/vite` suggesting the Vite root was the base was misleading — trust an
   oxide Scanner probe over minified-plugin reading.)
2. **A glob containing wildcards must end in a recursive file tail.**
   `../../packages/*/docs` (directory tail) matches ZERO files — oxide does not
   auto-expand directories that already contain glob wildcards. A magic-free path
   (`../../packages/core/docs`) does auto-expand. Probe directly when unsure:

       cd docs && node -e "
       const { Scanner } = require('@tailwindcss/oxide');
       const c = new Scanner({ sources: [{ base: process.cwd(), pattern: '<pattern>', negated: false }] }).scan();
       console.log(c.includes('alert-soft'));"

Side gotcha: a CSS comment containing the literal `/**/*` terminates itself early
(`*/` inside) → tailwind "Unterminated string" build error. Spell the tail in words.

# Evidence

- `docs/src/global.css` — the two `@source` lines (this fix, session 2026-08-27).
- `docs/node_modules/daisyui/components/alert/index.js` + `object.js` — `.alert`,
  `.alert-info`, `.alert-soft` all registered via `addComponents` in one call, yet only
  detected candidates survive into `dist/_astro/*.css`.
- Built markup vs CSS before fix: `docs/dist/learn/concepts/reactivity/index.html`
  carried `class="alert alert-info alert-soft"` while the linked CSS had zero
  `.alert-info`/`.alert-soft` rules.
- After fix: `bun run build` in `docs/` → `dist/_astro/components.*.css` contains
  `.alert-info` ×1, `.alert-soft` ×5, and control class `btn-success` (used only in
  `packages/css/docs/concepts/styling.mdx`) ×1.
- Oxide probes (base `docs/`): `"../packages/*/docs"` → 0 candidates;
  `"../packages/*/docs/**/*"` and `"../packages/core/docs"` → `alert-soft` present.

Re-verify before trusting if `tailwindcss`/`@tailwindcss/oxide` major-bumps (scanner
semantics) or the docs site restructures (aliases moving package docs under `docs/`).
