# Why

The five facts: core has zero DOM refs; store is SSR-safe but NO LONGER grep-clean — persistStore and the storage adaptors add `window` refs behind explicit guards (the old "store: zero DOM refs" claim is dead); css is server-runnable under v3 unified registration (079), with `cssText()` as the server text source; resource is server-import-safe behind hasDocument/hasWindow/hasNavigator guards; dom is importable-but-inert (`mountNode` is hardwired to `document.createElement`) yet `component()`, the symbol babel auto-imports, is server-executable; and the html`` parser + babel AST is the DOM-free seam shared by the mountNode and ssr() backends. These facts are the evidence base for the SSR architecture (shipped `@hellajs/ssr` stringifier + dom `hydrate()`). Recalling them prevents three classes of rework on any SSR run: (1) re-auditing each package's DOM surface from scratch, (2) re-deriving the css drain point, and (3) re-falling-for the wrong claim that resource's listeners are unguarded. Point-in-time — re-verify against `lib/` source before trusting if a package's internals shift.

# Evidence

Verified 2026-09-26 against `lib/` source (`rg 'document\.|window\.|MutationObserver|customElements'` per package, plus targeted reads):

- **core** (`packages/core/lib/`): zero matches. Pure reactive primitives; the only env surface is typeof-based helpers (`internal/env.ts`: `hasWindow`/`hasDocument`/`hasNavigator`, re-exported store/resource-side). Runs as-is on server.
- **store** (`packages/store/lib/`): SSR-safe but NOT grep-clean anymore — persistStore and the storage adaptors changed this since 005. `persistStore.ts:27` early-returns a no-op handle (`hydrated: () => true`, resolved ready, empty dispose) when `!hasWindow()`; the `pagehide` listener (`persistStore.ts:116`) is only reachable past that guard. `localStorageAdaptor`/`sessionStorageAdaptor` wrap lazy thunks — storage is touched only inside read/write/clear (`internal/storage.ts`), never at import/factory time. Import-safe and persistStore-safe on the server; "zero DOM refs" is false.
- **css** (`packages/css/lib/`): server-runnable, v3 unified registration (see 079). `css()` runs `registerText` on both platforms and returns `""` (`css.ts:52`); registration state (single `injectedMap`) is platform-independent — sheet mutation (`internal/sheet.ts`: `document.createElement`/`getElementById`/`head.insertBefore`) is the only DOM-gated step, a server no-op; `cssText()` collects the server `<style>` text (css-side rules, then vars buckets). Tests: `tests/ssr.test.ts`.
- **resource** (`packages/resource/lib/`): server-import-safe, guards intact (file layout drifted since 005: `cache.ts` is now `resourceCache.ts`). `internal/lifecycle.ts:27` guards `visibilitychange` with `hasDocument()`, `:38` guards the focus listener with `hasWindow()`; `resourceCache.ts:22` `onlineStatus = hasNavigator() ? navigator.onLine : true` (defaults online), `:25` `if (hasWindow())` gates the online/offline listeners; `internal/polling.ts:47` guards the visibility check; `resource.ts:190` `if (!hasWindow()) return;`. The early grep-only "unguarded" read was WRONG — read the guard context around matches, never assert from the match alone.
- **dom** (`packages/dom/lib/`): importable server-side — no module-scope `document.`/`window.`/`new MutationObserver`/`customElements.define`; every touch point sits inside a function body (`$ref.ts:27`, `internal/render.ts`, `internal/events.ts`, `internal/queue.ts`, `internal/selectors.ts`, `element.ts:116` — define inside `element()`; `internal/deferred.ts` creates the MutationObserver lazily inside `startDeferredRegionWatch()`). Every call path requires a live DOM: `mountNode` is hardwired to `document.createElement(tag)` (now `internal/render.ts:177`, plus createElementNS siblings). `component()` (`lib/component.ts`) is server-EXECUTABLE — `scope(() => result = fn(props))` + `dispatchError` on catch + scope plumbing (static-root spread, `chainScopes`); zero `document`/`window` refs; `mountNode` is never on its path. This is the load-bearing fact for any SSR renderer that imports a compiled hellajs component. `hydrate()` is BUILT (`hydrate.ts`); `mountNode` and `ssr()` are the two backends over one HellaNode AST.
- **html`` / babel**: `lib/html.ts` + `lib/internal/template.ts` have zero `document.`/`window.` refs (parser is DOM-free, builds HellaNode AST by tokenization). babel transformers directory holds only `component.mjs` + `jsx.mjs` (`<style>` transform deleted); emits the same HellaNode AST shape. This AST is the DOM-free seam a string renderer walks.
- **@hellajs/ssr**: BUILT — `ssr()` stringifier in `packages/ssr/lib/ssr.ts` with zero runtime `@hellajs/*` imports (type-only from `@hellajs/dom`), plus `ssrAsync`/`ssrStream`/`ssrHead` siblings.
