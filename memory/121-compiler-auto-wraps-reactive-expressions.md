# Why

Predicting reactivity from JSX shape alone misanswers the most common docs/tests question: "does `{count()}` update?" At element position yes (the compiler wraps it), at component position no (nothing wraps it). Rules or examples claiming `class={theme()}` freezes in compiled JSX are wrong; the real silent freeze is component props and children. Hand-authored `@hellajs/dom/runtime` `prop`/`child` calls behave like the component arm: a plain value applies once, a function value is effect-wrapped.

The `@hellajs/css` corollary: `cx(...)` and a `cva()` recipe call are themselves calls, so `class={cx('todo', done() && 'done')}` and `class={button({ size: size() })}` re-derive in element position with no explicit arrow (the `===` memo in `prop()` skips the DOM write when the string is unchanged). The only static positions are a hoisted result (`const cls = cx(...); class={cls}` binds an identifier, no call, no wrap) and component props (`<Btn class={cx(...)} />` delivers a string; pass `class={() => cx(...)}` and forward it through `{...props}`, which routes each key through `prop()`). Docs steering readers to the array form "when the fragments are reactive" are wrong: both forms are equally reactive there; `cx` adds the keyed object form, nesting, and use outside templates.

# Evidence

`plugins/compiler/src/processors/attributes.mjs` `processAttributes`: `if (!isComponent) value = maybeReactive(value);` and `plugins/compiler/src/processors/children.mjs`: `result.push(isComponent ? expression : maybeReactive(expression));` — `maybeReactive` (`plugins/compiler/src/utils/reactive.mjs`) wraps any expression whose subtree contains a call unless the top level is already a function (or a top-level `raw()` call, the value sentinel). Verified by live compile through `plugins/compiler/index.mjs` `transform` 2026-11-05: `<p>{count()}</p>` emits `_hellaChild(root, () => count())`, `<p title={count()}>` emits `_hellaProp(root, "title", () => count())`, while `<Card>{count()}</Card>` emits `children: [count()]` and `<Card label={count()}>` emits `label: count()` — resolved, unwrapped. `guides/docs.md` §Example Code Style already encodes the element arm ("attribute values written directly ... auto-wraps call-containing expressions").

The css corollary verified 2026-11-25 by a scratch dom test (7/7 passing, since deleted): call-containing `class={cx(...)}`, `class={cva(...)}`, the object form `cx('todo', { done: done() })`, and the array-with-call form all re-derive after `flush()`; a hoisted `const cls = cx(...)` bound by identifier stays frozen; TypeScript rejects a bare signal or a thunk as a `cx` argument (TS2345, `CXArg` is values-only). Pinned by `packages/dom/tests/prop-reactivity.test.tsx`: "a call-containing class expression re-derives when its signal changes", "an array class prop with a call inside re-derives when its signal changes", "a class expression hoisted into a variable stays a static snapshot".
