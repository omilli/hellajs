# Why

This concept supersedes 007: ssr v1 shipped unchanged (the stringifier facts in 007 hold), but hydration moved from "v2 candidate, NOT pre-committed" to **built in `@hellajs/dom`** (2026-07-10), and the design doc's load-bearing claim was corrected against source. Captures the resolved architecture so the next SSR/hydration run starts from built reality, not the candidate framing.

Key decisions (verified against source this session):

1. **`hydrate()` lives in `@hellajs/dom`, NOT `@hellajs/ssr`.** ssr's core invariant is zero runtime imports from `@hellajs/*` (it only reads the AST). Hydrate re-executes the tree + wires reactivity (needs dom + core at runtime), so it cannot live in ssr without violating that invariant. `hydrate` sits beside `mount` (`lib/hydrate.ts`), returns the same `MountHandle`.

2. **ForEach/Transition adoption needs a component hydrate-mode — NOT free.** The design doc (`plans/ssr/code/hydration-design.md`) claimed "Option C is zero-cost — the component tree re-executes on hydrate anyway." FALSE: `ForEach`/`Transition`/`Portal`/`Lazy` are self-contained closures that hard-code fresh DOM creation (`appendChild(anchor)` + first-render `insertBefore(fragment, anchor)`); calling `fn(parent)` on hydrate DUPLICATES server DOM. Resolution: the walker pushes a `HydrateCtx` (`{ anchor, existingNodes, hydrateNode }`) onto a module stack; each component's first-render reads it, reuses the walker's pre-positioned anchor, and adopts existing nodes into its `keyToNode`/`current`. The LIS/leave update paths run UNCHANGED against the seeded maps. One source of truth for key resolution.

3. **Mismatch = warn + subtree-replace** (consistent with dom's error-boundary philosophy; `dispatchError` never hard-throws). `__static` fast-path skips effects; missing element → re-mount.

4. **Coalesced reactive text is rebuilt, not adopted** — see 010 for the contract divergence.
