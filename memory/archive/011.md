# Why

`packages/dom/package.json` declares only `@hellajs/core` as a `peerDependency` — `dependencies` and `devDependencies` are both absent. Yet `packages/dom/tests/helpers.ts` imports `{ ssr, ssrStream }` from `@hellajs/ssr/bundle` (the `ssrContainer`/`streamContainer` helpers consumed by every `hydrate*.test.ts`).

The import resolves because the monorepo workspace links `@hellajs/ssr` into `node_modules/@hellajs/`. So `bun coverage dom` is green in-repo. But the dep is **undeclared** — a clean install outside the workspace, or anyone running dom's tests in isolation, would NOT resolve the import. A future agent that wants it declared should add `"devDependencies": { "@hellajs/ssr": "workspace:*" }` to dom's `package.json` (a packaging change — ask first); until then, treat the working import as workspace-dependent, not declared. This is NOT a guide violation (no rule mandates declaring imported workspace packages) — it is a robustness/packaging fact.

This supersedes the earlier failure mode. Pre-2026-07-11 (before `bun install` re-ran during the SSR marker rework), `@hellajs/ssr` was absent from `bun.lock`/`node_modules` and the import failed with `Cannot find module '@hellajs/ssr/bundle'`. That is no longer the failure — the link exists. The old `serverContainer` workaround (mount → serialize `innerHTML` to reproduce ssr text coalescing) is also retired, replaced by a real-`ssr()` `ssrContainer` helper; `serverContainer`'s divergences (Portal target populated, Lazy loader fired, sync `beforeMount` fired by mount) no longer apply.

# Evidence

- `jq '{dependencies, devDependencies, peerDependencies}' packages/dom/package.json` (2026-07-12) → `dependencies: null`, `devDependencies: null`, `peerDependencies: {"@hellajs/core": "^1.0.6"}`. No ssr dep declared.
- `ls node_modules/@hellajs/ssr` (2026-07-12) → PRESENT (workspace-linked).
- `packages/dom/tests/helpers.ts:2` → `import { ssr, ssrStream } from "@hellajs/ssr/bundle";` (used by `ssrContainer`/`streamContainer`).
- Prior evidence (2026-07-10): `rg "@hellajs/ssr" bun.lock` had no matches and the import threw `Cannot find module` — both now false; `bun install` ran 2026-07-11 (SSR marker rework Unit 3).
