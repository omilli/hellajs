# Why

v1 shipped 2026-07-10 as `packages/ssr/` (`lib/ssr.ts` — `ssr(node): string`, consolidated into one file; zero runtime `@hellajs/*` imports). This concept records the design decisions the build followed, so the next SSR run (e.g. hydration v2) starts from resolved forks instead of re-deriving them.

Key decisions:

1. **ssr naming**: `renderToString` violated the single-word convention (css/store/resource/router all match their package name). Renamed to `ssr()` — matches the package-named-function pattern. Verified via grep of `packages/*/lib/index.ts`.

2. **Enhancement model (not re-mount) for v1**: the plan originally described `mount(app(), "#app")` (full re-mount, wipes server HTML). The user clarified: v1's client flow is selective enhancement — `$ref`/`$collection` bind existing static nodes, `mount()` adds islands to empty placeholders. Full re-mount over server HTML is a documented footgun (`packages/dom/lib/mount.ts:59` — `container.replaceChildren`).

3. **Hydration is NOT pre-committed**: the v1 plan does not commit to hydration as a v2 goal. A full hydration design doc exists (`plans/ssr/code/hydration-design.md`) with all forks resolved, but the build/don't-build decision waits for v1 usage data.

4. **ForEach key contract = Option C (re-run-and-match)**: the hydrate walker calls `each()` + `use(item, index)` to re-derive keys (same logic as `ForEach.ts:48-50` / `75-90`). No HTML markers needed. Count-mismatch → warn + subtree-replace. Zero serializer changes — v1 output is already hydration-ready. Rejected: data-key markers (HTML pollution), comment markers (parser risk), all in favor of C's zero-pollution, zero-enrichment approach.

5. **Mismatch = warn + subtree-replace**: consistent with HellaJS's error-boundary philosophy (`packages/dom/AGENTS.md`: "`dispatchError` never hard-throws"). Hard-throw would be the only crash-on-error site in the system.

6. **CSS on hydrate = no problem**: under platform-dependent return (entry 006), server styles are in a caller-controlled `<style>`, client runtime styles are in `<style id="hella-css">`. Separate elements, no wipe, no clearing.
