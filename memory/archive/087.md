# Why

The five-check `bun lint:structure` guard advertises "tutorial Complete-Code parity" (root AGENTS.md §Scripts), and plans lean on it as the lockstep oracle for tutorial edits. The gate can never fire:

```ts
const COMPLETE_CODE_RE = /^## Complete Code/;   // no m flag
...
if (content === null || !COMPLETE_CODE_RE.test(content)) continue;  // whole-file content
```

Without `m`, `^` matches only at position 0 of the file; every tutorial begins with `# Build ...`, so `.test()` returns false for all seven examples (verified empirically: gate-pass false, has-section true, all files). The byte-compare body below the gate is unreachable — a green lint:structure says nothing about parity. Real drift therefore accumulates silently: the four listed pre-existing drifts (confirmed at HEAD via git stash before the em-dash unit's edits) were all invisible to the guard.

# Evidence

- scripts/doc-structure.ts `checkTutorialParity`: gate line + `COMPLETE_CODE_RE` const (read in session, 2026-09-06).
- `bun -e` probe over all examples/*/tutorial.mdx: `gate-pass: false` for every file while each contains `\n## Complete Code`.
- Manual replica of the intended check (python fence-collector + rstrip byte-compare, 2026-09-06): blog 13/13 blocks match, ssr-islands 3/3, ssr-routing 4/4, ssr-streaming 3/4 (theme.ts drifts); counter/theme-switcher/todo document zero `### src/...` blocks while carrying real src files.
- ssr-streaming drift at HEAD: tutorial block line 1 `import { css, cssText } from '@hellajs/css';` vs real theme.ts `import { css, style, cssText } from '@hellajs/css';` (git show HEAD comparison).
