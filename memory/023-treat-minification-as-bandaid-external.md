# Why

During the 2026-12-17 bundle-size session (bench `dist/main.js` 58,727 bytes unminified vs Solid ~27kb), the user set two standing constraints. First, wiring up terser/minification to shrink the reported number was rejected outright — "this is a bandaid over the real issue"; the target is actual shipped code volume, so proposals must cut real wiring, not measurement overhead. Re-confirmed 2026-10-24: reporting a 51,344→70,130-byte bench growth as "exaggerated by the unminified build, only +5kb minified" and proposing terser wiring drew the same correction — the unminified number IS the metric; minified deltas never discount a growth report. Second, cutting the external-removal auto-cleanup (the MutationObserver cleanup arm in `packages/dom/lib/internal/queue.ts` that disposes effects when user code removes nodes via `el.remove()`/`innerHTML = ""`) was rejected even though it is ~4kb — it is the product's flagship "effects are cleaned up automatically when removed from the DOM" promise (`docs/concepts/control-flow.mdx`). Re-proposing either wastes a decision round.

# Evidence

- User statements, 2026-12-17: "You should ignore terser options, this is a bandaid over the real issue"; "I dont want to drop the external-removal."
- `packages/dom/lib/internal/queue.ts` `ensureContainerObserver`/`collectRemovedNode` — the observer serves cleanup (kept), afterMount delivery (`docs/api/hook.mdx` promises "dynamically added nodes on the next microtask"), and overlay re-registration for moved nodes; all three arms stay.
- Baseline measurements (unminified bytes): bench bundle 58,727 / minified 21,762 / gzip 8,042; ForEach 11,481 of it; the approved reduction direction is feature-gating unused subsystems (hooks, error boundaries, `e:` direct events, raw, hydrate coupling) via injectable feature modules + babel-plugin-emitted imports, not removing behavior.
- 2026-10-24 follow-up measurement (post imperative migration): bench `dist/main.js` 51,344→70,130 (+18.8kb). Decomposition: ~12.2kb hydrate-adoption closure (`internal/adoption.ts` claim family + `internal/hydrate.ts` adopt family) that CANNOT tree-shake because `runtime.ts` statically imports claim fns into `element()`/`fragment()`/`child()` and `render.ts` imports `peekAdoption`; ~7.6kb runtime construction module; ~4.4kb survivor growth (ForEach hctx arms +2.8kb). The old architecture tree-shook 100% of hydrate code (it hung off the lone `hydrate()` export). The in-repo seam pattern to restore shakability exists twice: `registry.ts`'s `export let runEffectHooks` + feature registration at module init (proven — hooks/errors features ship zero bytes in bench), and `internal/deferred.ts`'s `setDeferredAdopters` cycle break. Unminified byte counts are the working metric for this work.
