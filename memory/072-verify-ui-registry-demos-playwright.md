# Why

Registry demo defects (hydration failures, invisible portaled panels, clipped viewports, padding) are only observable by driving the real site; unit suites exercise compiled parts in happy-dom and never catch docs-site integration breaks (nested-button SSR parse fixups, unset css vars, demo-frame layout). Three operational traps make naive probing wedge: astro 7 daemonizes `astro dev` (a stale daemon serves 500 `FailedToLoadModuleSSR` until `astro dev stop`), worktree seeds install only the root workspace so `docs/` lacks `node_modules` until `npm install` runs there (same class as the examples rule), and parallel unit worktrees collide on the default 4321 port.

# Evidence

Diagnosing the ui demo defect set (dead dropdown hydration, popover trigger emptied by the HTML parser's nested-button fixup, 2px navigation-menu viewport from unset `--radix-navigation-menu-viewport-*` vars, sheet/drawer zero padding, fixed sidebar hidden under docs chrome): every root cause reproduced only through a playwright probe of the running site; the pre-existing dev daemon returned `FailedToLoadModuleSSR` 500s until `astro dev stop` + fresh start; `chromium.launch({ channel: "chrome" })` is the repo's own pattern (`scripts/bench/driver.ts`). Probes as `.mjs` scripts under `packages/ui/tests/.tmp/` run with bare `node` and deleted (directory removed) after - the path is NOT gitignored (only `packages/ui/tests/cli/.tmp/` is), so deletion before any stage is the discipline, not ignore rules. Method re-verified 2026-11-01 on the headless docs-demo pilot (accordion demo island: 18-check probe, zero console errors).

# Amendment (2026-11-02): probe interactions against `astro preview`, not `astro dev`

The headless demos batch B unit burned five probe rounds on dev-server artifacts that vanish against the built site: `astro dev`'s unbundled module waterfall makes island hydration race layout and event wiring, so behavior flips run-to-run (navigationMenu hover-then-click announced open then closed within 3ms; messageScroller `atBottom` initialized false while at-bottom) while the identical source served by `astro preview` after `npm run build` is deterministic. Second trap in the same session: probing preview WITHOUT rebuilding after demo edits serves the stale dist silently (item counts and behaviors from the previous source). Working method: `npm run build` -> `fuser -k <port>/tcp` -> `astro preview --port 45NN` -> probe -> rebuild before every re-probe round. Related demo-authoring facts confirmed from source the same session: a messageScroller demo's viewport style must carry `overflowY: auto` (the factory leaves scrolling to the wrapper - without it scrollTop assignments clamp to 0 and sync computes distance from overflowing content, flipping `atBottom` false after the first append); the same wrapper-owned-overflow contract holds for `scrollArea()` - its `Viewport` renders no overflow of its own, so the demo's viewport style supplies `overflowY: auto` (verified 2026-11-01 against `packages/headless/lib/scrollArea.tsx`), seeded content must sit within the factory's 80px at-bottom threshold, and rows appended reactively render through keyed `ForEach` - a plain reactive `.map` child churns every item node on append and breaks stick.
