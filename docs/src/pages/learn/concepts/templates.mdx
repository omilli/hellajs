# Granular Templates

An approach that binds reactive values directly to DOM elements, enabling surgical updates when state changes without the need for virtual DOM diffing or full component re-renders.

## Template Approaches

Both approaches produce identical AST structures and support the same reactive features.

### JSX

A familiar syntax (with minor differences) for those coming from React or similar libraries.

```jsx
import { mount } from '@hellajs/dom';
import { signal } from '@hellajs/core';

const count = signal(0);

const App = () => (
  <div>
    <h1>{count}</h1>
    <button on:click={() => count(count() + 1)}>Increment</button>
  </div>
);

mount(App, "#app");
```

### Template Literals

Template literals allow for pure runtime compilation and caching. An optional build-time compile step offers the same speed and size benefits as JSX.

```jsx
import { mount, html } from '@hellajs/dom';
import { signal } from '@hellajs/core';

const count = signal(0);

const App = () => html`
  <div>
    <h1>${count}</h1>
    <button on:click=${() => count(count() + 1)}>Increment</button>
  </div>
`;

mount(App, "#app");
```

## Element Syntax

Behind the scenes, function references are used to create reactive bindings between signals (or derived signals) and DOM elements.

### Reactive Bindings

```jsx
// Direct signal reference
<h1>{count}</h1>

// Computed function
<h2>{() => count() * 2}</h2>

// Reactive conditional render
{() => count() > 5 && <p>Great job!</p>}

```

### Static Values

```jsx
// One-time value (no reactivity)
<h1>{count()}</h1>

// Computed once
<h2>{count() * 2}</h2>

// One time conditional render
{count() > 5 && <p>Great job!</p>}
```

## Attribute Prefixes

HellaJS uses a prefix system to categorize attributes.

### Events

Use the `on:` prefix for delegated event handlers (recommended for most cases). Events are delegated globally to `document.body` in the capture phase.

```jsx
<button on:click={handleClick}>Click Me</button>
```

Use the `e:` prefix for non-delegated events. These attach directly and fire in the bubble phase.

```jsx
<button e:click={handleClick}>Click Me</button>
```

**When to use `e:` instead of `on:`:**
- When you need `event.stopPropagation()` to work predictably
- When working with third-party libraries that expect direct event listeners
- For edge cases where delegation causes issues

**Note:** `on:` is recommended for most cases as it provides better performance with large numbers of elements through delegation.

### Reactive Attributes

Use the `bind:` prefix for reactive attribute bindings.

```jsx
<div bind:class={() => isActive() ? 'active' : ''}>Content</div>
```

### Lifecycle Hooks

Use the `hook:` prefix for element lifecycle hooks.

```jsx
<div
  hook:afterMount={() => console.log('Mounted')}
  hook:beforeDestroy={() => console.log('About to be removed')}
>Content</div>
```

### Error Configuration

Use the `error:` prefix for element-level error configuration.

```jsx
<div error:fallback={(e) => <span>Error: {e.message}</span>} error:category="sidebar">
  <ChildComponent />
</div>
```

**Available attributes:**
- `error:fallback` - Function receiving error, returns fallback UI
- `error:category` - String for error categorization

## Components

Simple functions that return JSX or template literal elements (which transform to [HellaNodes](/learn/concepts/templates#internal-mechanics)). Supports reactive data flow through [signal](/reference/core/signal) props.

### Component Syntax

For template literal syntax, use `<${Component}>` for dynamic components:

```jsx
// JSX
<MyComponent title="Hi">Content</MyComponent>

// html
<${MyComponent} title="Hi">Content</${MyComponent}>
```

### Component Composition

Since components are just functions, composition is straightforward with props and children.

```jsx
const Card = ({ title, variant = 'default' }, children) => (
  <div class={`card card-${variant}`}>
    <div class="card-header"><h2>{title}</h2></div>
    <div class="card-content">{children}</div>
  </div>
);

const Button = ({ variant = 'primary', click }, children) => (
  <button class={`btn btn-${variant}`} on:click={click}>
    {children}
  </button>
);

// Components compose naturally
const MyPage = () => (
  <Card title="Welcome" variant="highlighted">
    <p>Welcome to our application!</p>
    <Button click={() => alert('Hello!')}>Get Started</Button>
  </Card>
);
```

### Component Data Flow

Components functions maintain their reactivity across boundaries.

```jsx
const TodoCard = ({ todo }) => (
  <div class="todo-card">
    <h3>{() => todo().text}</h3>
    <p>Priority: {() => todo().priority}</p>
    <span bind:class={() => `status ${todo().done ? 'completed' : 'pending'}`}>
      {() => todo().done ? 'Completed' : 'Pending'}
    </span>
  </div>
);

const TodoApp = () => {
  const selectedTodo = signal({
    id: 1,
    text: 'Learn HellaJS',
    priority: 'high',
    done: false
  });

  return (
    <div class="todo-app">
      <TodoCard todo={selectedTodo} />
      <button on:click={() => selectedTodo({
        id: 2,
        text: 'Build awesome app',
        priority: 'medium',
        done: true
      })}>
        Switch Todo
      </button>
    </div>
  );
};
```

### Component Scope

Effects created within components are automatically scoped and cleaned up when removed from the DOM.

```jsx
const Timer = () => {
  const count = signal(0);
  const interval = setInterval(() => count(count() + 1), 1000);

  // Auto-cleanup via component scope wrapper
  effect(() => console.log(`Count: ${count()}`));

  return (
    <div>
      <h1>{count}</h1>
    </div>
  );
  // Interval and effect auto-cleanup on unmount
};
```

## Control Flow

### Conditional Rendering

Use function references for conditional rendering.

<div role="alert" class="alert alert-error text-base">
  <Icon name="ph:warning" width={24} height={24} />
  <span>Unlike other frameworks, you <strong style="color: inherit; font-weight:800">MUST</strong> wrap conditionals in a reactive function.</span>
</div>

```jsx
const Counter = () => {
  const count = signal(0);

  return (
    <div>
      <h1>Count: {count}</h1>
      <h2>Doubled: {() => count() * 2}</h2>
      <p>Count is: {() => count() % 2 === 0 ? 'even' : 'odd'}</p>
      {() => count() > 5 && <p>Great job! Count is greater than 5!</p>}
      <button on:click={() => count(count() + 1)}>
        Increment
      </button>
    </div>
  );
};
```

### Lists and Iteration

Create reactive lists using the optimized [ForEach](/reference/dom/foreach) component. Use regular array methods for one-time rendering of static lists that don't change over time. 


Reactive: `<ul><ForEach each={todos} use={(todo) => <li>{todo.text}</li>} /></ul>`

Static: `<ul>{todos().map(todo => <li>{todo.text}</li>)}</ul>`

```jsx
const TodoList = () => {
  const todos = signal([
    { id: 1, text: 'Learn HellaJS', done: false },
    { id: 2, text: 'Build an app', done: false }
  ]);

  const addTodo = (text) => {
    todos([...todos(), {
      id: Date.now(),
      text,
      done: false
    }]);
  };

  return (
    <div>
      <ul>
        <ForEach each={todos} use={(todo) => (
          <li key={todo.id} class={todo.done ? 'done' : ''}>
            <input
              type="checkbox"
              checked={todo.done}
              on:change={e => {
                const updated = todos().map(t =>
                  t.id === todo.id ? { ...t, done: e.target.checked } : t
                );
                todos(updated);
              }}
            />
            {todo.text}
          </li>
        )} />
      </ul>
    </div>
  );
};
```

### Portals

Render content to a different DOM location while maintaining reactivity.

```jsx
import { Portal } from '@hellajs/dom';

const Modal = () => {
  const isOpen = signal(false);

  return (
    <div>
      <button on:click={() => isOpen(true)}>Open</button>
      {() => isOpen() && (
        <Portal to="#modal-root" type="append">
          <div class="modal">
            <button on:click={() => isOpen(false)}>Close</button>
            <p>Content rendered in modal-root</p>
          </div>
        </Portal>
      )}
    </div>
  );
};
```

**Portal types:**
- `append` (default) - Add as last child
- `prepend` - Add as first child
- `replace` - Replace all content
- `before` - Insert before target
- `after` - Insert after target

### Lazy Loading

Load components asynchronously with automatic code splitting. `Lazy` shows optional loading state during load and optional fallback on error.

```jsx
import { Lazy } from '@hellajs/dom';

const Dashboard = () => {
  return (
    <div>
      <h1>Dashboard</h1>
      {/* loading state shown during async load */}
      <Lazy
        loader={() => import('./HeavyChart')}
        loading={<div>Loading chart...</div>}
        fallback={<div>Failed to load chart</div>}
      />
    </div>
  );
};
```

**Lazy behavior:**
- `loading` prop - Shown during async load (optional)
- `fallback` prop - Shown on loader error only (optional)
- Component re-renders when content changes

## Element Lifecycle

<div role="alert" class="alert alert-error text-base">
  <Icon name="ph:warning" width={24} height={24} />
  <span>Unlike other frameworks, lifecycle hooks are tied directly to elements, not component scope.</span>
</div>

### Mount Lifecycle

**`hook:beforeMount`** - Called synchronously before the element is created. Use for initialization logic that must run before DOM creation.

**`hook:afterMount`** - Called asynchronously (deferred via `setTimeout`) after the element is mounted to the DOM. Safe for DOM measurements and third-party library initialization.

```jsx
const Component = () => {
  return (
    <div
      hook:beforeMount={() => {
        console.log('Preparing to mount');
      }}
      hook:afterMount={() => {
        console.log('Element is now in DOM');
        // Safe to measure dimensions, initialize libraries, etc.
      }}
    >
      Content
    </div>
  );
};
```

### Update Lifecycle

**`hook:beforeUpdate`** - Called before reactive properties, attributes, or content update on the element.

**`hook:afterUpdate`** - Called after reactive properties, attributes, or content update on the element.

```jsx
const Counter = () => {
  const count = signal(0);

  return (
    <div
      data-count={count}
      hook:beforeUpdate={() => {
        console.log('About to update');
      }}
      hook:afterUpdate={() => {
        console.log('Element updated');
      }}
    >
      <h1>{count}</h1>
      <button on:click={() => count(count() + 1)}>Increment</button>
    </div>
  );
};
```

### Destroy Lifecycle

**`hook:beforeDestroy`** - Called before the element is removed from the DOM. Use to cancel pending operations or save state.

**`hook:afterDestroy`** - Called after the element is removed from the DOM and all effects are cleaned up. Use for cleanup of external resources.

```jsx
const WebSocketComponent = () => {
  const ws = new WebSocket('ws://localhost:8080');

  return (
    <div
      hook:beforeDestroy={() => {
        console.log('About to cleanup');
      }}
      hook:afterDestroy={() => {
        ws.close();
        console.log('Connection closed');
      }}
    >
      Content
    </div>
  );
};
```

### Lifecycle Execution Order

- **`hook:beforeMount`** - before element creation
- **`hook:afterMount`** - after element is in DOM (deferred via `setTimeout`)
- **`hook:beforeUpdate`** - before reactive updates (not during initial render)
- **`hook:afterUpdate`** - after reactive updates (not during initial render)
- **`hook:beforeDestroy`** - before removal
- **`hook:afterDestroy`** - after removal and effect cleanup

### When to Use Each Hook

- **`hook:beforeMount`** - For initialization logic before DOM creation
- **`hook:afterMount`** - For DOM measurements, third-party library initialization
- **`hook:beforeUpdate`** - For saving state before reactive changes
- **`hook:afterUpdate`** - For responding to reactive changes
- **`hook:beforeDestroy`** - For canceling pending operations, saving state
- **`hook:afterDestroy`** - For cleanup of external resources (timers, WebSockets, subscriptions)

## Error Handling

HellaJS provides a global error handler with element-level configuration for fine-grained control.

### Global Error Handler

Set up a global handler using [`onError`](/reference/dom/onerror):

```jsx
import { onError, html } from '@hellajs/dom';

onError((error, context) => {
  console.error(`[${context.phase}]`, error.message);
  return html`<div class="error">Something went wrong</div>`;
});
```

### Element Error Configuration

Configure error behavior on elements with the `error:` prefix:

```jsx
<div error:fallback=${(e) => html`<span>Error: ${e.message}</span>`}>
  <FlakyComponent />
</div>
```

**Available attributes:**
- `error:fallback` - Function that receives error and returns fallback UI
- `error:category` - String for categorizing errors (passed to handler)

### Error Handling Flow

```
Error occurs
    ↓
Walk up DOM tree for error:fallback
    ↓
Call global onError with config
    ↓
Return HellaNode → Render fallback (bind/event/reactive child only)
Return null/void → Log only
```

### Full Example

```jsx
import { signal } from '@hellajs/core';
import { mount, html, onError } from '@hellajs/dom';

// Global handler
onError((error, context) => {
  // Use element's fallback if configured
  if (context.config?.fallback) {
    return context.config.fallback(error);
  }
  // Default fallback
  return html`<div class="error">${error.message}</div>`;
});

const App = () => {
  const data = signal(null);

  return html`
    <div error:fallback=${(e) => html`
      <div class="error-boundary">
        <p>Failed to load: ${e.message}</p>
        <button on:click=${() => location.reload()}>
          Reload Page
        </button>
      </div>
    `}>
      <DataDisplay data=${data} />
    </div>
  `;
};
```

**Error sources caught (with fallback UI rendered):**
- Reactive children that throw during render
- `bind:` callback errors
- `on:` and `e:` event handler errors

**Error sources caught (logged only, no fallback UI):**
- `hook:beforeMount` errors

**Note:** `beforeUpdate` and `afterUpdate` hook errors are not explicitly caught by the error system.

## Reactive DOM References

Work with existing DOM elements reactively using `$ref` for single elements and `$collection` for multiple elements.

### $ref - Single Element

Select a single element and chain methods for reactive bindings.

```js
import { signal } from '@hellajs/core';
import { $ref } from '@hellajs/dom';

const count = signal(0);
const isDisabled = signal(false);

// Reactive text content
$ref('.counter').bind(count);

// Reactive attributes
$ref('.input').bind({ disabled: isDisabled });

// Event handlers
$ref('.button').on('click', () => count(count() + 1));

// Lifecycle hooks
$ref('.modal').hooks({
  afterMount: (el) => console.log('Modal mounted'),
  beforeDestroy: () => console.log('Modal will close')
});

// Method chaining
$ref('.node')
  .bind(() => `Count: ${count()}`)
  .bind({ 'data-active': () => count() > 5 })
  .on('click', handleClick);
```

### Auto-Watching

`$ref` automatically watches for elements that don't exist yet:

```js
// Element doesn't exist yet - operations are queued
$ref('.future-element')
  .bind({ 'data-test': 'value' })
  .on('click', handleClick);

// Later, when element is added to DOM...
document.body.appendChild(
  Object.assign(document.createElement('div'), { className: 'future-element' })
);

// Queued operations automatically apply!
```

### $collection - Multiple Elements

Select multiple elements and apply operations to all of them:

```js
import { $collection } from '@hellajs/dom';

const status = signal('ready');
const items = $collection('.status-indicator');

// All current and future elements get the binding
items.bind(() => `Status: ${status()}`);
items.bind({ class: () => `indicator ${status()}` });
items.on('click', () => console.log('Indicator clicked'));
```

### Form Element Detection

`$ref` automatically detects form elements and uses `.value` instead of `.textContent`:

```js
const inputValue = signal('initial');

// Uses .value for input/textarea/select elements
$ref('#text-input').bind(inputValue);

 inputValue('updated');
// Input element's value property updates reactively
```

## Custom Elements

Define reusable Web Components with reactive props, slots, and lifecycle management.

### Basic Element

```jsx
import { element } from '@hellajs/dom';
import { signal } from '@hellajs/core';

element('my-counter', (props) => {
  const count = signal(Number(props.initial?.()) || 0);

  return (
    <div>
      <span id="count">{count}</span>
      <button onClick={() => count(count() + 1)}>+</button>
    </div>
  );
});
```

### Reactive Props

Props are reactive getter functions that track attribute changes:

```jsx
element('my-greeter', (props) => {
  // Props are functions - call them to get values
  return (
    <div>
      {/* Automatically updates when attribute changes */}
      {() => `Hello, ${props.name?.() ?? 'World'}!`}
    </div>
  );
});
```

### Slots

Support default and named slots for flexible content projection:

```jsx
element('my-card', (props) => (
  <article>
    {/* Named slot via props.slots */}
    <header>{props.slots?.title}</header>
    {/* Default slot via props.children */}
    <main>{props.children}</main>
    <footer>{props.slots?.footer}</footer>
  </article>
));
```

Usage:
```html
<my-card>
  <h1 slot="title">Card Title</h1>
  <p>Default slot content</p>
  <small slot="footer">© 2025</small>
</my-card>
```

### Reconnection Behavior

Elements reinitialize from scratch on reconnection:

```jsx
element('my-stateful', () => {
  let initCount = 0;
  initCount++; // Runs again on reconnect

  return <span>Initialized {initCount} times</span>;
});

const el = document.createElement('my-stateful');
document.body.appendChild(el); // initCount = 1
el.remove();
document.body.appendChild(el); // initCount = 2 (fresh start)
```

## Internal Mechanics

A sophisticated yet lightweight approach to binding reactive data directly to DOM elements.

#### Architecture

Every template element is represented as a **HellaNode** object containing categorized properties.

- **tag** - The HTML element name or fragment identifier (`"$"` for fragments)
- **props** - Static attributes and properties
- **on** - Delegated event handlers (`on:` prefix)
- **e** - Direct (non-delegated) event handlers (`e:` prefix)
- **bind** - Reactive bindings (`bind:` prefix)
- **hooks** - Lifecycle hooks (`hook:` prefix)
- **error** - Error configuration (`error:` prefix)
- **children** - Array of child HellaNodes or primitive values

```
HellaNode {
  tag: "div",
  props: { id: "my-div" },
  on: { click: handleClick },
  e: { submit: handleSubmit },
  bind: { class: isActive },
  hooks: { afterMount: init },
  error: { fallback: handleError, category: "sidebar" },
  children: [count, "text"]
}
```

Unlike virtual DOM systems that diff entire trees, HellaNodes serve as templates, establishing reactive connections during render.

#### Manual HellaNodes

For scenarios where JSX isn't available or when programmatically generating templates, you can construct HellaNodes directly.

```jsx
const Counter = () => {
  const count = signal(0);

  return {
    tag: 'div',
    children: [
      {
        tag: 'h1',
        children: count  // Function reference for reactivity
      },
      {
        tag: 'button',
        on: { click: () => count(count() + 1) },  // Delegated (recommended)
        children: 'Increment'
      }
    ]
  };
};

// With direct event handler (for specific use cases)
const Form = () => {
  return {
    tag: 'form',
    e: { submit: (event) => event.preventDefault() },  // Direct handler
    children: [
      {
        tag: 'input',
        props: { type: 'submit' }
      }
    ]
  };
};
```

#### Binding Process

When mounting a template, the system distinguishes between static values and function references to establish reactive bindings.

1. **Function Detection** - The mount system identifies function references in props and children
2. **Effect Creation** - Each reactive binding creates a dedicated effect using the core reactivity system
3. **Direct DOM Binding** - Effects update specific DOM properties without intermediate virtual representations
4. **Lifecycle Integration** - Element lifecycle hooks are wired directly to DOM mutation events

```
Signal Change → Effect Execution → Direct DOM Update
     ↑                                      ↓
     └── No Virtual DOM Diffing ←──────────┘
```

#### Dynamic Content

Dynamic children (conditional renders and function expressions) use a sophisticated comment-marker system for efficient DOM updates.

- **Boundary Markers** - HTML comments mark the start and end of dynamic content regions (`<!--start-->`, `<!--end-->`)
- **Content Replacement** - When expressions change, only content between markers is replaced
- **Fragment Support** - Multiple elements can be inserted or removed as cohesive units
- **Cleanup Coordination** - Removed elements trigger automatic effect cleanup and lifecycle hooks

#### Event Delegation

Global event delegation system in capture phase for maximum efficiency. A single listener per event type is attached to `document.body`.

When you write `<button on:click={handleClick}>`, HellaJS:
1. Creates a global click listener on `document.body` in capture phase (if none exists)
2. Stores your `handleClick` function directly on the button element
3. When clicked, the global listener routes the event to your handler via `composedPath()` traversal

**Benefits**: 1,000 buttons = 1 click listener (not 1,000). Capture-phase delegation enables consistent event handling. Direct property storage eliminates Map lookup overhead.

#### Direct Event Handlers

For cases where delegation isn't suitable, use the `e:` prefix to attach event handlers directly to elements:

```jsx
<button e:click={handleClick}>Click</button>
<button e:submit={handleSubmit}>Submit</button>
```

Direct handlers:
- Attach via `addEventListener` directly to the element
- Fire in the bubble phase (default DOM behavior)
- Support predictable `stopPropagation()` behavior
- Are automatically cleaned up when elements are removed

**Trade-offs**: Direct handlers create one listener per element vs. one global listener. Use sparingly and only when delegation causes issues.

#### List Optimization

The `ForEach` component implements advanced list diffing using the Longest Increasing Subsequence (LIS) algorithm.

- **Key-Based Tracking** - Items are tracked by unique keys for efficient reordering
- **Minimal DOM Operations** - Only elements that actually need moving are repositioned
- **Memory Efficiency** - Node references are cached and reused across updates
- **Performance Scaling** - Algorithms ensure performance remains optimal even with large lists
- **Boundary Markers** - `<!--forEach-->` comments mark list boundaries

#### Memory Management

Element lifecycle is managed through direct property storage combined with automatic observation.

- **MutationObserver Integration** - A global observer watches for DOM removals and processes each removed node
- **Property-Based Storage** - Effects and handlers are stored directly on elements as properties (`__hella_effects`, `__hella_handlers`)
- **Automatic Cleanup** - When elements are removed, the observer recursively cleans all descendants
- **Memory Efficiency** - No separate registry Map overhead, reducing memory footprint by ~50%
- **Memory Safety** - Circular references are prevented through coordinated cleanup sequencing

#### Rendering

The complete rendering process follows this optimized pipeline.

1. **Template Transformation** - JSX transforms to HellaNode at compile-time; html`` parses to HellaNode at runtime with WeakMap caching
2. **Component Wrapping** - Non-passthrough components wrapped with `componentScope()` for automatic effect cleanup (passthrough: Lazy, ForEach, Portal)
3. **HellaNode Resolution** - Templates are converted to HellaNode objects
4. **Element Creation** - Real DOM elements are created for each HellaNode
5. **Property Binding** - Static properties set directly, `bind:` properties create effects
6. **Child Mounting** - Child elements recursively processed and appended
7. **Effect Activation** - All reactive bindings begin tracking dependencies
8. **Lifecycle Registration** - Elements registered for automatic cleanup on removal

**Boundary Markers:**
- `<!--start-->` / `<!--end-->` - Dynamic content regions
- `<!--forEach-->` - ForEach list boundaries
- `<!--portal-->` - Portal marker for cleanup tracking
- `<!--lazy-start-->` / `<!--lazy-end-->` - Lazy loading boundaries
