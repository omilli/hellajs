# Routing

Reactive client-side routing that integrates seamlessly with the reactivity system.

## Mental Model

HellaJS routing works through three primitives:

- **[`router`](/reference/router/router)** configures route patterns and their handlers
- **[`route`](/reference/router/route)** is a reactive signal holding the current path, params, query, and handler
- **[`navigate`](/reference/router/navigate)** triggers programmatic navigation

Route handlers execute immediately when their pattern matches. The typical pattern is a signal that holds the current view, updated by each route handler:

```jsx
import { router, navigate } from '@hellajs/router';
import { signal } from '@hellajs/core';

const currentView = signal(null);

router({
  routes: {
    '/': () => currentView(<HomePage />),
    '/about': () => currentView(<AboutPage />),
    '/todos/:id': (params) => currentView(<TodoDetail id={params.id} />)
  },
  notFound: () => currentView(<NotFound />)
});
```

The `currentView` signal drives the UI — when navigation occurs, the matching handler updates the signal and any reactive dependencies re-render automatically.

## Route Parameters

### Dynamic Segments

Parameters are extracted from the URL and passed as the first argument to route handlers.

```jsx
import { router } from '@hellajs/router';
import { signal } from '@hellajs/core';

const currentView = signal(null);

router({
  routes: {
    '/users/:userId/todos/:todoId': (params) => {
      // /users/42/todos/7 → params.userId = '42', params.todoId = '7'
      currentView(<UserTodo userId={params.userId} todoId={params.todoId} />);
    }
  }
});
```

### Query Parameters

Query parameters are parsed automatically and passed as the second argument.

```jsx
router({
  routes: {
    '/search': (params, query) => {
      // /search?q=hello&sort=date → query.q = 'hello', query.sort = 'date'
      currentView(<SearchResults term={query.q} sort={query.sort} />);
    }
  }
});
```

### Wildcard Routes

The `*` syntax captures all remaining path segments.

```jsx
router({
  routes: {
    '/files/*': (params) => {
      // /files/docs/readme.md → params['*'] = 'docs/readme.md'
      currentView(<FileViewer path={params['*']} />);
    }
  }
});
```

All route parameters and query values are strings — cast to other types as needed.

## Nested Routes

Routes can be organized hierarchically using the `children` property. Child routes automatically inherit parameters from their parents.

```jsx
import { router } from '@hellajs/router';
import { signal } from '@hellajs/core';

const currentView = signal(null);

router({
  routes: {
    '/admin': {
      handler: () => currentView(<AdminDashboard />),
      children: {
        '/users': {
          handler: () => currentView(<UsersList />),
          children: {
            '/:id': (params) => currentView(<UserDetail id={params.id} />)
          }
        },
        '/settings': () => currentView(<AdminSettings />)
      }
    }
  }
});

// /admin → AdminDashboard
// /admin/users → UsersList
// /admin/users/123 → UserDetail (params.id = '123', inherited from nested match)
// /admin/settings → AdminSettings
```

Key benefits of nested routes:

- **Hierarchical organization** — route structure mirrors application structure
- **Parameter inheritance** — child routes receive all parent parameters automatically
- **Hook cascading** — parent hooks execute before child hooks, enabling guard patterns
- **Shared layout** — parent handlers set up layout, children fill in content areas

## Route Hooks

Routes can be defined as objects with `before`, `after`, and `handler` properties for lifecycle control.

```jsx
import { router, navigate } from '@hellajs/router';
import { signal } from '@hellajs/core';

const currentView = signal(null);

router({
  routes: {
    '/profile': {
      before: () => {
        if (!isAuthenticated()) {
          navigate('/login');
        }
      },
      handler: () => currentView(<UserProfile />),
      after: () => trackPageView('profile')
    }
  }
});
```

Hooks execute in cascade order for nested routes:

1. Global `before` hooks
2. Parent `before` → child `before` (top-down)
3. Route `handler`
4. Child `after` → parent `after` (bottom-up)
5. Global `after` hooks

See [`router`](/reference/router/router) for all hook configuration options.

## Route Guards

Guards use `before` hooks to protect routes. A critical detail: `before` hooks execute before the handler, but **do not block handler execution** — the handler always runs regardless of what the `before` hook does. Check auth state inside the handler for reliable access control.

```jsx
import { router, navigate } from '@hellajs/router';
import { signal } from '@hellajs/core';

const user = signal(null);
const currentView = signal(null);

const requireAuth = () => {
  if (!user()) navigate('/login');
};

router({
  routes: {
    '/login': () => currentView(<LoginPage />),
    '/dashboard': {
      before: requireAuth,
      handler: () => {
        // Guard the view state inside the handler
        if (!user()) return;
        currentView(<Dashboard user={user()} />);
      }
    },
    '/admin': {
      before: requireAuth,
      children: {
        '/settings': {
          before: () => {
            if (!user()?.isAdmin) navigate('/dashboard');
          },
          handler: () => {
            if (!user()?.isAdmin) return;
            currentView(<AdminSettings />);
          }
        }
      }
    }
  }
});
```

Multiple guards stack naturally through nesting — each level adds its own `before` check.

## Redirects

The router supports three redirect mechanisms.

```jsx
// String redirects — simplest form
router({
  routes: {
    '/home': '/',              // Redirect /home → /
    '/profile': '/user/me'     // Redirect /profile → /user/me
  }
});

// Global redirects — multiple sources to one destination
router({
  routes: {
    '/todos': () => currentView(<TodoList />)
  },
  redirects: [
    { from: ['/tasks', '/items', '/list'], to: '/todos' }
  ]
});
```

## Navigation

The [`navigate`](/reference/router/navigate) function provides programmatic routing with parameter substitution, query strings, and scroll control. Navigation is asynchronous — route state updates on the next microtask.

```jsx
import { navigate } from '@hellajs/router';

// Static path
navigate('/dashboard');

// Parameter substitution → /users/123
navigate('/users/:id', { params: { id: '123' } });

// With query string → /search?q=hello&sort=date
navigate('/search', { query: { q: 'hello', sort: 'date' } });

// Replace history entry (user cannot go back)
navigate('/login', { replace: true });

// All options combined
navigate('/users/:id', {
  params: { id: '123' },
  query: { tab: 'overview' },
  replace: true,
  scroll: 'top',
  meta: { analytics: 'user-view' }
});
```

### Navigation in Components

```jsx
const TodoList = ({ todos }) => {
  const viewTodo = (id) => {
    navigate('/todos/:id', { params: { id: String(id) } });
  };

  return (
    <ul>
      <ForEach each={todos}>
        {(todo) => (
          <li>
            <span>{todo.text}</span>
            <button on:click={() => viewTodo(todo.id)}>View</button>
          </li>
        )}
      </ForEach>
    </ul>
  );
};
```

See [`navigate`](/reference/router/navigate) for all navigation options including scroll overrides and metadata.

## Route Signal

The [`route`](/reference/router/route) signal provides reactive access to the current route information. Components can read it directly to respond to navigation changes.

```jsx
import { route } from '@hellajs/router';
import { effect } from '@hellajs/core';

// Update page title reactively
effect(() => {
  const { meta, path } = route();
  document.title = meta?.title || 'My App';
});

// Use in components
const Breadcrumbs = () => (
  <nav>
    <span>Path: {route().path}</span>
    {route().params.id && <span> / Item {route().params.id}</span>}
  </nav>
);
```

Route metadata is defined per-route and accessed via `route().meta`:

```jsx
router({
  routes: {
    '/about': {
      meta: { title: 'About Us', requiresAuth: false },
      handler: () => currentView(<AboutPage />)
    },
    '/admin': {
      meta: { title: 'Admin Panel', requiresAuth: true },
      handler: () => currentView(<AdminPanel />)
    }
  }
});
```

See [`route`](/reference/router/route) for the complete `RouteInfo` structure.

## Router Modes

The router supports two URL modes.

```jsx
// History API (default) — clean URLs: example.com/about
router({
  routes: { '/about': () => currentView(<AboutPage />) }
});

// Hash mode — no server config needed: example.com/#/about
router({
  mode: 'hash',
  routes: { '/about': () => currentView(<AboutPage />) }
});
```

## Scroll Behavior

Control scroll position after navigation at three levels of specificity.

```jsx
// Global default
router({
  scrollBehavior: 'top', // 'auto' (default) | 'top' | 'preserve'
  routes: { /* ... */ }
});

// Route-level override
router({
  scrollBehavior: 'top',
  routes: {
    '/feed': {
      scroll: 'preserve', // Override: keep scroll position
      handler: () => currentView(<Feed />)
    },
    '/chat': {
      scroll: false, // Disable scroll handling
      handler: () => currentView(<Chat />)
    }
  }
});

// Inline override (highest priority)
navigate('/long-page', { scroll: 'top' });
```

Custom scroll functions receive `(to, from)` paths and return `{ top, left? }` or `null` to skip.

**Scroll priority:** Inline `navigate()` > Route-level `scroll` > Global `scrollBehavior`

See [`router`](/reference/router/router) for all scroll configuration options.

<summary>Internal Mechanics</summary>

Reactive routing with minimal overhead while integrating seamlessly with HellaJS's signal system.

#### Route Resolution Engine

The router implements a **5-phase resolution algorithm** that processes routes in strict priority order. Understanding this algorithm is crucial for predicting route behavior in complex applications.

**Phase 1: Global Redirects**
```typescript
// Processed first - highest priority
router({
  redirects: [
    { from: ['/old-path', '/legacy'], to: '/new-path' }
  ],
  routes: { '/new-path': () => handleNewPath() }
});
```

**Phase 2: Route Map Redirects**
```typescript
// String values in routes object
router({
  routes: {
    '/home': '/', // Redirect /home to /
    '/': () => handleHome()
  }
});
```

**Phase 3: Nested Route Matching**
```typescript
// Hierarchical routes with parameter inheritance
router({
  routes: {
    '/api': {
      children: {
        '/v1': {
          children: {
            '/users': () => handleUsers() // More specific wins
          }
        },
        '/*': () => handleApiWildcard() // Less specific
      }
    }
  }
});
```

**Phase 4: Flat Route Matching**
```typescript
// Traditional flat routes as fallback - order matters!
router({
  routes: {
    '/users/admin': () => handleAdminUser(), // Listed first, matches first
    '/users/:id': (params, query) => handleUser(params.id) // Dynamic fallback
  }
});
```

**Phase 5: Not Found Handler**
```typescript
// Final fallback for unmatched paths
router({
  routes: { /* ... */ },
  notFound: () => handle404()
});
```

**Specificity Rules:**
- Nested routes are sorted by specificity: non-wildcard before wildcard, deeper paths before shallow
- Flat routes match in object entry order (list specific routes before generic ones)
- Nested routes are processed before flat routes (phase order)
- For flat routes with overlapping patterns, order matters in the routes object

**Parameter Inheritance:**
```typescript
// /users/123/profile
router({
  routes: {
    '/users/:userId': {
      children: {
        '/profile': (params, query) => {
          // params = { userId: '123' }
          // Child inherits parent parameters automatically
          return showUserProfile(params.userId);
        }
      }
    }
  }
});
```

Each phase uses **early termination** - once a match is found, processing stops immediately without checking subsequent phases.

#### Reactive State Management

The router maintains all internal state using [signals](/reference/core/signal) from `@hellajs/core`, creating a naturally reactive system.

```
Current Route Signal
    ↓
Route Handler Execution
    ↓
Component State Updates
    ↓
Automatic UI Re-rendering
```

The `route` signal contains the complete routing context including handler, parameters, query string, and current path, enabling components to reactively respond to any routing changes.

#### Parameter Extraction Algorithm

Dynamic path matching uses a single-pass algorithm that efficiently extracts parameters.

1. **Pattern Parsing** - Route patterns are split by `/` and analyzed for dynamic segments
2. **Segment Matching** - Each URL segment is matched against its corresponding pattern segment
3. **Parameter Capture** - `:parameter` segments extract their values into the params object
4. **Wildcard Handling** - `*` segments capture all remaining path components
5. **Type Safety** - TypeScript template literals provide compile-time parameter validation

#### Navigation State Coordination

The router processes each navigation through a coordinated pipeline:

- **URL Change Detection** - `popstate` events and `navigate()` calls trigger route updates
- **Route Resolution** - 5-phase algorithm (above) determines matching route, including parameter inheritance for nested routes
- **State Updates** - Reactive `route()` signal updates with matched params, query, and meta
- **Hook Execution** - Before hooks execute in cascade order (global → parent → child)
- **Handler Invocation** - Only the final matched route handler executes
- **Cleanup Hooks** - After hooks execute in reverse cascade order (child → parent → global)

**Hook Execution Order:**
```typescript
// For route: /admin/users
router({
  routes: {
    '/admin': {
      before: () => console.log('Admin before'),
      after: () => console.log('Admin after'),
      children: {
        '/users': {
          before: () => console.log('Users before'),
          handler: () => console.log('Users handler'),
          after: () => console.log('Users after')
        }
      }
    }
  },
  hooks: {
    before: () => console.log('Global before'),
    after: () => console.log('Global after')
  }
});

// Output: Global before → Admin before → Users before → Users handler → Users after → Admin after → Global after
```

#### History Management

The router provides intelligent history management using the HTML5 History API.

- **History Mode** - Uses `pushState`/`replaceState` for clean URLs with server support requirements
- **Hash Mode** - Uses `hashchange` events with `#/path` URL format, no server config required

The router maintains proper browser history behavior including back/forward navigation and bookmark support.


#### Browser Integration

The router provides seamless browser integration:

- **History API** - Uses `pushState`/`replaceState` for clean URLs
- **Automatic Navigation** - Handles back/forward button navigation
- **URL Encoding** - Proper parameter and query string encoding
- **Server-Side Safe** - All DOM operations are safely wrapped
