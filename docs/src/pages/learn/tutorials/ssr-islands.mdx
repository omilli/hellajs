# Build an SSR Islands App

Render a static HTML shell on the server with [`ssr`](/reference/ssr/ssr), then make it interactive on the client without a full re-render: mount a reactive island into an empty slot the server left open. No router, no full-tree [`hydrate`](/reference/dom/hydrate) — the lightest server-rendered mode.

Jump to the [Complete Code](#complete-code) for the finished application.

## What You'll Learn

- **[`ssr`](/reference/ssr/ssr)**: Serialize a template to an HTML string on the server
- **[`doc`](/reference/ssr/doc)**: Wrap rendered HTML into a full document with a stylesheet and script tag
- **[`css`](/reference/css/css)**: Define styles that return CSS text on the server (no DOM), exported for `doc()` to emit
- **[`mount`](/reference/dom/mount)**: Mount a reactive island into an empty slot the server left open

This example runs entirely on [Bun](https://bun.sh): `Bun.serve` renders the shell and `Bun.build` bundles the client at startup — one runtime, one command, no separate build step. The [`html`](/reference/dom/html) tag parses templates at runtime, so no compile-time plugin is needed.

## Project Setup

### Installation

Create a project folder and install the packages. This tutorial requires [Bun](https://bun.sh) for the server.

```bash
mkdir ssr-islands && cd ssr-islands
bun init -y
bun add @hellajs/core @hellajs/dom @hellajs/ssr @hellajs/css
```

### Configuration

`package.json` marks the project as an ES module and adds a single `start` script. `Bun.build` handles the client bundle at server startup, so there is no `build` script and no second tool.

```json
{
  "name": "ssr-islands",
  "private": true,
  "version": "0.0.0",
  "type": "module",
  "scripts": {
    "start": "bun src/server.js"
  }
}
```

## The App Template

The shared module exports two things: the page's styles and a static shell template — a heading plus an empty slot for the island. Both are pure data, no DOM. The server renders the template with [`ssr`](/reference/ssr/ssr) and emits the styles via [`doc`](/reference/ssr/doc); the client mounts an island into the slot by selector.

Create `src/app.js`:

```js
// src/app.js
import { html } from '@hellajs/dom';
import { css } from '@hellajs/css';

export const styles = css({
  body: {
    fontFamily: 'sans-serif',
    margin: '2rem',
    color: '#333',
  },
  '#slot button': {
    marginTop: '1rem',
    padding: '0.5rem 1rem',
    fontSize: '1rem',
    cursor: 'pointer',
    borderRadius: '0.375rem',
    border: '1px solid #2563eb',
    backgroundColor: '#fff',
  },
});

export const App = () => html`
  <div>
    <h1>SSR Islands</h1>
    <div id="slot"></div>
  </div>
`;
```

**Code Explanation**

- **[`html`](/reference/dom/html)**: A tagged template that parses to a HellaNode AST at runtime (no build step). Interpolations become reactive bindings
- **[`css`](/reference/css/css)`({ ... })`**: On the server (no DOM), returns the generated CSS text instead of injecting a stylesheet. Exported as `styles` so the server can emit it through `doc()`
- **`<div id="slot"></div>`**: An empty placeholder. The client mounts a reactive island here

## Server Rendering

The server stringifies the template with [`ssr`](/reference/ssr/ssr) and wraps it into a full document with [`doc`](/reference/ssr/doc). It imports the server-generated `styles` from `app.js` and passes them to `doc()`'s `styles` to emit a single `<style>` tag. `Bun.build` bundles the client once at startup, resolving the bare `@hellajs/*` specifiers the browser can't.

Create `src/server.js`:

```js
// src/server.js
import { ssr, doc } from '@hellajs/ssr';
import { App, styles } from './app.js';

const build = await Bun.build({ entrypoints: ['src/client.js'], target: 'browser' });
if (!build.success) throw new Error(`client build failed:\n${build.logs}`);
const client = await build.outputs[0].text();

Bun.serve({
  port: 3000,
  fetch(req) {
    const { pathname } = new URL(req.url);

    if (pathname === '/client.js') {
      return new Response(client, {
        headers: { 'content-type': 'text/javascript' },
      });
    }

    const page = doc({
      head: {
        title: 'SSR Islands',
        styles: [styles],
        scripts: [{ src: '/client.js', type: 'module' }],
      },
      body: ssr(App()),
    });

    return new Response(page, { headers: { 'content-type': 'text/html' } });
  },
});
```

**Code Explanation**

- **`import { App, styles } from './app.js'`**: Pulls the template and the server-generated CSS text from the shared module
- **[`ssr`](/reference/ssr/ssr)`(App())`**: Walks the template AST to an HTML string. `App()` runs server-side; `html` parsing is DOM-free
- **`Bun.build({ entrypoints, target: 'browser' })`**: Bundles `src/client.js` once at startup, resolving the bare specifiers. Held in memory — no `dist/` to manage. Edit the client and restart to re-bundle
- **[`doc`](/reference/ssr/doc)`({ head, body })`**: Assembles a full document. `styles` joins into one `<style>` tag; `scripts` emits each tag

## Client Enhancement

The client mounts a reactive `Counter` island into the empty `#slot` the server left open. The island owns the count — a `<p>` bound to the signal plus an Increment button — so the server shell needs no full re-render.

Create `src/client.js`:

```js
// src/client.js
import { signal } from '@hellajs/core';
import { html, mount } from '@hellajs/dom';

const count = signal(0);

const Counter = () => html`
  <p>Count: ${count}</p>
  <button on:click=${() => count(count() + 1)}>
    Increment
  </button>
`;

mount(Counter, '#slot');
```

**Code Explanation**

- **[`signal`](/reference/core/signal)`(0)`**: Holds the click count
- **`<p>Count: ${count}</p>`**: A reactive text binding. Interpolating the signal creates a node that updates automatically when `count` changes
- **`on:click=${() => count(count() + 1)}`**: Updates the signal value on click
- **[`mount`](/reference/dom/mount)`(Counter, '#slot')`**: Renders the island into the empty slot. The server left `#slot` empty, so nothing is wiped

<div role="alert" class="alert alert-error text-base">
  <Icon name="ph:warning" width={24} height={24} />
  <span>mount calls replaceChildren on its target — pointing it at any element the server already populated wipes that HTML. Always mount into an empty slot.</span>
</div>

**Good:** Target the empty server slot
```js
mount(Counter, '#slot');
```

**Bad:** Target a populated container — wipes its contents
```js
mount(Counter, 'body'); // replaceChildren destroys the server HTML
```

## Run the App

Start the server. It bundles the client at startup and serves both the rendered HTML and the client bundle.

```bash
bun src/server.js
```

The server renders at `http://localhost:3000`. The initial HTML contains the server-rendered shell with an empty slot:

```bash
curl -s localhost:3000
# <!DOCTYPE html>...<h1>SSR Islands</h1>...<div id="slot"></div>...
```

After the client script loads, the `Counter` island mounts into `#slot`. Clicking Increment updates the count reactively — without replacing the server-rendered shell.
